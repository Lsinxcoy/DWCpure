## 二、影子的三宗罪（实测，不是感觉）

### 罪 1 · 影子把"该决的事"推给时间，但时间不会替你决

```python
# 母巢 gene_applier.py 原文
"""影子开关:
    SHADOW=True (默认) → 只出计划与缺口清单, 绝不 mutate.
    生产观测满 20 tick 且 need_setter 清零后, 经
    gene_applier.set_shadow(False) 翻真实应用.
"""
SHADOW = True  # 影子开关: True=只出计划; False=真写运行时旋钮
```

**"生产观测满 20 tick 且 need_setter 清零后" —— 这个条件谁来判？没人。**

```text
实测: set_shadow(False) 全仓调用 0 次
⇒ 影子期永不到期
⇒ 这不是"谨慎", 是"永久搁置"
```

### 罪 2 · 影子期的"观测"本身没有判据

```text
母巢的观测目标是 "need_setter 清零" —— 即"消费点都接好了"
但这不是"进化好不好"的判据, 只是"接线完不完成"的判据。

★ 关键区别:
  影子期该回答的问题是: "这个变更好不好?"
  母巢的观测条件回答的是: "这个变更接好了没?"
  ⇒ 两者不是一回事。观测了 20 tick 也不知道好不好。
```

### 罪 3 · 影子转正率实测 = 0

```text
母巢 GeneChampion 实测 (源码注释原文):
  "124 次回退 (实测 promoted=1/reverted=124)"
  "0.1→0.9 判 reverted gain=0.0"
  "4/7 轮回退的 gain 恰为 0.0 (逐位相同)"

★ 即: 影子期跑了很多次, 结论永远是"回退"。
  转正 1 次 / 回退 124 次 = 转正率 0.8%
  ★ 这不是"门很严", 是"门根本没有分辨率" (见下)
```

**根因（母巢自己诊断的）**：

```python
# gene_champion.py 原文注释
#   真因: `score_in` 是**量化阶梯函数** (由 _tick_summary 离散计数
#   决定 _base), 同一台阶内基因无分辨率 ⇒ gain 恒 0,
#   **降门槛无用**。4/7 轮回退的 gain 恰为 0.0 (逐位相同)。
```

**★ 影子的真正问题：它需要一个"能分辨好坏"的打分器。没有分辨率的打分器 + 影子期 = 无限回退。**

## 三、★ 你自己的替代方案：离线回放（已实现 + 已接线）

### 3.1 源码原文

```python
# 母巢 evolution/offline_replay.py (P2, 2026-09-21)
"""P2 (2026-09-21): 离线回放选择器 — Dream-RSI §3 的落地, **替代影子制度**.

## 论文依据 (arXiv 2609.14858 §3)

Dream-RSI 的核心不是"上线观察", 而是**离线在冻结历史上回放**:

    V = max_v s_v − β₁·N + β₂·N / max{1, k}

  - `max_v s_v` = 发现质量 (历史树上最好节点的分数)
  - `− β₁·N`    = 执行成本惩罚 (N = 揭示的非根节点数)
  - `+ β₂·N/k`  = 并行度收益 (k = 并行 worker 数)

**不回退保证** (论文原文):

> Because the candidate set includes the current policy, this selection
> satisfies V^{m⋆} ≥ V^0. Thus, the selected policy π_{t+1} is **no worse**
> than the current policy π_t in average replay score on the fixed history.

⇒ 候选集**必含当前策略** ⇒ argmax 的结果**不可能差于现状**。
这是**数学结论**, 不是经验观察 ⇒ **不需要影子期、不需要到期裁决**。

## 与影子的分界 (本模块的设计理由)

| | 影子 | 本模块 |
|---|---|---|
| 在哪跑 | 生产上被动观察 | **离线** (冻结历史) |
| 何时决 | N 天后 | **算完即决** |
| 安全来源 | 经验观察 | **数学保证** V^{m⋆} ≥ V^0 |
| 母巢实测 | 转正率 **0** | — |
"""
```

**★ 这张对照表就是答案** —— 而且是你自己写的。

### 3.4 任务源：同一批任务，确定性切分

```python
# evolution/probe_tasks.py 原文
"""探针任务源 —— 从母巢**真实状态**取任务, 不用人造样本.

方差唯一合法来源 = 任务差异, 所以任务必须是真的、且对候选与在位者**同一批**
```

## 四、DWC 的替代方案：离线回放（不要影子）

### 4.1 三个替代

```text
影子机制                      →  DWC 替代
──────────────────────────────────────────────────────────
① 生产上被动观察 N tick       →  离线在冻结历史/同一批任务上回放
② N 天后到期裁决              →  算完即决 (没有等待期)
③ 安全靠"经验观察"            →  安全靠数学保证 V^{m⋆} ≥ V^0
                                (候选集必含 current ⇒ argmax 不差于现状)
```

### 4.2 落地器改造（去掉 window 与 promoted/reverted）

```text
母巢 GeneChampion 的形态 (有影子残留):
  cold → hold → explore → evaluating(窗口 N tick) → promoted | reverted
                                ↑ 这一段就是影子

DWC 落地器的形态 (无影子):
  snapshot(current) → score_all(current + candidates) → argmax → apply
  
  ① 取当前配置 (current)
  ② 在同一批任务上给 current 和所有候选打分
  ③ argmax (候选集含 current ⇒ 结果不差于现状)
  ④ 应用胜出者 (带读回验证)
  ⑤ 无等待期, 无到期裁决
```

### 4.3 但离线回放有两个已知代价（论文自陈）

```python
# offline_replay.py 原文
"""## 诚实边界

- 保证只在**模拟器内**成立: 若 probe 集不代表真实分布, 离线赢 ≠ 线上赢。
  这是论文的**已知代价**, 靠 probe 集覆盖度缓解 (已有 `probe_tasks.py`)。
- 本模块是**纯函数层**, 不碰注册表、不 enable/prune、不写任何状态。
"""
```

**★ 即：离线回放的安全性来自"probe 集代表真实分布"。这一条必须守住。**

```text
DWC 必须做的:
  ① probe 集必须从真实状态取 (照 probe_tasks.py, 不造人造样本)
  ② 候选与在位者必须跑同一批任务 (同 tick 快照)
  ③ 抽样必须确定性 (无随机/无时钟 ⇒ 可复现)
```

## 五、★ 还有一半问题没解：打分器分辨率

```text
离线回放解决了"何时决"和"安全来源"。
但没有解决"打分器有没有分辨率"。

★ 你自己的项目里也有答案 —— task_contract.py (P3-B 秤芯):

"""任务条件化校准分数 v(task, output) ∈ [0,1] —— P3-B 秤芯.

## 为什么存在 (取证, 非推断)

旧秤 `effect_tracker._compute_task_output_score` 的四分量
(presence 0.2 / richness 0.3 / novelty 0.2 / quality 0.5) **全是输出形状**:
键的个数、输出长度、与自己最近 8 条历史输出的 3gram 相似度。零分量问"任务解没解",
且判分依赖历史状态。实测同一批 probe: 实干 0.5359 vs 空壳 0.8504 (方向反了),
换历史状态后 Δ 翻号 ⇒ 生产 `eff` 全史只有 3 个取值、含信息量比较 0 次。

## 本模块的口径 (名字 ⟷ 实现对齐, 不夸大)

`score_output` 只测两件**客观可判据、且随任务变化**的事:
1. **否决** (hard 0): 抛错 / `ok is False` / 空产出 / `schema_violation`。
2. **任务接地 grounding**: 输出是否引用了任务实际提供的实体 (id / 内容片段)。
   比例 = 命中实体数 / 任务实体数。

## 硬约束 (旧秤病根的免疫)
- 只依赖 `(task, output)`; **禁止**读历史输出、输出长度、键的个数。
- 无隐藏维度: 参与计分的维度全部来自 `contract` 声明; 未声明 ⇒ 不评分。
- 无可评维度 ⇒ 返回 `None` (诚实"不可评"), **不得**伪造 0/0.5。
- 纯函数, 零 `try/except`, 零随机, 零时钟。
"""
```

**★ 四条硬约束正是"打分器有分辨率"的判据**：

```text
① 只依赖 (task, output) —— 不读历史 ⇒ 同一任务恒同分 (可复现)
② 维度全部声明 —— 无隐藏维度 ⇒ 分数可解释
③ 不可评返回 None —— 不伪造 ⇒ 不会用假分数骗过门
④ 纯函数零随机零时钟 —— 可复现

★ 关键实测 (旧秤的病): "实干 0.5359 vs 空壳 0.8504 (方向反了)"
  ⇒ 打分器反向! 这是比"没分辨率"更严重的病
```

## 六、DWC 应用层最终形态（无影子）

```text
┌──────────────────────────────────────────────────────────────┐
│ ① 打分器 (scorer)                                             │
│    约束: 只依赖 (task, output) / 无隐藏维度 / 不可评返回 None  │
│          / 纯函数零随机零时钟                                  │
│    ★ 先验证分辨率: 不同配置在同一批任务上必须产出不同分         │
├──────────────────────────────────────────────────────────────┤
│ ② 任务源 (probe)                                              │
│    从真实状态取 / 确定性切分 / 候选与在位者同一批               │
├──────────────────────────────────────────────────────────────┤
│ ③ 选择器 (offline replay)                                     │
│    V = max(s) − β₁·N + β₂·N/max(1,k)                          │
│    候选集必含 current ⇒ 数学保证不回退                         │
│    ★ 算完即决, 无等待期                                       │
├──────────────────────────────────────────────────────────────┤
│ ④ 落地器 (applier)                                            │

│ ⑤ 回滚器 (rollback)                                           │
│    存旧值; 回退 = 写回 + 读回确认                              │
└──────────────────────────────────────────────────────────────┘

★ 全程无"影子"二字: 没有被动观察期, 没有到期裁决, 没有"等 N tick"
```

## 七、一句话

```text
影子 = 用时间换安全。
但实测: 母巢影子转正率 0.8%, 且根因是打分器没分辨率 ——

安全来自: ① 候选集必含 current (数学保证) ② probe 集真实 ③ 打分器可复现

★ 两者都不是"更谨慎"或"更激进", 是"一个有判据, 一个没有"。
```
