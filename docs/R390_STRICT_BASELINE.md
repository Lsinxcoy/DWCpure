三、R389 · 猜测不记功
════════════════════════════════════════════════════════════
现场（rf05）：

    问：DWC 记忆系统内核类名？
    答：抱歉，我目前没有关于 DWC 记忆系统内核类名的**可用取证信息**，
        无法给出确切的类名（例如**可能是** MemoryKernel…）
    判据：contains "MemoryKernel"  ⇒  ✓

模型自己都说没取证，判据却把"猜对了"当"找到了"。

修法（保守，避免误伤）：
· 统一前置门 `_hedge_block()` —— contains / contains_any /
  contains_equiv / contains_all / regex 五类全过这道门
· 命中明确的猜测/弃权措辞 ⇒ 判 ✗，how 记 `guess-credit-blocked`
· 措辞表只收**明确的**（可能是/大概是/推测/无法确认/没有取证…）
· **"如果…则…"这类假设句不收**（太常见，会误杀正常答案）
· `allow_guess: true` 显式豁免（开放题允许推测）

四、R390 · 三个"命令跑不通"的坑（7 单 incomplete 的主因）
════════════════════════════════════════════════════════════
① **无空格串联**：`ls; find . -iname README*` 被 shlex 切成
   `['ls;', 'find', ...]` —— 首 token 带 `;`，不是可执行文件
   ⇒ nb_1020_185728_32 卡死 11 轮。
   修：识别**首尾**分隔符并切分。

② **`cd` 是 shell 内建**（Windows 无 cd.exe）：模型写
   `cd . && ls -la` / `cd src; ls` ⇒ 必然失败。
   修：跳过 `cd` 段，取下一段真命令。

③ **不能按中间 `|` 切**：`-E "max_round|max_rounds"` 里是 grep 的
   **交替模式**，按字符串切会切坏（只搜 `max_round`）。
   修：只认**首尾**分隔符，中间 `|` 原样保留。

六、诚实边界
════════════════════════════════════════════════════════════
1. **55.6% 仍是单次跑批**，无重复采样；端点有波动。
2. `_HEDGE_PATTERNS` 是**黑名单**式检测：模型换说法（"据我推断"、
   "从上下文看应该是"）可能漏网；按**全文**扫描偏严（长答案里出现
   一次"不确定"就整条判 ✗）。
3. `_agent_ran` 的 needle 是子串匹配：同一文件不同用例无法区分。
4. **code-locate 2/10 = 20% 是当前最弱项**，7 单 incomplete 里多数
   是"反复 ls/grep 同一路径被复读熔断"——模型探索策略差，不是工具坏了。
5. run-verify 的真实能力仍可能低于 40%：新判据只验"agent 跑过 + 复核绿"，
   没验"agent 是否真的用它来回答"。
6. 历史基线 13/39 = 33.3%（旧 harness）与本轮不可直接比较。
