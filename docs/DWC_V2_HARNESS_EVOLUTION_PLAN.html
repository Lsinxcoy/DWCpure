1 · 版本边界

做（六项能力）

#能力一句话验收
V2-1成本可观测每次调用都有 token 记账，可按任务/按轮汇总美元成本
V2-2输出可回溯截断后原文落盘，模型可按路径定向回读
V2-3预算可约束economy→strict→finalize 三段，finalize 后硬阻断
V2-4双目标进化fitness 同时含 pass_rate 与 cost，任一退化即 reject
V2-5按任务选档按任务特征选 profile，而非全局一个值
V2-6三档产物一轮进化产出 lite / medium / heavy 三套策略

不做（红线）

不做理由
label-free（放弃 ground truth）DWC 有真实评测池 53/54 = 98.1%，放弃真值是倒退
多候选并行（3 计划 × G=3）一轮 90 次调用会吃光日预算（96/80）
全 harness 重写19 对象已按维度隔离，全放开破坏结构完整性
CoP 当唯一 fitness成功数为 0 时发散；DWC 失败样本少，噪声爆炸
引入重型依赖预算/压缩/路由全部用 stdlib + 现有依赖

P1-a · 三段式预算（R441）

阶段触发行为
economy计数 ≥ 18提醒：批量独立检查、别重复读、别叙述过程
strict计数 ≥ 38，每 8 次重复提醒：停止发散，只查与当前失败直接相关的证据
finalize计数 > 60拒绝新工具调用，要求基于现有证据给最终答案
硬性红线：提醒只能追加到工具结果，不许重写 system prompt—— 否则 prompt cache 前缀失效，越省越贵。

P1-b · 双目标 fitness（R442）

scalar = realization * outcome                                  # 现有
scalar = scalar * (1 - cost_weight * normalized_cost_delta)     # 新增
新门判据
cost_measured本轮所有候选都有 cost_usd，否则 fail-closed
no_cost_regressioncost(cand) ≤ cost(base) × (1 + tolerance)

验收：「分数不变但成本翻倍」必须 reject；「+2pp 且成本 +5%」在 tolerance 内可 accept。

P1-c · 对比式探针 + 纠正继承式起草（R443）

这是本版本最重要的一条修正。 Harness² 实测：直接改基础 harness、不看参考执行 / 候选探针 / 库 ⇒ 性能反而下降 （WB-code 73.4 → 63.2，−10.2；WB-web 69.9 → 65.0，−4.9）。
而 DWC 现在正是这种模式：读签名 → 起草 → 试跑，且把上一轮的 p.code 当起点 = 继承。
#现状要改成
1trial 只产出 success/in_score/baseline_in，不比轨迹产出结构化行为对比：消失 / 未变 / 新增的失败模式
2Mutator.propose 把 p.code 当下轮起草起点下轮从基线起，只从库里按 cue 选择性取用
@dataclass
class Contrast:
    disappeared: list[str]   # 参考有、候选没有
    persisted:   list[str]   # 两边都有
    introduced:  list[str]   # 候选新增
    evidence:    dict        # 每条判定的观测依据

验收：三条列表之和 = 失败模式总数；无库时 propose 不得读上一轮 p.code（哨兵值断言）； 引入新失败模式的候选即使分数略高，也必须进 introduced 并被下游门看到。

P3 · 三档 Pareto（R446+）

d_perf = (P_max - P) / (P_max - P_min)
d_cost = (C - C_min) / (C_max - C_min)
J_m    = a_m * d_perf² + b_m * d_cost²
pick   = argmin(J_m)

(lite, medium, heavy) 的 (a, b) = (1,2) / (1,1) / (2,1)

验收：三档成本单调（lite ≤ medium ≤ heavy）；三档都过 PR ≥ PR(h0) 地板；可单独启用某一档。

P4 · 改进库：让"改进器"自己进化（R447+）

把 R438 #14 的 meta_evolution（只调一个旋钮）升级为带经验的改进器。

    INDEX.md                     # 索引：每条一行 cue
    entries/<task_id>/

        EXPERIENCE.md            # cue / lesson / evidence / confidence
#硬规则论文依据
1缺证据不入库：cue/lesson/evidence 任一为空 ⇒ 不写（返回 None，不写半条）library.py:43-47
2防泄漏：写库前断言无判据/评分；库只保留当前任务之前的条目library.py:101-104,122-123
3选择性复用：下轮从基线起，按 cue 取用，不自动继承§2.3
4库空时只能"恢复"不能"提升"：k=1 只能拉回基线，增益需 k≥5 的探索量Figure 7

验收：缺 evidence 写不进；含判据字样被拒；第二轮起草提示里出现第一轮 cue；删库 ⇒ 性能回基线。

6 · 风险与对策

风险后果对策
成本噪声大（单次 ±20%）误判"变贵了"两轮均值 + 极差；单轮结论不引用
预算过紧掉分通过率跌破地板PR ≥ PR(h0) 硬地板；finalize 后仍允许作答

三档维护成本配置爆炸三档共用对象定义，只差参数
