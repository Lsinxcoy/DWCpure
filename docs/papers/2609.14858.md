## 1. 问题

### 论文自己承认的缺口

论文把问题定位在**元层（meta-level）**：RSI 的引擎是"探索"，但探索策略本身通常是手工固定或在线试错的。

1. **固定策略不能从累积的发现经验中学习。** "Fixed strategies cannot improve from accumulated discovery experience and may repeatedly allocate computation to ineffective search directions."

2. **在线优化探索策略撞上两个瓶颈**（论文原话分列）：
   - **反馈延迟且昂贵（feedback is delayed and expensive at the meta level）**——"assessing an exploration policy requires observing how it shapes the subsequent discovery process over many proposal–evaluation cycles"。
   - **元策略空间巨大（the meta-policy space is vast）**——"a newly proposed policy may perform poorly, so many alternatives may need to be tried"。
   - 合并后果："each policy may require a long online rollout before receiving useful feedback, making it difficult to efficiently close the self-improvement loop at the exploration layer."

3. **已有做法对历史的两类用法都不够。** 论文点名：既有工作把历史当**静态文本上下文**（Hu 2025, Ouyang 2026b）或**权重微调训练数据**（Yuksekgonul 2026, Wang 2025）。而"a completed discovery process inherently records a structured tree of past exploration decisions and their realized code-execution outcomes"——**这个结构化资产此前被浪费了**。

论文的核心洞见（原文类比）："**Surprisingly, completed discovery histories already provide such a simulator.**"

## 2. 核心机制

### 2.1 探索策略的可编程化：编排层（orchestration layer）

设计上的第一个决策："We first make exploration explicit and programmable through a lightweight orchestration layer that controls **branching, parallel exploration, and stopping** while leaving the underlying coding agent unchanged."

**关键约束（全文反复强调）**："Only the exploration-policy code changes; the underlying models, evaluator, and execution interfaces remain fixed." 这是它与"改权重""改 harness"路线的分界。

### 2.2 Discovery Tree 数据结构

- 树根 r 表示**初始工作区状态**。
- 每个非根节点 v 有**恰好一个 primary parent**（根或先前创建的节点）。该 parent 标识"where the attempt in the discovery agent resumes the parent's saved workspace and uses its accumulated observations as context to produce a new attempt"。
- 节点保存 **inherited history**，并记录本次 generation–evaluation attempt 的产出：**resulting filesystem snapshot、generated artifact、evaluation diagnostics、score s_v**。
- 分数遵循"a fixed task-scoring protocol, with larger values indicating better quality"。

### 2.3 共享决策接口（Online 与 Offline 完全共用）

策略观察树 𝒯（初始只有根），选择从哪些节点继续探索。可选节点集合：

**A(𝒯) = {r} ∪ {v ∈ 𝒯 : v is a leaf}**

（"where leaves are determined from the currently observed tree"）

并行度 W = "the number of parallel workers, each of which can execute one generation–evaluation request at a time (e.g. concurrent API calls)"。

动作是**一个批次**：

**A(𝒯; W) = { C ⊆ A(𝒯) : |C| ≤ W }**

论文说明这个设计的意义："Each selected node specifies the starting point of one attempt, so the batch determines both **where** exploration continues and **how many** attempts are scheduled in parallel."

**在线与离线用同一个决策接口，区别只在 batch 之后的转移。**

### 2.4 Online rollout（外层迭代 t）

- 从初始策略与空历史开始；每次迭代 t，π_t 指导一次新 rollout，**可访问已完成的历史 ℋ_{t−1}**——但"this history provides context for exploration but **remains separate from the new tree being constructed**"。
- "The policy code stays fixed throughout the rollout."（单次 rollout 内策略冻结）
- 新树 𝒯_t^k（k = 已完成决策轮数），𝒯_t^0 = {r}；最多 **K₁** 轮。
- 第 k 轮：策略选 batch C_t^k ∈ A(𝒯_t^k; W)，每个节点分配给一个 worker，discovery agent 恢复 v 的工作区产出候选，evaluator 评估，**并行**，每个选中节点产生一个新子节点。
- **随机性来源**："This transition is stochastic because the discovery agent may generate different outcomes from the same starting workspace."
- 终止：策略选空 batch，或完成 K₁ 轮。
- 历史增长：**ℋ_t = ℋ_{t−1} ∪ {𝒯_t}**

### 2.5 Offline evaluation（"Dreaming"）

- 迭代 t 的离线阶段，ℋ_t **固定不变**，方法构造并评估 **M ≥ 1 个策略版本 π_t^0, …, π_t^{M−1}**，起始 π_t^0 = π_t（当前策略）。**每个版本在每个历史树上单独评估完毕，才从反馈中开发下一个版本。**
- 索引：m = 策略版本，i = replay world，k = 单次 policy–world 评估内的决策轮数。外层索引 t 在此阶段固定，notation 中省略。
- 对每个 (m, i) 对，replay **重置该策略的 per-rollout 状态**并从 𝒯_i^{m,0} = {r} 起步。**完整记录的树 𝒯_i 保持固定，只有策略可观测的部分 𝒯_i^{m,k} ⊆ 𝒯_i 在变。**
- 转移（与在线的关键区别）："Unlike online execution, replay returns recorded children of the selected nodes **deterministically** rather than generating new candidates."
  **𝒯_i^{m,k+1} = 𝒯_i^{m,k} ∪ ⋃_{v ∈ C_i^{m,k}} Child(v; 𝒯_i, 𝒯_i^{m,k})**
  Child(v; 𝒯_i, 𝒯_i^{m,k}) = v 在 𝒯_i 中未观测的子节点集；无记录后继时 = ∅。
  因为 v 是 𝒯_i^{m,k} 的叶子，其记录子节点必然尚未揭示。若 v 是根，replay 返回根最早的已记录子节点。
- 新揭示的节点**在策略做下一次决策前**先暴露其存储的 observation。
- 终止：选 C = ∅、达到轮数上限 **K₂**、或 **𝒯_i^{m,k} = 𝒯_i**（所有已记录节点都被揭示）。记终止轮数 **k_i^{m,⋆} ∈ {0,…,K₂}**，终态子树 𝒯_i^{m,k_i^{m,⋆}}。
- **replay 评估的正是**：每个打开的分支追多远、怎么把 attempt 分组成并行批次、何时另开分支或停止。
- **论文自陈的限制**："each branch is traversed in its recorded parent–child order, and no outcomes beyond 𝒯_i are generated."——**这是 replay 的根本偏置**：只能重排，不能探索新分支。

### 2.6 Replay objective（式 1）

N_i^m = replay 中揭示的非根节点数。论文强调："Although replay itself does not execute new discovery attempts, N_i^m counts the generation–evaluation requests **represented by** its trajectory."

固定系数 **β₁, β₂ ≥ 0**：

**V_i^m = max_{v ∈ 𝒯_i^{m,k_i^{m,⋆}}} s_v − β₁ · N_i^m + β₂ · ( N_i^m / max{1, k_i^{m,⋆}} )**
  （三项分别是 discovery quality / execution cost / parallelism bonus）

第三项"rewards the average number of attempts executed per decision round, favoring policies that batch useful continuations rather than execute them sequentially."

**诚实标注**：论文**未报告 β₁ 与 β₂ 的具体取值**，只给出"fixed coefficients"与符号约束。

### 2.7 策略改进与选择（单调性保证）

策略版本 m 的评估分是它在固定历史上的平均 replay 分 V^m。

- 离线阶段先评估当前策略；policy-development agent 接收 π_t^m 的 replay 轨迹与分数，加上前几次修订的反馈，"identify successful decisions and recurring failures"，然后**修订可执行的策略代码**，在**同一组** replay worlds 上评估。
- 下一轮在线策略从所有已评估版本中选：

**π_{t+1} = π_t^{m^⋆}，其中 m^⋆ ∈ argmax_{m∈{0,…,M−1}} V^m**

**论文给出了一个真实的单调性保证**："Because the candidate set includes the current policy, this selection satisfies [不等式，LaTeX 在纯文本中未完整渲染]。 Thus, the selected policy is **no worse than the current policy in average replay score on the fixed history**."

注意这个保证的**确切边界**：它是"在固定历史上平均 replay 分不劣"，**不是**"在线发现性能不劣"。因为 replay 的分支顺序被记录树限制，这个保证的实际强度有限——见 §4。

## 3. 关键实验与数字

### 3.1 主对照：Recursive Fixed Exploration

这是本文设计上最讲究的地方：**对照组不是弱基线，是同配置的"永不进化"版本。**

- "Across all tasks, Dream-RSI and Recursive Fixed Exploration use the **same discovery agent, evaluator, initialization, and resource constraints**."
- "Both methods start from the same manually designed exploration policy."——一个 **parallel refining** 策略："launches multiple independent exploration workspaces in parallel, with each workspace maintaining its own local discovery trajectory and repeatedly refining its current candidate based on the history accumulated within that workspace."
- "The two methods therefore follow the **same exploration policy in the first discovery round**."（第 1 轮轨迹完全相同，之后分叉）
- 唯一差别：后续轮次里 Fixed 保持策略静态，Dream-RSI 通过 dreaming 逐轮改进策略。
- **成本度量**："The discovery cost is quantified by the **total cumulative number of discovery-agent calls**."

**每轮预算（论文给出）**：
- Gemini-3.1 Pro：10 个并行 workspace × 最多 11 步精化 = **10 × 11 = 110 次 discovery-agent calls / 轮**
- Gemini-3.7-Flash：32 个并行 workspace × 最多 20 步精化 = **32 × 20 = 640 次 calls / 轮**
- Dream-RSI "maintains identical per-round budgets"

### 3.5 §5.1 关键消融：历史用作 replay simulator vs 仅用作 guidance

这是全文最重要的机制性证据（Figure 5，ConvDiv 任务）。对照设计：把历史轨迹抽象成高层方向性洞见，**直接注入 prompt 作为显式语义指引**，分别施加于 Fixed Exploration 与 Dream-RSI。

**结果（论文原话）**："explicit directional guidance **consistently underperforms** its unguided counterpart across both paradigms under equivalent discovery budgets."

论文的解释："in long-horizon discovery—where multiple parallel threads are deployed for exploration—imposing strong semantic inductive biases regarding future search directions tends to **over-constrain the search space and impede diverse exploration**."

**诚实标注**：Figure 5 的具体分数与代数区间**论文未报告**（图上代数轴 0–1,000，性能轴 0.4–2）。

### 3.6 §5.2 探索行为的演化（Figure 6，ConvDiv）

- (a) **Round-best performance** 逐轮：0.427, 0.625, 0.855, 1.403, 1.488, 1.499, 1.770, 1.880, 1.898（单位 1/ms）
- (b) **Exploration effort**（每轮评估的 attempt 数）：110, 87, 80, 50, 92, 80, 91, 86

论文描述的行为模式："as performance improves, it **initially conserves** discovery compute (e.g., reducing the number of evaluated attempts **from 110 to 50**). When progress subsequently plateaus, it **increases exploration effort again**, coinciding with further performance gains."

**这是我在这篇里认为最有 DWC 价值的观察**：进化出来的策略学会了"**交替节流与冲刺**"——这正是 DWC 门 4（生灭配套）与门 6（加减平衡）想要的资源调度行为，而它是**从历史中学出来的，不是手写的**。

### 3.7 负面结果与未报告项（诚实清单）

**明确报告的负面/有限制的**：
1. §5.1：**prompt 级语义 guidance 明确劣于 replay simulator**，在两种范式下都是。这是个反直觉且有价值的负面结果。
2. Replay 的结构性限制（§2.5 原文）："no outcomes beyond 𝒯_i are generated"——**只能重排历史分支，不能发现新方向**。
3. Autocorrelation 任务上**落后于 SimpleTES**（1.456375 vs 1.453675），只靠预算优势辩护。
4. Circle Packing 上**只是打平**最强结果。

**论文未报告的（必须写"论文未报告"）**：

- **无显著性检验**（无 p 值、无 bootstrap CI）。
- **β₁、β₂、K₁、K₂、M 的具体取值全部未报告**（只给出符号与约束）。
- Figure 3(b)、4、5 的数值点未报告。
- **未报告** replay simulator 池随递归轮次增长到多大（|ℋ_t| 的最终规模）——这是该方法成本的核心变量。

- **未报告** Dream-RSI 相对 SimpleTES 在 Autocorrelation 上若给同等 51,200 预算能到多少。

## 4. 它假定了什么

1. **历史记录树已经足够"覆盖"目标分布。** 这是最深也最脆弱的前提。replay 只能在已记录分支上重排顺序/分组/停止。**如果最优策略需要探索一个历史上从未走过的分支，replay 在原理上无法评估它**——而且无法知道自己无法评估它。论文承认这个限制（"no outcomes beyond 𝒯_i are generated"）但**没有量化由此产生的乐观偏差**。所谓"单调性保证"（选中策略在固定历史上平均 replay 分不劣）因此**不能外推到在线性能**。

2. **重放历史与真实执行的分布差异可以忽略。** 在线转移是随机的（"the discovery agent may generate different outcomes from the same starting workspace"），离线是确定性的。论文把这种差异当作可接受的代价，但**未做敏感性分析**（例如同一分支重复执行的方差有多大）。

3. **任务评分 s_v 是可信的外部真值。** replay objective 的第一项是 max s_v。这假设了"a fixed task-scoring protocol"给的分数能代表真实质量。在 Lasso 上成立（wall-clock runtime + 正确性检查）；**在开放研究任务上不成立**。DWC 若要借用这个 objective，必须先回答"我的 s_v 从哪来"。

4. **探索策略是唯一值得进化的东西。** "Only the exploration-policy code changes; the underlying models, evaluator, and execution interfaces remain fixed." 这是一个**强假设**：更好的模型或更好的评估器带来的增益被完全排除在这个框架的视野之外。

5. **策略代码可被 LLM 安全地改写。** policy-development agent 直接改写可执行代码，没有报告形式化约束（对比 SEVerA 的 FGGM / 一阶逻辑契约）。**论文未报告**改写导致的编译失败率或行为越界。

6. **并行 worker 数 W 是外生给定的常量。** replay objective 里的 parallelism bonus 奖励"每轮平均 attempt 数"，但 W 本身不进策略决策空间。论文**未报告** W 是否也曾被演化。

7. **"replay simulator / worlds" 的隐喻成立。** 论文明确"We use the terms replay simulator and worlds interchangeably." 这个类比借用的是 model-based RL（Ha & Schmidhuber 2018, Dreamer 系列），但 **model-based RL 的 dream 通常在学出来的动力学模型里想象，而这里"模型"就是记录树本身**——没有学习成分。论文自己在 Motivation 里也承认这是"an **empirical** replay simulator: a grounded model of the portion of the discovery space that has already been observed"。措辞是诚实的，但读者容易把它误读为"学到了世界模型"。**DWC 尤其要警惕这一点——母巢的教训正是"声称有世界模型、实则是空壳"。**

## 5. 可迁移到 DWC 的点 / 不可迁移的点

### 可迁移（给具体接口）

**① replay simulator 作为 DWC 记忆系统的第二消费者（这是最强的可迁移点）**

DWC 的记忆目前（按项目背景）用于检索与复用。Dream-RSI 证明同一份记忆可以**换一种消费方式**：不作为上下文注入，而作为**可回放的仿真器**，让"策略"在其中被反复、低成本地评估。

```python
# DWC 侧接口建议：src/dwc/memory/replay_sim.py
class ReplaySimulator:
    """把记忆里的执行历史组织成可回放的决策树。
    对应论文：discovery tree + Child(v; T_i, T_i^{m,k})"""
    def __init__(self, nodes: dict[NodeId, MemoryNode]):
        self.nodes = nodes
    def eligible(self, observed: set[NodeId]) -> set[NodeId]:
        """A(T) = {root} ∪ {v : v is a leaf of the OBSERVED tree}"""
        return {self.root} | {v for v in observed if not self.children(v)}

    def step(self, observed: set[NodeId], batch: list[NodeId]) -> set[NodeId]:
        """T^{m,k+1} = T^{m,k} ∪ ⋃ Child(v; T, T^{m,k})
           关键：只揭示已记录子节点，绝不生成新节点。"""
        revealed = set(observed)
        for v in batch:
            revealed |= self.unrevealed_children(v) - observed
        return revealed
```

**DWC 侧的落点**：`src/dwc/memory/` 里，记忆节点增加 `parent_id` + `children` + `score` 字段后，历史即成树。这个接口**不需要任何前沿模型**。

**② 三阶段循环的编排骨架**

```python
# DWC 侧接口建议：src/dwc/evolution/three_stage.py
def rsi_cycle(policy_code, history, evo):
    # ① Online Explore：策略固定，跑一轮，产出新树
    tree = evo.online_rollout(policy_code, history, K1=evo.K1)
    # ② Construct Replay Simulator：历史成池
    history.add(tree)                       # H_t = H_{t-1} ∪ {T_t}
    # ③ Dreaming-based Policy Improvement：离线评估 M 个版本
    best = evo.current_policy
    for m in range(evo.M):
        cand = evo.develop_policy(best, history)     # policy-development agent 改代码
        V = evo.evaluate_replay(cand, history)       # 全部 replay worlds
        if V > evo.score(best):
            best = cand
    return best   # π_{t+1} = π_t^{m*}，argmax 选优
```

**③ "记忆注入 ≠ 记忆回放" 的消融（这是 DWC 最该立刻做的实验）**

§5.1 的负面结果直接可翻译成 DWC 的实验设计：DWC 现有记忆机制大概率是"把相关历史拼进 prompt"（= guidance）。论文证明在多线程长程搜索里，**guidance 一致劣于 replay**。

DWC 应做：`src/dwc/experiments/mem_guidance_vs_replay.py` —— 同一批记忆，A 组注入 prompt，B 组组织成 replay tree 跑同一策略，对比下游效果。**这是 DWC 记忆模块第一个有对照的实验，目前母巢没有。**

**④ 交替节流-冲刺的调度行为（Figure 6）**

学到的策略行为：性能上升时把每轮 attempt 从 110 降到 50，平台期再升回 92/91/86。**这可以直接作为 DWC 进化预算调度的行为模板**：

```python
# DWC 侧接口建议：src/dwc/evolution/effort_schedule.py
def next_effort(round_best_perf, prev_effort, plateau_eps=0.02):
    """对应 §5.2 观察到的交替模式：
       性能仍在提升 -> 收缩预算；平台期 -> 放大预算。
       注意：这是从 ConvDiv 单任务观察到的行为，DWC 需自己验证。"""
    if round_best_perf - prev["last_gain"] < plateau_eps:
        return prev_effort * 1.15   # 平台期：冲刺
    return max(1, prev_effort * 0.9) # 上升期：节流
```

标注：这是**单任务观察**，不是论文提出的算法，论文也没有把它形式化。DWC 照搬时必须自己验证。

**⑤ replay objective 的三项分解（可作 DWC 进化件评分模板）**

**V = max(质量) − β₁(成本) + β₂(并行度)**

DWC 的进化件评分目前若只按"是否产出效果"打分，可引入这个分解。**但 β₁/β₂ 必须 DWC 自己定**（论文未报告取值）。

### 不可迁移（写清为什么）

**① 整个 Gemini-3.1 Pro / Gemini-3.7-Flash 依赖（必须标注 · 闭源）**

- 全部 discovery agent：Gemini-3.1 Pro、Gemini-3.7-Flash（经 Gemini CLI）
- 对比基线 SimpleTES：GPT-OSS-120B
- 对比基线 TTS-Discovery：Qwen3-8B；ThetaEvolve：Distilled-Qwen3-8B（这两个是开源，但 Dream-RSI 与之不可直接对标）

**DWC 不具备同等模型条件**，因此：317 vs 550 calls、1.7×、2.43×/1.79×/2.09×/1.44× 这些数字**均不可复用**。可复用的只有结构（§2 的算法），不是性能。

**② 162× / 50× 的预算倍数（不可迁移，且原文口径需修正）**

162× 是相对 SimpleTES（51,200 代）——**那是一个用了两年迭代、51,200 次生成预算的系统**，不是同配置对照。相对同配置 Fixed Exploration 的真实计算量优势是 1.7×。若 DWC 在任何文档里引用"162×"，会把跨系统的预算差误读成方法增益。**这是这篇论文最容易被误引的数字。**

**③ Replay 的"单调性保证"不可当作 DWC 的正确性保证**

论文的保证是"在固定历史上平均 replay 分不劣"。因为 replay 无法评估历史上不存在的分支，这个保证**在分布外无效**。DWC 若把它当成"进化不会变差"的证据，就是把一个条件性结论当无条件结论用。

**④ "replay simulator ≈ world model" 的框架定位（不可迁移）**

尽管标题叫 "Evolving Worlds"，论文自己明确它不是学出来的模型，是 "an **empirical** replay simulator"。DWC 若把它包装成"我们有了世界模型"，就是**重演母巢 445 万行空壳的路径**——这正是 DWC 立项的背景教训。可迁移的定位是"**记忆的第二个消费者**"，不是"世界模型"。

**⑤ 单任务、单 backbone 的 Figure 6 行为观察**

交替节流模式只在 ConvDiv 一个任务上观察到，论文**未报告**在其他 7 个任务上是否复现。DWC 照搬调度模板时必须自建对照。

## 6. 与其他论文的关系

**在 RSI 图谱中的位置**：**元层（meta-level）自进化**，且是"**off-policy 元优化**"的代表。

论文自己的定位（Related Work）：
- **vs 对象层（object-level）自进化**："Prior methods evolve model weights、agent harnesses、contexts、skills、test-time learning、rubrics、environments ... Most operate at the object level, improving components used for task execution or reasoning."**Dream-RSI 属于最近才开始的一批：优化元层机制（search strategies and self-improvement procedures）。**
- **vs 同期元层工作**：点名 Liu 2026a（EvoX）、Yan 2026a、Wang 2025、Zhang 2026b、Zhang 2026c、Kim 2026 "However, such meta-level strategies are difficult to improve because their quality is often revealed only after costly long-horizon rollouts."——**Dream-RSI 对这批工作的差异化正是"把延迟反馈变成便宜反馈"。**

**与 2607.27201 / 2607.27924（世界模型类）的关系**：论文明确类比 model-based RL 与 Dreamer 系列（Ha & Schmidhuber 2018; Hafner 2019/2020/2023/2025），并用 "replay simulator" 与 "worlds" 两个词。**但这是类比而非同类**：Dreamer 在**学出来的动力学模型**里想象，Dream-RSI 在**记录树**里重排。DWC 若把这两篇混为一谈会得出错误结论——**一个学到了状态转移，一个只是重排已知记录**。

**与 2609.04128（本批次第一篇，Environment Evolution）的关系**：**方向相反、结构同源，这是我读这两篇得到的最重要判断。**

| | 2609.04128 Environment Evolution | 2609.14858 Dream-RSI |
|---|---|---|
| 递归的是什么 | **环境**（难度逐代上升） | **探索策略代码**（能力逐代上升） |
| 离线/在线分离 | 离线产 15 代谱系，EL Scheduler 按 6/8 阈值在线放行 | 离线造 M 个策略版本用 replay 评，在线部署最优 |
| 测量真值来源 | 声称 off-policy 的 p_𝒯（**构造未报告**） | 任务自身的 s_v（**明确的外部评分协议**） |
| 评测者 | 无需目标 agent rollout | 需要一个固定 discovery agent |
| 目标领域 | 终端 agent 的 RL 训练 | 科学发现 / 算法工程 / GPU kernel |

**互补性**：两篇都在做"**先离线廉价评估候选，再在线部署**"。2609.04128 离线评估的是"环境"，2609.14858 离线评估的是"策略"。**DWC 若两者都要，架构上是同一套"离线评估器 + 在线调度器"骨架的两个实例。**

**竞争点**：两者都在"递归地产生越来越好的东西"，但 2609.04128 的递归是**开环的**（谱系逐代变难，不看学得怎么样），2609.14858 的递归是**闭环的**（每代策略都从历史里学）。若 DWC 只能选一个做第一版，**闭环的更符合自进化定位**。

**与 2609.13406（GAI）的对接**：GAI 的两个 dial 是"改善机制是否在 agent 内"和"评估标准是否 grounded outside"。Dream-RSI 的位置非常清晰：
- 改善机制（探索策略代码）**在 agent 之外**——是编排层，不是被训练的策略本身；
- 评估标准 **grounded outside**——replay score 的第一项是任务的 s_v，来自固定的任务评分协议，**不来自策略自身的判断**。

**按 GAI 的分类，Dream-RSI 是"改进机制在 agent 外 + 标准在外部"的 RSI 实例**，而它的"递进"体现在策略代码逐代被改写。这一点比 2609.04128 更接近完整 RSI（因为它有真实的"历史 → 学习 → 部署"链条）。

**与 2609.14857（ModularRSI）/ 2606.14249（HarnessX）/ 2606.09498（Self-Harness）的关系**：那三篇改的是 **harness**（提示、控制流、工具、记忆、上下文管理）；Dream-RSI 改的是**编排层的探索策略**。**边界是模糊的**——"controls branching, parallel exploration, and stopping" 这三项在很多 harness 实现里就是 harness 的一部分。Dream-RSI 的区分主张是"leaving the underlying coding agent unchanged"，即**改的是 harness 之上的调度决策，不碰 harness 本身**。这个区分是否站得住，论文**未与 harness 自进化工作做直接对比实验**（只在 Related Work 讨论，无实验）。

**与 2609.24972（RRSI）的关系 —— 这是最直接的竞争关系**：两篇都在做 harness/策略级递归，差别在**防过拟合的机制**：
- RRSI：temporally annealed budget（限制单候选捆绑的编辑数）+ critic（筛掉 benchmark 特定的提案）+ pruner。
- Dream-RSI：不用正则化，而是**用 held-out 的 replay world 做选择**——但 replay world 就是历史，历史恰恰是从初始分布来的。

**这个对比里 Dream-RSI 有一个论文没讨论的弱点**：它的"held-out"是相对于**在线新 rollout**，不是相对于**初始分布**。如果历史本身就在初始分布上，replay 选择仍可能过拟合到初始分布。这与 RRSI 关心的问题是同一类，但 Dream-RSI 全文未涉及泛化/过拟合讨论（检索无相关论述）。

**与 2603.06333（SAHOO）/ 2609.06396（MetaRSI）的弱关系**：SAHOO 做 high-order optimization 的护栏，MetaRSI 做 Data/Harness/Model 三个 typed operator 的调度。**两篇都需要"目标函数"，而 Dream-RSI 提供的 replay objective（式 1）正是一个可用的目标函数形式**（质量 − 成本 + 并行度）。这是潜在组合点。

**与 2607.12790（本批次第三篇，Double Ratchet）的关系 —— 关键的反面教材**：2607.12790 证明**当被评估的对象与评估它的机制同源时，会发生共谋塌缩**。Dream-RSI 的 replay world 由目标 discovery agent 产生，replay objective 的 s_v 由固定 evaluator 给出——**evaluator 是外部固定的（"a fixed [evaluator] scores the resulting candidates"），所以不构成同源自评。** 这是 Dream-RSI 相对安全的地方，而它**没有意识到这一点、也没有把它作为设计原则声明出来**。DWC 若借用 replay 结构，应显式继承这条纪律：**回放世界由谁产生、分数由谁给，二者必须分离。**
