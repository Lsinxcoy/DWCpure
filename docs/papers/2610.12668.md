# 2610.12668 — Recurrent Harness for Agentic Continual Learning (ReHarness)

> **读到范围**：arXiv HTML 全文（正文 §1-§6 + Discussion/limitations + 表 1/2/3/4 + 附录逐 backbone 表）。
> 无配套代码仓库（纯方法论文）。**模型条件**：Claude Opus 4.8 / GPT-5.5 / Gemini 3.7 Flash
> 三前沿骨干 + Qwen3-Embedding-8B 检索。**DWC 不具备前沿模型条件** ⇒ 迁移机制与纪律。

**出处**：Yuxin Xiao 等（MIT/Meta 系）, arXiv:2610.12668v1 [cs.LG], 2026-10-08。

## 1. 问题：forward-only 记忆的病

harness 只有前向流（τ→反思→写库→检索→指导）：**写入的条目永不基于下游效果更新**。
- sorting 反例：降序任务写入"大数在前"→ 升序任务检索到它被误导 → 新反思写入后**旧的误导条目仍留库**并再次命中
- 实测：Mem0/RBank/DoT/ACE/GEPA **stability 全为负**——分布漂移时记忆库是负资产
- 现有 add/delete 只维护一致性, 不吸收下游反馈; validation-based 优化违反严格流式协议

## 2. 机制（§3.2/3.3）

**后向修订**：任务完成后, π_R 用「**源轨迹 τ_i** + 当前任务轨迹 τ_t」修订该任务检索用过的条目 R_i→R_i'。
- **grounding 约束**：R_i' 新内容必须 grounded 在 τ_i；**τ_t 只作反馈不作信息源**（防泄漏——FActScore 分解验证: >95% grounded, leakage 0.8-2.1%, unsupported 0.5-2.6%）
- 修订典型形态：补 τ_i 里被漏掉的证据 / 纠正无支持假设 / **加限定条件**（"仅降序时大数在前"）
- **修订作为 forward-write 的 demo**：R_i' 演示给 π_M → 新反思也带限定语义
- k=5 检索修订已饱和; k 过大 → reflection drift + 成本

## 3. 关键数字

| 项 | 数字 |
|---|---|
| 主结果 | ReHarness 0.240 vs Top-K Raw 0.168 / Full Raw 0.164（9 组合 8 胜, Wilcoxon 全显著 p_adj<0.05） |
| 修订能力上限 | counterfactual replay 0.335（修订后状态重打同一任务） |
| 消融 | 去掉修订做 demo：0.217→0.191 |
| token | 比 Full Raw 省 3.4×（紧凑反思 vs 原始轨迹重复入上下文） |
| **适用边界** | exploitable poker 失败——**下游反馈无诊断性（credit assignment 噪声）时修订无效** |
| 论文自认 | 需存原始轨迹（存储开销）; 修订 agent 成本 k 次 LLM 调用/任务 |

## 4. DWC 病灶核实（代码级）

`memory.py` 操作集：remember / archive / record_effect / 近重复合并——**无 revise**；
`record_effect` 只计数从不驱动回写。agent 侧教训面（dwc_skills/*.md）固化后**永不更新**（consolidate_skills 还会覆盖）。
**forward-only 两轨皆实锤。**

## 5. 落地（R258 · 四点全做）

### ① memory 轨版本链修订（`MemoryKernel.revise`）
新 SKILL 节点 `_rev_prev` 链回旧节点；旧节点**内容字段原样只加** `_revised_to` 指针（守门单调性 + 可回滚）。只对 SKILL（事件流 FAILURE_SIGNATURE/TRACE 是事实不修订——R104 同族）。**D6 五字段门槛**：修订 payload 以旧为底只覆盖修订字段（实现中抓到的真 bug——初版 3 字段会被 D6 拦）。

### ② diagnostic gate（poker 教训的纪律化）
`revision.revise_from_outcome`：**status ∉ {done, failed} ⇒ 跳过且零 LLM 调用**（incomplete/超时=噪声反馈）。检索留痕（`recall_search`→`_note_retrieved`）提供"该任务用过哪些条目"的候选集（`last_retrieved`）。

### ③ 修订做 forward-write 的 demo
文件轨：修订对写 `dwc_skills/_revision_demo.md`（最近 2 条）；`consolidate_skills` 固化新规矩时**读 demo 注入**且**不覆盖已修订规矩**（修订版是 outcome 驱动的更优版本）。memory 轨：`revision_demo()`。

### ④ grounding 纪律
`revise(source_traj=...)` **必填**——无源修订 raise（G2：当前任务只作反馈）。文件轨修订 prompt 明令"不许编造新要求", 旧版 `.hist/{mode}.{ts}.md` 存档。

### 主链接线
`dwc_agent.run_user_task`：任务 rep 落盘后 → `revision_lessons(...)`（失败/成功都过 gate；修订结果入台账 `_log`）。

## 6. 不可迁移（写清）

- normalized gain 度量与三 benchmark（DWC 有自己的 judge/anchor 判分）
- embedding 检索（recall_search 场景词检索已有, 且 DWC 记忆量级用不上 top-k embedding）
- stability/plasticity 分解（可参考思路, 不搬度量）
- 修订 agent 独立模型（DWC 修订复用任务 LLM, 失败即 fallback——修订故障绝不阻断主链）

## 7. 诚实清单

- 论文三个骨干全前沿（Claude/GPT/Gemini）——**"弱 LLM 当修订器"未被测试**; DWC 修订质量依赖 MiMo 级模型, 首版不设修订质量评分（修订对可回滚是安全网）
- 修订候选集 DWC 用**会话内检索留痕**（单任务级）, 论文用 top-k 检索集（流式全局）——DWC 语义更窄（每次任务只修自己用过的）, 是保守起点
- 文件轨（dwc_skills）修订的 fail_mode 命中依赖 `recall_lessons` 的 token 重叠检索——命中率为零时修订不发生（零伤害零收益）
- memory 轨 SKILL 主链写入目前仅实验脚本（生产线在实验期）——revise 结构件就绪待生产线接入（诚实 gap）
