## 1. 问题

### 1.1 环境预测式世界模型的失效论证

既有语言世界模型（预测工具响应/检索结果/代码执行输出）被论文从**信息论**角度否定：
这些观测是**高熵且执行依赖**的（搜索结果依赖实时网页与不透明排序; 终端输出依赖文件系统
与运行时状态）——"Predicting them is difficult and offers limited value when real tools
provide grounded feedback. **Simulation may introduce fabricated evidence** without
improving the agent's interpretation or subsequent decisions."

★ 这与 DWC 的既有立场**直接同源**：世界树 W2 纪律「想象节点永远没有分数, 分数只经
observe() 从 judge 回填」= 同一恐惧的结构化表达（母巢"声称有世界模型实则空壳"教训）。
**DWC 从未做观测预测 ⇒ 此篇对 DWC 不是纠偏, 是共振。**

### 1.2 task-state contamination（核心失效机制）

轨迹分析揭示的复发机制：agent 从部分观测维护假设/计划/进度判断时——
1. **把无支持的假设当事实**（unsupported assumptions accepted as facts）
2. **反馈矛盾后仍保留过时计划**（outdated plans persist）
3. **把部分进度误当完成**（partial progress mistaken for completion）

"These errors persist in history and **compound through locally plausible actions**,
despite grounded observations." —— 关键句：**有真实反馈 ≠ 理解被正确更新**。

## 2. 核心机制

### 2.1 建模目标的翻转

| | 观环境世界模型 | AEWM |
|---|---|---|
| 预测什么 | P(观测 \| 状态, 动作) | **决策效果**（该步对任务进展的贡献类型） |
| 干预手段 | 提供预测/批评 | **直接替换**当前 reasoning-action 对 |
| 观测来源 | 模拟 | **真实执行**（编辑后照常 act, 观测来自真环境） |

### 2.2 Action Judge（判别）

- 输入（**执行前**）: task + 历史 + agent 当前 thought + 候选动作（+ 同轮兄弟调用）
- 输出三分类：
  - **critical**：属于"从当前环境状态到正确终态的连贯直路"——移除它会失去必要状态转移/
    决定性诊断/必要产物/实质验证（Judge prompt 逐字定义）
  - **exploratory**：有意义地降低不确定性或测试一个合理分支（**显式保留探索类**——
    防止判别器把有用的信息收集当噪声砍掉）
  - **noisy**：几乎无预期进展, 或助长重复/无关/违反约束/错误方向
- ★ 判别**明确禁止**使用执行后信息（"Do not assume its observation, exit status,
  later consequences"）——**先验判别, 回顾标签监督前瞻预测**（标注时看完整轨迹,
  输入只给执行前可见部分——防泄漏过滤：标签一致性/action-observation 对齐/
  推理不引用执行后信息）。

### 2.3 State Revision（修订）

- 仅对 noisy 触发：从**同一历史**重新生成 (reasoning', action')，编辑**两个**分量
- 修订动作缺证据时**去真实环境取证据**（"when evidence is missing, it seeks that
  evidence through interaction with the real environment"）
- ★ 修订必须**真正执行**——改变的是"后续决策所基于的状态", 不是批评文本

### 2.4 EditAct（推理循环, 代码级确认）

```
每步: actor 提案 → Action Judge(仅 judgeable 工具; finish 不判)
      ├─ critical/exploratory → 原样执行
      └─ noisy → State Revision(重试 N 次直到有实质响应)
                 ├─ 修订过结构门 → 执行修订版
                 └─ 修订失败/校验不过/连续重复 → **fallback 保留原提案**
      → 真实执行 → (选中动作+真实观测) 进历史
```

### 2.5 AEWM-RFT（蒸馏回传）

用**验证过的 EditAct 轨迹**（含 AEWM 修订 + 后续真实反馈）做拒绝采样微调，
把"状态纠错模式"内化进 agent——**推理时不再需要世界模型**。

## 3. 关键实验数字

### 3.1 Action Judge benchmark（3,000 决策, 1,000/域）

| 模型 | Search F1 | Terminal F1 | SWE F1 | Overall F1 |
|---|---|---|---|---|
| Gemini-3-Pro | 39.2 | 52.0 | 42.8 | 45.1 |
| GPT-5.5 | 46.6 | 61.3 | 54.4 | 55.3 |
| DeepSeek-V4-Pro（最强基线） | 50.6 | 61.6 | 64.4 | 59.9 |
| **AEWM** | **60.9** | **72.1** | **77.8** | **70.5**（+10.6） |

★ **前沿通用模型自己判决策也就 ~60% F1** —— 三分类判别不是"顺手就能做对"的事,
这为"判别器值得专门做"提供了**反面证据**（连 GPT-5.5 都只有 55.3）。

### 3.2 主结果（六基准 × 三 backbone, EditAct vs 最强基线均值）

| backbone | ReAct | 最强基线 | EditAct | 增益 |
|---|---|---|---|---|
| Qwen3.5-4B | 28.5 | 35.1 | **41.8** | **+6.7** |
| Qwen3.5-9B | 34.5 | 38.9 | **44.1** | +5.2 |
| Qwen3.5-35B-A3B | 42.2 | 45.6 | **48.8** | +3.2 |

- 9B+EditAct(44.1) **超过** 35B+ReAct(42.2) —— 编辑机制缩窄模型规模差距
- 增益随 backbone 变强而**递减**（6.7→3.2）—— 强 agent 自身纠错能力更强, 编辑的边际价值下降（论文归因 capacity gap, 与 Qwen3.5-Plus 上 Terminal/SWE 增益受限一致）

### 3.3 AEWM-RFT（免在线 AEWM）

| | BrowseComp | TB2.0 | Doc2Repo |
|---|---|---|---|
| Self-RFT | 43.2 / 44.0 turns | 40.8 / 73.6 | 46.1 / 76.3 |
| **AEWM-RFT** | **45.4** / 39.3 | **43.4** / 69.2 | **48.6** / 89.8 |

修正轨迹的监督比 agent 自己成功轨迹更好（+2.2/+2.6/+2.5）——**纠错样本比成功样本多学东西**。

### 3.4 消融（Table 3, 35B backbone）—— 对 DWC 最有信息量的行

| 对照 | BC | TB2 | Doc2Repo | 结论 |
|---|---|---|---|---|
| ReAct | 40.9 | 37.1 | 42.8 | — |
| Random Gate | 44.1 | 40.8 | 43.9 | **学到的判别 > 随机门**（判别器在做事） |
| Agent Resampling | 36.2 | 40.4 | 42.8 | 重采样**不如不干预**（BC 上 36.2<40.9） |
| AEWM Hint（批评指导） | 41.8 | 39.3 | 43.2 | 批评几乎无效 |
| **Full EditAct** | **48.1** | **48.3** | **48.9** | **直接替换 > 批评/重采样/提示** |
| Reasoning-only / Action-only 修订 | 45.8/41.8 | 39.7/40.8 | 45.9/46.9 | 单分量修订**都不如双分量联合** |
| Self-WM（自己当裁判） | 47.4 | 41.9 | 44.6 | 自评在 BC/TB2 更差 —— **同源自评风险的实证** |
| DeepSeek-V4-Pro WM | 47.3 | 44.2 | 44.6 | 通用强模型当 WM **全部低于专训 AEWM** |

★ 关键推论链：Random Gate < Full（判别要学到才行）; Hint/Resampling < Edit（**干预必须改状态而非给意见**）;
Self-WM < 专训（**裁判与执行者分离**）。

### 3.5 域行为分布（Figure 4, 标注数据）

Search: noisy **60.0%**（未验证假设收窄检索/用相关证据替代必要检查）
Terminal: exploratory **43.2%**, noisy 25.1%（误读执行证据/中间进度误当已验证成功）
SWE: critical 42.1%, noisy 28.0%（依赖假设错误/忽视兼容性与接口约束）

★ **DWC 对照**：DWC 执行核的失败（17:12/17:13 两单）逐条落在这三类——
read 同段 3 连=noisy（重复）; wsl 命令=错误方向 noisy; 幻觉路径=noisy。
**AEWM 的分类法给 DWC 的事故库提供了外部分类词汇表。**

## 4. 它假定了什么（脆弱前提）

1. **有一个专训的 35B 世界模型可调用**。整个 EditAct 依赖 AJ/SR 两个 LLM 调用/步
   （成本≈每步多 2 次推理）。DWC 的 LLM 条件（MiMo-Flash 级）下, **判别质量必然下降**
   ⇒ 迁移必须做**规则版/轻量版**。
2. **判别可以从历史+当前提案做出**（不看执行结果）。标注靠回顾, 判别靠前瞻——
   若历史本身被污染（contamination 正在发生）, 判别器看到的就是污染视图。
   论文用 `_ObservedCondenser` 保证判别器与 actor **看同一视图**（含压缩后）——
   **一致性被显式维护, 污染无法借此被识别为"视图差异"**。这是个论文未讨论的递归弱点。
3. **修订产出的"实质进展"可被后续轨迹验证**（SR 数据构造用真实执行过滤）。
   开放任务上"substantive progress"无外部验证器 ⇒ SR 数据质量无法保证。
4. **noisy 率是域常数**。干预频率按域标定（Search 高 noisy/ Terminal 高 exploratory）,
   但个体任务差异大, 论文未做 per-adaptive rate。
5. **fallback 安全性**：修订失败保留原提案 —— 意味着判别器**冤杀好动作时修订也会失败**
   → 该步无损; 但判别器**放过坏动作时无第二道防线**（单层判别）。

## 5. 可迁移到 DWC 的点（按优先级）

### ★① 决策效果判别的**规则版** + State Revision 轻量版（最高优先）

**直击 DWC 执行核现状**：R247 的复读熔断是**事后**检测（同 op+target+obs 3 连才断）,
AEWM 证明**事前判别**（提案执行前判 noisy）+ 直接替换更有效（消融: Hint/重采样都不如替换）。

DWC 落法（无 35B 训练条件 ⇒ 规则版判别器）：
```python
# src/dwc/llm/step_judge.py（建议落点）
def judge_step(step, recent_log, ctx) -> "critical|exploratory|noisy":
    # noisy 规则族（全部来自 DWC 实测事故 + 论文域分布）:
    #  R1: 同 (op, target) 连续 2 次且 obs 无新信息          (17:12 read 同段案)
    #  R2: run 连续失败同 cmd 且 rc!=0                        (wsl 案)
    #  R3: read 路径不存在（幻觉路径）                        (17:13 docs/world_model.py 案)
    #  R4: op 与任务关键词零交集（无关探索）                  (论文 Search 60% noisy 语义)
    # critical: final 前验证步 / ask 授权链步
    # 其余: exploratory（显式保留探索类 — 论文教训: 不设 exploratory 会误砍信息收集）
```
State Revision 轻量版：判 noisy → **一次** LLM 重写（要求: 换路径/换参数/或基于已有信息
final）→ **修订必须过动作校验**（revision.py 的 validate_code 纪律: 参数形状/路径存在/
工具在白名单）→ 校验不过/连续重复签名 → **fallback 保留原提案**（绝不因修订器故障卡任务）。

**预期收益**：17:12/17:13 类失败从"跑满轮上限后熔断"变为"早期被判 noisy→修订→走通"。
R247 熔断降级为第二道防线（论文§4.5 单层判别弱点的 DWC 式补层）。

### ★② AEWM-Action-Judge-Bench 作**外部校准锚**（第二优先, GAI grounded②）

HF 公开 3,000 决策（1,000/域, **Terminal 域与 DWC run/read/edit 动作同构**）。
DWC 规则版判别器的 R1–R4 阈值/权重**可以用 Terminal 子集校准**（gold label 对照,
Layer-22 校准协议）——**判别器有外部真值源, 不是自评**。
★ 这同时是"前沿模型判决策只有 ~55-60% F1"的可复核现场 —— 规则版若在其上超过
通用 LLM 基线（55.3 GPT-5.5）, 即为"规则版在窄域可行"的**硬证据**。

### ③ compaction 的**矛盾标记**（中优先, 执行核 R221 升级）

AEWM 的 contamination 三型给 R221 滑窗摘要补一个语义: 摘要压缩时, 对**被后续 obs
证伪的假设**打 `[已证伪]` 标签而非直接删（删=彻底遗忘, 标签=保留证伪记录防复用）。
DWC 的 obs 历史（R247 留痕 target/obs/ok）已具备识别"证伪"的原料（ok=False 链）。
成本: compaction prompt 改造 + 测试锁; 收益: 与 AEWM 三型污染的第 1 型直接对抗。

### ④ 失败任务的**修订重试**（AEWM-RFT 的 DWC 等价, 中优先）

R247 已留痕每步 (target/obs/ok)。任务 failed 后: 基于留痕生成"修订版任务理解"重跑一次;
成功则该"失败→修订→成功"对入记忆（correction 轨迹比成功轨迹多学东西 — §3.3 实证）。
对接 DWC retention（R233 双判据晋级）: 修订对作为一类候选进 4 臂配对。

### ⑤ 不可迁移（写清）

- **35B 专训模型 / 52B+120K 训练配方** —— DWC 无训练条件, 数字与配方均不可迁移
- **每步 2 次额外 LLM 调用的成本结构** —— DWC 用规则版规避; 若用 LLM 判别,
  MiMo-Flash 质量下限未测（bench 可先测: judge-only 模式跑 Terminal 子集）
- **judge/revision 的 Search 文本动作格式** —— DWC 动作面是 JSON step, 不适用
- **AEWM-RFT 蒸馏** —— 需要训练, 不可迁移; 可迁移的只是"修订对入记忆"的**数据策略**

### ⑥ 世界树的边界（明确不做）

世界树节点**不加 decision-effect 标签进收束排序** —— WORLD_TREE §4.3 收束键只能
信息增益（宪法级）。若要记录 effect 标签, 只能作为 dream 回放的审计字段或
PolicySpec 修订域参数（W2 同款: 不进分数）。**AEWM 的判别服务于执行核, 不进世界树判分。**

## 7. 诚实清单

- 论文**无** Limitations 章节; 三次运行**未报**方差/散布; 域 noisy 率来自标注数据统计
  非在线验证全集
- EditAct 增益随 backbone 增强递减 — **对 DWC（弱 LLM）增益方向利好, 但"弱 LLM 当
  actor + 规则判别器"的组合从未被论文测试**（论文是 强模型判 + 弱模型演）——
  DWC 方案①是**外推**, bench 校准（②）是其最小验证
- Action Judge benchmark 是 AEWM 团队**自建**（非第三方）, 构造含自家模型参与的
  annotation-review 链 — 作为校准锚可用, 但注意**非独立基准**的乐观偏差
- 代码仓库为**推理与评测发布**（inference-only）; SR/AJ 数据构造与 RFT 训练管线未开源
