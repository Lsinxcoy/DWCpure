## 1. 问题定位（与 DWC 的关系）

原文：*"Modern AI systems advance through continuous iteration: a loop of proposing evolution directions, implementing code, training, and evaluation. While the latter three stages are increasingly automated, the starting point — proposing effective evolution directions — remains a critical bottleneck that still relies heavily on senior experts."*

⇒ **Astar 攻的正是 DWC `direction.py` 那一格**（方向提出）。但手段是**训练专用模型**（Qwen3-based 0.6B/4B/8B），DWC 无此算力 ⇒ R188 已据此排除训练路径，只取其**结构性洞见**。

原文（GPT-5.5 为何不行）：*"general-purpose LLMs, even the advanced GPT-5.5, offer only generic and misaligned suggestions: the required expertise is accumulated through experience rather than explicitly codified, and thus hard to inject directly."*

## 2. 四挑战（C1-C4）与其解法 — DWC 逐条对表

| # | 挑战（逐字摘） | Astar 解法 | DWC 可迁移性 |
|---|---|---|---|
| C1 | *"Historical records carry limited direct supervision signals... typically on the order of hundreds"*（相邻 commit 才带方向 ⇒ 监督稀疏） | **pairwise sample expansion**：*"pair arbitrary two versions in the iteration history to create a quadratic number of training samples: we label which version is better by comparing their full loss curves"* | **可迁移（无算力版）**：DWC 的规则只有 7 条 ⇒ 同 C1。但 DWC 的"label which is better"由 judge 真判给（replay/门组），**不需要 loss curve** — 判据面已在系统外 |
| C2 | *"Informative samples are buried in noise... irrelevant edits such as configuration changes, logging, and refactoring"* | **三层过滤**：reachability analysis（构调用图，不可达分支判 dead code 丢弃）→ AST normalization（parse 掉 print/assert/注释，归一化）→ configuration whitelisting；再用 LLM 语义分析**丢弃意图含糊的样本** | **可迁移且已同构**：DWC 的 `leakage.py` / G7 / sink 门就是这类"执行语义过滤"；**新洞见**：Astar 把"不可达=死码"作为第一层，DWC 的 main() 无副作用检测可对照 |
| C3 | *"Vast evolution direction space"* | **hierarchical hints（三级 taxonomy）**：见 §3 | ★ **R187 B 案的论文依据**（DWC `granularity` 组件的空白在此有对应物） |
| C4 | *"prohibitively expensive verification"*（真跑一次要数天） | **reward model as surrogate evaluator**（AUC 0.8487 vs 人类 0.6142） | **可迁移（部分）**：DWC 的 `_trial_run` 就是"便宜试跑替代贵验证"的同族 — 但 DWC 试跑是真执行（便宜因为任务小），不是学出来的代理 |

## 3. ★ 三级 taxonomy（C3 解法 — 逐字段）

原文逐字：

```text
(Level-1) Coarse-Grained Direction
(Level-2) Fine-Grained Modification Action
(Level-3) Concrete Modification Plan
```

*"This design guides the model to progressively narrow the search space: generating coarse-grained directions first, then localizing fine-grained modification actions, and finally producing a concrete modification plan within the identified scope."*

论文给的实例（MoE 改造）：*"Astar identifies that the baseline shared feed-forward network (FFN) in the decoder forces a single set of parameters to fit both coarse-grained and fine-grained codebook token distributions simultaneously, causing interference across levels. It recommends replacing the shared FFN with a mixture-of-experts architecture that assigns one dedicated expert per codebook level..."*

**⇒ 对 DWC 的意义（R189"A 步"ABSENT 清单里 `granularity` 组件的那条有据了）**：
- DWC 现在 `direction`（三方向）与 `granularity`（粒度）**没有分层树**：`mechanical_candidates` 是扁平的（两层：op 组合），fallback_order 是扁全序。
- Astar 的三级 = **coarse(方向) → fine(动作) → concrete(plan)** 正好对应 DWC 缺的 `granularity` 记账面：`direction` 是 L1，`component/target_layer` 是 L2，具体 patch 文本是 L3。**DWC 三者都有数据但没显式分层** ⇒ 这是 ABSENT 组件 `granularity` 的施工蓝图（不是从零发明）。
- **诚实口径**：Astar 的 taxonomy 是**分类 schema**（把历史修改归类），不是**选择器**；它不回答"何时选哪个方向"。

## 5. 对 DWC 的排除项（诚实记账）

**R188 排除训练路径的依据（本篇原文支持）**：需要 mid-training + SFT + RL 三段训练 + Qwen3 基座 + reward model 训练 + 工业级 iteration history（"on the order of hundreds" 起步）。DWC 的环境面（6 dev 任务 / 7 条 RULES / 无 GPU 训练流水线）**不满足 C1 的数据规模**，也不满足 C4 的代理模型训练条件。⇒ **不移植**，只留 taxonomy 结构与 surrogate 思想。
