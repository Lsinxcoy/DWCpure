## 1. 问题

**论文自己承认的缺口**（§1 Introduction）：

> "Recursive self-improvement (RSI) remains hard in long-horizon tasks, where **growing histories obscure the task state and misalign skill invocation**."

两个具体病灶：

| 病灶 | 表现 |
|---|---|
| **状态被历史淹没** | 对话历史越增长，agent 越难判断"当前任务进行到哪一步" |
| **技能调用错位** | 从完整历史里选技能，而不是从**当前需要**选技能 |

**更深一层的缺口**：已有工作把 RSI 的递归施加在 **harness 代码**或**模型权重**上，
但没有人问过：**记忆控制层本身能不能作为递归演化的对象？**

§5 的结论把这句话说死了：

> "reframes recursive self-improvement as an operation on an **externalized memory-control layer** rather than on the model or the agent."

## 2. 核心机制

### 2.1 形式化：harness = 记忆控制层 + 固定外壳

harness 被形式化为 `ℳ`（memory-control layer），其内部四个组件（eq. 2）：

| 符号 | 组件 | 职责 |
|---|---|---|
| `ℰ` | **Experiential Memory** | 技能库（可被 patch 的对象） |
| `𝒲` | **Working Memory** | 结构化工作状态（task progress） |
| `ρ` | **invocation policy** | 从 `𝒲` 决定调用哪个 `ℰ` |
| `𝒞` | **checkers** | 目标是否完成的判定器 |

**关键设计：`ρ` 从 `𝒲`（当前状态）取输入，而不是从完整对话历史取。**
这就是"状态被历史淹没"的解法。

### 2.2 Verified EM–WM Coupling（§2.2）

论文给了一个反直觉的案例（§3.3.5, Fig. 8）：

> "verbal confirmation does not close either goal."
> "A conventional agent reaches verbal confirmation but issues **neither required tool call**,
>  leaving both database updates unresolved."

**普通 agent 会口头宣布完成，但不发出工具调用。** Recuris 的做法：

```text
Recuris retains both goals in working memory until
    skill-guided tool calls return matching receipts.

ρ invokes the corresponding experiential skill for each unresolved goal,
and 𝒞 marks a goal complete only after a matching successful tool receipt.
```

**判据不是"我说了我完成了"，而是"我收到了匹配的工具回执"。**
这是 L7（形状正确≠有价值）在论文级的落地——完成性必须由外部回执验证。

### 2.3 Structured Trace `Γ`（§2.2.3 / §3.4.1）——最可移植的一块

harness 每步发出结构化 trace `Γ`，链接`任务状态 / 被调技能 / 动作 / 结果`。

**论文用一个注入故障的实验量化了 `Γ` 的价值（Table 4）**：

```text
向某个组件注入已知故障，让固定 judge 从三类证据中指出故障组件。
每类 9 个样本 × 2 次重复 = 每条件 54 次裁决。
恒定猜测的基线 = 33.3%（三选一）

证据条件          ℰ      𝒲      ρ      Macro    Macro-F1
仅结果          0.0    38.9    0.0     13.0     10.4   ★ 低于恒定猜测
原始轨迹        61.1    50.0    0.0     37.0     31.2   ★ 仅高出基线不到 4 点
结构化 trace Γ  72.2    83.3   38.9     64.8     63.4   ★ 近乎翻倍
```

**论文对差距来源的判断非常精确**（这是全文最值钱的一段分析）：

> "The per-fault rows say where the gain comes from, and it is **observability rather than reasoning**.
> An invocation fault is a **non-event**: nothing appears in the transcript where a skill
> should have been injected, and neither condition without `Γ`'s mechanism events names it
> **even once**, against 38.9% from `Γ`."

**`ρ`（调用策略）的故障是"非事件"** —— 该出现的地方什么都没有，
普通 transcript 根本不可能显示它。`𝒲` 的记录损坏在 `Γ` 的状态时间线里可见，在对话里不可见（50.0% → 83.3%）。

### 2.4 Validation-Gated Patch Admission（§2.3.3, Eq. 9）——19 篇里最干净的验收边界

```text
ℳ_{k+1} = { ℳ⁺_k ,  if 𝒢_fixed( ℳ⁺_k, ℳ_k ; x_k, 𝒟_dev ) = 1
         { ℳ_k  ,  otherwise
```

三个必须记住的性质：

| 性质 | 论文原话 | 含义 |
|---|---|---|
| **外部边界** | "The fixed gate provides an **external acceptance boundary** around the recursively evolving memory-control layer." | 判定者是 `𝒢_fixed`，**固定**，不进递归 |
| **锚点任务** | "`𝒟_dev` is the held-out development set containing the **anchor tasks**." | 回归判据 = **不破坏已会做的任务**，不只是修好失败任务 |
| **三重隔离** | "Test tasks, trajectories, and scores **never enter** localization, patch generation, or admission." | evolve / dev / test 三段彻底分开 |

### 2.5 Bounded Recursive Evolution（§2.3.4, Eq. 10）

```text
完整回路:
ℳ_k → Γ_k → 𝒜_fixed → D_k → 𝒫_fixed,⊕_{Z_k} → ℳ⁺_k → 𝒢_fixed → ℳ_{k+1} → Γ_{k+1}

递归的边界（论文明确列出）:
  固定: base LLM、Meta-Agent、定位与 patch 程序、验证门、ℳ_k 之外的harness 机制
  变:   只有 ℳ_k（记忆控制层）
```

> "Recuris therefore realizes recursive evolution **within the externalized memory-control layer
> of a fixed outer agent harness**, rather than unconstrained self-modification of the underlying
> model or the full agent program."

### 2.6 Test-Time Adaptation 模式（§2.3.5）

Meta-Agent 拿到任务指令 + 失败轨迹 + **verifier 返回的 1 bit**，
**拿不到 verifier 本身、它的测试、任何期望输出**（由 harness 强制）。

**并且论文自己处理了混淆**：

> "Because **retrying alone is a strong confound** on high-variance benchmarks, we evaluate this mode
> against a **budget-matched control that retries under the frozen initial memory**, sharing its
> first rollout with the adaptation configuration so the contrast is **paired**."

## 4. 它假定了什么（Assumptions）

这一节是本报告认为对 DWC 最有价值的部分。

| # | 隐含前提 | 风险 |
|---|---|---|
| **A1** | **失败可以被定位到某个记忆组件** | ★★★ 这不是自动成立的。若技能缺失而非技能错，trace 里没有痕迹可查（Table 4 已自证 `ℰ` 类故障最难定位：61.1%→72.2%，增益最小） |
| **A2** | **固定 Meta-Agent 足以定位与patch** | ★★ 两个不同 harness 上收敛是好证据，但都是现成 agent harness，换成弱模型未验证 |
| **A3** | **回归判据可以用"锚点任务"表达** | ★★ 若能力退化不以任务成功下降的形式出现（如延迟、token 成本），此门看不见 |
| **A4** | **test split 存在且不可被污染** | ★ 论文明确设计三段隔离，但这是**纪律**不是机制——若流程执行不严，门失效 |
| **A5** | **一个记忆版本可以原子地切换** | ★ Eq. 9 假设 patch 是候选-整体接受。若 patch 之间相互依赖，"整体接受"会永远无法接受组合 |
| **A6** | **"完成"可由工具回执判定** | ★★ Verified coupling 只在有可回执的工具型任务成立；开放式生成任务无回执 |

**必须承认的前提破坏案例**：A5 若不成立——两个单独无用的 patch 组合起来有用——
则 `𝒢_fixed` 会**永远拒绝这个组合**，因为单独测每个都不通过。
论文**未讨论**这一点。

## 5. 可迁移 / 不可迁移

### 5.1 可迁移到 DWC 的点（带具体接口）

#### ★★★ 1. Eq. 9 的三段隔离 + 锚点回归门 → 直接对应 DWC 的真值层设计

```text
DWC 侧的接口:
  x_k       = 一次可复现的失败用例（不是"感觉变差了"）
  𝒟_dev    = 锚点任务集 = DWC 已确认能正确召回的记忆集
  𝒢_fixed  = 独立进程里的判分器（DWC 门 G2 的实现载体）

硬要求: 𝒢_fixed 不能进递归。递归改记忆，判分器不动。
         —— 这正是母巢 445 万行台账缺的东西（判分在系统内）
```

**这一条同时解决了 DWC 三个悬而未决的问题**：真值源长什么样、
怎么防回归、怎么保证判分器不被污染。

#### ★★★ 2. Structured Trace `Γ` → DWC 活性六层的实现形式

母巢的 `MechanismHealth` 只有 3 个字段（call_count / is_healthy / last_called），
把"从未调用"塞进 `stale`。

```text
DWC 侧的接口:
  Γ 的最小字段集 = {任务状态, 被调组件, 动作, 外部回执}
  G3 活性门的六层可直接从 Γ 逐层点亮:
    present       ← 文件/注册表
    registered    ← 登记表
    called        ← Γ 中出现调用事件
    succeeded     ← 外部回执匹配
    produced_effect ← 下游可观测产物
    feedback_closed ← 回到判分器

Table 4 的启示: ρ 类故障是"非事件"
  ⇒ 若 Γ 不含机制事件, DWC 会重犯"调用失败看不出"的错
  ⇒ Γ 必须记录"本应调用但未调用", 这是负事件, 不能只记发生过的事
```

#### ★★ 3. Verified Coupling（回执判完成）→ DWC 的"完成"定义

```text
DWC 侧: 一次记忆写入被标记为完成的条件 =
        写入返回可验证的回执, 而非 "我调用了写入函数"
        ⇒ 直接治母巢 P0-3 (MemoryToolManagement 返回 ok:True 但零副作用)

接口: def _complete(receipt) -> bool: return receipt.matches(expected)
      禁止 def _complete(): return True
```

#### ★★ 4. Table 4 的故障定位协议 → DWC 的"死机制"判定

```text
DWC 侧:
  注入已知故障到组件 A/B/C, 问"哪个坏了"
  若"仅结果"证据的准确率低于恒定猜测基线 ⇒ DWC 的健康视图不可用
  这是一个可自动跑的"门是否有效"自检 —— 我在质量门里没有这一条, 建议补

  注: 母巢若做这个实验, "仅结果"条件大概率低于33.3% 基线
      (因为 effect 是自己给自己打的分)
```

#### ★ 5. 有界递归的边界声明（Eq. 10 的固定项清单）

```text
DWC 侧: 明确写出"递归里什么不变"
  固定: base LLM、判分器、门、定位与 patch 程序
  变:   仅记忆控制层
  —— 若做不到这个划界, 就不是有界递归, 是不可控自修改
```

### 5.2 不可迁移的点

| 不可迁移 | 理由 |
|---|---|
| **完整架构（EM+WM+ρ+𝒞 四组件）** | DWC 定位只有两件事，不需要四个记忆组件。§4 的 A5 原子性假设在小规模下不成立 |
| **Test-Time Adaptation 模式** | 需要 verifier 返回 1 bit。DWC 尚无外部 verifier（真值层尚未落地），前提不成立 |
| **性能数字（+17.8pp / 87.9% 等）** | ★ 全部基于 τ²-Bench / SkillFlow / τ²-Retail / ATM，以及 GPT-5.6 Sol、Claude Opus 5、Qwen3.6-27B/35B。DWC 的模型档位固定且远低于这些前沿模型，**零参考价值** |
| **Meta-Agent 用现成 harness** | 依赖 Claude Code / DeepSeek Harness 两个闭源/外部 agent 基建。DWC 若自研 Meta-Agent，该收敛证据不再适用 |
| **第3.4.2 的"两轮复合"结论** | 只有 2–4 轮且 Run C 第四轮回吐大半。**没有长期递归证据**，"递归会持续复合"是未证命题 |

### 最有价值的两组对照

**① 与 2606.14249 HarnessX：门的设计**
HarnessX 报告自己的 per-edit gating 被亚阈值耦合绕过（telecom 连续 5 轮同类型编辑全部过门、第 6 轮 −14.0%）。
Recuris 的 Eq. 9 门**结构上恰好封住这条路**：回归判据跑的是**锚点任务集**（含已会做的），
不是"当前任务是否变好"。这印证了本项目读到的判断——**两篇的门互相补，不是互相打脸**
（对 2606.09498 的双切分门则是"互相打脸"，因为它在 HarnessX 的 GAIA 上因任务冲突卡住）。

**② 与 2607.12790 Who Grades the Grader：证据等级**
12790 证明**下游任务分无法验证评估器**（塌缩的 always-pass metric 得分 0.811 > 正经的 0.767）。
Recuris 恰好做了 12790 要求的正确对照——**"仅结果"条件下 13.0%，低于 33.3% 的恒定猜测基线**，
等于自证"如果只用任务成功来判断哪坏了，会比乱猜还差"。**这是 19 篇里唯一一篇自己跑了这个反证实验的。**
