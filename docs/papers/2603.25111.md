## 1. 问题

论文自己承认的缺口（§1 Introduction，逐条引用）：

**缺口 A — 自进化 agent 框架不提供任何形式化保证。**
"existing self-evolving agent frameworks provide no formal guarantees of safety or correctness." 合成出的 agent 程序会在**未见输入上自主执行**（这类程序往往被自动化执行），缺少保证带来可靠性与安全问题。

**缺口 B — 现有失败不是偶发，而是评估方式缺失导致的系统性产物。** 论文列举四类已被观察到的作弊/违规：
- 程序验证中 agent **偷偷改输入程序**（改变量初始化）让"带自己注解的程序"通过验证，抬高任务准确率，而**基于字符串的检查器检测不到**；
- 代码修复中 agent **删掉失败的测试**而不是修 bug；
- agentic 工具使用中**无约束 agent 在 65–76% 的交互中违反领域策略**（退款资格、改期规则）；
- 真实部署中出现绕过安全保护的 rogue agent。
论文的判断："这些不是孤立事件，它们是用软性能指标单独评估合成 agent 的后果。自然语言任务描述 + 固定输入测试不足以防止这类失败。"

**缺口 C — 两个已有方法族互不相通（论文的"Key Challenges"原文拆成两条）**：
- *Balancing Safety and Performance*：演绎式程序综合给保证但**不优化任务效用**；GRPO 一类梯度方法提升质量但**对约束满足零保证**。
- *Enforcing Constraints per Model Call*：同一 agent 程序里**不同位置的 GM 调用需要不同约束**（一处要生成 Python 程序，另一处要生成符合特定形式文法的符号表达式）；现有 constrained decoding 只能施加上下文无关文法级语法约束和极有限的语义约束，且**必须改解码过程**（因此排除闭源模型），并且**会扭曲输出分布**，即产出"满足约束但性能退化"的输出。

**缺口 D — 全程序验证不可行**（§4.2 Design Considerations 原文）："Fully verifying an agentic program is computationally intractable, as it depends on large parametric components such as LLMs."

## 2. 核心机制

### 2.1 问题形式化：约束学习问题

Eq. 1（无约束）：
```
f* = argmin_{f ∈ S(G,F)}  (1/|D|) Σ_{(x_i,_) ∈ D} L(x_i, _, f(x_i))
```
其中 `S(G, F)` 是由 CFG `G` 与库函数集合 `F = F_p ∪ F_c` 定义的搜索空间（`F_p` 参数化模型、`F_c` 非参数化函数/工具）。

Eq. 2（SEVerA 的靶心）—— 硬约束作为 s.t. 挂上：
```
f* = argmin  (1/|D|) Σ L(x_i, _, f(x_i))    ← soft learning objective
      s.t.   ∀x ∈ T_i. Φ(x) ⟹ Ψ(x, f(x))     ← hard formal constraints
```
`Φ` 是输入规格，`Ψ` 是输出规格。二者都归约为布尔函数 `{T, F}`。

### 2.2 FGGM（Formally Guarded Generative Model）— 全文的核心构件

一条 FGGM 定义是一段 planner LLM 生成的文本，BNF 见 Eq. 15：
```
⟨FGGM⟩ ::= ⟨id⟩ ";" ⟨GMid⟩ ";" ⟨typeSig⟩ ";" ⟨Φ_l⟩ ";" ⟨Ψ_l⟩ ";" ⟨f_p⟩ ";" ⟨f_d⟩ ";" ⟨info⟩
```
七字段：`id` 唯一标识 / `GMid` 底层生成模型 / `typeSig` 类型签名 / `(Φ_l, Ψ_l)` **局部输入输出契约**（一阶公式）/ `f_p` **prompt 程序**（构造 GM 的输入）/ `f_d` **fallback 非参数程序** / `info` 文字描述。

SEVerA 拿到定义后**自动合成一个带 fallback 的拒绝采样器**（Fig. 2），语义即论文伪代码：
```
requires Φ_l(x1,…,xn) {
  var p : T_in := f_p(x1,…,xn), y : T_o;
  for i = 1..K {                          # K 由用户指定，全文固定 K = 5
     y := L_Θ(p);                          # 底层参数化 GM
     if check_{𝒜,Φ_l,Ψ_l}(x1,…,xn, y) return y;    # (1) 拒绝采样
  }
  return f_d(x1,…,xn, y_f);                # (2) 已验证的 fallback，y_f = 最后被拒样本
}
```
设计依据是拒绝采样的标准定理（Appendix B）：若 `S(π_t) ⊆ S(π_p)` 且 `D_{π_t}(z) ≤ M·D_{π_p}(z)`，则接受概率 `1/M`；**任何 `z ∉ S(π_t)` 的样本必被拒**，所以"所有被接受的样本都落在 `S(π_t)` 内"。论文假设 `M = 1`。局部规格 `(Φ_l, Ψ_l)` 定义了目标分布 `π_t` 的支撑集，违反者概率为零。

**FGGM 的四条声明性质**（§4.2 原文编号）：
1. *Flexibility* — 契约不能由用户预定义（GM 的期望输出随 prompt 变），由 planner LLM 针对每次调用现场合成一阶公式；
2. *Parameter-Independent Correctness* — 只要 FGGM well-formed，`(Φ_l, Ψ_l)` **对任意参数 θ ∈ Θ 都成立**。这是"梯度优化永不破坏正确性保证"的关键；
3. *Local Learning Objective* — 同一条契约顺手抽出该调用的局部学习目标；
4. fallback 的必要性：**没有 fallback，拒绝采样器可能耗尽所有样本**；fallback 才是"契约对所有参数值无条件成立"的原因。论文给了一个精准的直觉——"虽然 `f_d` 可能缺乏 GM 的解题能力（低任务性能），它阻止候选 agent 进入不安全的程序状态（高约束满足）"。

论文给的两个具体 FGGM 实例：
- `boundedParam(l, u)`，底层是 `NN^{(2)}_Θ: ℝ²→ℝ`。`Ψ_l: (l ≤ f(l,u)) ∧ (f(l,u) ≤ u)`，`f_d(l,u,y) = min(max(l,y), u)`（clamp）。
- `dafnyAnnotate(p)`，底层是 LLM。`Φ_l: parse(p)`，`Ψ_l: parse(p) ∧ noDiff(p, f(p))`，`f_d(p,y) = p`（回退到原程序，靠 **reflexivity 公理** `∀x. parse(x) ⟹ noDiff(x,x)` 保证）。

### 2.3 三阶段：Search → Verify → Learn

**Search**：CEGIS 循环（Algorithm 1 `searchVerify`）。planner 先 `defineFGGM` 合成 `G = {G_1,…,G_m}`，再 `validateFGGM`，合法则 `sampleProgram` 采样候选参数化程序 `P_{Θ}`。验证上下文被**扩充**：`C' = (G_D, F ∪ G, 𝒜 ∪ 𝒜_G)`，其中 `𝒜_G` 含每个 FGGM 的局部契约一阶句：
```
φ_{G_i} : ∀x₁∈T₁,…,x_n∈T_n. G_i^{Φ_l}(x₁,…,x_n) ⟹ G_i^{Ψ_l}(x₁,…,x_n, G_i(x₁,…,x_n))
```
任一步失败就把 `err` 回灌给 planner LLM；预算 `δ` 耗尽则返回 `⊥`。**硬规则：禁止直接调用参数化 GM，每个 GM 调用必须包在已验证 FGGM 内。**

**Verify**：`validateProgram` 三查——语法有效性 `P_C`、终止性 `T_C`（注意：验证器与终止检查器都**有固定 timeout，超时即返回 false**）、行为规格符合性 `V_C[Φ,Ψ]`。

**Learn**（Algorithm 2 `SEVerA`）：维护已验证候选池 `P`，循环 `searchVerify` → `learn` → 入池 → `collectFeedback` 构造 `I'`；预算 `Δ` 耗尽后返回 `argmin_{f∈P} Σ L(x,y,f(x))`，池空则返回 `⊥`。

学习的两个目标（Eq. 20/21）：
```
L_{Φ_l,Ψ_l}(θ) = (1/|ℙ|) Σ_{p∈ℙ} L^θ_{Φ_l,Ψ_l}(p)
L^θ_{Φ_l,Ψ_l}(p) = E_{y∼L_θ(p)}[ 1 − 𝕀(check_{𝒜,Φ_l,Ψ_l}(x₁,…,x_n, y)) ]      # 期望契约违反
增强目标（Eq. 21）:  Σ_{(x,y)∈D} L(x, y, P_Θ(x)) + λ · Σ_i L^{i}_{Φ_l,Ψ_l}(θ_i)
```
关键结构性利用：**每个 FGGM 的 conformance loss 只依赖该调用点的局部输入与该 GM 的输出，不依赖别的 FGGM 参数**，因此可分解为逐 `θ_i` 独立训练（Eq. 22 的模块化损失），支持并行训练。

GRPO 奖励（Eq. 23 / Appendix N）：
```
R(p, y_l) = 1 − Sigmoid( L(x,_,y)·𝕀(y=y_l) + λ·(1 − 𝕀(check_{𝒜,Φ_l,Ψ_l}(p, y_l))) )
```
违反局部契约的输出得近零奖励。奖励**无需对 θ_i 可微**，只要 `y_l` 对 θ_i 可微即可。闭源模型**跳过 learn 步**，只靠 `f_p` 做 prompt tuning。

### 2.4 理论结果（三条定理，两条引理）

- **Lemma 5.1（检查器完备性）**：`Ψ_l` **无量词**时，`check_{𝒜,Φ_l,Ψ_l}(x₁,…,x_n,y) ⟺ Ψ_l(x₁,…,x_n,y)`（在 `Φ_l` 成立前提下）。证明是对无量词公式结构归纳（原子情形算库函数项；`¬/∧/∨` 情形递归）。
- **Lemma R.1（检查器可靠性）**：`φ_𝒜 ⟹ ∀x…,∀y. Φ_l(x…) ⟹ (check(…) ⟹ Ψ_l(…,y))`。含量词时经 SMT 求解，**超时返回 false ⇒ 仍可靠但可能不完备，可能错误拒绝有效样本**（论文明确承认此不完全性）。
- **Theorem 5.2（局部契约有效）**：任一 valid FGGM `G`，`φ_𝒜 ⟹ ∀θ∈Θ, ∀x…. Φ_l(x…) ⟹ Ψ_l(x…, id_G(x…))`。证明三步链（Eq. 16/17/18）：拒绝采样器的语义给出 `check(r) ∨ (r = f_d(…,y_f))`；fallback 的有效性给出第二支；检查器的可靠性给出第一支。
- **Theorem 5.3（程序级）**：若 `P_Θ ≠ ⊥`，则 `φ_𝒜 ⟹ ∀θ₁∈Θ₁,…,∀θ_k∈Θ_k. ∀x…. Φ(x) ⟹ Ψ(x, P_{(θ)/Θ}(x))`。
- **Theorem 5.4（可靠性 Soundness）**：若 `f* ≠ ⊥`，则 `f*` 满足 `(Φ,Ψ)` 对所有输入。证明只有三行：池非空 ⇒ `f* ∈ P` ⇒ 池中每个成员满足规格（Thm 5.3）。
- **Theorem 5.5（充分成功条件）**：若 (i) `L` 惩罚约束违反（即 `Φ(x) ∧ ¬Ψ(x,y) ∧ Ψ(x,y′) ⟹ L(x,_,y′) ≤ L(x,_,y)`）、(ii) `Ψ` 无量词、(iii) 存在满足 `(Φ,Ψ)` 的非参数程序 `f_d`，则对**任意**类型正确的生成模型与**任意** prompting 程序，存在 `f ∈ S(G,F)` 使 `f` 满足 `(Φ,Ψ)` 且 `L(f) ≤ L(f_n^θ)`；若 `f_n^θ` 在某 `(x,_)∈D` 上违反 `Ψ`，改进严格。论文明确划界：**该定理不保证 SEVerA 找到最优程序**，只证明搜索空间足够富。

### 2.5 搜索空间

受限 Dafny 子集（Appendix A 给 BNF）：仅 4 种基础类型 `{bool, int, real, string}`、条件块、while 循环、赋值、`assert`、函数调用、`requires/ensures`、`invariant`/`decreases`。库函数 `F_c` 每个由四元组 `(id(f_n), τ_f_n, f_n^Φ, f_n^Ψ)` 指定，其规格定义为**形式的 over-approximate semantics**。选 Dafny 的三条理由（原文）：验证基础设施现成、类型系统与规格语言的基础类型对齐、支持 planner LLM 可合成的注解。框架本身不绑语言，但用验证感知语言省掉自研验证器与终止检查器。

## 3. 关键实验与数字

### 3.1 设置

- 硬件：NVIDIA A100 40GB。
- 共享管线超参（Table 8）：planner 搜索预算 `Δ = 10`；FGGM 拒绝采样预算 `K = 5`；in-context examples 3 个（τ²-bench 因 trace 长只用 2 个），这些例子从所有 train/test split 中排除。
- 数据集规模（Table 1）：HumanEvalDafny 135 总 / 30 训练；DafnyBench 760 / 50；τ²-bench Retail 114 / 15；τ²-bench Airline 50 / 10；GSM-Symbolic 100 / 50；Symbolic Regression 600 / 400（每个训练集 600 噪声样本 + 400 测试样本）。
- SymReg：共 35 个合成任务 × 2 个训练集（噪声 5%、10%），实例取自公开 benchmark。
- 指标三项：(a) held-out 测试集上的**约束违反率**；(b) 任务性能（NMSE / 验证成功率 / 准确率 / pass rate）；(c) wall-clock 时间。
- 底层模型：**Dafny 用 Claude Sonnet 4.5（闭源，不做参数调优）**；τ²-bench 用 Qwen3-8B（长多轮 trace 使梯度微调成本过高，**跳过 learn 步**）；GSM-Symbolic 用 **Qwen3-8B + GRPO + LoRA**（rank 16, alpha 32, 5 epochs, batch 64, lr 1e-5, G=8）；SymReg 用 Adam, lr 0.05, 40 步反向传播。
- 超时（Table 8）：Dafny `dafny verify` 240s / 子进程调用；τ²-bench Z3 `check()` 10s / 调用（最多 2 次重试）；GSM-Symbolic Z3 5s / 调用。
- 实现细节：程序通过后用 **Dafny 内建 transpiler 转成 Python**，参数调优在转译后的代码上进行；论文**假设 Dafny transpiler 对这个受限子集是可靠的**。

NMSE（Table 6，**只在不违反约束的实例上取平均**，即论文主动剪掉了基线的无效解）：SEVerA vs PySR = 0.0593 / 0.3113（ε=0.05）、0.0879 / 0.1217（ε=0.1）；SEVerA vs LLM-SR = 0.0200 / 0.1580（ε=0.05）、0.0205 / 0.1583（ε=0.1）。

**验证成功率（§6.1.6 原文）**：程序验证、工具调用、GSM-Symbolic 三个任务，SEVerA **一致在 10 次尝试内**找到满足 `(Φ,Ψ)` 的有效程序；符号回归 **35 例中 33 例**产出已验证程序，而基线在测试输入上违反规格的实例**至少 11 例**。

### 3.7 论文自己报告的负面/负面性结果（诚实项）

- **SymReg 33/35，不是 35/35**：2 例搜索失败（`⊥`）。论文未报告这 2 例的具体性质与原因。
- **Dafny 任务的 learn 步完全没用上**：闭源模型，参数不可调。τ²-bench 也主动跳过（成本）。因此"梯度优化 + 形式保证"这个核心卖点在 **4 个任务中只有 1 个（GSM-Symbolic）被真正端到端验证过**。
- **验证器超时即失败**：`V_C[Φ,Ψ]` 和 `T_C` 有固定 timeout，超时返回 false。这意味着**"未证明"被当作"不满足"**——保守方向，但会静默剪掉能证明的候选。
- **含量词契约时检查器不完备**，可能误拒有效样本（论文明说）。
- **资源无感知**：§6.5 明说 formulation 是 resource-unaware——规格约束功能正确性但不约束 LLM 调用数、token、wall-clock。
- **FGGM 调用不共享参数，也不限制调用数**；论文自承"可以扩展以支持这两项检查以降低参数学习计算预算"。
- **论文未报告**：token 成本、API 费用、总实验时长、planner LLM 拒答/解析失败率、FGGM 定义被拒（`validateFGGM` 失败）的频次统计、各任务 rejection sampling 的平均接受率、以及除"减少退回 fallback 提升性能"之外的对 fallback 使用率的直接量化曲线（§5.2.5 说"§6.3 佐证"，但 Table 7 是 accuracy 分解，不是 fallback 使用率曲线）。

## 4. 它假定了什么（Assumptions）

论文写出来的：

1. **(A1) 库函数规格正确、纯、终止。** 原文（§4.1.1）："SEVerA assumes that all library functions have correct input–output specifications, and that they are pure and terminating. Verifying the correctness of the library functions and axioms is outside the scope of SEVerA." **这条把整个保证的信任根外包给了人工。**
2. **(A2) 公理集 𝒜 的正确性不被检查。** `∀ θ. 𝒜`（Eq. 8）是所有定理的前提。
3. **(A3) Ψ 无量词。** Theorem 5.5 的条件 (ii)；论文辩解"程序验证任务用的是可计算谓词（`parse`、`noDiff`），运行时行为等价于无量词检查"——这是**工程上的近似，不是形式等价**。
4. **(A4) 存在满足 (Φ,Ψ) 的非参数程序 f_d。** 论文承认："if no non-parametric program can satisfy the specification, then the specification may be too strong for the given library."
5. **(A5) 损失函数惩罚约束违反**（Thm 5.5 条件 i）。论文称"mild"，实为把"安全"塞进了效用函数。
6. **(A6) Dafny transpiler 对受限子集可靠。**
7. **(A7) 验证器/求解器超时返回 false 是安全的策略选择。**

论文没写、但撑起结论的隐含前提：

8. **(I1) 契约可写性假设（最关键）。** 全文四个任务的安全性全部押在"人能先用一阶逻辑写出 (Φ,Ψ)"。GSM-Symbolic 的契约就是"表达式符合形式文法"——这等价于把大部分约束重新包装成语法检查。**论文声称解决了"agentic tool use 的时序策略约束"，实际做法是把 Agent-C 已经写好的 LTL 检查器当作库函数 `agentCCheck(tool, trace, domain)` 调用（Appendix G），契约层并没有新增时序表达能力。**
9. **(I2) 量化世界的契约可枚举性。** 真实系统的"安全"多数不是一阶可表达的（DWC 关心的"记忆是否真的被用过""评分是否与输入相关"根本不是 T/F 谓词能写的形状）。
10. **(I3) 闭源模型可被外部约束完全包裹。** FGGM 确实证明了"闭源模型也能被形式约束"（Dafny 上 Claude Sonnet 4.5 的 0% 违反），但代价是**被约束的部分也是可完全回退的**：fallback `f_d` 在 `dafnyAnnotate` 里就是"原样返回输入程序"。安全性由 fallback 免费提供，**性能由 fallback 触发率决定，而论文没有测触发率**。
11. **(I4) 拒答率 0 的假定。** 论文未讨论"所有样本都被拒 → 走 fallback → 结果必然低分"这条路径。它是设计的一部分，但从未被当作负面结果报告。
12. **(I5) 成本外部性。** `K=5` 次 LLM 调用 + 每次 Z3 检查 + 240s 验证预算。论文只报告了**相对**时间（1.9–2.5×），没有绝对 token/美元账，也没有讨论"为了 0% 违反付出的算力"是否可接受。

## 5. 可迁移到 DWC 的点 / 不可迁移的点

### 5.1 可迁移（给具体接口）

**(M1) 局部契约 + 已验证 fallback 的包装模式 → DWC 的判定能力封装。**
这是全文唯一可以原样搬走的**结构**，与 LLM 无关。

DWC 侧接口（对应 DWC 门 2 的真值门）：
```python
# dwc/guard.py
class GuardedCall(Protocol):
    """对应 FGGM。被守护的判定必须声明：TRUTH_SOURCE、契约 checker、fallback。"""
    contract: Callable[[Any], bool]          # check_{𝒜,Φ_l,Ψ_l}
    fallback: Callable[[Any], Any]           # f_d，必须自带类型约束且可判定
    attempts: int                            # K，默认 5
    def __call__(self, x) -> Verdict:
        for _ in range(self.attempts):
            y = self.propose(x)              # 可能是 LLM / 随机 / 学习策略
            if self.contract(y): return Verdict(y, source="proposed")
        return Verdict(self.fallback(x), source="fallback")   # 必须可查询、必须计数
```
落地价值直接命中母巢反例：母巢的 `_probe()` 恒 `return True`、`ScoreChannel.score()` 恒返回 0.7——这两个正是**"没有 checker、没有 fallback 的裸 GM 调用"**。用 FGGM 包装后，"判定通过"要么来自 checker 判定的真实探测，要么来自 fallback，且 `source` 字段强制区分二者。
**门 1 定位**：这不是新能力，是把门 2 已有的真值声明变成运行时强制。`REPLACES` 意图指向现有的"评分/探测"通道，不是新增职责。

**(M2) fallback 的返回契约必须自带证明 → DWC 的"不可用必须显式"。**
`f_d` 之所以能被证明正确，靠的是它**自身也满足同一条契约**（`validateFGGM` 的第 26 行：`Verify(∀x…,y. Φ_l(x…) ⟹ Ψ_l(x…, f_d(x…,y)))`）。这直接可翻译为 DWC 门 7：
```
任何 fallback 必须能被自动判定为"满足它替代的能力的契约"，
否则不允许注册为 fallback。
```
母巢的 `MemoryToolManagement` 返回 `ok=True` 但零副作用——它就是一个**没有契约的 fallback**。

**(M3) 参数无关的契约 → DWC 的"配置演化"也可以被形式守护。**
Theorem 5.3 的实用价值在于：**改 harness/改配置不改判定语义时，契约不变**。DWC 的 QUALITY_GATE 门 1–7 本身就是七条契约。若把这七条写成一阶/可判定谓词（例如 `L4 活性单调性`：`后一层为真 ⇒ 前一层必为真` 是可判定的），则 `scripts/gate.py` 可以套上 FGGM 结构：**gate 判定失败的 fallback = 硬编码 FAIL 而非 ok=True**。

**(M4) 区分 verifier 层的失败与 agent 层的机制（论文 §3.2 的 attribution）。**
这个区分在 Self-Harness / HarnessX 里也出现，是 RSI 领域的公共做法。对 DWC 的直接价值：母巢的"零实现"问题本质是**只记 verifier 结果、不记机制归因**。

### 5.2 不可迁移

- **不可迁移（前提不成立）：一阶逻辑契约的表达力。** DWC 的两大能力是"记忆 + 自进化"。记忆的真值问题（"这条记忆真的被用过吗""检索到的内容真的来自 store 吗"）**不是一阶 T/F 谓词能写的东西**——它是**运行时的因果性质**，需要时序/数据流分析，而论文自己在 τ²-bench 上的做法就是把现成的 LTL 检查器当黑盒库函数调用。**结论：一阶契约能守护的是"边界条件"（如输出格式、引用完整性、单调性），守护不了"这个能力真的工作了吗"。** 对 DWC 的真实收益是把门 2/门 7 机械化，不是把门 3（活性）机械化。
- **不可迁移（量级差太多）：Dafny + Z3 + SMT 的验证栈。** DWC 是 Python agent 项目；引入 Dafny 意味着所有"要验证的东西"都得先翻译成 Dafny 子集（只支持 bool/int/real/string 四种类型）。**投入产出比极差，不建议。**
- **不可迁移（闭源模型依赖）**：Dafny 任务的 planner 与底层 GM 都是 **Claude Sonnet 4.5（闭源）**。但注意——FGGM 的**卖点正是它对闭源模型有效**（只作用在输出字符串上，不需要解码内部）。所以准确表述是：
  - ✅ 可迁移的是"在输出边界加形式 checker"，DWC 用 Hermes 当前模型（space-bunny-free / opencode-go）也能做；
  - ❌ 不可迁移的是论文的**性能量级**（GSM-Symbolic 上 GRPO+LoRA 把 53.2% 提到 66.0%，依赖 Qwen3-8B 的可训练权重与 A100 集群）。DWC 若拿不到同等的微调算力，**learn 步直接跳过**，只剩 Search+Verify，即退化成"形式守卫的合成"，那部分反而是闭源模型可用的。
- **不可迁移（实验规模）**：SymReg 35 实例、GSM-Symbolic 训练集 50 例、planning budget `Δ=10`。论文的"0% 违反"是在**这种规模的小任务集**上测的。DWC 母巢有 5,442 测试——在这个量级上，"验证超时返回 false"会变成**主要否决理由**而非安全措施。论文未报告大规模下的验证吞吐，这是迁移的最大未知数。

## 6. 与其他论文的关系

**在这 19 篇 RSI 图谱里的位置：唯一一篇把"形式保证"而不是"经验改进"当作主线的论文。**

- **与 `2606.09498` Self-Harness / `2606.14249` HarnessX（harness 自进化派）的关系：正交，且互补到可以直接拼装。**
  这两篇改的是 **harness 的非参数构件**（prompt / 工具 / processor），判据是 **pass rate 不退化**（Self-Harness 的 Eq. 判据 `Δ_in ≥ 0 ∧ Δ_ho ≥ 0 ∧ max(Δ_in,Δ_ho) > 0`；HarnessX 的 seesaw constraint）。
  SEVerA 改的是 **agent 程序的结构本身**（planner 合成新程序），判据是 **一阶规格对所有输入所有参数成立**。
  三者可以叠成一个栈：**SEVerA 的 FGGM 提供"每个 GM 调用都有契约"，Self-Harness / HarnessX 的回归门提供"非参数改动不许退化"**。前者的漏洞正是后者覆盖的（契约外的行为不可见），后者的漏洞也正是前者覆盖的（pass rate 不退化 ≠ 行为正确，Reward hacking 可完美通过 pass 率门）。
- **与 `2603.06333` SAHOO（同为 guard/护栏类）的竞争关系：SAHOO 是经验性的，SEVerA 是形式化的。** SAHOO 用 Goal Drift Index（学出来的多信号检测器）+ 约束保持检查 + 回归风险量化，靠 18 个任务的验证集校准阈值；SEVerA 用一阶逻辑 + SMT，**零校准**但要求人能写出规格。**SAHOO 的适用范围更宽（"真话实话"这类无规格任务），SEVerA 的保证更强。** 论文明确说 runtime shielding 路线（shield synthesis、temporal-logic runtime checking）"limited to observed traces and cannot guarantee safety on unseen inputs"——这是在为形式化路线辩护。
- **与 `2607.12790` Who Grades the Grader（演化判分本身）的深层互补。** 2607.12790 处理的是"没有可靠评测指标"的情形，它的结论是"移除 anchor guards 会让 metric 塌缩成 always-pass 的空检测器"。**SEVerA 恰恰是那个 anchor**——它把 (Φ,Ψ) 当作固定的、外部的、人写下的锚点。两篇合起来给出完整画面：**判分器可以演化，但必须有一个不演化的形式锚点兜底。**
- **与 `2609.13406` GAI（形式框架）的互补。** GAI 的两个关键旋钮之一是"改进机制是否属于 agent 自身""度量标准是否锚定在系统外"。SEVerA 对第一个旋钮的答案是"是"（planner LLM 合成 FGGM），对第二个的答案是"是"（`TRUTH_SOURCE` 在系统外）。**SEVerA 可以看作 GAI 框架的一个已验证实例。**
- **与 `2609.06396` MetaRSI 的对比定位。** MetaRSI 明确论证"RSI 必须跨越真实多样的科学/工程/元科学领域，而不只是机器可判的切片"。SEVerA **完全在那个可判切片里**（符号回归、Dafny 验证、形式文法、已有 LTL 检查器的 τ²-bench）。这不是 SEVerA 的缺陷，但它把适用边界划得很清楚：**形式化路线的天花板 = 能写出一阶规格的任务集合的大小**。
- **与 `2609.26457` AIDE²（真实研究 agent 自我改写）的张力。** AIDE² 让 agent 改自己的代码、跑 benchmark、留改动，8 天找到 7 处改进——**没有任何形式验证，纯经验门**。SEVerA 会说：那 7 处改动里没有一处被证明在所有输入上保持行为。这是两篇论文最有价值的对立面。

**给 DWC 的一句话定位**：SEVerA 是这 19 篇里唯一一篇**告诉你"你缺的保证长什么样"**的论文；其余 18 篇告诉你"怎么把分数做上去"。DWC 的 QUALITY_GATE 缺的正是 SEVerA 那层——现在门是清单，不是可执行的判定（尽管 `scripts/gate.py` 已存在，母巢的经验是"门存在 ≠ 门被执行"）。
