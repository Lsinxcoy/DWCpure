## 一句话总结

把 10 个静态数据集改造成**顺序任务流**，用统一的 **Search–Synthesize–Evolve** 协议给 10+ 个记忆模块打"测试时进化"分，并提出 **ReMem**（把 `Think / Act / Refine` 做成动作空间的 MDP，Refine 是对记忆本身的元推理）——多轮环境 Claude 3.7 Sonnet 上平均 S/P 从 **0.24/0.52** 拉到 **0.78/0.91**、步数从 **22.6 降到 11.5**，同时证明**把成功与失败经验不加过滤地塞进记忆会让朴素方法显著退化**而 ReMem 仍稳。

## 核心方法（细颗粒度）

### 1. 问题：会记 ≠ 会用（§1 的中心区分）

> "agents **remember what was said but not what was learned**."
> "Conversational recall retrieves **prior facts**, whereas experience reuse **abstracts reasoning strategies** for future tasks. Without such reuse, models repeatedly solve similar problems..."

对既有工作的定位批评：StreamBench 只测事实保持、LifelongBench 不建模记忆结构与更新，其余测长对话一致性——"there is still **no unified framework** for evaluating how different memory methods retrieve, integrate, and evolve historical strategies in realistic streaming scenarios."

### 2. 形式化：四元组 + 三步循环（§3.1）

- 记忆 agent = **(F, U, R, C)**：F = base LLM，U = memory update pipeline，R = retrieval，C = contextual construction。
- 迭代式：$R_t=R(M_t,x_t)$ → $\tilde C_t=C(x_t,R_t)$ → $\hat y_t=F(\tilde C_t)$ → 新记忆 $m_t=h(x_t,\hat y_t,f_t)$（**$f_t$ = 反馈，如任务是否完成**）→ $M_{t+1}=U(M_t,m_t)$。
- 三步命名：**Search**（相似检索 / 索引 / 注意力）、**Synthesis**（结构化 prompt、挑关键条目、合并成短摘要）、**Evolve**（U 的实例化：检索型直接 append、长期存储做摘要压缩、有界容量做替换）。
- 数据改造：每个数据集转成 $\tau=\{(x_1,y_1),...,(x_T,y_T)\}$，**前面的任务为后面提供信息或策略**，预测轨迹 $(x_1,\hat y_1,M_1)\to\cdots\to(x_T,\hat y_T,M_T)$。全员跑同一 `search–predict–evolve` 循环。

### 3. ExpRAG（§3.2，简单基线）

- 记忆条目 $m_i=S(x_i,\hat y_i,f_i)$（模板化结构经验文本）；$R_t=\mathrm{Top}\text{-}k_{m_i\in M_t}\phi(x_t,m_i)$；按 in-context learning 原则条件生成；**append-only** $M_{t+1}=M_t\cup\{(x_t,\hat y_t,f_t)\}$。
- 自陈边界："performs **one-shot experience reuse** through retrieval and aggregation... **lacks iterative reasoning or adaptive refinement** during inference."

### 4. ReMem（§3.3，本文主方法）

- 每步 t 的动作 $a_t^n\in\{\mathbf{Think},\mathbf{Act},\mathbf{Refine}\}$，输出 $o_t^n=Agent(x_t,M_t,a_t^n)$。
- **Think**：内部推理轨迹，任务分解；**Act**：环境操作或给用户的最终回答；**Refine**：**对记忆的元推理**——原文「exploiting useful experiences, **pruning noise**, and reorganizing」（其后原文接符号 𝑀_𝑡，为避免 LaTeX 转写与原字符不一致，符号不入引文）。
- 步内可多轮 Think 与 Refine，**一旦选中 Act 该步终止**；状态 $s_t^n=(x_t,M_t,o_t^{1:n-1})$，动作空间 `{Think,Act,Refine}` → **诱导出一个 MDP**。
- 定位句：「expands the action space of ReAct-style (Yao et al., 2023) agents by introducing an **explicit memory reasoning mechanism**」……「memory becomes an adaptive component that interacts with reasoning in real time rather than remaining a passive context.」（原文在 ReAct-style 后插入了引用 (Yao et al., 2023)）。
- 附录 D 给了**实际输出协议**：`Think-Prune: <IDs>`（从 `RELEVANT EXPERIENCE` 段删指定 ID，如 "1,3" 或 "2-4"）/ `Think: <推理>` / `Action: <命令>`——**剪枝是模型显式输出的结构化动作**，不是外部启发式。

### 5. 统一检索与评测配置（附录 A.2 / A.3）

- 检索器 **BAAI/bge-base-en-v1.5**，query 与记忆条目都过它建索引，默认 **top-k = 4**（"ensures a consistent retrieval budget across all methods"），按相关度从高到低拼进 prompt；检索文本与任务输入**截断到同一 prompt 长度**。
- 自适应方法（SelfRAG、ReMem）"introduce additional reasoning modules that determine whether to retrieve and what to retrieve"，但原文是「operate on **top of the same retrieval pool**」以保证可比。
- **同一数据集内任务顺序全局统一**（"maintain a unified task sequence ordering within each dataset"），保证各模型的记忆演化动力学一致。
- **四个评估维度**：answer accuracy / success rate / **step efficiency** / **sequence robustness**。

### 6. 对比方法四族（§4.1.2 / 附录 A.4）

1. **无程序记忆 agent**：ReAct（记忆=当下 context）、Amem（缓存近期观察与反思的轻量记忆）；
2. **自适应检索记忆**：SelfRAG、MemOS、Mem0、LangMem（读/写/更新）；
3. **程序性记忆**：Dynamic Cheatsheet 两变体 **DC-Cu（curated）/ DC-RS（retrieval-based）**、**AWM**（Agent Workflow Memory）；
4. **本文**：ExpRecent（近期轨迹的压缩片段）、ExpRAG、ReMem。
- 排除项（原文）：只测事实召回的 MemoryGPT / MemoryBank 被排除；**MemOS 与 LangMem 因与具身环境不兼容，被排除出多轮评测**。
- backbone：**Gemini-2.5（Flash / Flash-Lite / Pro）+ Claude（3.5-Haiku / 3.7-Sonnet）**，全部走官方 API。

### 7. 数据集与规模（§4.1.1 / 附录 F，逐个）

**单轮**：MMLU-Pro（Engineering **969** 题、Economics **844** 题、Philosophy **499** 题，全库约 12K/14 学科）· GPQA-Diamond **198** 题 · AIME-24 / AIME-25 各 **30** 题 · ToolBench **750** 个工具调用任务。
**多轮**：AlfWorld **134**（家务指令跟随）· BabyAI **112**（网格导航+组合语言）· ScienceWorld **90**（开放式科学实验）· PDDL **60**（符号规划）。

### RQ2 · 收益来自任务相似度（§4.2.2 / 图 3）

> "ReMem's improvement strongly correlates with within-dataset task similarity (**Pearson r = 0.717** on Gemini 2.5 Flash and **r = 0.563** on Claude 3.7 Sonnet)."
> 相似度度量："average **cosine distance** between each task embedding and its dataset cluster center"（embedding 取自 retriever encoder；距离越小 = 越同质）。

> 步数："ReMem achieving the largest and most stable reductions (e.g., **from 22.6 to 11.5 steps on AlfWorld**)."

### 论文未报告 / 负面项

- **无方差、无显著性检验、无重复随机种子说明**——"Reported results are averaged across multiple task instances and trajectories"，**论文未报告** std / CI / 显著性。

- 风险（附录 C 自陈）：记忆更新依赖 LLM 输出 → "Imperfect or inconsistent LLM outputs may lead to **unreliable memory updates**"；且"memory-based agents may be vulnerable to **attacks or poisoning**"。

## 与 DWC 的映射（机制｜DWC 现状｜判定，代码级具体）

| Evo-Memory 机制 | DWC 现状（代码级） | 判定 |
|---|---|---|
| **ExpRAG：结构化经验 `S(x,ŷ,f)` + top-k 检索 + append-only**（k=4，bge-base-en-v1.5，相关度降序入 prompt） | `MemoryKernel.recall_search(scene, terms, k=5)`：**四路**（场景词 / 同 q·m 签名 / 同 chain / 双时间轴）+ **RRF 融合**（"不用加权求和，免得各路量纲不可比"）；写入 `remember()` 是 append | **同型确认且 DWC 更强**：路数更多、融合更稳。差异：Evo-Memory 的条目带 $f_t$(正确性)直接进检索语境，DWC 的反馈以 `effect_count` 存在节点上，**没有进 prompt 的显式"这条经验当时成没成"字段** |
| **ReMem `Refine` / `Think-Prune: <IDs>`（模型主动剪枝）** | `MemoryKernel.eviction_candidates()`：**只列证据不删**——`evictable = access_count==0 and effect_count==0 and not rare_protected`，"淘汰决策由 evolver 依 GAI dials 决定"；`dream(c,q,m)` 两级门槛（被用过 / **跨簇唯一签名豁免**） | **同型但驱动相反，DWC 更安全**：Evo-Memory 让 LLM 每步直接删（可误删），DWC 是"证据摆出来 → 别处决定"。**判定：半有（能力同位，权限边界不同，DWC 的设计更好）** |
| **RQ4：不加过滤地存失败经验 → 朴素记忆显著退化**（Gemini 上 Amem/DC-Cu/AWM 的 Avg S 只有 0.28–0.31；Claude 上 ExpRAG 在 ScienceWorld 掉到 **0.27/0.63**，ReMem 仍有 0.69/0.91） | DWC **刻意**把 `MemoryKind.FAILURE_SIGNATURE` 存进 **EXPERIENCE 区**（D6 门槛：payload 必须含 `(c,q,m)`，否则 raise）；`dream()` 把 N 条同类失败归纳成一条技能 `{"scene","method","boundary"}` | **风险直接对应，且 DWC 有对冲、无对照**：DWC 的对冲 = D6 写入门槛 + dream 归纳（失败不当经验直接用）+ 稀有保护；但 **DWC 没有做过"带失败记忆 vs 不带"的对照实验** —— 这是 Evo-Memory 表 3 那种实验，DWC 可直接抄（同一批任务，`FAILURE_SIGNATURE` 全量 vs 仅 `SKILL` 两种记忆态） |
| **收益与任务相似度相关：r=0.717 / r=0.563**（相似度 = 任务 embedding 到簇中心的平均余弦距离） | `recall_search` 的路 1（场景词）与路 2（同 q·m 签名）本质都是相似度先验；`judge.task_scores()`（**C3' TS3 口①**：逐任务分数序列）是 δ_θ 的数据源 | **可迁移的度量方法（缺）**：DWC 可用 `task_scores()` 按能力组算"组内任务相似度 vs 记忆召回收益"的相关，把"记忆什么时候有用"从断言变成曲线。Evo-Memory 给了**可直接套用的分析范式** |
| **剪枝率随任务多样性变化**（GPQA 36.8% vs AIME 10.8–17.5%） | `eviction_candidates()` 的稀有保护：同 `(c,q,m)` 全库计数 ≤1 ⇒ `rare_protected=True` 不淘汰；`dream` 的 `unique_waiver` 是**同量的镜像**（"淘汰时唯一签名受保护，归纳时唯一签名也不该被'没人用'卡住"） | **确认型 + 可抄报表**：DWC 有稀有保护机制但**从未报过各区淘汰候选率/实际淘汰率**，Evo-Memory 的"按数据集报剪枝率"是现成的健康度指标 |
| **统一 `search–predict–evolve` 协议 + 数据集内任务序全局固定** | `el_sched.ELScheduler.decide(...)` 的 `n_envs` 每次传入，因为"DWC 世界树的代内环境数是**动态的**（legal_actions 随揭示变化），调度器自己数不了 —— 这是与论文任务集静态 N 的**实例化差异**（明标）" | **明标的实例化差异**：Evo-Memory 的可比性建立在"静态任务流 + 固定顺序"上，DWC 的任务流是揭示驱动的。**照搬其评测协议需先冻结任务序**，否则顺序效应无法归因 |
| **记忆外置于模型、不改权重**（附录 E.3："Memory modules operate externally and **do not alter the underlying model weights**"） | `MemoryKernel` = sqlite（WAL），`MemoryNode` frozen dataclass；七管 `REMEMBER/RECALL/LEARN/REFLECT/EVOLVE/DREAM/MAINTAIN` | **同型确认**（同为外置、可审计、不碰权重） |
| **step efficiency（AlfWorld 22.6→11.5 步）与 sequence robustness（Easy↔Hard 方向）两个指标** | DWC **无**"完成任务步数"指标（`el_sched` 只吃 8 次布尔观测算 pass rate）；也**无**任务顺序鲁棒性对照 | **缺（两个都是可直接加的指标）**：步数可挂在世界树节点深度上；顺序鲁棒性可挂在 `score_history` 上 |
| **风险章：记忆投毒 / LLM 不可靠输出污染记忆** | `TRUTH_SOURCE` 全模块声明 + 启动期 `_check_truth_source` raise；D6 写入时字段门槛（"缺就不许进 EXPERIENCE"）；judge "只读 agent 可见面，绝不读 r_priv" | **同型确认**：DWC 用**结构门槛**（写入时校验、真值源在系统外）对付同一风险，比 Evo-Memory 的"留给未来工作"更进一步 |

**最该抄的两条**：
1. **表 3 的对照设计**（存成功+失败 vs 只存成功）——直接对应 DWC"失败签名进 EXPERIENCE"这个设计选择，DWC 目前只有机制、没有证据。落点：`tests/` 加一组记忆态对照跑同一批 dev 任务，读 `judge.score()` 的 `pass_rate` 与 `task_scores()` 序列，不动判据面。
2. **相似度–收益相关分析**（r 值 + 簇中心余弦距离）——DWC 已有 `task_scores()`（C3' 口①）与记忆的 `chain_id`/场景词分组，缺的只是把两者接起来算一次相关。

**不可迁移的**：① 10 个学术基准 + 闭源 API 的**量级**（"tens of thousands of US dollars"）——DWC 承重阶段跑不起；② **bge-base-en-v1.5 + top-k=4** 这套检索预算的普适性——DWC 是中文场景词 + 签名 + 链的混合检索，语义检索那一层 DWC 没有，硬加等于扩判据面；③ ReMem 的"模型自己决定何时剪枝"——DWC 的可写面与判据面分离原则（G1/G2）不允许把删记忆的权力直接交给 LLM 单步输出。

## 综述 L 定位

- **L 几**：**L4（Autonomy in Deployment and Environmental Adaptation）**。综述 2609.11873 **§3.5** 与 **§3.5.1（Trajectory distillation）** 引用它（`Cited by: §3.5.1`）。
- **综述表中原行**（L4 表列 = Method / Update target / Timing / Update validation，位于 "Success/failure contrasts and teacher distillation" 组内）：
  `Evo-Memory | Wei et al. [2025b] | Accumulated agent memory (benchmark) | Sequential task streams | Long-horizon evaluation of memory reuse.`
- **综述正文原句**（§3.5.1 Evaluation protocols 段；原文在 Evo-Memory 后插入了引用 "Wei et al. [2025b]"，故分两段引）：「Evaluation protocols for this family differ in time horizon and in what they count as benefit.」……「restructures datasets into sequential task streams so that **memory accumulation and reuse can be measured over long horizons**.」
- **技术族**：**trajectory distillation / 持久记忆复用的"评测协议"**——注意综述把它归为 benchmark（Update target 列明写 `(benchmark)`），它**不是**新的记忆方法，而是给 Dynamic Cheatsheet / ACE / ReasoningBank / APEX / PersonaAgent 这一族方法**提供测量面**的那件工具。
- **为什么不是 L1/L3**：按 11873 的分工，L3 中心是"为学习获取什么经验"、**L4 中心是"运行经验如何改变后续任务用的记忆/技能/执行组件"**——Evo-Memory 测的正是后者（"accumulated agent memory" + "long-horizon evaluation of memory reuse"），所以落 L4 而非 L1 评估层（评估层代表是 HealthBench，见 2505.08775 报告）。
- **structural / effective 判定**：**Evo-Memory 自身两者皆不成立**——它不持久修改任何"负责未来改进的机制"（无递归），且它是**别人做 L4 时给 effective 证据用的测量工具**。论文提出的 ReMem/ExpRAG 在综述语境下属于 L4 的**被测方法**；若某系统用 Evo-Memory 的分数反过来改自己的记忆更新策略并跨轮持久，那才是 structural L4 → L5 的第一步，**本文没有这个闭环**。
