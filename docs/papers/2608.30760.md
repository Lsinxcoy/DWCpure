## 一句话总结

PRACTICE 把"技能库怎么更新"从**人写的 prompt 工作流**变成**可训练的策略**：一个参数化的 skill learner `S` 读（当前技能库 `V` + 新轨迹批 `B`）产出结构化 batch-edits（`ADD/REVISE/MERGE/REMOVE`），层级化 consolidate 成下版库，而 **executor 参数全程冻结**；训练走三段课程（Stage 0 用 oracle 成功轨迹冷启动生成/编辑/合并 → Stage 1 用**同任务、多 executor 成败对照**学 `invalid_conditions` 与 `recovery_strategies` → Stage 2 Skill OPD 在学生自己生成的 edit 序列上对 32B teacher 做 Top-K forward-KL 蒸馏），最终在 EB-ALFRED / EB-Habitat 上把冻结 executor 的平均成功率从 24.3% 推到 **49.7% / 58.3%**，比最强经验类基线（MemCompiler 40.0 / 55.7）高 **9.7 / 2.6 个百分点**。

## 核心方法（细颗粒度）

### 0. 论文自陈的缺口（§1）

`existing experience-based methods often rely on manually designed prompting workflows to extract and update skills. Such fixed procedures may struggle to learn updated skills from new and diverse experiences.`（Abstract，L12–16）；正文归纳为：这些方法"the library content evolves, **its update policy does not learn** from accumulated experience or downstream execution outcomes"（L119–122）。核心问题原文：`Can an embodied agent learn not only new skills, but also how to grow and refine those skills?`（L123–124）。

### 1. 形式化（§3.1）

- **Executor**：部分可观测决策过程，轨迹 `τ = (I, o1, a1, …, oT, aT, y)`，`y∈{0,1}` 成败；**`π_exec` 参数恒冻结**（L263–268）。
- **技能库**：`V = {v_j}`，技能卡 `v_j = (p_j, u_j)`，`p_j = [(a1,φ1),…,(aL,φL)]`（原语动作+参数，如 `(pick_up, object_target)`），`u_j` = 使用规格（**何时适用 + 失败如何恢复**）（L269–284）。
- **技能引导执行**：`a_t ~ π_exec(·| I, h_t, V)`（Eq.4）—— 库变了，动作分布与轨迹分布就变，**尽管参数没变**（L285–295）。
- **学习器**：`Δ = S(V, T)`（Eq.5），`V' = Apply(V, Δ)`（Eq.6）；闭环 `V_i → T_i → S_{i+1} → V_{i+1} → T_{i+1}`（Eq.7，L334）。

### 2. 初始库：BPE 式动作模式发现（§3.2）

无技能增强的 executor 跑成功轨迹 → 转原语动作序列 → 迭代合并**频繁相邻子序列**（借 Sennrich 2016 的 byte-pair encoding 思想）→ 由初始 learner `S0` 固化成结构化技能卡，得 `V0`（L341–350）。

### 3. 三段课程（§3.3，Algorithm 1 = L966–1012）

监督目标：teacher `G` 产出结构化 edit 集 `Δ*_i = G(V_i, B_i)`（Eq.8），SFT 目标为标准自回归负对数似然（Eq.9，L374–384）。

- **Stage 0 · Oracle-Grounded SFT**（只用成功 oracle 轨迹），三类互补监督：
  - `Δ^gen = G(∅, B)`：**空库生成**（学抽象，不依赖既有卡）；
  - `Δ^edit = G(V0, B)`：**给定 BPE 库做局部编辑**（增/改/并/删/保持，学"只动局部"）；
  - `C0 = G_merge(V0, {Δ^edit_b}_{b=1}^M)`：**跨批合并**（`M` 个独立批的 edit 去语义重复、并兼容动作模式、调和重叠触发条件、前置/效果不同则保留），学"库级一致性"（L396–443）。`D0 = D_gen ∪ D_edit ∪ D_con`。
- **Stage 1 · Failure-Aware SFT**：batch 不再随机混合，而是**同一任务 q 的多 executor 轨迹** `B_{1,q} = {τ_{q,m} | m∈M}`（L454–460），teacher 联合分析产出 failure-aware edit `Δ*_1 = G(V1, B_{1,q})`，额外写进卡里的字段是 **`invalid_conditions` 与 `recovery_strategies`**（L956–960）。executor 池 8 个异构模型：Gemini-2.5-Flash / 3-Flash / 3.1-Pro / 3.5-Flash / GPT-5.4 / Qwen3.5-Flash / Qwen3-VL-8B / 32B-Instruct（L949–955）。
- **Stage 2 · Skill OPD**（§3.4，Algorithm 2 = L1084–1124）：学生在**自己采样的多轮 edit rollout** 上，被冻结 teacher 在同前缀打分，最小化 **teacher top-K 重归一化分布 → 学生的 forward KL**：
  ```
  L_OPD = E_{c_ℓ}[ D_KL( p_T^(K)(·|c_ℓ) ‖ p_S(·|c_ℓ) ) ]        (Eq.19)
  ℓ_t = Σ_{v∈K_t} π_T(v|s_t)·[log π_T(v|s_t) − log π_S(v|s_t)]   (Eq.22)
  L_total = L_OPD                                                (Eq.24, K=32)
  ```
  **无任务奖励、无 PPO/GRPO 策略梯度**（L1050–1055）；log-prob 从 −10 截断、单 token loss 裁到 [0,10]（Algorithm 2 第 25、29 行）。
- **更新子程序**（Algorithm 1 第 23–31 行）：轨迹分批 → 每批 `Δ_m ← S(V,B_m)` → `ApplyEdits` → **`HierarchicalConsolidation`** → 返回 `V'`。

### 4. 训练配置（§4.1 + 附录 B/表 6）

SFT：student Qwen3-VL-8B-Instruct、监督 Qwen3.7-Max、3 epochs、lr 5e-7、AdamW、cosine、bf16、max seq 8,192；Stage 0 ≈4 GPU·h、Stage 1 ≈3 GPU·h。OPD：teacher Qwen3-VL-32B-Instruct（冻结）、**6 epochs（表 6）**、全局 rollout batch 8、每 prompt 1 rollout、K=32、chunk 8、**≈64 GPU·h**、8×A100-40GB（FSDP）+ vLLM（TP=2/8）。`The training time for SFT stages are about 7 GPU hours in total and 64 GPU hours for OPD. So overall, the method is computationally lightweight.`（L1070–1072）。技能编辑批 = 10 条轨迹，每次 consolidation 合并 15 个候选 edit（L531–533）。**⚠️ §4.1 正文写 `train for 20 epochs`（L536），表 6 写 `Training epochs 6`（L1166），二者矛盾，论文未解释。**

### 5. 评测设定（§4.1）

EmbodiedBench 的 **EB-ALFRED** 与 **EB-Habitat**，各 6 个 split：Base / Common / Complex / Visual / Spatial / Long；每 split **50 episode**（表 7 注，L1327），主表指标 = task success rate (%)。

## 它假定了什么（Assumptions）

1. **executor 冻结、库外挂就够** —— 全部收益建立在"库改变动作分布"上；对需要新感知/新 grounding 能力的任务（Visual/Spatial 的弱表现）不成立，论文自己承认 `spatial grounding and extended state tracking remain difficult to encode through fixed skill structures`（L1303–1306）。
2. **有一个足够强且固定的 teacher**（Qwen3.7-Max 出监督、Qwen3-VL-32B 出 OPD 目标）。更新策略的学习能力**上限由 teacher 给定**，learner 不产生 teacher 之外的新编辑知识 —— 这与"自进化"的直觉不同，它更像**蒸馏 + 在线分布对齐**。
3. **成败信号可信且任务级可比**（Stage 1 的同任务对照依赖 `y∈{0,1}` 正确）。
4. **技能卡是可枚举的结构化对象**（ADD/REVISE/MERGE/REMOVE 四操作封闭），合并有唯一正确答案 —— `HierarchicalConsolidation` 的正确性没有独立度量。
5. **基准规模可接受统计噪声**：每 split 50 episode、全库 29/15 张卡、SFT 2,250 条 —— 在这个尺度上 +2.6pp = 1.3 个 episode 的量级，**无重复实验无区间**。
6. **技能库不无限增长**（`consistent as it changes rather than growing unbounded`，综述转述语；本篇自己也说 consolidate 会删并）—— 但**何时该退役技能**没有判据（只在 C.2 用 benefit–risk 四象限做事后观察）。

## 综述 L 定位（2609.11873）

- **引用位置**：§3.5.1 *Trajectory distillation* + Table 6（L4 代表系统表），f=2。
- **Table 6 那一行**：`PRACTICE | Bai et al. [2026] | Embodied skill library | Offline batches | Success/failure contrasts and teacher distillation.`（更新对象=具身技能库；时机=离线分批；验证=成败对照 + teacher 蒸馏）。
- **§3.5.1 正文那句**：`PRACTICE Bai et al. [2026] applies the same offline distillation to embodied agents while keeping the skill library consistent as it changes rather than growing unbounded, where a trainable skill learner proposes batch edits that add, refine, merge, or remove entries. The learner first learns basic skill generation and library maintenance from oracle trajectories, then learns failure awareness by contrasting successful and failed trajectories from different executors on the same tasks, and is finally distilled toward a stronger teacher on its own edit distribution.` —— 综述把它放在 Trace2Skill 之后，作为"**程序性技能库**"子类的代表。
- **按 B0→L5 判据定级**：persistence ✓ ⇒ 越过 B0；更新对象=持久技能库、时机=部署/离线批次 ⇒ **L4**；与 MemToolAgent 的关键差别在于 **更新策略本身是训练出来的**（strategy selection 不再完全由人写 prompt 决定）⇒ 在 L4 内部属于"策略已学"的强形态，接近 L3–L4 交界（它也决定了"下一轮需要什么经验"：Stage 1 主动收集同任务成败轨迹）。**不是 L5**：learner 从不修改 teacher、不修改评估、不修改自己的训练过程（无 meta-recursion，综述 Table 8 第六维缺位）。
- **与 11873 的两处呼应**：① 综述把 L4 的失败分成 activation/execution 两类，PRACTICE 的表 7 把它落成 `Inv. / Exp. / Acc.` 三个可测比例（297/300、270/300、80.2%）—— **可直接借作 DWC 记忆的 activation 度量**；② 综述的 Library Drift 警告在本篇有微观证据（卡数非单调、低频技能无效）。
- **与同批论文的关系**：相对 `2603.25158`（Trace2Skill，prompt 工作流）是**同对象、换更新策略**的竞争/升级关系；相对 `2606.07909`（MemToolAgent，检索式复用、不动策略）是**更强自主**的一侧；相对 MemCompiler（表 1/表 2 的直接基线）是**明确的 SOTA 挑战者**（+9.7/+2.6）。三者合起来正好覆盖综述 Table 6 的三行：检索式记忆 / 技能库 / 用户偏好记忆。
