## 2. 核心机制

本文是**综述**，没有算法。它给出的"机制"是**一套形式化定义 + 三级分类法 + 判据**。这三样都可直接搬到 DWC。

### 2.1 形式系统（§2.1–2.2）

**Agentic system**：`S = (A, E)`，A 是 agent collective，E 是环境。
**Agent 是统一演化单元**：`a_i = (m_i, h_i)` —— m_i 是模型 backbone，h_i 是 harness（"such as memory, tools, skills, prompts, or workflows"）。

```
Δa_i ≠ 0  ⇔  (Δm_i ≠ 0) ∨ (Δh_i ≠ 0)
```

**关键定义（原文明确）**："Agents may share the same backbone yet remain distinct if their harnesses instantiate different roles or objectives."（**共享 backbone 仍是不同 agent —— 差异在 harness。** DWC 的记忆底座与自我强化引擎可以是同一个模型的两个不同 agent，这条定义给出了依据。）

**Agent 不是无序集**：

```
A = ( {a_1, …, a_n},  Π )
```

Π 编码角色、通信拓扑、分工。"A evolves whenever an $a_i$ **or** Π changes."
**Trajectory**：`τ^t` 是截至第 t 步累积的 thought–action–observation 序列。

**Evolution mechanism Ω**：`S^{t+1} = Ω(S^t, τ^t)`。"It specifies **what can evolve, when evolution is triggered, how variants are generated or updated, where evolution takes place, and how evolution quality is evaluated**."（这五项即 §5.1 的分解维度，是全文最可搬运的一块。）

**Co-Evolution 的定义（§2.2，加粗强调原文）**：**coupled 形式的自进化，其中至少两个演化单元共同适应并持续重塑彼此后续的进化，而非仅仅交换信息或交互。** 要求三件事同时成立：

```
S^{t+1} = Ω(S^t, τ^t),
∃ x ≠ y ∈ S^t :  x^{t+1} ≠ x^t,  y^{t+1} ≠ y^t,
x  ←→(evolutionary pressure)  y
```

### 2.2 三阶段 taxonomy（§2.3，Figure 2）

| 阶段 | 递推式 | 变了什么 | 原文对边界的说明 |
|---|---|---|---|
| **Stage 1** Agent–Agent | `A^{t+1} = ({a_i^{t+1}}_{i=1..n}, Π^{t+1}) = Ω(A^t, E, τ^t)` | agent 集体内部：backbone、harness、组织结构 Π | "**Within a fixed environment**"；"Co-evolution begins when an agent no longer learns against a **static counterpart**" |
| **Stage 2** Agent–Environment | `(A^{t+1}, E^{t+1}) = Ω(A^t, E^t, τ^t)` | 环境也变：任务、反馈、交互空间 | "This coupled process can continuously change the agents, **but not the environment** in which they interact. When the environment remains fixed, **it limits the new experiences and pressures**" |
| **Stage 3** Meta | `Ω^{t+1} = Γ^t(S^t, Ω^t, τ^t)`，然后 `S^{t+1} = Ω^{t+1}(S^t, τ^t)` | **进化机制本身** | "In Stage 2, the evolution mechanism remains human-designed, so the system **can change its contents but not how they change**" |

**Stage 3 的判据（§5.1，最有价值的一段）**：机制修订必须**由下层 co-evolving 生态系统的联合轨迹诱导**，并且**必须反过来改变该生态系统的后续进化条件**。论文用这条把 meta co-evolution 与孤立的 meta-evolution 分开：

> "This criterion separates meta co-evolution from isolated meta-evolution. The mechanism revision must be induced by the joint trajectory of a lower-level co-evolving system and must then alter that ecosystem's subsequent evolutionary conditions."

**Open-endedness 的形式条件（§2.3/§5.1）**：**continuous novelty**（`Ω^{t+1} ≠ Ω^t`）+ **unbounded divergence**（`lim_{t→∞} H(S^t, Ω^t) = ∞`，H 为 adaptive capability）。

### 2.3 Ω 的五维分解（§5.1）

1. **what to evolve** —— 适应目标：agent backbone / harness / organization，或环境侧的 task / reward / world；
2. **when to evolve** —— 触发条件：failures、plateaus、distribution shifts；
3. **how to evolve** —— 变体生成：backbone training / harness revision / 结构生成与编辑；
4. **where to evolve** —— **两义**：进化域（tool use / web / robotics）+ 运行设置（sandboxes / simulated / real）；
5. **how to evaluate** —— 用 performance / novelty / safety / robustness 判定进化质量，"shaping the direction of later evolution"。

### 2.5 概念边界（Appendix A）—— 十条，本文最精确的贡献之一

| 概念 | 区分判据（原文要点） |
|---|---|
| Multi-agent interaction | "Interaction becomes co-evolution only when it produces **persistent updates to multiple agents** and their changes continue to shape one another" |
| Agent loops / loop engineering | 关心**任务如何被执行**，不关心 agent 是否跨任务改变 |
| Harness engineering | "**Designing a harness alone is not evolution. Evolution occurs only if the model, the harness, or both are updated and retained across runs. Even when both change, they still constitute one evolving agent**" |
| Evolutionary optimization | "candidates only need to be evaluated and selected, while co-evolution requires **persistent adaptive units**" |
| Continual learning | 变更累积在**一个持续学习者**内；"**no other component needs to adapt**" |
| Self-play | "can support self-evolution even when **only the current learner changes**"；co-evolution 要求多个保留各自改动的自适应单元 |
| Self-evolution | 任务/反馈规则/对手**固定**时仍可自我进化；co-evolution 要求另一个自适应单元**双向**重塑 |
| Meta-evolution | "The meta-level controller **may remain fixed** as long as it modifies this mechanism"；Meta Co-Evolution 额外要求修订**由下层 co-evolving 系统驱动并反过来改变它** |
| Iterative / recursive self-improvement | "Both may occur **within a single system** and therefore do not necessarily constitute co-evolution" |
| Open-endedness | "describes a possible long-term outcome rather than a particular form of evolution, and **co-evolution does not automatically guarantee it**" |

### 2.6 跨论文证据图的构造方法（Appendix C）—— 唯一有"方法"味道的部分

**Panel A / B（matched comparison）**：只纳入**同时报告静态/冻结对手与演化对手、且 backbone 与评测设置相同**的论文；多基线时选"controlled variant that differs from the full method primarily in whether the relevant counterpart is allowed to evolve"，而不是"arbitrary or strongest baseline"。指标**方向对齐后**再平均。**论文明确警告**：两端"should therefore be interpreted only as a within-paper comparison; their **absolute positions are not directly comparable across papers**"。
**Panel B 编码**：x = matched 评测设置数量，y = 启用对手演化带来的平均配对提升，气泡面积 = 正提升设置的比例，颜色 = taxonomy 阶段。
**Panel C（normalized trajectory）**：

```
x̂_t = (x_t − x_0) / (x_T − x_0)
ŷ_t = (y_t − y_0) / (max_τ y_τ − y_0)
```

lower-is-better 指标先方向对齐；**"Trajectories without an observed positive improvement are not included"**（这是一个会造成幸存者偏差的筛选规则，论文未讨论）；同论文多模型多指标先在论文内平均（每篇贡献一条等权曲线）；实线 = 论文级轨迹均值，阴影 = **一个样本标准差**，"reflects **cross-paper heterogeneity rather than experimental uncertainty or a confidence interval**"。

## 4. 它假定了什么（挖隐含前提）

1. **假定"共同适应"是可判定的。** 定义要求 `∃ x≠y ∈ S^t: x^{t+1}≠x^t, y^{t+1}≠y^t, x ⟷ y`。但**"y 的改变是由 x 引起的吗"无法从轨迹判定**——两个单元可能各自被同一外部环境驱动。本文从未给出因果识别方法。**这是整套 taxonomy 最脆的一环。**
2. **假定 Π（组织结构）的变化属于 co-evolution 而非工程变更。** §3.3（SkillMAS、MetaAgent-X、R3DM）被列入 Stage 1，但这些系统的组织改变通常由**人写死的更新规则**触发。**按本文自己的判据（§5.1：修订必须由下层联合轨迹诱导），它们更接近单实体演化。** 论文未处理这个张力。
3. **假定 Ω 可写成 S^{t+1} = Ω(S^t, τ^t) 这样的无记忆函数。** 但 Stage 3 的 Ω 本身在演化，且 §2.3 明确 `Ω^{t+1} ≠ Ω^t` —— **同一个符号 Ω 在两个阶段含义不同**（Stage 1/2 是固定机制，Stage 3 是变量）。论文用上标区分了符号，但论证时把两者放在一起说"evolution mechanism Ω specifies…"，这在逻辑上是混用的。
4. **假定五维分解（what/when/how/where/how-to-evaluate）是完备且互斥的。** 论文称 "We decompose the evolution mechanism into five adaptive decisions"，但未论证穷尽性。**"where" 的两义（域 vs 设置）本身就是不完备的证据。**
5. **假定跨论文比较可以靠方法学修补。** Appendix C 的 matched-pair 规则是认真的，但它无法修正**任务分布、骨干规模、训练预算、评测协议的系统性差异**。论文自己承认"absolute positions are not directly comparable across papers"——**那么 Figure 4 的跨论文均值带在语义上代表什么，论文没有回答。**
6. **假定 Stage 3 是值得追求的目标。** §5.1 称 meta co-evolution 提供通往 open-endedness 的路径。但**没有任何理论或实验说明 Ω 的演化不会走向退化**。论文引用 Stanley et al. (2017)、Hughes et al. (2024) 作为开放性定义，但**开放性与"机制可演化"之间的因果链在本文是断言不是论证**。
7. **假定"人类设计约束的逐步剥离"是单调的、方向正确的。** taxonomy 的叙事轴是"逐步 shedding human-engineered constraints"。但本文自己列出的风险（evaluator exploitation、partner overfitting）是**在 Stage 1/2 就会发生的**——剥离更多人类约束与更早出现退化之间，本文没有排序。
8. **假定文献里的"co-evolution"都是真 co-evolution。** 论文对被引论文的分类是**按其自述意图**（"authors position X as…"），未逐篇核实是否满足自己的三条件判据。因此 **Stage 归属存在系统性乐观偏差**。
9. **假定 Red Queen 类比成立。** "sustained progress requires mutual adaptation rather than adaptation on only one side" 是从生物演化借来的隐喻，不是论证。

## 5. 可迁移到 DWC 的点 / 不可迁移的点

> DWC 当前状态：`README.md` 记 "代码 0"；两件定位内的事 = **记忆底座** + **自我强化**；`docs/QUALITY_GATE.md` 已有 7 道可执行门；`scripts/gate.py` 已存在。本节给出的是前向接口定义。

### 5.1 可迁移（每条给出具体接口）

**① `a_i = (m_i, h_i)` 与 `Δa_i ≠ 0 ⇔ (Δm_i≠0) ∨ (Δh_i≠0)` → DWC 自我强化的记账单位**

- **搬什么**：把 agent 定义为 backbone + harness 的二元组，且**任一变化即演化**。这条直接解决 DWC 的一个现实问题：DWC 的自我强化大部分落在 harness 层（记忆写入策略、检索策略、改进提案生成），**不动权重**。
- **DWC 接口**：`src/dwc/selfevolve/agent_state.py`
  ```python
  @dataclass(frozen=True)
  class AgentState:
      backbone_id: str          # m_i，DWC 阶段内恒为同一模型
      harness: HarnessRef      # h_i，指向具体配置文件/代码路径
      org: OrgSpec | None      # Π，DWC 单体则可为 None
  def delta(a_prev: AgentState, a_now: AgentState) -> Delta:  # 显式返回改了哪个面
  ```
- **价值**：`delta()` 的输出可直接喂给 `scripts/gate.py` 的门 1——**"这个改动服务哪件定位内的事"从一个声明字段变成一个可机读的 Δ**。

**② Ω 的五维分解 → DWC 自我强化循环的五元配置**

- **搬什么**：what / when / how / where / how-to-evaluate 五个决策点，以及论文给 each 的候选项（what：backbone/harness/org/task/reward/world；when：failures/plateaus/distribution shifts；where：域 + 运行设置两义）。
- **DWC 接口**：`config/selfevolve.yaml`
  ```yaml
  selfevolve:
    what: [harness, memory]        # 阶段一白名单；不含 backbone
    when: [plateau, regression_risk] # 对应 2603.06333 的 R_c^adj 触发
    how: [harness_revision]         # 阶段一不开放结构生成
    where:
      domain: [memory_retrieval, proposal_generation]
      setting: sandbox             # 论文明确 where 有两义，必须写两行
    evaluate:
      metric: {truth_source: null, note: "见下"}
  ```
- **价值**：**"where 的两义"这一条不是纸上谈兵**——DWC 的自我强化必须在沙箱里试，论文明确把 sandboxes 列为 where 的一个取值。写在配置里，运行时可校验"实际运行设置是否与声明一致"。

**③ co-evolution 的三条件判据 → DWC 的"这算不算真自进化"判门**

- **搬什么**：`x^{t+1} ≠ x^t`、`y^{t+1} ≠ y^t`、`x ⟷ y` 三条同时成立。
- **DWC 接口**：`src/dwc/selfevolve/coupling.py::is_co_evolution(history) -> CouplingVerdict`，返回三字段 `both_changed / mutual_pressure_evidence / verdict`。
- **为什么 DWC 需要它**：DWC 的记忆底座与自我强化引擎**天然是一对耦合单元**——改进提案会改变记忆写入策略，写入策略改变会改变后续提案的质量。按本判据，**DWC 的第一版就处在 Stage 2**（agent–environment：环境=记忆状态随 agent 改变）。**但必须诚实：论文自己承认 `x ⟷ y` 无法从轨迹判定**（见 §4 第 1 条），所以这个接口的输出应标为 `UNKNOWN`，直接对接**门 2（真值门：没有外部真值源的评分 = 自说自话，一律标记 UNKNOWN）**。
- **警告**：不得把这个接口当成"已证明共演化"来写进 PROGRESS.md。门 5 明令"分析过了/设计好了/读过了不算进度"。

**④ 生态位分化判据 → DWC 记忆与强化的分工形式化**

- **搬什么**：§2.1 "Agents may share the same backbone yet remain distinct if their harnesses instantiate **different roles or objectives**"，以及 Π 编码 "roles, communication topology, and division of labor"。
- **DWC 接口**：`src/dwc/org.py::OrgSpec`（roles / topology / division_of_labor 三个字段）。DWC 阶段一是单体（Π = 退化值），但**接口先定义好**，因为综述的 Stage 1 → Stage 2 递进说明单体是特例而非终点。
- **价值**：这条让 DWC 的"记忆底座"与"自我强化"成为**两个有明确角色的 agent**，而不是一个系统的两个模块。**这正是 mother巢教训 L1（职责必须可声明、可去重）的形式化。**

**⑤ 邻居概念表（Appendix A）→ DWC 的术语纪律**

- **搬什么**：十条边界，尤其是三条会直接影响 DWC 表述的：
  1. "Designing a harness alone is not evolution" → **DWC 说"我改了 harness"时不许说"我进化了"**，除非能指出跨运行保留的痕迹；
  2. "Meta-evolution: The meta-level controller may remain fixed" → **DWC 改调度器不等于 meta co-evolution**；
  3. "Open-endedness is an outcome, not a form of evolution; co-evolution does not automatically guarantee it" → **禁止把"持续改进"称作"开放式"**。
- **DWC 接口**：`docs/adr/ADR-0001-术语纪律.md` 的术语表 + `scripts/gate.py` 门 1 的关键词检查（`docs/` 中出现 "开放式/open-ended" 而无 `OPEN_ENDEDNESS_EVIDENCE` 段落 → FAIL）。

**⑥ §6 的四个 co-evolution 特有失效模式 → DWC 门 7 的分类基线**

- **搬什么**：evaluator exploitation / partner overfitting / diversity collapse 三项 + "higher task success can hide exploitative behavior"，以及推荐的评估手段：historical cross-play、component ablations、held-out evaluators。
- **DWC 接口**：`src/dwc/selfevolve/failure_modes.py`，三项各一个计数器 + 基线快照；接到**门 7（静默可见门）**。其中 **held-out evaluators** 直接对接 DWC 门 2 的 `TRUTH_SOURCE` 字段：**任何评估器必须声明它是否 held-out**。
- **与已完成的 `2607.12790.md` 报告的呼应**：那篇证明"移除 anchor guards 会让 metric 塌缩成 always-pass 空检测器"——**diversity collapse 与 evaluator exploitation 是同一失效在两个层面的表现**，DWC 门 7 的分类计数器应该把两者分开记但共用一条基线。

### 5.2 不可迁移（写清为什么搬不了）

1. **三级 taxonomy 的"渐进性"不可直接当作 DWC 的路线图。** 论文是**分类**不是**建议**；Stage 1 → 2 → 3 的顺序来自"允许变的东西越来越多"这一描述轴，不含"应该先做哪个"的论证。**DWC 不许拿它当 roadmap。**
2. **Stage 3（Meta Co-Evolution）几乎不可迁移。** 论文自认 "Only limited work currently meets our definition of Stage 3"，唯一候选 RQGM（arXiv 编号论文未在正文给出，仅 Iacob et al., 2026）。**DWC 当前代码 0，离 Stage 3 差至少两级。**
3. **Ω 五维分解的完备性不可搬。** 论文未论证五维穷尽（见 §4 第 4 条）。DWC 用它做配置**只应作为"当前需要显式决定这五件事"的清单**，不能声称这是完整的机制空间。
4. **Figure 4 的跨论文结论不可作为 DWC 的效果预期。** 论文自述绝对位置跨论文不可比、阴影带不是置信区间、且"无正提升的轨迹被排除"（潜在幸存者偏差）。**任何"DWC 靠 co-evolution 能提升 X%"的说法都不能引用本篇。**
5. **依赖 RL/多智能体训练范式的方法族不可搬。** §3.1–§4.1 大量条目基于 GRPO、MARL、league training、reward model 重标注——**这些需要成规模 GPU 训练**（论文未逐篇报告算力，但 AlphaStar、POET、DRM 类工作的量级是公开的）。**标注：GPU 密集，DWC 不具备条件。**
6. **闭源模型依赖：本文不报告，但被引对象大量依赖。** ECHO、ARCO、SIA、ACE-Safety 等使用 Claude/GPT 级模型；本文对此不作汇总。**DWC 若照抄这些方法的实现，会继承同样的 API 依赖与成本结构——必须在 ADR 里标注（README 的诚实条款第 5 条）。**
7. **"evolution mechanism Ω 是无记忆函数"这一写法不可搬。** DWC 的自我强化循环是**有记忆的**（README 的第一件定位就是记忆底座）。Ω 需要参数化为带状态转移的算子，不能沿用本文的记号。

(2026)（Tool-R0）；而 `2609.04128.md` 记录的缺口是"本文没有触及安全性"——**而综述 §6 自己说 safety/governance 只是 desiderata、不提供具体方案**。**两篇的缺口完全重合：Stage 2 已经有人做，Stage 2 + 治理还没有人做。**

**与 `2606.14249` HarnessX 的关系：Stage 3 的一个具体实例（据 `2606.14249.md` §6 已记："HarnessX 是该综述 taxonomy 里 Meta Co-Evolution 的一个具体实例"）。** 本篇侧可补的判据检验：HarnessX 让 trace 同时成为 harness 演化的诊断证据与模型训练的 RL 信号——**按本文 §5.1 的 Stage 3 判据（修订必须由下层联合轨迹诱导、并反过来改变后续进化条件），HarnessX 满足第二条、不易验证第一条。** 这正好用来说明为什么本文说 Stage 3 稀缺。

**与 `2609.26457` AIDE²（本批次第三篇）的关系：一个精确的 Stage 归类 + 一个方法论冲突。**
- **Stage 归类**：AIDE² 的 Ω 由人写死（外环 = AIDE_human），**接受规则固定为 Eq.4 的 `argmax g(a)`**。按本文定义，**AIDE² 严格是单实体自进化**：内环 agent 被外环改写，但"counterpart"（任务集、评分脚本）是**固定的**，不随 agent 改变。**因此 AIDE² 是"iterative/recursive self-improvement"那一栏，不是 co-evolution 那一栏**——而 AIDE² 自己正是用这两个词命名其工作的（正文 §1 "Recursive self-improvement (RSI) points the research process at itself"）。
- **方法论冲突（重要）**：AIDE² 靠 `r_t^pub` 与 `r_t^priv` 的**信号解耦**防止内环直接优化外环判据，并实测 reward hacking 率从 55% 降到 32%。**本综述把"evaluator exploitation"列为 co-evolution 的特有失效模式但不给方案；AIDE² 给了一个不依赖 co-evolution 的方案（信号解耦）。** 这两篇合起来给出一条明确的判断：**"防 evaluator exploitation"不需要先做到 co-evolution 就能做。** DWC 若照综述的 taxonomy 规划，会误以为必须先建共演化才能防钻空子。
- **反向张力**：AIDE² 的 discovery 是"被改的是 harness 代码"，而综述 §2.3 明确 "changes to both still constitute **one** evolving agent"——**所以即使 AIDE² 持续改进 harness，它也永远不会变成 co-evolution，除非有人改任务集或评分脚本。**

**与 `2609.11873` Last AI 的关系：Roadmap 层级 vs 分类轴。** 据 `2609.11873.md`，11873 给出 L1→L5 的自主性路线（改进执行 → 改进策略 → 经验获取 → 环境适应 → 递归元改进）。**把本篇的三阶段叠上去看**：Stage 1/2 主要落在 11873 的 L2–L4，Stage 3 落在 L5。**两者是交叉的两套坐标**：11873 问"自主性有多高"，本篇问"哪些组件在共同演化"。**11873 未引用本篇；本篇未引用 11873**（本篇参考文献中检索 "Last AI"/11873 无命中）。

**与 `2609.06396` MetaRSI 的关系：Stage 3 判据的一处直接应用。** 据 `2609.06396.md`，MetaRSI 的元层改 `φ`（失败签名）——**即改"如何从失败产生下一次改进"这一 Ω 的一部分**，由下层轨迹驱动。**按本篇判据，这就是 Stage 3 的形状。** 本篇侧的可补检验：MetaRSI 的 Eq.30 把 `Q*`、release rule、账本排除在一切写入面之外（含元层）——**这恰好满足本篇 Stage 3 判据隐含的"锚不能自己被改"要求**，尽管本篇没有明说这一条。

**与 `2603.06333` SAHOO（本批次第一篇）的关系：综述点名了 SAHOO 所属的问题域，但没有覆盖它。** 综述 §6 的安全治理段列出具体失效模式与治理手段（"sandboxed deployment, continuous monitoring, rollback to verified states, and human intervention points"），**这四项恰好覆盖 SAHOO 的全部机制**（GDI = continuous monitoring；CPS 硬停 = human intervention point；checkpoint/rollback = F.3 Rollback Capabilities；漂移阈值外检测 = sandboxed deployment 的监测面）。**换言之：SAHOO 提供了综述所缺的具体协议，而综述提供了 SAHOO 缺失的定位。** 但 SAHOO 的保护对象是**单实体**（模型 θ_c 自身），综述的治理对象是**多组件联合演化**——**SAHOO 的 GDI 是否能测"多个组件同时漂移"，论文未涉及**。
