## 一句话总结

指出自我改进有两条互不来往的路线——**harness-update**（meta-agent 改工具/提示/重试/搜索逻辑，权重冻结）与 **test-time training**（手写 RL 管线改权重，harness 冻结）——并造一个 Feedback-Agent 在**同一个循环里**自由选择两种动作：harness 更新（`A_{g+1} = F(A_g, τ_g(π_θ), E_g, U)`，权重固定）或权重更新（LoRA，harness 固定）；三个域上 **SIA-W+H 严格优于 SIA-H**：LawBench 50.0%→70.1%（比前 SOTA 45.0% 高 **25.1 个百分点**，摘要写成"25.1%"是 pp 不是相对百分比）、TriMul runtime 12,483→**1,017 µs**（比前 SOTA 1,161 µs 快 12.4%，最终 speedup 14.02×）、去噪 mse norm 0.241→**0.289**（比前 SOTA 0.240 高 20.4%）。**但方法节只写了 harness 更新，权重更新的算法选择（PPO/GRPO/entropic/REINFORCE/BC/DPO 六种）放在 §7.3 讨论节、且自陈是"更广实验中观察到的常见模式"、"完整处理推迟到 v2"** —— 这是一篇结论清楚、协议登记不完整的论文。

## 核心方法（细颗粒度）

### 0. 问题定性（§1.2，两条 silo 与缺口）

- **Silo 1 Harness/scaffold self-improvement**：「A meta-agent rewrites the scaffold of the task-specific agent its system prompt, tool-dispatch logic, retry policy, and answer-extraction code across generations, while the underlying language-model weights are held fixed.」代表作 Darwin Gödel Machine、Meta-Harness、Hyperagents、ADAS(Hu 2024)。这条线的通病被点名：「scaffold edits concentrate on software-engineering hygiene parsing, retries, dispatch and rarely deliver domain-specific reasoning that the base model could not produce given any prompt.」
- **Silo 2 Test-time post-training**：「A hand-written RL pipeline updates the model's own weights on task feedback at test time, typically with the harness held fixed at a single prompt-and-grader template.」代表作 TTRL、Discover 线的 TTT、Akyürek 2024。这条线的问题：「the pipeline that delivers it is engineered by humans and does not adapt to the task structure that a scaffolded agent would expose.」
- **缺口**逐字：「These two silos operate in isolation. Harness work leaves the model fixed; test-time training leaves the harness fixed.」
- 目标声明：系统**只拿任务规格 U 与 verifier V**，「improves both its scaffold and its model weights without further human intervention」。

### 1. 术语与分解（§3）

- **task-specific agent** = LLM（权重 θ）+ system prompt + tool-dispatch logic（解析 tool-call 并路由到文件/执行/数据集/grader handler 的 Python）+ answer extraction + grader（确定性 verifier）。**scaffold ≡ harness = 非权重的固定部分**（system prompt ∪ tool-dispatch ∪ answer extraction ∪ 支撑设施）——「every part of the agent that is fixed code rather than model output」。
- 两个 **meta-agent**：Meta-Agent `A₁ = M(U, R)`（R = benchmark 自带参考实现）；Feedback-Agent `A_{g+1} = F(A_g, τ_g, E_g, U)`。
- **轨迹 τ_g 是完整结构化执行日志**（每个实例的每个 prompt、模型响应、tool call、tool result、抽取答案），不只是聚合指标——「This allows F to diagnose specific failure modes rather than react to summary statistics.」
- **三阶段协议（每代 g）**：① Execution（`A_g` 在沙箱里跑 `D`，数据集目录只读、工作目录可读写，抓 τ_g）→ ② Analysis（F 拿 `A_g` 源码 + τ_g + 指标 E_g + 可选样本任务描述，后者"以抑制单实例过拟合"）→ ③ Improvement（F 先产 **improvement report**（散文分析 + 拟改点），再产下一代 `A_{g+1}`）。
- 符号表里 `G_max` = 最大代数、`G` = RL 每状态 rollout 数——**两者的取值全文从未给**（见诚实条款）。

### 2. 方法总览（§5.1–5.3，Fig 2/Fig 3）

- 三个 LLM 组件：Meta-Agent（初始化 scaffold）、Task-Specific Agent（执行）、Feedback-Agent（选下一动作）。
- **动作 = 两类，软标签非硬阶段**：「Harness Update Phase and Weight Update Phase are soft labels for these two action types, not rigid sequential stages.」Feedback-Agent 在每步之后选 harness 或 weight，**选择依据是任务类型与观测到的奖励动态**（"conditioned on task type and observed reward dynamics"）。
- Fig 2(b) 给的**示例 7 步序列**：`A1 → A2 → A3 → θ1 → A4 → θ2 → θ3`，动作标 `FB: H, FB: H, FB: W, FB: H, FB: W, FB: W`（4 次 harness、3 次 weight，**交错**）。
- **harness 更新递推**：`A_{g+1} = F(A_g, τ_g(π_θ), E_g, U)`，其中 `τ_g(π_θ)` = 用当前模型 π_θ 执行 scaffold A_g 得到的轨迹；该步内**权重 θ 固定**。
- **Sample-task 正则**：Meta-Agent 初始化 scaffold 时用多样任务规格作条件，防止单实例过拟合。
- 实现分工：**Meta-Agent 与 Feedback-Agent 用 Claude Sonnet 4.6**；task-specific agent 用 `gpt-oss-120b`（harness 步）或其 RL 适配 checkpoint（训练步）。权重更新全走 **LoRA r=32、lr=4×10⁻⁵**（原文文本层作 `4×10 −5`，上标是我按语义补的可读形式），在 **H100（经 Modal）**上执行，「which handles rollout generation, reward assignment, and gradient updates within a single managed pipeline」。

### 3. 动作选择的现场规则（§6.2 + §6.3）

- **基线结构（关键的自证设计）**：初始分数**构造上就是** `gpt-oss-120b` 过一遍 Meta-Agent 初始 scaffold `A₁`（任务专属 system prompt + 单工具 dispatch 循环 + 输出 parser，**在任何 Feedback-Agent 迭代之前从 benchmark 规格生成一次**）。于是：harness 轨迹 = 脚手架迭代在基线之上加了多少；weight 轨迹 = 权重更新在 **harness-only best** 之上加了多少。
- **切换规则（原文）**：「Across all tasks, the Feedback-Agent begins with scaffold iteration and switches to weight updates once harness progress stalls; we report SIA-H (harness-only best) and SIA-W+H (harness + weight updates best) to isolate each lever's contribution.」——即**先 harness、平台期后转 weight**，且三个任务上都是这个模式（每节都写了"prompting the Feedback-Agent to switch to weight updates"）。

### 4. 权重更新的算法库（§7.3，**讨论节**；六种，各带触发条件与公式）

| 算法 | 触发条件（原文 "Observed when"） | 关键式 |
|---|---|---|
| **PPO + GAE** | 步级奖励稠密、训练稳定性是约束（多步工具使用 / 长代码生成，一次灾难性更新会把策略打崩） | `Â_t = Σ_l (γλ)^l δ_{t+l}`；截断代理 `min(r_t Â_t, clip(r_t, 1±ε) Â_t)`；学一个 value head V_ϕ |
| **GRPO** | rollout 便宜、verifier 在 episode 末才触发（分类/简答/单测，一次前向可打几百个完成） | 组内归一 `Â_i = (r_i − r̄)/σ_r`，**去掉 value 网络**，省内存、可大并行批 |
| **Entropic advantage weighting** | 奖励分布强右偏（正确解稀少但单个信号强，如困难证明、低通过率代码合成） | `w_i ∝ exp(r_i/β)`（引 Yuksekgonul 2026），**温度 β 在线调，使有效样本量高于下限阈值**，防塌到单条轨迹 |
| **REINFORCE + KL-to-base** | 奖励稠密、主要风险是能力回退而非梯度方差（底座已接近可用、不希望大参数移动） | MC 回报 `R_t = Σ_{t'≥t} γ^{t'−t} r_{t'}` 直接作 advantage，加 `α·KL(π_θ‖π_{θ0})`；无 critic、无分组 |
| **Best-of-N 行为克隆** | 奖励稀疏到 `E[r]≈0`、策略梯度数值为零 —— 作 **phase-zero 冷启动** | top-k rollout 按 verifier 分用交叉熵蒸馏回模型，把通过率抬到能接 PPO/GRPO 的水平 |
| **DPO** | verifier 能排序但不能绝对打分（序数信号可靠、基数不可靠） | 直接最小化 `−log σ(β log π_θ(y⁺)/π_{θ0}(y⁺) − β log π_θ(y⁻)/π_{θ0}(y⁻))`，**无 reward model** |

- 收尾逐字：「Each training approach is conditioned on trajectory observations rather than a fixed schedule.」
- **协议警告（原文自己给的）**：「While this paper reports three tasks, we have been running SIA across a wider set of tasks not included here; the algorithm descriptions below reflect common patterns observed across that broader experimentation.」+「A fuller treatment of algorithm selection across tasks is deferred to v2.」——**这六条不是预注册协议，是回看式归纳**。

### 5. 局限与未来（§8–§9）

- **Coupled co-evolutionary Goodhart（本篇最有价值的自陈）**：harness 搜索与 RL 更新**对同一个固定 verifier V** 优化，互相塑造对方看到的分布——「The joint fixed point of this coupled system is a Nash equilibrium between two optimisers that are blind to each other's update history（**英式拼写 optimisers**，我第一稿误写 optimizers，已按原文改回）, not a point that maximises V on out-of-distribution scaffolds（**英式拼写 maximises**，同句我第一稿写成 maximizes，已改） or novel policies.」并指出标准 Goodhart 分析假设单优化器，双杠杆产生一个 **coupled 变体**，其不动点「can appear strong on the training verifier while being fragile under any perturbation to either component」。
- **Future work ① Meta-RL over the action-selection policy**：当前选择用**冻结的 LLM 先验**；正道是把选择策略本身当学习对象——跨任务分布跑 SIA、把每个 `(trajectory, action, outcome)` 三元组当外层 MDP 的 transition、用 RL 训选择器；作者自陈这会形成「a self-improving system whose improvement mechanism is itself self-improving」并带来**嵌套循环稳定性**这一新问题。
- **Future work ② 更细粒度的交错**：当前是「discrete, coarse-grained rounds」，更细的调度（harness 搜索中途触发权重更新、或梯度步后立刻恢复 harness 探索）可减少"看到平台期"到"行动"之间的滞后。

**逐任务过程（§6.3）**

- **LawBench（191 类中国刑事罪名分类，5,332/913，随机猜 <1%）**：
  - harness：早期几代建起可用分类管线，后续把结构重排为 **TF-IDF + LinearSVC**，逐代调 character n-gram 范围与正则 C，「steadily improving accuracy until gains levelled off at 50.0%」，随后 F 检测到 **stalled reward** 切到 weight。
  - weight：奖励是干净的 outcome 标量（罪名对不对）且 rollout（生成的解题脚本在测试集上跑）便宜可并行 ⇒ F 选 **PPO+GAE**（value head 逐 token advantage + 截断代理），「pushing accuracy to 70.1%, an additional 20.1 percentage point gain」。
- **AlphaEvolve TriMul（AlphaFold2 Evoformer 的三角乘法更新，H100 CUDA kernel）**：
  - 任务性质：memory-bandwidth-bound（三角稀疏导致非连续访存、warp divergence、cache miss），cuBLAS/cuSPARSE 不适用；score = 1500/runtime。
  - harness：逐代堆可用 kernel、收敛到 **12,483**（1.14×），增量改动是「memory layout hints, compilation flags, retry logic」，到平台期切 weight。
  - weight：奖励**稀疏、重尾**（多数 kernel 编译不过或很烂，冷启动的裸梯度无信息）⇒ F 选 **entropic advantage weighting**（`w_i ∝ exp(r_i/β)`，自适应温度），使「productive gradient flow even when most kernels in a rollout batch are poor」，最终 runtime **1,017**、总 speedup **14.02×**、相对 harness 峰值降 **91.9%**。学到的是「H100-specific design patterns, shared-memory tiling, fp32 register accumulation, blocksize selection, that no scaffold edit could encode（原文作 `blocksize`，无连字符）」。
- **MAGIC scRNA-seq 去噪（调 k、t、α 与预处理，pancreas 数据；k 太小过拟合、太大过平滑）**：
  - harness：扫耦合超参空间到 **mse norm 0.241** 平台，切 weight。
  - weight：用 **GRPO**；**第一个权重更新 checkpoint 就给出一个 harness 全程从未生成的结构性改动**——两行后处理 `np.clip + np.rint`（把插补计数取整为非负整数，强制生物不变量），「a two-line post-processing step ... that rounds imputed counts to non-negative integers, enforcing a biological invariant that is trivially correct yet absent from any prior scaffold version.」把 mse norm 抬到 **0.289**（+20%）。

**§7.2 harness 到底改了什么（RQ2a）**：三任务都是**外化**改动——LawBench：结构化答案抽取层 + 对模型 top 候选的 SVC 重排器；TriMul：把 CUDA 诊断回喂成结构上下文的编译错误 parser + 返回中位 runtime 的计时 harness；MAGIC：批量配置 driver + 把 (参数组, 分数) 配对整理给模型推理的结果解析工具。结论逐字：「In all three cases, the changes are software-engineering improvements: new tools, tighter output parsers, smarter retry logic. The model checkpoint is unchanged throughout.」

**§7.4 weight 到底改了什么（RQ2b）**：**内化**知识——LawBench：191 类罪名梯度让相邻类别（盗窃各型、伤害各档、诈骗变体）的区分更锐利，**且没有任何 prompt 侧提示**；TriMul：权重收敛到 H100 专属 kernel 设计模式（共享内存 tiling、fp32 寄存器累加、block-size 选择），「that the base model never produced regardless of scaffold quality」；MAGIC：就是上面那两行 `np.clip + np.rint`。总括句：「The harness shapes how the agent searches; weight updates change what the model knows.」

## 与 DWC 的映射（机制 | DWC 现状 | 判定）

| SIA 机制 | DWC 现状（代码级） | 判定 |
|---|---|---|

## 综述 L 定位

- **L2（Improvement Strategy Autonomy）**，而且是综述明确点名的 L2 样本——§C.1.4（Toward Recursively Improving Science Agents）逐字：「**L2 represents the strongest current frontier, with systems autonomously selecting or applying updates to model weights, tools, skills, workflows, and scaffolds** `Hebbar et al. [2026]`, Lu et al. [2026b], Huang et al. [2026d].」同一段接着说：「A few systems exhibit aspects of L3 ... whereas end-to-end L4 environment adaptation and **L5 evolution of the improver itself remain largely unexplored**」——即 SIA 被放在 L2 的代表位、**明确不进 L3+**。
- **§4.1（S1: RSI for Science / AI4Sci 应用段）的裁决更直接**：「SIA `Hebbar et al. [2026]` extends the editable surface to agent scaffolds, tools, search logic, and model weights. These systems demonstrate persistent improvement of scientific-agent components, **but their evaluators, update-selection rules, and promotion criteria remain largely fixed**; improving a molecule, equation, or hypothesis alone therefore **remains RSI-adjacent rather than evidence that the scientific agent has improved itself**.」——可编辑面很宽，但**判据/选择规则/晋升准则全固定** ⇒ **RSI-adjacent，非 RSI**。
- **§C.1.3（Evolving Reflection Systems and Improvers）的定位**：「SIA `Hebbar et al. [2026]` **provides the broadest component-level update loop among current AI4Sci systems**. Its Feedback-Agent uses task outcomes to choose between modifying the agent scaffold, tools, retry and search logic, and low-rank adapter (LoRA) weights with different strategies.」——族内"可编辑面最宽"，但同段的判据是「an evolving improver must instead **update its own diagnostic, intervention, or promotion policy** from the outcomes of earlier improvements」——SIA 的 F **没有**更新自己的诊断/干预/晋升策略（选择规则是冻结的 LLM 先验，见 §9 自陈）。
- **技术族**：综述 Table 2/4/5/7 **均未收录 SIA**（我 grep 综述全文 `Hebbar` 5 处：bibliography 2 处 + §4.1 + §C.1.3 + §C.1.4，**没有表行**）。族位 = **AI4Sci §C.1.3 的"反思系统与改进器"**，且在 §4.1 归入 S1（科学智能）应用域。
- **structural / effective（按 §3.6 判据类推）**：
  - *structural*：**半有**——harness 与 LoRA 权重都持久到下一代（`A_{g+1}`、θ_{g+1}），符合"改动持久并控制后续一轮"；**但综述指认的缺口是"负责后续改进的机制"没被改**——F 的选择规则、verifier、晋升准则全固定 ⇒ 按 §3.6「Self-modifying task code provides insufficient evidence when the process responsible for later revisions remains unchanged」，**不构成 structural L5**（这也是综述把它放 L2 不放 Table 7 的原因）。
  - *effective*：**未测**——论文证的是"SIA-W+H > SIA-H"（两个杠杆叠加优于单杠杆），不是"改进机制被改进后产出更好后继"；`G_max`、种子、方差全缺，连单系统的 effective 证据都只有单点。
- **对 DWC 最有用的一句**：综述 §4.1 那句判据（evaluators / update-selection rules / promotion criteria 是否固定）正好是 DWC-AUTO 要向 L5 走时的**三件待改物**——DWC 现状里 `评估器` 已明标不可编辑（对齐"判据外置"），而**选择规则（`_el_pick` 的 δ 降序、`ELScheduler` 的 τ、`stall_signal` 的 δ）与晋升准则（`ProposalGate`/`Evolver.accept`）目前都是人写死的** ⇒ 这三件正是 L5 的靶子。
