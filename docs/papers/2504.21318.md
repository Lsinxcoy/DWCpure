## 一句话总结

一份“**把人定的选题判据执行到底**”的推理配方：以 Phi-4 为底座，用 LLM 评审管线从百万级种子里**只挑 base 能力边界上的“teachable”题**（无真值时用强模型多数票当代理真值，再看弱模型同意率差距），配 o3-mini 的 **140 万条 / 8.3B token** 长推理 demo 做 SFT；再用**纯规则 reward**（答对 0.5–1.0、答错 −1.0–−0.5 的长度整形 + 5-gram 重复罚 + 格式硬罚，权重 8/13 与 1/13 人定，满分封顶 0.615）跑 **90 步 GRPO** 得 plus 版；14B 在 AIME 2025 做到 78.0（DeepSeek-R1 70.4）。它把**评测方法学本身**当贡献——两次 5-run 平均在 AIME 上可差 **5–10pp**。无任何“改自己改进机制”的递归，属综述 **L1（执行人定程序·数据层）**，综述也正于 §3.2.1 + Table 3 的 Data Level 行引用它。

## 核心方法

### 1. 种子库与“最可教”筛选（§2.1）——最可迁移的一节

- 种子来自公开网页、已有数据集、授权集合与合成题（STEM/coding/通用问答 + 对齐安全），初期目标 “maximizing diversity and coverage”；**合成改写（Fig 3）**：证明题 → 已知 AB=13、BC=10 求 AC 的**可验证数值题**，部分数学题改短答案，因 “more amenable for easier verification in downstream RL”。
- **挑边界题**（原文）：“we specifically target seeds situated at the edge ofPhi-4’s current abilities”，并优先 “prompts that demand complex multi-step reasoning, as opposed to those primarily testing factual recall”。
- **无真值时的难度代理**（原文）：“we use plurality responses from a strong reference model as a proxy for ground truth and then estimate seed difficulty based on the agreement rate of weaker model’s (e.g., Phi-4 or GPT-4o) generations with the (proxy) ground-truth solution.” ⇒ 保留标准是差距：“Seeds that show a meaningful gap, indicating room for improvement, are retained.”
- 第二道信号：“rubric-based LLM evaluators are used to assess the number and complexity of reasoning steps required to solve a prompt”。
- **数据混合的权重 = epoch**（原文）：“Designing the data mixture translates to specifyingweights associated with different data sources”；按领域与质量聚类、同簇同权。
- **可加性**（原文）：“mixtures could be optimized independently for each domain—such as math and code—and then combined by simply concatenating their respective weights.” ⇒ 各域独立调到 “saturation on a selected set of metrics” 再拼权重；Fig 5 的点 8（math 最优）→ 9（均匀加 code）→ 10–11（code 独立调优）→ 12（加 RAI）。

### 2. SFT（§3）

- 架构只改两处：base 的两个占位 token 改造成 ` 与 `；**RoPE base frequency 翻倍**（16K→32K）。
- 规模（原文）：“Our SFT data comprises over 1.4 million prompt-response pairs, totaling 8.3 billion unique tokens”；“Training is run over roughly 16K steps, with a global batch size of 32”；AdamW **lr 1e-5**、450 步线性 warm up、weight decay 1e-4。§3.2 “The final model was trained for 16B tokens using this mixture.” 与之自洽——§3 自陈 “we have a relatively long SFT stage with2+ passes over reasoning data sources”（`with2+` 提取粘连，即 2+ epoch：8.3B×~2≈16B）。
- **配方不可迁移**（原文）：“the optimal hyperparameters for reasoning data differed significantly from those used for alignment-focused tuning inPhi-4”；LR 在 [1e-6, 2e-5] 网格取 **1e-5**（更高 LR 训练 loss 更低但下游退化）；weight decay 0 vs 1e-4 “within benchmark variance”。
- **探索→放大**（Fig 5）：探索期短训练快迭代，固定 **AIME 2024 + GPQA diamond** 当进度标尺；放大期才合并全领域。合成短答案数学数据增益（原文）：“improving performance by 3–10% on AIME 2022–2024”。
- **system message 定死**（原文）：“we used the following fixed reasoning-focused system message in the final SFT training.”；部分移除/替换能提高鲁棒性，但原消息下 “greater variability in benchmarks scores and a slight decrease in average benchmark performance”；核心句：“Your role as an assistant involves thoroughly exploring questions through a systematic thinking process before providing the final precise and accurate solutions.”
- **训练动态（Fig 4）**：模型 “begins to use explicit “thinking” tokens very early in training, indicating the superficial structured format itself is learned quickly”，而准确率继续上升 ⇒ “not merely copying format, but actually acquiring reasoning as a learned skill”；**响应长度在 SFT 中不升反降** ⇒ “learning to use its token budget more efficiently as training progresses”。
- **base 与教师**：Phi-4 vs Phi-4-base 推理面 “performed similarly”，但 “Phi-4 performed slightly better in terms of safety and alignment” 故取 Phi-4；o3-mini medium “to have similar effect to DeepSeek-R1 when used as teachers” 却 “was more token efficient”，high 更强更长 ⇒ 扩上下文到 32K。
- **脱污染**：清单含 AIME-2024、MATH、GPQA、LiveCodeBench、Codeforces、OmniMATH、SWE-Bench Verified、GSM8k、HumanEval、ArenaHard、MT-Bench、PhiBench 等 **23 项**；“AIME-2025 was released after the data forPhi-4-reasoning was finalized” 故该基准无污染。
- **安全数据两动作**：合成时挂 safety guidelines、**训练时摘掉**（“to incentivize the model to implicitly learn the expected behavior”）；因 “the model tends to regurgitate variations of these guidelines in the “thinking” block”，故不许在 “answer” 块透露 guidelines 或 CoT。

### 3. plus 版的 RL（§4）——判据全部人写死

- GRPO（DeepSeekMath/R1 谱系）、outcome-based、**只做数学**；种子（原文）：“The seed dataset for GRPO consisted of 72,401 mathematical problems (prompts without solutions), from which we subsample 64 problem seeds per RL iteration.”；“even performing RL over a small set of 6,400 problems significantly improved accuracy”；checkpoint = AIME24 最高分那步 = **90 步**、约 6k 样本 × 8 轨迹。
- **规则 reward**（动机原文）：“We employ a rule-based reward model to avoid complexities and potential reward hacking associated with neural reward models” ⇒ 不用学习出的 RM。
- **双向长度整形**（意图原文）：“we encourage the model to generate concise outputs when the answer is correct, while provoking it to think more when the answer is incorrect.” 常数 `L_max=31,744`（留 1024 给 prompt）、`L_pos_control=25,600`、`L_neg_control=3,702`：
  - 答对：ρ⁺ = min(1, max(L−25600,0)/6144)，`R_acc_scaled ∈ [0.5,1.0]`，`R = R⁺_min + 0.5·(R⁺_max−R⁺_min)·(1+cos(πρ⁺))` ⇒ **越短越接近 1.0**；
  - 答错：ρ⁻ = min(1, L/3702)，`R_acc_scaled ∈ [−1.0,−0.5]` 同形余弦 ⇒ **越长罚越少**（3,702 token 起只罚 0.5）；
  - 格式硬覆盖：缺 EOS ⇒ **−0.5**；thinking 块非法/缺失 ⇒ **−1.0**；
  - 重复罚 `R_rep` 基于 5-gram 频率（freq>5 的占比与最高频占比取负）；
  - 合成 `R_final = w_acc·R_acc_scaled + w_rep·R_rep`，**w_acc=8/13、w_rep=1/13**；脚注 3：“The maximum possibleRfinal = 8/13 ≈ 0.62 by our reward function design.”（**满分封顶 0.615**）。
- 训练（原文）：“a global batch size of 64 across 32 Nvidia H100 GPUs, Adam optimizer learning rate 5 × 10−8 with cosine warm-up in the first 10 steps”，**G=8**、KL β=0.001、entropy γ=0.001、verl；上限 32K、实测 64K、**超 31k 被截断**；Â = `(R_final − mean)/std`。

### 评测方法学（§5.1.2）——本文自认的第二项贡献

- 反对单次单分（原文）：“For all models including ours and those in the OpenAI and DeepSeek family, two runs of average-of-5 evaluations can differ significantly (by up to 5-10 percentage points on AIME), thus making side-by- side comparisons unreliable for all models.”
- 分布证据（Fig 9，50 次、温度 0.8）：“accuracy of answers generated byDeepSeek-R1- Distill-Llama-70B ranges from 30% to 70%, whileo3-mini’s accuracy range is from 70% to 100%” ⇒ “any comparison among models using a single run can easily produce misleading conclusions”。
- **重复对象冲突**：脚注 4 写 AIME25=50、HMMT=64；脚注 5 写 “We use 50 and 64 generations for AIME 2025 and GPQA respectively” ⇒ 64 次的对象（HMMT vs GPQA）两处不一致，**标未核**（不影响方向）。
- 温度/prompt：Phi 0.8、DeepSeek 0.6、其余 1.0 或默认；统一 CoT 模板，唯 o1 用非 CoT（“because of policy violation refusals usually triggered by CoT requests”）。Codeforces 协议 “we allow each model ten independent submission attempts for every problem and finally compute the Elo rating.”（校验 R1-Distil-Qwen-14B 得 **Elo 1481**，与 [21] 差 “within 1 accuracy point for LiveCodeBench” / “within 20 Elo rating points”）
- 聚合（Fig 12/17）：worst/average/majority/best-of-5 四种，但**提取层每子图只剩 2 组 × 9 模型 = 18 个数值** ⇒ 缺两组；可定的一组与 Fig 8/Table 1 平均值逐格相同（GPQA 54.7/67.1/69.3…），另一组（75.3/84.3/85.4/…）更高、**推断 best-of-5，标未核**；Fig 2 的 Maj@N/Best-of-64 可越过教师基线，**逐点数值不可读，标未核**。

### 安全与局限（§5.3 / §6）

- 自动 RAI 框架（LLM 扮用户 + LLM 评回答；三类：越狱 / 有害内容 / IP 泄露）原文：“Results show thatPhi-4-reasoning shows minor regression compared to the base modelPhi-4.”（**回退且无数字**）
- 判官不适配长推理：“current LLM judges and tools have not yet been optimized”（原文后接 `for long, step-by-step traces`，提取层断词为 `step-by- step`）。
- Limitations 照抄三条：**32K 上下文**（“sometimes generates responses that exceed its context window size, leading to truncation”）；**数据域受限**（“the supervised fine-tuning (SFT) training data is limited to STEM, code, and safety, while the reinforcement learning (RL) data is limited to math.”）；更慢且 “may produce responses that contradict their own reasoning chains”。

## 与 DWC 的映射

> 共享背景：DWC = 世界树(W1–W6) + judge 判分(C3') + δ 失败签名排序 + EL 调度(B/τ) + Dreaming 回放(K₂/β) + M>1 策略修订。

| # | 机制（Phi-4-reasoning） | DWC 现状（代码级） | 判定 |
|---|---|---|---|
| 1 | **可教边界选题**：LLM 评审筛“base 能力边缘”的题；无真值用强模型多数票当代理真值 + 弱模型同意率 gap；rubric 评推理步数 | `weakness.py`：δ_θ^group=`[−log r_group]₊`、`r=(n_z+1)/(n+1)`（Laplace k=1）；`z_id_from_signature()` 把 z 操作化为失败签名族 `c:…\|q:…`；`task_delta_map()` = 任务历史失败签名的**最大 δ**；`weak_ranking()` 只给顺序不给阈值（ARCHITECTURE L1105）；`core._task_deltas()` 已接进 step | **同构（半确认型）**：都是“把预算投到能力边界”。差异在判据形态——Phi-4 是“有 gap 才保留”的阈值式 + 模型当评审；DWC 是纯排序偏置、明令无阈值、判据是观测频率。“多数票+同意率”是**无需真值的 gap 估计**，可作 δ 第二信号，但引入模型依赖、撞 `el_sched` 零模型纪律 ⇒ 需裁决 |
| 2 | **数据混合可加性**：按域独立调 epoch 权重到饱和再拼接，增益不互斥 | DWC 无训练数据混合（`llm/client.py` 为 API 接入）；最近同构是**分组独立标定**：`el_sched.decide_from_rate` 的组内窗口、`weakness.delta_group` 按 `group_id` 各算（绝对值不许跨组比） | **方法论可迁、机制不适用**：DWC 没有“权重=epoch”。可搬的是**验证方式**——Phi-4 用 Fig 5 的 12 点证明“独立调优再相加不掉点”，DWC 要证明“各器官独立标定后合起来不互拆”同样要**组合实验**而非单点报告 |

## 综述 L 定位

> L 框架（2609.11873 §3）：B0 任务内 / **L1 执行人定程序** / L2 自主选改法 / L3 自定学习议程 / L4 部署改持久态 / L5 改改进机制本身；structural = 改动持久并控制下一轮，effective = 同预算独立评估下产出更好后继。

- **L 几：L1（Data Level）**。回综述核：引用位置 = **§3.2.1**（“3.2.1 Data Level”）+ **Table 3**，与 refmap `Cited by: §3.2.1 , Table 3`、`freq=2` 吻合；**Table 3 = “Representative L1 systems organized by AI development pipeline levels”**，本行逐格 `Phi-4-reasoning | Abdin et al. [2025] | Training data selection | LLM evaluation + boundary filtering | Human-defined selection criteria` —— 末列即定性：**筛选判据由人定义**。
- §3.2.1 正文（原文）：“A similar division of labor appears in the construction of training data for Phi-4-reasoning: researchers specify the desired difficulty and reasoning characteristics together with their evaluation procedures, while LLM-based evaluation pipelines apply these criteria to select samples near the model’s capability boundary Abdin et al. [2025]” ⇒ 综述把它的贡献定位为**人定标准 + LLM 执行筛选的分工**，与核心方法第 1 节一致。它**不在 Table 2（族 × 等级）**（refmap 只列 §3.2.1 与 Table 3）⇒ 不承担技术族代表位。
- **技术族**：数据层单族（training data selection / LLM evaluation + boundary filtering），不占 B1/C1/C2/D3 的族格。
- **structural / effective L5：均不适用。** 无 improver、无 evaluator 替换、无跨轮继承；RL 阶段**也不抬级**——reward 与超参全部人写死（含按 AIME24 挑 checkpoint），带“自动”色彩的两环（LLM 筛题、长度整形）判据同样人定 ⇒ 不构成 L2。
- **与 DWC 的关系**：它是“**判据人定 + 执行可自动化**”的样板；DWC 同处 L1 判据哲学（golden reference 与规则写死）但执行面是**规则而非 LLM**。三条价值：① 无真值 gap 估计的可选信号；② 连续判分的形状参照；③ 用 50 次重复**反证 DWC 单次判分的脆弱**——DWC 现处 L4 形状 + L1 判据，L4 要被 effective 判定恰需“同预算多采样”的口径。
