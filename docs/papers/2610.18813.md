## 一、核心问题

Agent 自适应有两条路：改模型权重，或改包围模型的软件脚手架（harness：prompt、记忆、工作流、可执行组件）。论文给第二条路正式命名 **Harness RSI** 并建立框架：反馈驱动、被采纳的修改跨 run 持久、模型权重固定。核心洞见一句话：**把"改什么"（update target）与"怎么改、谁批准"（proposal/admission）分开，前者按可变边界分类，后者用进化搜索刻画、用 continual PAC-learning 给条件保证。**

## 二、理论基础

### 2.1 形式框架（§2）

- Harness 定义： governing 模型 M 在环境 E 中执行的软件＋配置； rollout τ∼Run(M,H,E)，得分 y=J(τ)。**J 含评分、结果验证、决定结果的记录；候选可改 H 内 critic，不可改 J。**
- 更新轮：B_k = {τ}（本轮 rollouts＋feedback）→ H_k = Update(H_{k-1}, B_k)；Update = diagnose＋propose＋assess＋admit；无 admit 则 H_k=H_{k-1}。
- 生命周期两要求：(1) operational feedback＋update continuity（用自己的执行反馈算法化构造修改，且更新机制保留）；(2) persistence across runs。**只 append 日志/固定规则压上下文≠进化；学可复用规程或改记忆策略才算。**
- 术语：self-evolution=过程，self-improvement=比较确立的增益；weight-only 不在 scope。

### 2.2 进化搜索视角（§4.1＋Figure 2）

更新四要素：可变状态表示、变异、fitness 评估、保留选择。八种对应（每种都声明"对应≠等价"）：(1+1) 精英（SICA/MCE/SkillOpt/SkillOpt-Lite/SkillClaw）、(1+λ)（Self-Harness）、archive（DGM/DarwinX/HGM）、重组 crossover（DarwinX/HarnessCompass/Self-Harness/MCE/Trace2Skill）、quality-diversity MAP-Elites（HarnessBank＋verification gates）、协同进化、Pareto 选择（Meta-Harness/Self-Harness/SkillMOO）、bandit 分配预算（HGM＋Thompson sampling）。

### 2.3 Continual PAC-learning（§4.2，三个界）

- **泛化界 Eq.5**：replace-one task 稳定性 β_{s,k} ≥ 期望泛化 gap。只控期望量，不控单轮；小代码编辑≠全更新过程稳定。
- **保持界 Eq.6**：遗忘 F_{s,k} ≤ Σ ε_{s,u}（历史 regression budgets 累加；budget 是外加假设，不从稳定性推出）。
- **准入规则 Eq.8**：fresh 独立验证集 V_k（m 个，采自历史混合分布），候选比较 ≤KT 次，Hoeffding＋union bound：Δ_k ≤ Δ̂_k ＋ √(2ln(KT/δ)/m)。**只接受上界为负的候选。** HarnessBank（训任务筛＋终测分开）、Self-Harness（held-out 回归 split）都缺独立性——"search-time checks lack the assumed independence"。评估者漂移时加 Eq.9（＋2η，η 需独立证据）。

## 三、方法（分类法 §3：DWC 的官方坐标系）

- **解释态 vs 可执行**：看被改产物的"角色"不看语言。改任务级排序/路由（经固定协调接口）仍是解释态；改 operator 实现或执行协调的运行时机制即是可执行修订。
- **3.1 工具与代码补丁**：变异限在可调用过程/指定模块（Self-Harness/HarnessCompass/Agentic Harness Engineering）。**改记忆管理函数=改机器；整理存储条目=改解释态。** archive 存候选供后搜；protocol perturbation 测增益在评估条件变化下是否存活。
- **3.2 仓库与运行时逻辑**：context 构造、编排循环、hook、恢复、终止全可改（whole-agent synthesis vs repository evolution 保留 lineage）。**archive≠adopt：进 archive 只保留候选，adopt 还要把选中程序推进 later tasks 用的 runtime。** update 机制本身可进化（optimizer 的 prompt/hook/tool）。
- **3.3 万物皆插件（EIP）**：接口契约只给兼容性检查，**不给行为隔离和安全准入；采纳仍需验证组合后行为。** DSH Everything/Codex 插件：首任务 tool calls 13→3，但 wall＋54.9％、tokens＋15.7％；5 任务累计省 110,351 tokens／22.97s。

## 六、讨论

### 6.1 方法论诚实（本文最大优点）

作者三次主动降级自己的数字：crossover 未 matched-cost（§3.2）、EIP 双报告对不上（§3.3）、LiveBrowseComp"需重复运行＋matched budget＋matched quality 才算因果"（§3.3）。以及"对应≠等价"在 Figure 2 每个 panel 下都写一遍。**这套"数字＋scope 同行"的写法就是 DWC 判分纪律的论文版。**

### 6.2 五应用＋安全边界（§5–6.5，对 DWC 可直接用的）

- J 必须在可改面之外（§5 scientific discovery）；DWC 对齐但建议形式化检查（见七）。
- 累积更新难追踪：临时 workaround 变常驻规则、注入指令跨任务持久（§5 personal workspaces）——DWC 的 RULES persist 正在积累同类风险。
- 回滚只覆盖恢复模型内的效果（§6.5）；物理/支出不可逆要授权＋限额。
- 持续验证：time-stamped tasks、version-pinned env、difficulty calibration（§6.4）；**复用 calibration 任务不能替代 fresh admission 证据；换 evaluator 后 η 要重标定。**
- 预算分配（calibration vs admission vs regression checks）是 open problem。

### 7.2 关键建议

1. **补 admission 独立性**：held_out 从 LLM 生成改成绩效隔离的 fresh 任务集（先小规模：sealed_tasks 思想已有 ARSI 渊源）；在 accept 门旁加 Eq.8 式注释（m、K、T、δ 四数显式化）。
2. **J 保护机器化**：gate 加一条"evo 本轮写了 judge/anchor 文件即红"（防未来失手，不是现在有错）。
3. **RULES 引入 lineage 选择**：同 key 多候选并存＋parent 选择，而不是 key 唯一制（archive→adopt 两步走，论文 §3.2 原话）。
4. **术语对齐**：run_round 四段改名与论文一致（diagnose/propose/assess/admit），报告 triage 已有分类机、门阵列已有 gates——DWC 已领先论文案例处可回标。

## 九、总结性评价

### 核心贡献

1. Harness RSI 的正式定义＋两要求（feedback continuity、persistence），把"是不是进化"判据化（DWC 可直接当 checklist 用）。
2. 解释态/可执行三分法＋八种进化结构对应（含 limits 声明），DWC 在此坐标系的位置可精确定位（elitist 1+1＋知识 archive）。
3. 三个条件界（泛化/保持/准入），尤其 Eq.8 给了 admission 的可计算形态（m、K、T、δ）。

### 关键结论

1. 小模型＋好 harness 可超大模型（crossover，matched-cost 待补）。
2. Search-time 独立性缺失是全领域通病（点名 HarnessBank/Self-Harness；DWC 同病）。
3. 接口契约≠行为隔离，采纳必须验组合行为（EIP 警告＝DWC caps 开关的下一课）。

### 局限性

1. 无自有实验，全是二手数字（诚实但单薄）。
2. 三个界全是条件式（稳定性假设、budget 外加、独立采样），生产环境三条全难满足——论文自己承认。
3. 18 页正文是执行摘要性质，evaluation（§6 四 claims）等全在 companion report，本轮未读。

### 总体评估

这是 DWC 的"官方理论镜像"：我们用工程直觉长出来的结构（四段更新、accept 门、RULES archive、J 保护纪律），论文给了形式定义和条件界，并指出了我们最痛的缺口（admission 独立性）。方法论诚实度全场最高。建议入库＋按 §7.2 五条排期。**理解自评：L4（正文 935 行全读，数字逐表核对；companion 未读、repo code 无（本就没有））。**

## §十、Companion Report 增补（66 页，repo paper/harness-self-evolution.pdf）

### 10.1 四 Claims（§6.1，Figure 5）

报一个 gain 实际报四个 claim：**Selection**（报告数没被 proposal/ranking/admission/report-choice 用过）、**Activation**（update 在得分 run 里真干活了）、**Attribution**（差异来自 update 本身）、**Improvement**（差异超出形成它的条件：task distance＋baseline＋round）。

- Activation 三级：available（artifact 进了 run）→ reached（改的路径执行了）→ carried（效果到达下游：code 的输出活到模型输入里，instruction 的 trajectory 真照做了）。量化 Eq.11：load/reach/carry 三率（carry 对解释态按 L(u)、对可执行按 B(u) 条件）。
- **Presence ≠ use ≠ benefit**（Figure 5 原话）。DWC 对照：RULES 落了＝available；gates 全过＝reached 的弱证据；carried（RULES 真被后轮 proposal 用了）无记录——缺口。
- 命名纠偏：HarnessX 自称 "attribution signature" 的东西按此框架只是 activation；attribution 另需对照实验。**DWC 的 gates 命名已对**（gates=activation 记录，accept=admission）。

### 10.4 新增建议（companion 独有，追加卡 §7.2）

6. **carried 率**：RULES 每条记"被后轮 propose 引用次数"，ledger 已有 attempts 字段可扩展——activation 第三级。
7. **execution variation**：均分 ±spread 常驻 report（frozen state 同任务重跑 n 次），Δ 不过 spread 不算 gain。
8. **envelope 声明**：每轮 report 声明 LLM calls/rounds/tokens（search cost 另列，不混）。
9. **peak-picking 禁令**：report 只报当轮终态＋ledger，不报历史 peak——DWC 天然免疫，写进纪律防未来。

11. **crossed evaluation**：换 anchor/换模型时双向 cross（H_k×D_A、H_{k+1}×D_B 全跑），不跑就是 confounded。
