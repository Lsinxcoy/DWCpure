## 1. 一句话

DGM 的隐含前提是"任务能力和改代码能力同域对齐"（因为两者都是编码任务）。
Hyperagents 把 **task agent 与 meta agent 合并进同一个可编辑程序**，并让
**"改进程序本身"也可被编辑** ⇒ 去掉同域对齐假设。

## 2. ★★★ imp@k —— DWC §9 第 25 项 (a)(b) 的直接答案

**原文逐字（§5.1）**：

```text
"To quantify a meta agent's ability to generate improved task agents, we introduce
 the improvement@k (imp@k) metric. Given an initial meta agent M, an initial task
 agent A, an agent-generation algorithm (e.g., DGM or DGM-H variants), and a fixed
 task, M is allowed to generate up to k new task agents from A and its descendants
 using the specified algorithm. We define imp@k as the improvement in test performance
 from the initial task agent A to the best-performing generated task agent (selected
 based on validation score)."

"To isolate the meta agent's ability to improve task agents from its ability to
 improve itself, we hold the meta agent fixed throughout the process (i.e., the
 agent responsible for generating new task agents is always the initial meta agent M),
 yielding DGM w/o self-improve and DGM-H w/o self-improve as the agent-generation
 algorithms. All experiments in this section run for 50 iterations, measuring imp@50."
```

### ★ 与 2609.2680 的 Γ_t 对照（这是两篇的接口）

```text
2609.2680 式8:  Γ_t(B) = E_{S~P_start}[ g(I_t;S,B) − g(I_0;S,B) ]
  形式: 对同一分布的起始态 S, 比较进化后的改进器 I_t 与初始 I_0
  论文强调: "Controls must match starting states, feedback access and resource accounting"

Hyperagents imp@k 实测:
  ① 起始态: 固定 initial task agent A（一手数据不做平均）
  ② I_t vs I_0: ★ **靠"冻结 meta agent"实现** —— w/o self-improve 时
     "the agent responsible for generating new task agents is always the initial
      meta agent M" ⇒ 就是 I_0
  ③ 反馈口径: 全部选优都按 **validation score**，报 **test** 分数
  ④ 资源口径: k=50 次生成（即预算上限）

★★ 结论: Γ_t 的"隔离"在实践上就是**冻结改进器、只让任务侧跑**。
  这与 DWC §9 第 20 项（守卫① 矛盾）同源 ——
  DWC 现在的守卫① 用世界模型自算 confidence，恰恰是"让被测方自己打分"。
  ⇒ ★ imp@k 给出的做法是: **冻结 + 换手**, 不让同一状态既执行又评分。
```

## 3. ★ imp@50 实测结果（四个数字，全部带 CI）

```text
初始 meta agent（M0），数学竞赛级评分任务（Olympiad-level grading）:
  · initial task agent 的 test 分数 = 0.0
    原文: "it fails to produce outputs in the required format due to the lack of
           task-specific parsing or post-processing"  ← ★ 不是能力差，是格式不符
  · DGM 50 轮后最优 task agent（5 次重复运行取中位）= 0.0 (CI: 0.0 – 0.0)
    ⇒ imp@50 = 0.0 (CI: 0.0 – 0.0)

迁移后的 hyperagent（transfer hyperagent，从别的域学来）:
  · 初始 test 分数 = 0.0 (CI: 0.0 – 0.0)  ← 原文归因: "reflecting the domain shift"
  · DGM-H 50 轮后最优 task agent = 0.630 (CI: 0.540 – 0.630)
    ⇒ imp@50 = 0.630 (CI: 0.540 – 0.630)

显著性: "imp@50 for the transfer agents is significantly higher than imp@50 for the
          initial agent (p < 0.05)"
```

### ★ 三条极重要的推论

```text
① ★ 0.0 → 0.0 的基线不是"改进器差"，而是**初始 agent 连输出格式都产出不了**
   ⇒ DWC 对照设计必须区分"能力不足"与"接口/格式不通"
   ★ DWC 已有 ACTOR_DESIGN 的痕迹 schema（expected-observed）能承载这一点，
     但 ARCHITECTURE 里没写"初始 agent 可能格式为 0"这一类失败签名。

② ★ imp@50 = 0.630 的 CI 是 (0.540, 0.630) —— **上界等于点估计**
   这是中位数 + 5 次运行的分布，CI 形状本身说明有 3/5 次达到 0.630
   ⇒ ★ 引用时必须带 CI，不能只写 0.630。

③ ★★ "冻结 meta agent" 是隔离手段，不是缺陷
   原文: "While DGM w/o self-improve relies on a fixed handcrafted
           instruction-generation mechanism, DGM-H w/o self-improve does not."
   ⇒ 冻结的是**机制身份**（同一份代码跑到底），不是能力
   ★★ 这正是 DWC 需要的那条边界: 隔离变量时, 冻结的是"谁来评分"，
      不是"评出什么"。
```

## 4. 跨域迁移实验设计

```text
★ 迁移什么: 不是权重，是**可编辑的 agent 程序**（含 persistent memory、
  performance tracking 等 meta-level 机制）
★ 怎么选迁移体: "we select one transfer hyperagent per run using the same
  lineage-discounted criterion"（5 次运行各选 1 个）
  ★ "lineage-discounted criterion" = 按血统折扣挑赢家 ⇒ 抑制"纯血统运气"
  ★ 这与 DGM 的 archive + 非贪心采样是同一族思路。

★ 观测到的机制改进（原文举例）:
  "the DGM-H improves task agents by moving beyond surface-level prompt tweaks toward
   structured, reusable decision machinery"
  · paper review: 从表面行为指令 → 结构化可复用决策机制
  ★ 与 DGM 发现的 "better code editing tools, long-context window management,
    peer-review mechanisms" 是同一方向（见 2505.22954 报告）
```

## 6. 与 DGM 的关系（作者自陈）

```text
"the DGM (Zhang et al., 2025b) demonstrates that open-ended self-improvement is
 achievable in coding. ... Because both evaluation and self-modification are coding
 tasks, gains in coding ability can translate into gains in self-improvement ability.
 However, this alignment does not generally hold beyond coding domains."

"DGM-H eliminates the assumption of domain-specific alignment between task performance
 and self-modification skill"
```

### ★ 对 DWC 的含义（这条最重要）

```text
★ DWC 是**独立 agent**，其任务是"自我改进"这件事本身，不是编码。
⇒ DGM 的隐含前提（解题=改代码，同域）对 DWC **不成立**。
⇒ ★★ Hyperagents 的结构（task agent 与 meta agent 同处一个可编辑程序）
     正是 DWC §2.4 的"七环节归属"里 ①诊断②对象③门④落地 → evolver 的形态学依据。
```

## 7. 诚实条款（逐条照录）

```text
① imp@50 只在**一个**任务域（Olympiad-level grading）上测 ⇒ n=1 域
② 迁移实验的 5 次重复运行取的是中位数 + CI，未报均值
③ 初始 task agent 分数为 0.0 的原因是**格式不符**，不是完全不会
   ⇒ 0.630 的起点事实上极低，"提升幅度"的解释力被削弱
★ 这三条与 DGM 的"未报方差"是同一类证据弱点，但方向相反：
   Hyperagents 报了 CI 但起点低；DGM 起点正常但没报方差。
   ⇒ 两篇都不能单独支撑"改进器变强了"的强结论。
```

## 8. 可迁移条目

```text
★ M1. ★★ imp@k = Γ_t 的可运行实现 → DWC 应采用它作为 L3 审计的**主度量**
   协议三件套:
   ① 起始 task agent 固定不变
   ② I_0 与 I_t 的隔离靠"冻结 meta agent 身份"
   ③ 全部选优按 validation score，只报 test 分数
   ★ 对应 DWC §9 第 25 项 (a) 的裁决建议: 测 Γ_t，且实现方式 = 冻结+换手

★ M2. ★ imp@50 的 CI 形状是 (0.540, 0.630)，上界=点估计
   ⇒ DWC 若报 imp@k 类数字，必须报 CI；单点值不可用于门裁决

★ M3. "冻结 meta agent" ≠ 冻结能力
   ⇒ DWC 的守卫设计：隔离变量时冻结的是"评分者身份"，不是"评分标准"

★ M4. ★★ task agent 与 meta agent 必须同处一个可编辑程序
   ⇒ 这是 DWC 把七环节全部收进 evolver 的论文级依据
   ★ 与 DWC §9 第 12 项（m/U 接口形态）直接相关：
     两者若分成两个独立模块，imp@k 类归因就不成立

★ M5. "lineage-discounted criterion" 挑迁移体
   ⇒ DWC 归档选优时应按血统折扣，防止"血统运气"被当成"策略能力"

★ M6. 域间对齐假设对 DWC 不成立
   ⇒ DGM 的 +11.0pp（改代码净贡献）不可直接外推到 DWC
   ⇒ DWC 若要报"改自己的代码值多少"，必须先证明其任务域与改进域对齐
```
