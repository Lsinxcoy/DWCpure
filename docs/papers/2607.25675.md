# DecoEvo: Score-Decoupled Co-Evolution of Solver and Rubric-Generator Skills in Text Space

> 版本信息（原文行内）：`arXiv:2607.25675v1 [cs.AI] 28 Jul 2026`；作者 Jiangwang Chen、Zixin Song、Junlin Liu、Shuaiyu Zhou、Haiyan Wu 等 13 人（清华大学 · 中科院大学 · 北京大学 · **阿里巴巴 Qwen Business Unit**）。

## 一句话总结

DecoEvo 在**冻结 backbone** 上同时维护两份可编辑的自然语言工件——solver skill `s`（任务策略）与 rubric-generator skill `g`（生成题面评分细则的原则）——并把两者的更新目标**在定义上解耦**：solver 吃准则级 rubric 反馈，generator 只吃两个**与聚合分无关**的审计（task-conditioned 结构审计查"漏了什么" + rubric-blind 近平局对比审计查"区分不开什么"），验收走 Pareto 规则，从而避免"把 rubric 改松就能涨分"的 score-coupled 共适应。

## 核心方法/机制

### 0. 问题定性（论文自陈的缺口）

- 固定评估目标是 text-space 优化的瓶颈：`most existing text-space methods keep evaluation fixed. On open-ended tasks, this can become a bottleneck: once the solver improves on the criteria a rubric measures, omitted dimensions remain invisible to the optimization signal.`（Abstract）
- 单纯演化 rubric 也不可靠：`updates are selected by the current solver’s score, because apparent progress can come from making the rubric easier to satisfy.`（Abstract）
- 形式化为**识别问题**（§1）：`generator edits change the solver’s training proxy, creating an identification problem: aggregate score cannot distinguish solver improvement from a rubric that is easier to satisfy.`，并把它与经典共演化不稳定（Popovici 2012）和 reward overoptimization（Gao 2023）对齐。

### 1. 问题设定（§3.1，公式与对象）

```
R_q(g) = Gen(q; g) = {(c_i, w_i)}_{i=1..m_q}              (Eq.1)  c_i=自然语言准则, w_i>0 分值
S(q, r, R_q) = Σ_i w_i·e(q,r,c_i) / Σ_i w_i               (Eq.2)  e∈[0,1] 来自固定准则级 judge E
J_D(s, g) = (1/|D|) Σ_{q∈D} S(q, r_q(s), R_q(g))          (Eq.3)  训练期代理
U(s) = benchmark 官方 grader + 留出 gold rubric 的测试效用   ← 真正目标
```

- 训练准则写成"正权重的必需项"，不良行为写成 avoidance requirement（约定与 gold rubric 的计分规则独立）。
- **五种角色共用同一个冻结 backbone、只换 role-specific prompt**：`role separation changes the prompt and update objective, not the underlying model.`
- **数据互斥**：`D_tr`（改 solver）、探针集 `P`（产审计诊断）、`V_s`/`V_g`（分别验收 solver / generator 候选）、诊断集（只做事后轨迹）、测试集（从不在任何更新/选择中被查询）。`Gold rubrics are never exposed during optimization.`
- **Definition 1（分数解耦的生成器更新）**：`a generator update isscore-decoupledif its proposal and acceptance may use questions, generated rubrics, response-level scores, and structured audit records, but neither uses` J_D(s_t, g_t)、J_D(s_t, g′) `or their difference as the generator objective.` 即：**响应级分数**可用（用来找近平局），**聚合 solver 分**绝不可用作生成器目标。

### 2. 内环：solver skill 演化（§3.2）

1. 内环步 t：solver 用 `s_t` 回答 `B_t ⊂ D_tr`，generator 生成 `R_q(g_t)`；judge 对**每条准则**打分并给出文本 failure rationale。
2. 选出的失败被送入 **solver-skill rewriter**，把可复用诊断**整合**成候选 `s'`（`rather than appending question-specific fixes`）。
3. **验收（Eq.4）**：
   ```
   J_{V_s}(s', g_t) > J_{V_s}(s_t, g_t) + ε      (margin ε>0)
   ```
   同一对验证题、**缓存的每题 rubric** 上配对比较——把"solver 改动"与"rubric 生成噪声"隔离。否则保留原 skill 并**递增 stall counter**（连续 M 次被拒 ⇒ 触发外环审计）。

### 3. 外环：generator skill 演化（§3.3，audit–distill–verify）

触发：每 K 个内环步，或连续 M 个 solver 候选被拒。

**(A) Task-conditioned 结构审计**：对每个任务族 τ 用**公开任务描述 + 评估说明**构造 `π^τ_str`（`atask-level priorrather than per-example expert supervision; it is fixed before optimization and never uses question-specific gold rubrics`）。审计员输入 (π, q, 生成的 rubric)，**看不到任何 solver 响应或分数**，输出：
- 充分性分 `u_q(g) ∈ [0,1]`
- 证据接地的 rationale `ξ_q`（必须引用题面/细则具体内容并解释遗漏或歧义）
- 修复建议 `κ_q`（细则生成策略该怎么改）

聚合 `φ_str(g;D) = (1/|D|) Σ u_q(g)`（Eq.5）——**标量只用于配对候选验收**，方向信息来自 rationale+建议。

**(B) 近平局对比审计**：对每个探题 q，当前 solver 采 L 个随机 rollout，当前 rubric 打分 `z_{q,l}`，只用来**定位可能区分不开的对**：
```
N_q = {(i,j) : 1≤i<j≤L, |z_{q,i} − z_{q,j}| ≤ τ_tie}      (Eq.6)
取子集 Ñ_q ⊆ N_q，至多 H 对（优先分差最小、避免同一 rollout 重复配对）
```
两阶段协议（防锚定）：**先只给题面 + 两个响应**（无 rubric、无分数）→ 出 rubric-blind 标签 `y ∈ {i≻j, j≻i, equivalent}` + rationale `ξ`；**再给细则与准则级打分分解** → 解释细则为什么漏掉这个差异、提出缺失/欠权原则 `κ`。等价对丢弃；`Γ^t_ctr` 为空 ⇒ 本外环不提修改请求。

对保留记录 `p=(q, r+, r−, ξ, κ)` 定义**细则诱导间隔**与**解决率**：
```
m_g(p) = S(q, r+, R_q(g)) − S(q, r−, R_q(g))              (Eq.7)
φ_ctr(g; Γ) = 问题均衡的 (1/|Γ_q|) Σ 1[ m_g(p) ≥ γ ]       (Eq.8)
```
（`The score is defined only when|Γ|> 0`；γ ∈ (0,1] 是要求的解决间隔。）

**(C) 蒸馏 + Pareto 验收（Eq.9–10）**：rewriter 拿到两路审计记录，把反复出现的题级发现**蒸馏成通用细则生成原则**（`rather than appending local patches`）。**提案与验收用不同数据**：rewriter 只见探针记录，候选在 `V_g` 上评（对 rewriter 隐藏）；对比验收所用的 rollouts/配对/盲偏好**冻结**，使 `g_t` 与 `g'` 在同一审计集上打分。令 `Δ_k = Φ_k(g') − Φ_k(g_t)`：
```
accept ⟺ ∃k∈K_t : Δ_k > δ    且    ∀j∈K_t : Δ_j ≥ −η      (Eq.10)
```
**至少一个可用审计目标要有非平凡改善、任何目标都不许回退超过 η**，不做跨目标加权求和（`No weighted cross-objective aggregation is required`）。

**验收规则要点汇总**：solver 侧=配对 margin ε + 缓存 rubric；generator 侧=Pareto(δ, η) + 数据分离 + 冻结审计集；部署时 `At deployment, only the optimized solver skill is retained.`

### 4. 与对照的关键区别

SC-CoEvo（score-coupled）保持 DecoEvo 的初始化、solver 更新、提案侧审计、候选提案、触发规则、验证切分**全部一致**，只把生成器验收改成"用当前 solver 的聚合分"——因此它是最强的机制归因对照。

## 综述 L 框架定位

**共享背景**：DWC = 独立自进化 agent：世界树(seed/expand/observe, W1-W6 纪律) + judge 判分(C3' 证据链) + δ 失败签名稀有度排序 + EL 采样调度(B/τ 窗口) + Dreaming 回放(K₂/β/V) + M>1 策略修订(PolicySpec)。综述 L 框架: B0=任务内输出改, L1=执行人定程序, L2=自主选改法, L3=自主定学习议程, L4=部署交互改持久态, L5=改改进机制本身。

- **L 级别：L4（Deployment and Environmental Adaptation）**（综述判定）。Table 2 中 DecoEvo 出现在 **L4 Deployment** 列的**四个技术族**：**A1. Evolutionary Search**、**C5. Prompt / Context Optimization**、**D3. Reward Model / LLM-as-a-Judge**、**E4. Adaptive / Co-Evolving Evaluator**；正文引用在 **§3.5.2（Iterative revision of the agent system → Co-evolving components）** 与 **§3.5.4（Evaluating L4 Deployment Autonomy）**，另入 Table 6。综述对它的机制描述：`The rubric generator, in contrast, is gated by two score-independent audits: a structural audit checks that the generated rubric covers the task’s requirements, and a contrastive audit checks that it discriminates between near-tie responses, with Pareto verification across the two. Because the generator never sees the solver’s aggregate score, it cannot improve its standing by making the rubric easier.`
- **为何不是 L2/L3**：改法与议程（审计角色、ε/δ/η/τ_tie、触发规则 K/M、数据切分）全部**预先固定**，模型只在给定程序内产出候选并被程序验收——这是"执行/整合"而非"决定如何改进"；同时它把**部署期（优化期）反馈写入持久工件**，故落在 L4 而非 L2。综述在 §3.5.4 也把 DecoEvo 当作 L4 风险的引证：`Feedback may also be incomplete or endogenous to the loop, as outcome labels can be noisy, evaluators can change with the system, and a useful retained artifact may still fail to influence execution`（引 Chen et al. 2026a）。
- **structural L5：部分满足但不成立**。逐条对照 L5 判据：① `AI persistently modifies a mechanism responsible for future improvements` —— **形式上满足**：`g` 正是"决定后续 solver 候选如何被评/被选"的机制，被 AI 修改并在**后续内环轮次继续使用**；② 但被修改的是**判分工件（rubric 生成原则）**，不是**改进流程本身**（审计设计、验收规则、触发调度、数据切分逐字固定），且论文自陈 `At deployment, only the optimized solver skill is retained` —— 该机制**不跨部署/不跨改进循环继承**。按综述的分类纪律（`Classification therefore applies to the particular mechanism examined`），判**优化回路内局部结构性递归、整体不构成 structural L5**；综述归 L4 是正确且保守的。
- **effective L5：不成立**。effective L5 要求"修订后的机制在可比预算与独立评估下产出或选择更好的**后继**"。DecoEvo 的独立评估对象是**solver 的任务分与 rubric 对齐度**，不是"由修订机制产生的后继改进循环更好"；预算对照（Table 4）确凿，但被评的是被改进对象而非改进机制本身。
- **与 DWC 的层级对照**：DWC 的 judge/anchors 属"评估器不可编辑"（`LAYER_BY_ITEM["evaluator"]="architecture"`），即 **L4 的评估器通道被人为关死**；DecoEvo 证明这条通道可以开、但必须配**分数解耦 + 盲审计 + Pareto 验收 + 冻结审计集**四件套，否则会像 SC-CoEvo 那样 13/15 反向。这是"DWC 要不要开评估器修订通道"的直接前置证据。
