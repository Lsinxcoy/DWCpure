## 一句话总结

Metis 先用一个**受控实验**在同一批经验、同一 agent 骨架上把"文本记忆 vs 代码记忆"拆开量出三条互补权衡（构造成本 / 执行效率 / 迁移可靠性），据此造出**分层双表征记忆**：文本记忆分 `plan / env / pit` 三类作低成本底座，**只有被反复选中的 plan 才通过复发门 `|B(p)|≥θ` 升级成沙箱验证过的可调用工具**，而"哪种经验值得编码"这一选择本身由文本记忆的复用证据决定。

## 核心方法/机制

### 0. 问题定性（论文自陈的缺口）

- LLM agent 无状态：`this experience is only retained within the finite context window`；`it must rediscover solutions it has already found and is prone to repeating mistakes it has already made`
- 表征选择是设计期拍板、而非按经验本身特性决定：`the choice between these representations is typically made at design time rather than derived from the characteristics of the experience itself`（Abstract）；`in all cases, the representation form is fixeda prioriat the system level rather than selected according to the characteristics of individual experiences.`
- 文本/代码按**消费方式**划分（不是表面内容）：text memory = 注入上下文靠读与推理消费；code memory = 封装成可调用工件靠 invocation 消费——**存代码但靠上下文注入的系统归文本类**。

### 1. 前置受控研究（§1 + Appendix A，Metis 的设计依据）

- 平台：AppWorld 训练切分 90 题；executor 固定 GPT-4o、reflector 固定 Claude-Sonnet-4.6（**两角色分模型**，为的是把"造知识的成本"与"用知识的成本"分开）。三条件 No Memory / Text / Code 共享同一协议，只有存的形式不同；默认**流式**（每题只用严格更早任务产出的记忆），另有 **Oracle** 上界（跑完 90 题批量反思、人工只删掉唯一一个坏工具、原题重测）。
- **轴 1 构造成本**：`incurring roughly2.5× more ReAct turns as shown in Figure 1b and on the order of one million additional tokens compared with text-memory construction`；附录 A 细化为 `code reflection consumes 4.3M tokens across 562 LLM rounds, against text’s 3.3M tokens across 224 rounds` ⇒ **token 只差 1.3×、LLM 轮次差 2.5×**（代码要起草→查 API→沙箱执行→调试）。
- **轴 2 执行效率**（Commonly Solved 子集，同任务公平比）：code 1.1M tokens/204 steps、text 1.5M/272、无记忆 2.4M/375 ⇒ `it cuts tokens by 54% and steps by 46%, where text cuts them by 38% and 27%`。机制 = **注入不对称**：工具把"API 发现 + 组合 + 样板"折成一次调用 `bypasses reasoning`，文本提示**每次使用都要重推一遍流程**。
- **轴 3 迁移可靠性**：`code memory degrades by 22.3 points in the streaming setting, whereas text memory degrades by only 5.6 points`；附录数值：Oracle 下 code 75.6% / text 78.9% / 无记忆 63.3%，流式下 `codecollapsesto 53.3%, 10.0 pointsbelow the no-memory baseline, while text holds at 73.3%` ⇒ **流式时代码记忆跌到无记忆之下**。
- **安全面**（同轴第二层）：文本是"带建议、可斟酌采纳"的上下文，`an imperfect text entry incurs at most the cost of a disregarded suggestion, whereas an executable artifact would propagate its error through every invocation`；更严重的是 `the mere presence of a confident-looking toolsuppressesthe agent’s own recovery behavior`——工具返回空/错时 agent 不再自查环境。
- 结论：`Codification should therefore be reserved for experiences exhibiting stable and recurring procedural patterns rather than being applied indiscriminately.`

### 2. Metis 系统（§3，四组件 + 双路径回路）

记忆：`M = (M_text, M_code)`。

**(1) 差异化文本反思（§3.2）**
- Schema：`Mtext =M env∪M pit∪M plan`；条目 `m = (body, κ, v)`，`κ∈{env, pit, plan}`，`v∈{0,1}` 是**失效位**。
  - `M_env`：环境的任务无关属性与约束；
  - `M_pit`：结构化失败模式，`(trigger, mistake, consequence)` 三元组；
  - `M_plan`：可复用子流程模板——**唯一有资格升级为代码的类型**（`execution plans capture procedural patterns and are therefore the only type of textual experience eligible for promotion into code`）。
- **反思器本身是个 agent**（有界推理环、能调同一套环境工具、查同一套文档），不是一次性总结器。失败任务 → 探查环境找根因，产出 corrective pitfall 或 warning fact；成功任务 → 找低效（错误重试、多余探索）产出效率条目。
- **防过拟合**：反思器额外条件在**最近 N 个任务的 query 分布**上，使 plan 抓"跨任务反复出现的模式"而非单题解法。
- **维护 = merge / update，走 invalidate-and-replace**：`Both operations follow an invalidate-and-replace policy rather than in-place editing. Specifically, each superseded entry has its invalidation bit flipped (v: 0→1 ), and the merged or revised entry is appended as a new record.`
- 复用时文本是**建议不是控制流**，执行者可斟酌/部分采纳/忽略 ⇒ `graceful degradation`（引文见上）——这是"文本作默认低承诺表征"的理由。

**(2) 模式感知代码生成（§3.3 + Algorithm 1）**
```
Require: 完成的任务 i; 选中的 plan S^plan_i; 阈值 θ; 历史预算 β; M=(M_text, M_code)
1: for all p ∈ S^plan_i with v(p)=0 do
2:   B(p) ← B(p) ∪ {i}            ▷ 累积复发证据; success not required
3:   if |B(p)| < θ then continue  ▷ 复发门: 只升级成熟 plan
6:   Q_B ← {q_j | j∈B(p)}         ▷ 只给 query; 轨迹被有意排除
7:   Q_R ← {q_j | j∈R(p)}
8:   (ok, T) ← CODIFY(p, Q_B, Q_R, M_code)
9:   if not ok then continue       ▷ 依赖或编译检查失败(§3.5)
12:  M_code ← M_code ∪ T
13:  D(p) ← D(p) ∪ {id(t) | t∈T}   ▷ 登记 plan↔tool 链接
14:  R(p) ← Recent_β(R(p) ∪ B(p))  ▷ 消费掉的 buffer 折进历史
15:  B(p) ← ∅
```
- plan 的代码路径字段：`p = (body(p), v(p), B(p), R(p), D(p))`——B 是候选 buffer、R 是预算 β 内的关联任务历史、D 是已准入工具集；三者让 plan 成为**文本与代码之间的桥**。
- **复发证据 ≠ 成功证据**：`Metis treats plan reuse as recurrence evidence, not as proof that the plan caused task success.`；失败 rollout 也计入，但 `Codify uses the query but deliberately excludes the trajectory, such tasks contribute coverage without propagating erroneous execution paths into the generated tool`。
- **准入规则（Tool Admission）**：codifier 被要求合成**小的可组合 helper 而非端到端求解器**；`Each helper must be supported by at least two structurally distinct queries fromQB(p)∪Q R(p), and task-varying elements such as entities, time ranges, filters, and API options must be exposed as parameters rather than hard-coded.`；准入前必须过依赖闭包与编译检查（§3.5）。

**(3) 记忆管理器（§3.4）**：先对文本条目与工具描述各做 embedding top-k 取有界候选池，再由**轻量 LLM Manager 联合选择**（只见 query、文本条目、工具签名与 docstring，**不见工具实现**）；选中的 plan 通过 `Ref(p) ⊇ D(p)` 自动把实现它的工具带入可执行集合 ⇒ `selecting a codified plan automatically makes its tools eligible for execution`。

**(4) 反思 harness（§3.5）**
- **依赖闭包**（运行期）：`U_0 = S^tool_i ∪ ⋃_{m∈S^text_i} Ref(m)`，`U_{r+1} = U_r ∪ ⋃_{t∈U_r} Dep(t)` 直到不动点 `U_{R+1}=U_R` ⇒ 工具注入**依赖完备**而无需 Manager 理解实现细节。
- **工具准入守卫**（准入期，同一套闭包）：`Compile (impl(t),Close(∅,{t})) = 1`；`If compilation fails, the codifier receives the error message and is allowed one corrective round. A second failure rejects the candidate`——**一次纠错机会、二次失败即拒**。
- **渐进披露**：`˜s_t = (type(a_t), name(a_t), Trunc(a_t;h), Trunc(o_t;h))`，`Trunc(x;h) = head h(x)∥...∥tail h(x)`；反思器先看"保留首尾截中间"的紧凑视图，再按需申请展开某步/某区间/某工具实现 ⇒ `from a lightweight global sketch to targeted local inspection`。
- **回路顺序**：Memory Manager 选记忆 → 执行 → 若选中 plan 攒够复发证据则**先**触发 Code Generation → Differentiated Text Reflection 再看着轨迹 + 新工具库修订/新建条目 → 写回 M。`reflection in Metis lies entirely off the execution critical path`（两条反思路径都作用于已完成轨迹，可异步）。

### 3. 实验设置（§4.1）

- 基准 AppWorld：`9 applications exposing 457 APIs`，程序化状态测试判分（指标 TGC = 通过全部状态测试的任务占比）。
- 基线：No Memory（官方 ReAct 实现）、ACE（delta 式上下文更新的文本演化）、SkillX（离线批量构造结构化 skill 工件）——统一到同一 executor、任务顺序、sandbox 接口。
- 模型：executor = `GPT-4o with ReAct`；reflector = `Claude Sonnet 4.6`（对所有基于记忆的方法共用，只在离线训练期跑）；embedding = `text-embedding-3-large`。
- 协议 train-then-test：训练任务**单次固定顺序**一遍构造记忆 → **记忆冻结** → 评 held-out 测试；`We exclude test-challenge`（理由：该切分考的是对训练中不存在应用的域外泛化，任何经验法都"构造上"攒不出记忆，非本文重点）。
- 两切分：**Official**（原始 train/test-normal，场景级不相交、分布漂移，考泛化）与 **Resampled**（合并后按任务级重抽、同场景变体可跨侧，考复用）；除主结果外的分析都在 Resampled 下做（记忆被用得更频，组件差异分辨率更高）。

## 主结果

### Table 1 主表（逐格）

| 切分 | 方法 | Acc(%)↑ | 执行 tokens(K)↓ | ReAct 轮↓ | 反思成本(M) |
|---|---|---|---|---|---|
| **Official** | No Memory | 51.8 | 112.6 | 14.55 | 0 |
| | ACE | 53.6 | **422.4** | 13.60 | 6.9 |
| | SkillX | 54.8 | 100.3 | 12.30 | 9.4 |
| | **Metis** | **60.1** | **97.4** | **11.25** | 7.9 |
| **Resampled** | No Memory | 54.8 | 101.7 | 13.92 | 0 |
| | ACE | 57.7 | 204.8 | 11.90 | 4.3 |
| | SkillX | 65.5 | 89.5 | 11.03 | 17.8 |
| | **Metis** | **66.1** | **78.5** | **10.32** | 11.8 |

原文两句：`improving TGC over the no-memory baseline by 8.3 points on the Official split and 11.3 points on the Resampled split, where ACE and SkillX gain at most 2.9 and 10.7 points respectively`；`Metis reduces executor tokens by 13.5% and 22.8% relative to the baseline on the two splits, whereas ACE inflates execution cost by up to 3.8x despite its smaller accuracy gain`。摘要口径：`improves task accuracy by up to 20.6% over ReAct while reducing execution cost by up to 22.8%`（20.6% = 66.1/54.8 的相对增益，我按表核算一致）。
反思成本：Metis 在两个切分上都低于 SkillX（7.9 vs 9.4、11.8 vs 17.8），**尽管它还额外做了工具合成与验证**。

### 分布漂移下的稳健性（§4.2）

- 基线自身从 Resampled→Official 掉 3.0 点；SkillX 的增益从 **+10.7 缩到 +3.0**，Metis 的增益从 **+11.3 只缩到 +8.3** ⇒ `once task difficulty is controlled, SkillX loses the majority of its memory utility under distribution shift, whereas Metis retains most of it`。
- 归因（机制层）：SkillX 离线合成、**无复发证据** ⇒ 工件带进"从哪些任务蒸出来"的假设；Metis 的 plan 必须**跨不同 query 被反复选中**且 task-varying 元素必须参数化 ⇒ 工具蒸自更广观察、显式设计成容纳任务差异；不满足升级条件的留在文本形态（迁移更稳）。

### Table 2 · 共同解出的任务子集（62 题，公平比执行成本）

| 方法 | tokens(K)↓ | 轮↓ |
|---|---|---|
| No Memory | 85.2 | 12.2 |
| SkillX | 71.4 | 9.7 |
| **Metis** | **59.6** | **8.6** |

（ACE 被有意排除：其 playbook 注入成本随记忆增长而涨，与求解行为无关。）归因：SkillX 的含代码 skill 仍是**上下文信息**，agent 还要读与推理；Metis 把反复出现的流程注册成可调用工具，直接 invoke。

### Table 3 · 知识复用（test split）

| 指标 | Metis | SkillX |
|---|---|---|
| 任务无记忆注入 ↓ | **0%** | 20.8% |
| plan 级条目被复用 ↑ | 83% | 86% |
| 含代码条目被**调用** ↑ | **94%** | 84.1%（注入口径） |

原文：`94% of Metis’s tools areinvokedby the executor at least once, whereas only 84.1% of SkillX’s code-bearing skills areinjectedinto the context`，并自陈这个比较对 Metis `conservative`（`invocation is a strictly stronger criterion than injection`——注入的 skill 可能从未影响行为）。

### Table 4 · 消融（AppWorld dev split，各自从零重建记忆）

| 变体 | Acc(%)↑ | 构造成本(M)↓ | 执行 tokens(K)↓ | ReAct 轮↓ |
|---|---|---|---|---|
| No Memory | 56.1 | 0 | 74.4 | 11.46 |
| Metis (Text-only) | 62.3 | 4.96 | 55.6 | 9.25 |
| Metis (Code-only) | 60.2 | 4.89 | 58.7 | 8.89 |
| Metis (Eager，去掉复发门) | 63.2 | **11.6** | **49.9** | **7.68** |
| **Metis (full)** | **66.7** | 7.9 | 54.5 | 8.46 |

- 单表征各自有效（Text-only +6.2、Code-only +4.1），full 再高 4.4 / 6.5 ⇒ `The hybrid gain is therefore not additive bookkeeping but interaction: plans supply the recurrence signal that decides what deserves codification, and admitted tools in turn sharpen subsequent plans`。
- **复发门的净效应**：`Eager codification incurs 47% higher construction cost (11.6M vs. 7.9M tokens) and degrades dev accuracy by 3.5 points (63.2 vs. 66.7)`；Eager 的执行成本确实更低（49.9K/7.68 轮），但换来的是构造浪费 + 精度损失；利用率：`only 41% of Eager’s tools are ever invoked, against 56% for the full system`（并自陈 dev split 太小，绝对值受限；大 test split 上 full 达 94%）。结论：`The gate, in other words, is not free efficiency but a quality filter`。
- Code-only 不塌回基线的两条解释（与 profiling 的逐任务编码失败对账）：① codifier **只看 query 不看轨迹**（切断"错误执行路径被铸进工具"的通道）；② 变体继承完整 harness（沙箱验证、依赖闭包、编译门）；交互深度差仍在：text 反思器均 2.84 轮/任务 vs codifier 6.08 轮/任务（token 因只看 query 而相当：4.96M vs 4.89M）。

### 负面结果 / 论文未报告（诚实项）

- **逐任务（无门）编码在 profiling 阶段是失败的**：代码记忆流式跌到无记忆之下（53.3% < 63.3%）——这是论文自己造出来的负面结果，并作为 Metis 设计的直接动因。
- **ACE 的对照不完整**：共同解出子集的公平比把 ACE 排除（理由已给），且 ACE 在两个切分上的精度增益都最小。
- **test-challenge 被排除**（`evaluates out-of-domain generalization rather than experience reuse, which is not the focus of this work`）⇒ **跨应用域外泛化论文未报告**。
- 论文**未报告**：多 seed / 方差 / 显著性检验（Table 1–4 均为单次运行的点估计，无 SD、无 CI）；θ、β、N、h、top-k、L 等超参的具体取值（**本 txt 正文未给数值**，`a configurable reuse threshold` ⇒ **未核**）；人类评估；除 AppWorld 之外的第二个基准。
- dev split 小，作者自陈利用率绝对值受限（`the absolute rates are bounded by the small dev split`）。

## 与 DWC 的映射

| 机制（Metis） | DWC 现状（代码级） | 判定 |
|---|---|---|
| **分层双表征 M=(M_text, M_code)**，文本三类 plan/env/pit（按"怎么被消费"分类） | 单一 SQLite 记忆内核 `organs/memory.py::MemoryKernel`：`MemoryKind` 5 类（trace / working_state / failure_sig / skill / proposal）+ `Zone` 4 区（EXPERIENCE/PROXY/ARCHIVE/INERT）+ `Tube` 七管（remember/recall/learn/reflect/evolve/dream/maintain），并有 `EXPERIENCE_REQUIREMENTS` 准入门槛。**没有"文本 vs 代码"这条表征轴**，也没有"唯一可升级为可执行工件"的 plan 类型 | **缺**（分类轴不同：DWC 按"记忆是什么/进到哪个区"分，Metis 按"运行时怎么消费"分）；DWC 的 Zone/准入门槛是同族的**分层治理**思想 ⇒ 该分类思想 **确认型**，表征轴 **缺** |
| **复发门 `|B(p)|≥θ`** + **query-only codify**（轨迹被有意排除） | 无任何"把经验编译成可调用工件"的路径；`MemoryKind.SKILL`（scene/method/boundary）仍是文本；最接近的"何时保留"由 `evolver` 依 GAI dials 决定淘汰（`memory.py::eviction_candidates()` 只出证据不做决策） | **缺**（无 codify 通道，因而也无"复发证据 vs 成功证据"这条区分）；但"**淘汰决策与证据提供分离**"是同族纪律 ⇒ 记 **确认型（分离）/ 缺（升级）** |
| **工具准入守卫**：`Compile(impl(t), Close(∅,{t})) = 1` + 一次纠错、二次拒 | 门更靠前也更严但**验证内容不同**：`applier.apply_on_copy → commit/rollback` + 回归窗口 `window_settle` + `evolver.check_component`/`check_pairing`(K2 声明-层一致) + `candidates.record_rejection`（拒绝原因落库）。**无编译检查、无依赖闭包** | **半有**（同为"准入前验证 + 失败即拒 + 原因可查"；缺依赖完备性与可执行性这一类**静态验证**） |
| **依赖闭包不动点** `U_{r+1} = U_r ∪ ⋃Dep(t)`（运行期注入依赖完备） | 不存在"工具/工件依赖"概念（无工件图）；最接近的是 `memory_node.chain_id`（因果链 `foundation/causal_chain.py`）把记忆串成链，但**不是闭包、不参与注入** | **缺** |
| **invalidate-and-replace**（v:0→1、追加新记录、不原地改） | 同族纪律已在且更硬：`world_model.observe()` W5 —— `provenance 只许 simulated→observed，且真值不许覆盖`；`memory.py::maintain()` 的 `归档而非删除`（`archived_at` 时间戳 + 审计记录 + 三层判据）；`replay` 快照只读（`dream 不写树、不产分数`） | **确认型**（同一"不可回写、可审计"约束，对象不同：DWC 保护分数与 provenance，Metis 保护记忆条目版本） |
| **激活/复用统计**（Table 3：0% 无注入、94% invoked vs 84.1% injected） | `MemoryNode.access_count / last_access / effect_count`、`used()`、`record_effect()`、`recall_many()` 记 access 而 `recall_search()` 不记（纯查询可反复试）、`eviction_candidates()` 出证据；并**自陈病灶**：`母巢的病恰恰是"写入多、读取少"（98.8% access=0）` | **半有**：统计口齐全（access/effect 双计数）；缺 Metis 的**两级判据区分**——"注入了"（被检索到）vs "调用了"（真的参与执行），DWC 只有 recall 侧 access，无 invocation 侧强判据；也无"多少任务完全没拿到记忆"的覆盖率报表 |
| **联合选择**（文本 + 工具一起选；选中 plan 自动带入 D(p)） | `recall_search/recall_many(scene, terms, k)` 单通道检索 + `weakness.weak_ranking` 的 δ 稀有度**排序偏置**（`只可作排序偏置: 不给阈值, 只给顺序`）；无 LLM Manager 做跨表征联合选择 | **半有**（有检索 + 排序偏置纪律；跨工件"选 A 自动带 B"的联动机制缺——因为只有一种表征） |
| **渐进披露** `Trunc(x;h) = head h(x)∥...∥tail h(x)` + 按需展开 | DWC **没有反思器角色**：`Tube.REFLECT` 管阶段的对象是失败签名归因（`(c,q,m)`），不是长轨迹；无"先摘要后按需展开"的证据暴露协议 | **缺**（若 DWC 将来要对长 trace 做反思，这是现成可搬的接口设计） |
| **反思全在执行关键路径外**（可异步，不增 serving 延迟） | `core.dream()` 是**离线只读回放**（快照进 ℋ、回放不写树）；ACTIONS 路由 `remember/learn/dream/maintain/evolve` 分步 dispatch | **确认型**（重活离线化的同族设计；但 DWC 无"在线服务延迟"这一量纲 ⇒ 该指标 **不适用**） |

## 综述 L 框架定位

**共享背景**：DWC = 独立自进化 agent：世界树(seed/expand/observe, W1-W6 纪律) + judge 判分(C3' 证据链) + δ 失败签名稀有度排序 + EL 采样调度(B/τ 窗口) + Dreaming 回放(K₂/β/V) + M>1 策略修订(PolicySpec)。综述 L 框架: B0=任务内输出改, L1=执行人定程序, L2=自主选改法, L3=自主定学习议程, L4=部署交互改持久态, L5=改改进机制本身。

- **L 级别：L4（Deployment and Environmental Adaptation）**（综述判定，五个技术族全在 **L4** 列）：**A4. LLM Reflection / Critique**、**A5. LLM-guided Program / Code Search**、**C6. Memory / Skill Consolidation**、**D1. Execution / Unit-Test Verification**、**E2. Experience Replay / Online Memory Update**；引用位置 **§2.1、§3.5.1（Trajectory distillation → Executable artifacts）、§3.5.3（Selective retention → Candidate validation）**、Table 6。综述两处描述：
  - §3.5.1：`Metis Dai et al. [2026] achieves this through a dual memory, a text store of plans, environment facts, and pitfalls alongside a code library of callable tools. A reflector maintains the text entries, and a frequently reused text plan is rewritten as a callable tool and accepted only after it compiles and runs correctly in a sandbox.`
  - §3.5.3：`Metis Dai et al. [2026] , introduced earlier in the trajectory-distillation section, applies a similar gate after the text plan is already retained in memory, where a text plan becomes executable code only after it recurs across tasks and passes dependency and compilation checks.`
- **判据符合性**：L4 定义是 `The agent converts interaction histories into retained changes to memory, skills, harnesses, code, or model parameters, and these changes affect later tasks and feedback. Humans retain the objective, protected acceptance criteria, access boundaries, and final authority over consequential releases.` —— Metis 逐条命中（交互历史 → 记忆/工具持久变更 → 影响后续任务），而 **θ、准入门、反思 prompt、harness 检查、评测协议全部人定**。
- **structural L5：否**。被 AI 持久修改的是**任务资产（记忆条目与工具库）**，不是"负责未来改进的机制"——反思器提示、三类 schema、复发门 θ、准入双检查、渐进披露协议在论文中逐字固定，**没有任何一处让模型修改"如何去反思/如何去准入"**；也没有"修订后的改进机制回到下一轮改进的生成、评估或选择"的闭环。按综述的分类纪律（`Classification therefore applies to the particular mechanism examined`），Metis 是 L4 的标准样本而非 L5 过渡态。
- **effective L5：否**。全部效果证据（TGC、tokens、复用率）评的是**被改进对象（agent 的任务表现）**，没有"改进机制产出更好后继"的独立评估。
- **一个易被误判的点**：Metis 有 `D(p)`（plan↔tool 链接）、有准入门、有"反思器本身是 agent"——看起来像"改了评估/准入机制"。但准入门的**判据与阈值固定**、只由复发计数触发；反思器改的是**记忆内容**不是**反思程序**。综述把这类放 §3.5.3（**选择性保留**）而非 §3.6（L5），与本判定一致。
- **对 DWC 的层级含义**：DWC 的世界树/记忆/Dreaming 全部落在 L3–L4 通道（EL 调度选什么经验、Dreaming 回放选哪个策略、记忆归档淘汰），**改进程序本身（W1–W6 纪律、K1/K2 门、PolicySpec 修订域）由人锁定**——这正是 L4 的形态；Metis 提供的是 L4 通道内"如何选表征、何时升级工件"的可搬细节，不提供跨入 L5 的证据。
