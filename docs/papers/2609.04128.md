## 1. 问题

### 论文自己承认的缺口

论文在 §1 明确陈述了**一条因果链**上的三个断点：

1. **从零合成的环境对前沿模型不够难。**"these environments are often insufficiently challenging for current frontier models, which consistently solve them across repeated rollouts."这类环境在 RL 训练时被丢弃，因为"fail to provide effective learning signals that distinguish between better and worse trajectories"，浪费构造成本并降低保留分布的多样性。

2. **现有共演化方法被 rollout 模型和初始分布双重锁死。**"their dependence on on-policy rollouts limits generalization and the continuous provision of learning signals as the model becomes stronger."

3. **共演化只触及难度空间的一部分。**论文给出了一个形式化的诊断（§3）：在策略 θ 下，高层轨迹 ξ=(σ₀,κ₁,σ₁,…,κ_L,σ_L) 的负对数似然 D_θ(ξ)=−log p_θ(ξ|g)=Σ_{t=1..L}(−log p_θ(σ_{t−1}|g) − log p_θ(κ_t|σ_{t−1},g)) 有三个贡献者：步数 L、scenario novelty、skill rarity。而 on-policy 共演化产生的信号"is mainly Σ_t e_t^θ[−log p_θ(κ_t|σ_{t−1},g)]"——**只命中 skill 选择误差一项**，且局限在"scenarios contained in the seed environments and reached by the current model"。它"does not explicitly control the number of required solver steps L, nor does it systematically increase scenario novelty under p_T(σ|g)"。

论文因此把可操作的难度空间写成三元组：**( L, −log p_T(σ|g), −log p_T(κ|σ,g) )**，主张环境演化直接在这个完整空间上操作。

### 论文自陈的质量缺口（§2）

论文用"our large-scale rollout and quality assessment experiments"批评现有开源终端环境"suffer from low-quality reward signals (e.g., misalignment between task instructions and verification systems, corrupted environments)"且难度不足。**论文未报告**这批 rollout / 质量评估的具体规模与统计口径（只说 "large-scale"），也未报告被判定为低质量的比例。

## 2. 核心机制

### 2.1 核心判据：策略无关的 off-policy 难度公式

这是论文最可迁移的数学资产，分三步推导：

**第一步：把模型依赖项换成参考分布。** 设 𝒯 是"grounded in broad world knowledge"的参考分布，则

D_𝒯(ξ) = Σ_{t=1..L} ( −log p_𝒯(σ_{t−1}|g) − log p_𝒯(κ_t|σ_{t−1},g) )

论文明确：p_𝒯(σ|g) 度量"how common a scenario is within the environment family"，p_𝒯(κ|σ,g) 度量"how common the required skill is under that scenario"。**实现路径**：论文称"a deep-research agent can estimate both distributions through broad web search, grounding them in world knowledge, by providing the relative context of g and ξ"。注意这是估计，不是解析计算。

**第二步：agent weakness 是残差，不是难度本身。** 令 z_t=(σ_{t−1},κ_t)，逐步难度 d_θ(z_t|g) 与 d_𝒯(z_t|g)，则

δ_θ(z_t|g) = [ d_θ(z_t|g) − d_𝒯(z_t|g) ]₊ ，[x]₊ = max(x,0)

等价形式（论文给出，用于直接读概率比）：
δ_θ(z_t|g) = [ log( p_𝒯(σ_{t−1}|g) / p_θ(σ_{t−1}|g) ) + log( p_𝒯(κ_t|σ_{t−1},g) / p_θ(κ_t|σ_{t−1},g) ) ]₊

整条轨迹：Δ_θ(ξ) = Σ_{t=1..L} [ d_θ(z_t|g) − d_𝒯(z_t|g) ]₊

**这句是全文的枢纽**："weakness is not the difficulty of the environment itself; it is the portion of that trajectory that is unusually difficult for a particular model relative to the environment family."

**第三步：三条演化方向 = 三个分量。** 论文把 direction 逐一对应到公式的因子：
- `length` ← 控制 L
- `scenario` ← 控制 −log p_𝒯(σ|g)
- `skill` ← 控制 −log p_𝒯(κ|σ,g)

### 2.2 Loop-Engineered Multi-Agent Harness（Figure 2）

输入"the latest accepted environment"，输出下一代环境。两个带门控的反馈环：

**Loop 1: Plan Refinement**
- Proposer 从 E 抽取交错序列 ξ_E = (σ₁,κ₁), …, (σ_L,κ_L)（式 1）。
- 按当前 direction 改序列：`length` 插入 scenario–skill 对；`scenario` **替换一个 scenario 但保留其配对 skill**；`skill` **替换一个 skill**。
- 从"the difference between the updated and original sequences"生成 plan，交由 **rubric-based reviewer 迭代审查**，直到 accept 或"the current evolution direction fails"。

**Loop 2: Environment Refinement**
- Modifier 产出**残差** ΔE 并施加到当前环境。
- 三个 verifier **并行**跑：(i) **Oracle verifier**——reference solution 必须在沙箱成功；(ii) **Invalid-test verifier**——空解/no-op 解必须失败，"ensuring that the verification system is reliable"；(iii) adaptive **general-rubrics** verifier 查环境质量。

**关于 human-in-the-loop 的诚实细节**：论文写"During development, accepted environments undergo human-in-the-loop review"，且"Issues that bypass the rubric-based checks are converted into new rubrics"。但**论文未报告**人工复核了多少环境、每轮人工介入多少次、人工与 rubric 的 disagreement 率——**只声明目标是**"until the loop reliably produces environments with no issues identified by human reviewers"，没给这个"reliably"的量化达成条件。

### 2.3 Evolution Effort（进化强度）

prompt 控制的变异参数，"analogous in spirit to thinking effort"，三档：
- `low`：只改一个局部对 (σ_ℓ,κ_ℓ)
- `high`：一个连续 span
- `max`：序列的不受限部分

direction 决定"what type of sequence-level edit"，effort 决定"its scope"。

### 2.4 跨方向回退规则

"each generation, we randomly order the three evolution directions. If the Plan Reviewer rejects a plan or the repair budget for the current direction is exhausted, we fall back to the next direction, construct a new target sequence from the same environment, and repeat. **The branch terminates only when all three directions fail.**"

### 2.5 Evolution-Lineage (EL) Scheduler（式 2）

动机：后期代更难，全谱系随机采样会给出"all-failure rollout groups that provide no effective learning signal"。

设 E_{i,g,k} 为 lineage i 中第 g 代第 k 个环境，该代共 N_{i,g} 个。在 update u：

(g_{u+1}, k_{u+1}) = 
  (g_u, k_u)          若 p̂_u(E_{i,g_u,k_u}) ≤ τ
  (g_u, k_u+1)       若 p̂_u > τ 且 k_u < N_{i,g_u}
  (g_u+1, 1)         若 p̂_u > τ 且 k_u = N_{i,g_u}

其中 **p̂_u(E) = (1/B) Σ_{b=1..B} r_{u,b}**，**B=8，τ=6/8**。

即：**只有当某个环境的 rollout 通过率超过 6/8，才前进到下一个环境；当代内全部环境都越过阈值才进下一代。** 论文给出生理机制：这样"more rollout groups remain partially solved and retain non-zero within-group advantage"——因为 GRPO 的优势项在组内全对或全错时为零。

### 3.2 Evolution Effort（§5.2，Figure 3）

从同一种子环境出发，随机 cross-mode 策略构造 **15 代**谱系，low/high/max 各一套。论文声明 15 代上限的理由：一旦谱系进入 zero-pass regime，pass rate "provides no further resolution"，再加代次"cannot be assessed reliably from rollout outcomes"。

- **`low`**：avg turns 逐代上升（长程执行被拉长），但 **pass rate 波动且始终高于零**。论文给出机制解释：low 只改一个局部对，"successive generations may repeatedly edit the same pair and partially return to an earlier configuration"——**代数增加但难度不单调**。
- **`high` / `max`**：pass rate **单调降到零**，avg turns 上升；`max` 更早归零，难度变化更大。
- Figure 4（mutation rate）：`high`/`max` 下 instruction mutation 维持在 **95%–100%** 之间波动并略降；environment 与 verification system 的变更更"selective"（更低更收敛）。
- **默认档位**：论文选 `high`，理由是"Balancing effective and stable evolution against the controllability of each generation"。
- **注意**：Figure 3 / 4 的具体数值点是**图形**，正文只给定性描述与 95–100% 这一区间。**论文未报告** pass rate / turns 的精确表格数字。

### 3.3 Evolution Direction（§5.3，Table 1）——这是全文最硬的数字表

固定 `high` effort，两个区块：**1-step effect**（同一批种子环境各方向施加一次）与 **15-step mean effect**（沿方向专属谱系连续演化 15 步，对 15 次相邻代际转换取平均）。难度变化由 **Claude Opus 5（xhigh）** 测量，定义为后代减前代。mutation 率按 instruction / environment / verification 分别在 token / file / test-unit 层测量。

**1-step effect：**

| Direction | Δ Pass Rate | Δ Avg Turns | Instr Mut | Env Mut | Verif Mut | Total |
|---|---|---|---|---|---|---|
| scenario | **−4.7 pp** | +13.5 | 99.8% | 59.6% | 53.8% | 71.1% |
| skill | **−4.0 pp** | +12.5 | 99.1% | 50.3% | 58.4% | 69.3% |
| length | **−7.1 pp** | +9.4 | 87.5% | 45.2% | 58.6% | 63.8% |

**15-step mean effect：**

| Direction | Δ Pass Rate | Δ Avg Turns | Instr Mut | Env Mut | Verif Mut | Total |
|---|---|---|---|---|---|---|
| scenario | −2.9 pp | +9.5 | 97.1% | 34.6% | 43.7% | 58.5% |
| skill | −2.7 pp | +10.6 | 96.5% | 27.8% | 45.8% | 56.7% |
| length | **−4.8 pp** | +7.4 | 85.5% | 34.3% | 48.9% | 56.2% |

论文的三个结论：
- 三方向都降 pass rate、升 avg turns。
- `length` 降 pass rate 最多；`scenario` 与 `skill` 升 turns 更多。
- `scenario` 总 mutation 最大；`length` 用**最小**的总 mutation 拿到**最强**的 pass rate 降幅——即成本效率最高。
- **1-step 与 15-step 的方向画像一致**，作者用这个一致性论证"these direction-specific profiles persist beyond a single edit"。

### 3.4 RL 训练动态（§5.4）

- **EL Scheduler vs 随机调度**：在**前 50 步**、matched rollout budgets 下对比。Figure 5 实线 = 部分解出组占比（8 次 rollout 中 1–7 条成功），虚线 = 平均训练 reward。结论：EL Scheduler"uses the rollout budget more efficiently"，让更多 rollout 组保持部分解出、保留非零组内优势。**论文未报告**这两个曲线的具体数值。
- **Tokens per turn（Figure 6，200 步，有精确数字）**：
  - Qwen3.6-27B：**约 951 → 1,221**
  - Qwen3.6-35B-A3B：**约 947 → 1,103**
  论文解释：调度器逐步放行更难的环境，需要更长交互horizon，策略给每轮分配了更多思考量。**turns 与 tokens 的绝对值在图中，论文未在正文给出。**

### 3.5 主结果：三范式对比（§5.5，Figure 7）

控制变量：**固定 Claude Opus 5 为环境合成模型，训练环境总数保持恒定**。每 10 步做一次离线 Terminal-Bench 2.1 评测。

**三个基线的构造方式（论文给得很具体，可复现）：**
- **Environment Ensemble**：先在种子上评目标 agent，选出它**解不出**的环境；枚举**全部二元与三元组合**，每个组合合并成一个更难环境；递归套用为一棵树，一层的输出是下一层的输入。
- **Agent–Environment Co-Evolution**：目标 agent 先在种子上 rollout 生成轨迹，分析**失败轨迹**构建 **weakness bank**，从中采样组合合成新环境；**agent 训练 50 步后重复该过程**。
- **Environment Evolution**（本文）：每代随机排序三方向 + cross-mode fallback，**不使用目标 agent 的 rollout**，从每个种子产出已验证的 15 代谱系。

**Terminal-Bench 2.1 峰值准确率：**

| 模型 | Environment Evolution | Co-Evolution | Ensemble |
|---|---|---|---|
| Qwen3.6-27B | **71.5%** | 62.9% | 60.0% |
| Qwen3.6-35B-A3B | **64.9%** | 55.1% | 52.8% |

**换算成论文自己声称的提升幅度**：27B 上 **+14.4 pp**（vs Co-Evolution 62.9%），35B-A3B 上 **+18.0 pp**（vs Co-Evolution 55.1%）。即摘要里的 14.4 / 18.0 pp **是相对最强基线 Co-Evolution 的差值，不是相对 step 0 基线**。这一点论文正文只在 §5.5 给峰值、在 Abstract/Intro 给 pp 换算，两处并列阅读才不误读。

### 3.6 负面结果与未报告项（诚实清单）

- **明确报告的负面**：`low` effort 下 pass rate 波动且不归零，相邻代会"partially return to an earlier configuration"。这是作者主动披露的失败模式。
- **论文未报告**：① 任何成本核算（合成 token 数、人工复核工时、GPU 小时）；② Figure 3/4/5/6/7 的数值表格（只有图与定性描述）；③ 谱系在 15 代之后的行为；④ 消融 EL Scheduler 单独贡献多少（只与 random scheduling 比，未消融）；⑤ "evolved environments continue to provide challenging RL signals even when their seed environments have already been used for SFT" 这条论断**没有配数字**；⑥ Appendix A 明说"Future versions will also report RSI results in which the same model both constructs and learns from the environments"——即**真正的自举（自己造环境自己学）结果尚未报告**。

## 4. 它假定了什么

1. **"难度"可分解为 (L, scenario novelty, skill rarity) 三项，且可由 LLM 估计。** 这三项是从 NLL 分解推出来的数学恒等式，但**"可估计"这一步靠的是 deep-research agent 的网络搜索判断**，论文未报告估计的可靠性/校准度，也未验证三项之和与实测 pass rate 的相关性。

2. **参考分布 𝒯 存在且可被广泛访问。** 整个 off-policy 论证依赖"a reference distribution 𝒯 grounded in broad world knowledge"。若 𝒯 与 p_θ 高度相关（例如前沿模型已见过大量同类内容），δ_θ 会系统性偏小，方法的适用前提消失。**论文未报告** 𝒯 的具体构造方式（哪个模型、什么检索协议、怎么把搜索结果变成概率）。

3. **环境难度是可继承的（difficulty is heritable along lineages）。** 15 代谱系单调变难这个核心主张，**只在一个方向上被验证**（Table 1 的 15-step mean 是沿方向专属谱系）。但"任意序列的 15 步演化都单调变难"从未被直接测量——Figure 3 的 `low` 档恰恰是反例。

4. **验证系统的可靠性可以在合成时被判定。** Oracle verifier + Invalid-test verifier + rubric 三件套是 Loop 2 的门槛。但论文自己在 §2 批评别人"misalignment between task instructions and verification systems"——**它自己的 verifier 组合是否被独立验证过，论文未报告**（只有一句 human-in-the-loop 声明，无数字）。

5. **人工可以把 rubric 漏掉的问题转成新 rubric，形成收敛闭环。** "Issues that bypass the rubric-based checks are converted into new rubrics ... until the loop reliably produces environments with no issues"——这是把**人类判断当作可编码真值源**。它假定了 rubric 空间足够表达人类发现的所有问题，且这个过程会终止（论文未给出终止判据的量化形式）。

6. **Claude Code harness 与前端模型是固定的。** 全部评测与训练都在 Claude Code harness 下，工具协议跨模型固定。如果 harness 变了，"pass rate ≤ 4/8、avg turns ≥ 30"这些阈值是否还成立，论文未报告。

7. **Qwen3.6 系列可代表通用终端能力。** 只验证了两个 Qwen checkpoint（27B dense、35B-A3B MoE），**论文未报告**在 Claude/GPT 系终端 agent 上的训练结果。

## 5. 可迁移到 DWC 的点 / 不可迁移的点

### 可迁移（给具体接口）

**① δ_θ 残差公式 → DWC 的"真值门"判据（可直接实现）**

DWC `QUALITY_GATE.md` 门 2 要求每个判定模块声明 `TRUTH_SOURCE`，且"评分与输入无关 → FAIL"。δ_θ 正好给了一个可计算的判据，而不是布尔断言。

```python
# DWC 侧接口建议：src/dwc/quality/difficulty.py
def agent_weakness(z_theta, z_reference) -> float:
    """z_theta:   模型自评概率 {scenario: p, skill: p}
       z_reference: 参考/世界知识分布概率（可用检索计数或另一个更强模型的估计）
       对应论文 δ_θ(z_t|g) = [d_θ(z_t|g) - d_𝒯(z_t|g)]_+ """
    return max(0.0, d_theta(z_theta) - d_reference(z_reference))

def weakness_trajectory(zeta, g, theta, T) -> float:
    """对应 Δ_θ(ξ) = Σ_t [d_θ - d_𝒯]_+"""
    return sum(agent_weakness(zt, g, theta, T) for zt in zeta)
```

落点：`src/dwc/quality/` 下的真值门取证函数，输出可入台账的浮点数而非布尔。

**② EL Scheduler（式 2）→ DWC 的进化件投放节奏器（纯 Python，无外部依赖）**

B=8、τ=6/8 的判据完全可移植，且它解决的是 DWC 门 4（生灭配套）里的"何时放行"问题。

```python
# DWC 侧接口建议：src/dwc/evolution/lineage_scheduler.py
class EvolutionLineageScheduler:
    B = 8
    TAU = 6 / 8
    def __init__(self, lineage_sizes: dict[int, int]):
        self.N = lineage_sizes        # N_{i,g}: 每代环境数
        self.g, self.k = 1, 1
        self.hits = 0                 # 累积 r_{u,b}
    def observe(self, r: int) -> None: # r ∈ {0,1}: 单次 rollout 是否通过
        self.hits += r
    def p_hat(self) -> float:         # p̂_u(E) = (1/B)Σ r_{u,b}
        return self.hits / self.B
    def advance(self) -> tuple[int,int] | None:
        """论文式 2：(g_u, k_u) → (g_u+1, 1) 等三支"""
        if self.p_hat() <= self.TAU:
            return (self.g, self.k)
        self.hits = 0
        if self.k < self.N[self.g]:
            self.k += 1; return (self.g, self.k)
        self.g += 1; self.k = 1
        return (self.g, self.k) if self.g in self.N else None
```

这个调度器的关键可迁移性在于：**它不需要任何前沿模型**，只需要 8 次布尔观测。DWC 可以直接用它给自进化件排课——只有被试出 6/8 通过才放行下一代，避免生成一堆解不动的件（对应 DWC 门 4 的"淘汰判据可自动判定"）。

**③ Evolution Effort 三档 → DWC 的变异预算档位（结构可直接照搬）**

`low`（一个局部对）/ `high`（一个连续 span）/ `max`（不限片段）这个"作用范围"三档，与论文的 Table 1 结论直接配对：**`high` 是默认档**（因为它平衡了有效性与可控性），且 `length` 方向"用最小 mutation 拿到最强难度降幅"（−4.8 pp / Total 56.2%）。DWC 若要控制单轮改动幅度，可直接采用"局部对 / 连续 span / 不受限"三档，且默认 `high`。

**④ Oracle + Invalid-test 双验证 → DWC 门 2 的具体实现范式**

论文 Loop 2 的 (i)(ii) 是一对可直接抄的判据：既能过 Oracle、又能被空解卡住。这正是 DWC 门 2 反例（"`return True` 恒真"）的正面对照——

```python
# DWC 侧接口建议：src/dwc/quality/triple_gate.py
def accept_candidate(env, oracle_solution, no_op_solution) -> Verdict:
    ok_oracle = env.verify(oracle_solution)   # (i) Oracle 必须成功
    ok_noop    = env.verify(no_op_solution)   # (ii) 空解必须失败
    ok_rubric  = general_rubrics.check(env)    # (iii)
    if not ok_oracle:  return Verdict("reject", "oracle_failed")
    if ok_noop:        return Verdict("reject", "verification_trivially_passes")
    if not ok_rubric:  return Verdict("reject", "rubric_failed")
    return Verdict("accept", "all_three_passed")
```

**⑤ 跨方向回退规则 → DWC 的"修不好就换路"分支**

"randomly order the three directions ... The branch terminates only when all three directions fail"——这是**有限失败而非无限重试**。DWC 若有多个变异方向，可照此设"方向随机排序 + 单方向修复预算耗尽即换向 + 三方向全败才终止"，并在终止时把失败记入台账（对上门 7 静默可见门）。

### 不可迁移（写清为什么）

**① 整个 GRPO / 200 步 RL 训练栈。** 不可迁移。DWC 不训模型权重（按项目定位是记忆 + 自进化），且论文明确"Only the exploration-policy code changes; the underlying models, evaluator, and execution interfaces remain fixed"是其优势设计，而 DWC 没有 27B/35B MoE 级的 RL 基础设施（异步 GPU、staleness bound 5、R3 路由对齐）。**这不是"部分可用"，是零可用。**

**② 依赖闭源模型的全部环节（必须标注）**：
- **Claude Opus 5**：环境合成模型（对照实验中固定为它）、Table 1 难度变化测量（xhigh effort）、种子难度阈值 pass rate ≤ 4/8 的判定、Rollout 评估。**DWC 不具备同等模型条件。**
- **GPT-5.6 Sol**：rollout 评估（xhigh effort）。
- **Hy4 preview**：rollout 评估（high effort）。
- **Claude Code harness**：全部评测与 RL 训练的执行 harness。

具体影响：Table 1 的 −4.7/−4.0/−7.1 pp 这些数字**只在 Claude Opus 5 下成立**。换评估模型，pass rate 会整体平移，DWC 无法复用该表的绝对值。

**③ 47,678 → 127 → 500 的种子筛选规模。** 不可迁移（量级问题）。这条链依赖"strict rubric-based filtering"加上人工把 rubric 漏掉的问题回写成新 rubric。500 个已验证环境 × 15 代 = 7,500 个进化环境的构造成本，论文**未报告**该成本，因此 DWC 无法判断这条链是否在自己的预算内。**"论文未报告成本"本身就是不可迁移的理由**——DWC 门 6（加减平衡门）不允许引入成本不可测的能力。

**④ p_𝒯 的构造。** 论文只说"a deep-research agent can estimate both distributions through broad web search"，**未报告**具体协议（模型、检索源、概率如何从搜索结果导出）。DWC 若要实现 δ_θ，参考分布 𝒯 的构造是可复现性缺口——不能声称"照搬公式"就等于"照搬方法"。

**⑤ "15 代上限"这个工程约定。** 这是为 pass rate 度量分辨率做的妥协（进入 zero-pass regime 后测不出来），不是方法本身的性质。直接照搬 15 这个数字到 DWC 没有依据。

## 6. 与其他论文的关系

**在 RSI 图谱中的位置**：这是 **Agent–Environment Co-Evolution 范式的第三条路线**，且论文自己画了 Figure 1(a)(b)(c) 做范式定位。三者的区别在论文的定义里是清晰的：
- **Environment Ensemble**（Fig 1a）：通过组合若干困难原语环境得到新环境——**组合式**，难度来自规模。
- **Agent–Environment Co-Evolution**（Fig 1b）：在原语环境上 rollout 目标 agent，填充 **weakness bank**，据此构建新环境——**依赖目标策略**。
- **Environment Evolution**（Fig 1c， 本文）：**evolver 用推导出的难度信号沿 lineage 逐代产出后继环境**——**不依赖目标策略**。

**前序**：论文把自己接在 POET（Wang et al. 2019/2020）与 UED（Dennis 2021, Jiang 2021/2022, Parker-Holder 2023）之后，明确批评它们"require a designated agent to estimate environment difficulty through on-policy rollouts, and the resulting environments are related to both the rollout agent and the initial environment distribution"。它也直接引用了近期 LLM 侧的共演化工作（GenEnv、CoEvolve、SPADE、EnvGen、AgentGen、COvolve、WebRL）作为被超越的对象。

**同一作者组的连续工作**：种子筛选用的 **SkillSynth**（Fan et al. 2026, arXiv 2604.25727，"Toward scalable terminal task synthesis via skill graphs"）是本文作者的前作，负责"从零合成"那一段；本文负责"逐代进化"那一段。**两篇正好互补**——这正是 DWC 上一轮世界模型论文踩过的坑（读了不落地）的反面：一个完整 pipeline 被拆成"合成 + 进化"两篇，各自都能验证。

**与 2608.10299（Co-Evolution in Agentic Systems 综述）的关系**：该综述提出三阶段 taxonomy（Agent–Agent → Agent–Environment → Meta Co-Evolution）。**本文精确落在第二阶段**，并且是该阶段"Agent–Environment"的代表性实证之一。综述提到"keeping increasingly autonomous evolutionary processes safe and controllable"是开放挑战——**本文没有触及安全性**（没有护栏、没有对抗压力测试），这是它相对第三阶段的缺口。

**与 2603.25111（SEVerA）的关系**：互补且部分竞争。SEVerA 用 **FGGM**（Formally Guarded Generative Models）+ 一阶逻辑契约给 planner LLM 的每次模型调用加保证，用 rejection sampler + verified fallback 保证输出满足契约。**本文的 Loop 2 三 verifier 是同类思想的 LLM 版本但无形式化保证**——SEVerA 追的是"形式保证"，本文追的是"工程门控"。若 DWC 同时要看这两篇，应优先 SEVerA 的形式化路线。

**与 2609.13406（GAI，Generalized Agent Iteration）的关系**：**最强的理论对接点**。GAI 的两个"dial"是"the improving mechanism is part of the agent"与"the standard it is measured against is grounded outside it"。本文的方法恰好站在一个特定格子上：
- 改善机制（evolver harness）**在 agent 之外**（是环境构造器，不是被训练的策略）；
- 测量标准（difficulty 的三因子）声称是 **grounded outside**（在 𝒯 的世界知识里，不在 θ 里）——但这是**论文的主张而非验证过的结论**。

按 GAI 的框架，本文的严格自举版本（同一模型既造环境又从环境学）**正是 Appendix A 承认尚未报告的那一项**。这说明本文当前的自我定位是"外部机制驱动的迭代改进"，而非完整 RSI。

**与 2609.24972（RRSI）的关系**：RRSI 关心的是 harness 组件级编辑的**过拟合**（in-distribution 增益大、OOD 缩小），用 temporally annealed budget + critic + pruner 正则化。本文的做法在某个维度上是**反向的**——它通过"只用 held-out 基准 Terminal-Bench 2.1"来防过拟合，但环境演化本身是从种子分布**继承**并**收窄**的（后代围绕原环境分布做变异），多样性靠"introducing diverse variations around the original environment distribution"一句话带过，**未做多样性度量**。两篇合起来看：RRSI 管"组件编辑别过拟合"，本文管"环境供给别枯竭"，DWC 若两者都要，需要自己补多样性度量。

**与 2607.12790（本批次第三篇）的关系**：**互补，且都指向同一个缺口。** 本文的环境演化解决"环境供给"，2607.12790 的 Double Ratchet 解决"评估供给"。两篇有一个共同的隐含前提：论文 1 假设 verifier 可靠（三个 verifier 门控），论文 3 则证明**评估器本身会塌缩成 always-pass**，且"downstream task performance cannot validate a self-evolved evaluator"。**即：如果 2607.12790 的结论成立，本文的三个 verifier 也需要被一个"不会被 gamed、且自身被外部审计"的机制保护。** 这是 DWC 把两篇并读的最强理由。

**与 2609.14858（Dream-RSI，本批次第二篇）的关系**：**方向相反但结构同源。** 本文沿着**环境难度**这条轴做递归（环境逐代变难），Dream-RSI 沿着**探索策略**那条轴做递归（探索代码逐代变好）。两者的共同结构是"离线评估 + 在线部署"的分离：本文的 EL Scheduler 是离线产谱系、在线按阈值放行；Dream-RSI 的 replay simulator 是离线造世界、在线检验策略。两者的差异在**真值来源**：Dream-RSI 的 replay score 用任务自身的评分 s_v（系统外真值），本文的难度用 p_𝒯（声称系统外但构造未报告）。
