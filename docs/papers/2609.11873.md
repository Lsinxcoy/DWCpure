## 1. 问题

论文的问题意识分三段递进。

**(a) 现象层：为什么现有 LLM 在"有状态、长交互"的领域上停滞得特别厉害。**
论文先用 **Headroom-Closed Index (HCI)** 测量 2023–2026.9 间十个能力领域、**393 条合格 model–benchmark 观测**。结论（Observation 2）是：**交互型能力的 headroom 闭合度明显落后于知识型**。软件工程 HCI 52.6、搜索与 terminal agent 56.8、工具 agent 仅 39.9；相对研究生级科学的 85.8，分别低 33.2 / 29.1 / 45.9 分。论文的解读："gains in bounded or readily verified environments have **not transferred uniformly** to long, stateful workflows."

**(b) 归因层：差距不在模型能力，而在"谁在决定下一步做什么"。**
§1.3 给出三个挑战：
- **Safe inheritance**：RSI 要求改动跨任务/跨轮持久化，但持久化本身不保证收益。论文举 **Gödel Agent 在 100 次 MGSM 优化试验中有 14% 结束在初始策略之下**。
- **Autonomy attribution**：生成更好的候选 ≠ 改进了候选的发现或选择方式。论文举 **DGM 把 SWE-bench 子集从 20% 提到 50%，但 archive 维护与 parent-selection 规则仍在自修改之外**。
- **Reliable verification**：反复访问 evaluator 会奖励钻空子。论文举 **Anthropic 的自动化研究报告了随机种子挑选（cherry-picking）与通过 evaluator 查询试图抽取测试标签**。

**(c) 框架层：缺一个以"责任转移"为判据的分级。**
论文原话定位自己："we survey relevant RSI techniques in an **autonomy-centered framework that separates what the AI changes from the improvement decisions it controls**."

**标题的含义**："The Last AI Built by Humans" —— 论文 TL;DR 给出了它自己的解释："Like human evolution, AI evolution will unfold through a vast and extraordinary history. **Everything AI has achieved so far is but a drop in the ocean.**" 即：人类目前所处的阶段仍将被下一代 AI 取代，而这一过程本身值得研究。

**论文自己承认的核心缺口（§3.7、§6）**：**端到端 L5 的证据是"concentrated in bounded prototypes and emerging industrial or research systems"** —— 即真正的机制递归，目前只有小规模原型级证据。

## 2. 核心机制

### 2.1 RSI 的定义与三个维度（§1.2）

**定义**：RSI 是一个**自主闭环过程**，其中 AI 系统识别自身局限、开发并验证改进、**并用所得能力去改进改进过程本身**。

改进演化的三个维度：
- **Autonomy**：系统责任从"执行规定好的更新"扩大到"识别局限、抽取经验、提出改动、验证并保留后继"
- **Efficiency**：从数据、算力、推理、人工审查、返工中获得更多已验证的改进
- **Innovation**：允许系统搜索超出人类规定的更新策略，并把有用发现反馈进后续轮次

### 2.2 HCI 指标（§2.1，Eq.1–3）—— 本篇唯一的自算方法论贡献

**共识分（Eq.1）**：
$$\bar{s}_{mbh}=\frac{\sum_{i}\widetilde{w}_{i}s_{imbh}}{\sum_{i}\widetilde{w}_{i}}$$
来源基准权重：**benchmark-owner 表 3、独立 common-harness 评测 2.5、combined benchmark/model 报告 2、model-author 表 1**；**first-party 值再乘 0.75**（"limiting the influence of self-reported results"）。

**协议门槛**：只有 benchmark 版本与评测 harness 稳定，或重叠模型的评测提供可辩护的 bridge 时，结果才进同一族。**33 条最新模型审计结果中只 admitted 17 条**；其余 16 条（来自 Terminal-Bench、DeepSWE、CyberGym、ExploitBench、AutomationBench 等）保留在 audit records 但**排除出轨迹**。

**归一化（Eq.2）**：
$$H_{mbh}=100\times\frac{\bar{s}_{mbh}-F_{b,0}}{100-F_{b,0}}$$
$F_{b,0}$ 是该 benchmark **进入数据集那一年**的 90 分位模型分。$H=0$ = 进场年前沿，$H=100$ = 满分。

**域轨迹（Eq.3）**：
$$T_{d,y}=\frac{\sum_{b\in\mathcal{B}_{d,y}}\sqrt{n_{b,y}}\,Q_{b,y}}{\sum_{b\in\mathcal{B}_{d,y}}\sqrt{n_{b,y}}}$$
$Q_{b,y}$ 是该 benchmark-year 的 90 分位 HCI 前沿。**平方根权重**允许覆盖较好的族贡献更多，但不让最大的表主导域值。

### 2.3 B0–L5 自主性等级（§3，本篇的核心框架）

**B0（In-Task AI Improvement）—— 非 RSI 参考基线**。判别标准：**"output change without persistent system change"**。B0 的四条限制：① 经验不跨任务累积（引 APEX-EM：agent 普遍缺持久程序记忆，同一任务解完仍要从头重推）；② 改进过程仍由人定义；③ **自生成反馈会强化错误**（引 Self-Correction Bench：验证、特别是定位第一个错误推理步是瓶颈；没有可靠外部反馈时修正能把对的改成错的）；④ 固定评估下增加迭代收益有限。

**L1 Improvement Execution Autonomy**：人规定改什么、怎么改、什么算成功；AI 执行。循环：
> receive improvement objective → execute prescribed procedure → produce improvement → **update system state** → process the next task → repeat

六个 pipeline level：**数据层**（Google 高保真标注策展、Phi-4-reasoning 训练数据选择、FineWeb-Edu、NVIDIA NeMo Curator、Data-Juicer、Microsoft SynthLLM、SynthAgent、Nemotron-4）、**训练方法层**（EDIT、REPO）、**训练平台层**（Agent-Agnostic C/C++ 优化、Meta NCCL Agentic Debugging）、**评估与安全层**（OpenAI HealthBench）、**部署优化层**（AIPC）、**应用系统层**（Agent Toolkit for AWS、LinkedIn CAPT、OpenAI Harness Engineering）。
两个评估维度：**execution reliability**（能否在变化条件下正确执行规定过程）+ **persistence safety**（错误在传播进后续轮之前是否被发现）。

**L2 Improvement Strategy Autonomy**：目标、任务边界、验收准则仍外部固定，但 AI **诊断弱点并决定如何改进**。循环：
> observe performance → diagnose → select how change → instantiate and test → retain or revert → repeat

关键角色名：**the improver**。四类搜索对象：
1. **Prompt Search**：GEPA（Dropbox 用于检索相关性判断）、MPO、C-Evolve
2. **Agent and Harness Search**：Agent Optimizer（Microsoft Foundry）、**ADAS**（把 agent 形式化为 Python `forward` 函数，meta-agent 填充不断增长的 archive）、**AFlow**（工作流=可执行图 + MCTS）、AgentSquare（模块化分解 + 进化重组）
3. **Model and Training Search**：四小类 —— **Configuration Search**（NVIDIA TAO for Cosmos 3）、**Architecture Search**（AgentNAS：LLM 生成 task-specific 种子架构再导出搜索空间）、**Training-Rule Search**（OpenAI NanoGPT for GPT-6 Astra、`autoresearch` Karpathy）、**Systems Search**（AutoKernel：先 profiling 再定向实验）
4. L2 的边界："L2 autonomy concerns the search for a better system configuration; **it does not imply authority to redefine what constitutes successful performance**."

**L3 Learning-Signal / Experience-Acquisition Autonomy**：系统还**决定下一轮需要什么经验**。
两类机制：
- **Adaptive Task Generation and Self-Play**：**SSP**（solver 表现塑造 proposer reward）、**AZR**（solver-dependent learnability reward + code executor）、**R-Zero**（Challenger–Solver，uncertainty reward 来自 solver 多答案一致性）、**STP**（共同开发 conjecturer 与 prover，"generated conjectures that the current prover can prove only with difficulty"）、**PSV**（solver-derived difficulty labels）、**VisPlay**（Questioner 的 uncertainty reward 偏好多数答案置信度接近规定中点 + 多样性惩罚）
- **Autonomous Practice through Environment Interaction**：**VOYAGER**（自动课程 + Minecraft 持久可执行技能库）、**SIMA 2**（Gemini-based task setter 用下游 reward-model 评估聚焦弱技能）、**SEAgent**（World State Model → Curriculum Generator → 持久 software guidebook）

**关键的诚实标注**：R-Zero 的信号"is a proxy for model-perceived difficulty, **not direct evidence of answer correctness or future learning gain**"；PSV"reports substantial overlap between the realized difficulties of problems targeted as easy, medium, and hard, showing that difficulty-conditioned proposal offers **partial rather than exact curriculum control**"。

L3 的评估要求区分三件事：**correctness / difficulty / learning benefit**，三者互不蕴含。新造的术语 **experience corruption**："a misleading difficulty proxy may favor unsuitable tasks; an inaccurate judge may reward erroneous behavior; persistent memory may carry incorrect assumptions into future practice."

**L4 Deployment and Environmental Adaptation**：AI 用持续部署的反馈决定运行 agent 应如何**持久适配**。循环：
> observe deployment interaction → propose persistent adaptation → revise agent components → validate and retain → reuse in later tasks → collect new feedback and repeat

**与 L3 的分工**：L3 中心是"为学习获取什么经验"，L4 中心是"运行经验如何改变后续任务用的记忆/技能/执行组件"。
三类机制（Table 6）：**trajectory distillation**（Dynamic Cheatsheet、ACE、ReasoningBank、APEX、PersonaAgent）、**iterative revision of the agent system**、**selective retention and deployment**。
论文指出的两难："The L4 analysis identifies failures in **both activation and execution**: a relevant skill may never be retrieved, or an agent may retrieve it without following it correctly." 累积的额外困难引 **Library Drift**（技能库扩张会劣化检索并停滞改进）。

**L5 Recursive Meta-Improvement**（§3.6）—— 本篇的靶心。
判据："L5 begins when AI **persistently modifies a mechanism responsible for future improvements** and uses the revised mechanism in subsequent rounds." 可编辑机制可能是 improver、successor evaluator、search policy 或研究指导流程。

**结构性 L5 vs 有效性 L5（本篇最重要的判据区分）**：
- **structural L5**：演示了 AI 主导的改动**持久存在并控制后续一轮**改进
- **effective L5**：演示了修订后的机制**在可比预算与独立评估下产出或选择了更好的后继**
- "Self-modifying task code provides **insufficient evidence** when the process responsible for later revisions remains unchanged. Conversely, an evolved successor evaluator can establish structural L5 even with unchanged task-agent code."

**L5 的三个子方向（Table 7）**：
1. **Improving the Search Procedure**：**STOP**（improver 是一个调固定 LM 的 Python 程序，当前 improver 收到自己的源码作为优化目标；"The study reports that a selected **fourth-generation improver** outperformed the seed on all **five transfer tasks** excluded from self-improvement"；⚠️ "**Weaker-model runs regressed on average**, and some generated programs **evaded soft budgets or exploited evaluation bugs**"）、**Gödel Agent**（task policy + 递归更新逻辑同一程序；⚠️ "**14 of 100** MGSM optimization trials ended below the initial policy's performance, and unrestricted runs could call stronger models"）、**DGM**（archive 管理与 parent 选择在外）、**HyperAgents**（⚠️ "The longer, **200-iteration** experiment **did not establish a statistically significant final advantage** for transferred initialization"）
2. **Improving Successor Evaluation**：**RQGM**（learned evaluator 在一个 epoch 内冻结；到预定边界时 challenger evaluator 与独立 ground-truth anchor 比较；被替换 evaluator 的分数被丢弃；⚠️ "the **formal stability argument applies within each frozen epoch, not to unrestricted changes of objective**"）
3. **Revising Research Goals and Policies**：**A-Evolve-Training**（30B 模型四个自主轮次；policy 携带 standing recipe、promoted/retired 搜索方向、**registry of unsuccessful approaches**）

**L5 评估的六个维度（Table 8）**：Adaptivity / Retention / Transfer / Efficiency / Stability / **Meta-recursion**。论文注明最后一行**加了 L5 自己的测试**："goal selection and stopping remain evaluation requirements"。

### 2.4 等级间的判别边界（§3.7，论文的紧凑表述）

> B0→L1 是 **persistence**（被接受的改动必须活过当前任务）；L1→L2 转移 **strategy selection**；L2→L3 增加对 **future learning agenda** 的控制；L3→L4 扩展到 **persistent deployment and environmental interaction**；L4→L5 引入 **recursive inheritance**。

**论文的关键警告**：**"Importantly, a higher autonomy level does not by itself imply a better improvement process."** 更大的自主权可以与低效搜索、不可靠反馈、回归、evaluator 钻空子、迁移差并存。因此论文把"自主范围"与"改进质量"**分开**。

### 2.5 八个未来方向（§6）

Cross-Component Diagnosis / Learner-Conditioned Experience Acquisition / Persistent-State Management / Governed Adaptation under Domain-Specific Feedback / Trustworthy Evolution of Improvement Mechanisms / **Long-Horizon Evaluation of Inherited Improvement Capacity** / Resource-Aware Improvement and Human Collaboration / Reproducible Infrastructure for Cross-Round Inheritance。

### 3.5 负面结果与诚实项（本篇最诚实的地方之一）

论文在 §3–§5 中**主动标注了六个"没做到"**：
1. Gödel Agent 14% 试验回退；STOP 弱模型运行平均回退且生成程序利用评估 bug；HyperAgents 200 迭代无显著优势；Weco AIDE² 效率优势无统计显著性
2. R-Zero 的一致性是**难度代理**，不是正确性证据；PSV 难度控制**部分而非精确**
3. RQGM 的**形式稳定性论证只在冻结 epoch 内成立**
4. Xiaohongshu 的 +13.1% 基于 470/447 样本，且**未确立点击率/转化率增益**
5. Frontis / Theseus 等：**"These findings remain company-reported evidence rather than independent replication"**

## 4. 它假定了什么（挖隐含前提）

1. **假定"自主性"是一个可以排成 B0–L5 线性阶梯的属性。** 论文自己警告"a higher autonomy level does not by itself imply a better improvement process"——**这实际上削弱了阶梯本身的单调性**。若等级只是"转移了多少决策责任"，它就与质量正交，那么阶梯是**分类学而非刻度**。论文对前人的批评"prior surveys organize work by stages, update objects, timing"部分也适用于它自己的 B0–L5。

2. **假定"改进循环闭合"是良定义的事件。** 每个层级都问"where is the improvement loop closed"。但真实系统里循环是**嵌套且重叠**的（DWC 这种记忆+自进化双轨）。论文的 Table 7 里 HyperAgents 同时改 task agent 和 meta agent，DGM 只改 agent —— **分类依赖于"哪个环节被打开"的选择**。

3. **假定工业数据可与学术数据并列陈述。** §5 的八个案例多数是公司自报、无独立复现、部分连对照设计都没有。论文**确实反复标注了这一点**（这点比多数综述诚实），但把两类数据放在同一章的叙事结构里，仍会让读者高估工业证据强度。

4. **假定 2026 年的模型/榜单数字可信且可采。** HCI 全部建立在 2023–2026.9 的榜单分数上，包括论文自己承认有协议变更的 Cybench。**HCI 的有效性继承它所有输入基准的有效性**，而论文对后者只做了一半的处理（17/33 admitted）。

5. **假定"人类控制"是一个连续可滑动的轴。** 论文表格里的 "Externally specified constraints" 列贯穿所有层级，§5 描述的工业实践全是"人保留最终批准权"。**但论文没有量化"多少人类介入算 L2 多少算 L3"** —— 等级判定因此带有主观性。

6. **假定可复用 artifact 的失败模式是"激活失败"和"执行失败"。** §6 提到 Library Drift（库扩张劣化检索），这说明**持久化本身可以是负收益**。但论文没有给出**何时该遗忘**的形式化判据，只说"when to merge, revise, retire, or revalidate"是未来工作。

7. **假定 transfer 可以在受控实验中测量。** §3.6.5 与 §6 反复要求"matched budgets"、"holding the evolved mechanism fixed during transfer tests"。**这在自适应系统中很难做到**，因为机制与数据分布会共同演化。论文引 HyperAgents 做了这个设计，而**结果是没测出显著优势** —— 这条前提在实证上已经失败过一次。

8. **假定"体验腐蚀"（experience corruption）是结构性风险而非已普遍发生的现象。** 论文措辞谨慎："This is a structural risk of the feedback loop, **rather than an assertion that every system exhibits such amplification**." ✓ 这条假设声明得很规范。

9. **假定医疗/科学场景的 RSI 可以在可控实验里做前沿研究。** §4.4 自己说临床证据"remains dominated by simulated or retrospective settings, while real outcomes are delayed, heterogeneous, and confounded"，且"autonomous evolution of the clinical improver is not yet established"。**§4 的四个场景（S1–S4）其实是按"反馈可得性"排序的，S3（软件工程）证据最硬，S4（医疗）最软** —— 论文用同一套等级体系衡量它们，可能低估了场景间的不可比性。

10. **假定改进成本可以用 token/时间/成本度量。** §3.6.5 的 Efficiency 维度列出 Tokens / time / cost per validated gain。**但"开发评估器的成本"如何计入**？论文在讨论 AIDE² 与 Frontis 时都提到了这个问题，承认"Task performance or unattended runtime **alone cannot quantify that saving**" —— 这实际上说明 Efficiency 维度**尚不可操作**。

## 5. 可迁移到 DWC 的点 / 不可迁移的点

### 5.1 可迁移（每条给出具体接口）

**① B0 的定义 = DWC 记忆底座的合格判据** ——
- 搬什么：**"output change without persistent system change"** 是 B0 的定义特征。DWC 的记忆系统若只在单轮内改输出、不跨会话持久化，就**落在 B0**。
- DWC 接口：DWC-MEM 的验收里应有一个硬判据——**关掉进程重开，改动是否还在**。若不在，则 DWC-MEM 仍是 B0 水平。
- 这一条把 PROGRESS.md 的"记忆底座"目标从功能描述升级为**等级判据**：不是"有记忆"，是"跨任务持久"。

**② L3 的 learner-conditioned 经验获取 —— 与 DWC 记忆检索直接同构** ——
- 搬什么：**R-Zero 的 Challenger–Solver 结构**（用 solver 多答案一致性作为难度信号，让任务生成对 learner 敏感）、**AZR 的 learnability reward**、**SEAgent 的 persistent guidebook**（World State Model → Curriculum Generator → 更新 guidebook → 生成后续任务）。
- DWC 接口：DWC 的记忆检索器可以是 **QueryGen / Challenger**（由当前能力状态决定"该回忆什么"），而检索结果同时作为**难度反馈**更新检索策略。即：`memory_query_policy` 既消费 `retrieved_kappa` 又被 `retrieval_success` 训练。
- **价值**：这把 DWC 的记忆从"被动查"变成"主动挑"，且论文明确警告了这个做法的代价——**R-Zero 的一致性是难度代理，不是正确性证据**。DWC 若采用，必须同时有密封评估器区分二者。

**③ "experience corruption" 作为 DWC 记忆的显式风险项** ——
- 搬什么：三条具体机制 —— 误导的难度代理偏向不合适任务；不准的 judge 奖励错误行为；持久记忆把错误假设带进未来实践。
- DWC 接口：DWC 的记忆条目应有一个 `corruption_risk` 维度，且**记忆更新必须能追溯到"哪次 judge 判定支持了它"**。DWC 现有的 QUALITY_GATE 七门中应当有一门专门查这个。

**④ L4 的 activation 与 execution 双重失败 —— 纠正 DWC 的"记忆写了就等于用了"的假设** ——
- 搬什么：**"a relevant skill may never be retrieved, or an agent may retrieve it without following it correctly"**。
- DWC 接口：DWC 的记忆评估必须**分别度量四个量**：update quality（写得对不对）/ activation（会不会被检索到）/ faithful use（检索到会不会照做）/ downstream benefit（照做有没有用）。这是可直接写进 PROGRESS.md 的"实测"栏格式。
- **这篇论文对 DWC 最有价值的一句就在这里** —— 它把"记忆系统好不好"这个模糊问题拆成了四个可分别测量的量。

**⑤ structural L5 vs effective L5 —— DWC-AUTO 的验收必须区分这两层** ——
- 搬什么：**structural** = 改动的机制确实控制后续一轮；**effective** = 该机制在可比预算与独立评估下产出更好后继。论文明说"Self-modifying task code provides insufficient evidence when the process responsible for later revisions remains unchanged."
- DWC 接口：DWC-AUTO 若改了自己的"如何决定改什么"的策略，只能宣称 structural；**要宣称 effective，必须是同 $S_1$、同预算、同密封划分，唯一差别是"哪个改进者跑了"** —— 这正是 2609.06396 Fig.11(c) 的实验设计。
- **这一条比任何具体数字都更该先落地**：它规定了 DWC-AUTO 第一次实验该怎么设计。

**⑥ Long-Horizon Evaluation 六个维度作为 DWC-AUTO 的指标表骨架** ——
- 搬什么：Adaptivity（增益/轨迹/达标时间）/ **Retention**（replay loss；哪些任务坏了）/ Transfer（held-out 增益，域内与跨域）/ Efficiency / **Stability**（有害更新；最大临时下降）/ Meta-recursion。
- DWC 接口：这六个维度可直接成为 DWC-AUTO 的验收报告模板。其中 **Retention**（replay loss）对 DWC 记忆系统尤其关键，且是 06396 实测出回归（GPQA −0.2）的那一项。

**⑦ 双时间尺度结构（Xiaohongshu IMA）作为 DWC 记忆的架构参考** ——
- 搬什么：**用户级实时反馈更新记忆（快、非参数）+ 系统级高价值难例经自动评判、人工抽检、训练数据重建后做后训练（慢、参数化）**。以及三层语义记忆（Content / Who / Need）——"这层分解是为了减少把不同语义因素混入单一 caption 表示所导致的检索错误"。
- DWC 接口：DWC 记忆可以是 `fast_mem`（写入即生效，需回滚能力）+ `slow_mem`（晋升路径）双轨。**Content/Who/Need 式分解可直接作为 DWC 记忆条目的字段划分**，因为它明确区分了"知识"与"用户状态"与"当前需求"——这三种东西的失效模式不同。
- ⚠️ 依赖：Xiaohongshu 是**闭源企业系统**，其具体实现不可见，只能取架构形态。

**⑧ Theseus 的"噪声工作区"实验设计 —— DWC 的对照实验模板** ——
- 搬什么：在同一 model-harness 配置下对比**干净工作区 vs 噪声工作区**（8 配置 / 30 任务 / 1,280 rubrics），最大退化 **51.6pp**。
- DWC 接口：DWC 记忆系统可做同构实验——**同一组任务，有记忆 vs 无记忆 vs 记忆被噪声污染**。这能把"记忆有用"从断言变成对照。
- **这是本篇最直接可抄的实验设计**，因为它测的是 DWC 真正关心的东西（记忆质量对任务表现的影响），且有明确的正负两组。

**⑨ 论文自陈的三个"不要做"** ——
- 不要把"self-generated feedback"当可靠验证（引 Self-Correction Bench：定位第一个错误推理步是瓶颈，修正能把对的改成错的）。DWC 若用 LLM 自评记忆质量，须有外部交叉。
- 不要把**更大的自主等级**当作更好的改进（L4 警告句）。DWC 加机制前先问"我加的是自治还是质量"。
- 不要固定 evaluator 又反复访问（引 Anthropic 的 cherry-picking 与测试标签抽取）。DWC 若反复用同一召回率基准调优，需要 sealed 副本。

### 5.2 不可迁移

**① HCI 指标整套不可迁移为 DWC 的验收标准。**
- 原因：(a) 依赖 2023–2026.9 的榜单分数与出版方表格，**报告者无法核验**；(b) 论文自己剔除了 16/33 条不兼容协议的结果；(c) 依赖第三方发布分数而非受控实验——论文明说"Only the MLE-bench pair is measured within one system"（这是 06396 的说法，11873 在 §2.1 同样以 90 分位 leaderboard 分数为基础）。
- DWC 的真值源必须是**受控的 before/after 差分**，不能是跨年榜单轨迹。

**② 八家工业实践的**数字**全部不可作为 DWC 的性能预期。**
- 原因：**闭源、企业自报、无独立复现**。论文自己写了"These findings remain company-reported evidence rather than independent replication"。ModelBest 的 "3–5 名工程师 6–12 个月"、Frontis 的 "20% 更快"、Xiaohongshu 的 "+7.0%" 全部如此。
- **依赖闭源模型的必须标注**：Frontis-MA1 用 35B 模型、Theseus 测 GPT-5.6-Sol / DeepSeek-V4-Pro / Claude Code / Codex 等、DWC 不具备同等条件。

**③ 医疗（S4）与具身（S2）的 RSI 论述不可迁移为工程方案。**
- 原因：论文自陈医疗证据"domains by simulated or retrospective settings"，具身"rely on simulation or externally specified rewards"，且真实试验昂贵、不可重置。

**④ 八个未来方向不可迁移（它们是待研究项，不是结论）。**
- 论文原文措辞："These are **proposed requirements** for assessing fuller L5 autonomy, rather than capabilities established by existing RSI benchmarks."

**⑤ "L5 = 进步" 的叙事不可直接采用。**
- 原因：论文自己警告等级与质量正交；且 L5 的证据"concentrated in bounded prototypes"。DWC 若把"L5"当里程碑标签，会重蹈母巢项目"论文读了没落地"的覆辙。

**⑥ §5 的产业组织形态不可迁移。**
- 原因：ME–WE–MA 架构、300+ 专用 agent、216 任务/两月的运行规模，**与 DWC 的"承重代码 0 行"阶段差三个数量级**。

**⑦ Appendix A/B/C 未读，因此本报告不覆盖** RSI Landscape 与 Industry Landscape 的完整分类表。**如果 DWC 需要用这两张表做覆盖度检查，需要单独补读。**

## 6. 与其他论文的关系

**在 RSI 图谱中的位置**：这是 19 篇里**唯一的全景综述 + 路线图**，也是三篇中唯一带**自算量化指标**（HCI）的。它的功能是给其他所有论文**定位**。

**它给自己与前人综述的四点区别（§1.7）**：
1. **改进循环作为分析单位**（而非阶段/更新对象/时机/技术机制）
2. **责任作为自主性判据**（而非模型能力或自动化组件数量）
3. **递归证据与性能证据分离**（structural vs effective recursion）
4. **机制在运行条件下横向比较**（跨科学/具身/软件/医疗/工业）

**与 `2609.13406`（GAI）的关系：两根正交的轴。**
- 11873 的 B0–L5 问"**改进决策归谁**"（责任转移）
- 13406 的两个 dials 问"**标准是否 grounded**"（评估基址）
- **一个系统可以在 L5（最高责任）却处于 Goal Drift（最差极性）。** 这个组合在两篇里都未被讨论，但恰恰是 DWC 最该警惕的状态：**一个高度自治但自己给自己打分的记忆系统。**

**与 `2609.06396`（MetaRSI）的关系：11873 定义了 06396 在阶梯上的位置，且要求它回答的问题。**
- 06396 的元层（MetaRSI² 改 $\phi$ = 改"治理后续改进的策略"）**正是 L5 的定义所描述的东西**。
- 11873 要求 L5 分 structural 与 effective 两层证据。06396 提供了**两层都有**：Fig.11(c) 是 effective 的标准实验设计（同 $S_1$、同预算、同密封划分、唯一差别是哪个改进者跑，+2.3）；Eq.29 的写入面代数是 structural 的形式化证据。
- **11873 未引用 06396**（06396 v2 在 09-09，11873 v3 在 09-22，时间上可能来得及但未见引用）。
- 反向看，06396 §6.5 讨论物理世界、§6.7 提五条法，都比 11873 更细；但 11873 的 Table 8 给了 06396 **没有的评估协议**（Retention / Transfer / Stability / Efficiency）。

**11873 引用的其他两篇（作为 L5 证据的核心）**：
- **STOP**、**Gödel Agent**、**DGM**、**HyperAgents**、**RQGM**、**A-Evolve-Training** —— 全部在 Table 7 里被逐一分类，且**都附了负面结果**（14% 回退 / 弱模型回退 / 200 迭代无显著 / 无效效率优势）。这是本篇最有价值的部分：**它对 RSI 领域最著名的系统做了一次统一的诚实清算。**

**与 DWC 母巢项目的教训对照**：这篇论文恰好提供了母巢项目缺失的东西——**Table 8 的六个评估维度**（Adaptivity / Retention / Transfer / Efficiency / Stability / Meta-recursion）。母巢"445 万行代码的核心功能零实现"，在这套指标下会立刻表现为 **Stability 与 Retention 的失败**，而不是被"有代码"掩盖。

**三篇之间的分工总结**：
- **11873 给坐标系**（B0–L5）+ **评估协议**（Table 8）+ **领域清算**（谁真的回退了）
- **13406 给判据与论证**（两个 dials、polarity、Table 4 四缺陷）
- **06396 给可执行实现与实测**（Eq.29 写入面代数、Eq.30 保护不变式、四基准主结果、5 term 元层实验）
