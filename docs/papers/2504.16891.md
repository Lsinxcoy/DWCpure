## 一句话总结

Kaggle AIMO-2（50 道从未上网的国家队赛题）冠军配方：**540K AoPS 题 → 3.2M 蒸馏长思维 CoT → 1.7M "训练-生成-过滤"三轮自举的工具集成推理（TIR）→ 566K GenSelect 选择样本**，SFT 出 1.5B/7B/14B/32B 四模型，私有榜 34/50。它**没有一处自主改进**（阈值、epoch、merge 系数全人写死）＝标准 **L1 执行人定程序（数据层）**，但"被改进的模型生成自己的训练数据"这环是两篇里离递归最近的形状。对 DWC 最可搬：**pass@k/maj@k 差距**（"不会"还是"挑错"）与**配额写进 prompt、超限即弃**。

## 核心方法（细颗粒度）

### 1. 数据准备（§2.1 · Table 1–3）

- **来源**：AoPS 论坛全量讨论，**唯独剔除 "Middle School Math" 版块**（"too elemen- tary and unhelpful for training"，断词照录）；全流程默认 **Qwen2.5-32B-Instruct**（"Throughout our pipeline, we utilize Qwen2.5-32B-Instruct [39] for all processing steps unless specified otherwise."）。
- **五步流水线**：① LLM 抽题（一帖可能 0/1/多题）→ ② LLM 四分类（证明/选择/二元/有效），"We remove all multiple-choice questions, binary questions, and invalid problems from the final dataset." → ③ **证明题转答案题** → ④ 从论坛抽**最终答案**（不抽过程）→ ⑤ 基准去污："we use an LLM-based comparison to remove ques- tions that closely resemble those in popular math benchmarks"（依 [41]）。
- **Table 1 逐格（漏斗）**：Original forum discussions **620K** → Extracted problems **580K** → Removing "bad" problems **550K** → Benchmark decontamination **540K**。
- **Table 2 逐格（组成）**：Converted proofs **260K** / With extracted answer **190K** / No extracted answer **90K** / **Total 540K**——**28% 的题没有真值答案**，靠后文"共识当真值"兜底。
- **Table 3 逐格（同类对比）**：OpenMathReasoning(ours) **540K** / AoPS-Instruct **650K** / NuminaMath-1.5(AoPS 部分) **68K**（表注注明与 [20][14] 为**并行工作**）。

### 2. 验证集 Comp-Math-24-25（§2.2 · Table 4）

- 从 AoPS 抓的 AIME + HMMT 题，**只取 2024/2025**："We restricted our selection to 2024 and 2025 com- petitions to minimize potential data contamination."；剔除证明题与按估计精度给部分分的题。
- **Table 4 逐格**：AIME 2024 **30** / AIME 2025 **30** / HMMT Nov 2024 **62** / HMMT Feb 2024 **68** / HMMT Feb 2025 **66** / **Total 256**。
- 另定义 **HLE-Math**：HLE 的 975 道纯文本 Math 子集（"We only evaluate on a subset consisting of 975 text-only problems from "Math" category. We refer to it as HLE-Math."）。

### 3. CoT 蒸馏（§2.3 · Table 5）

- 用 **DeepSeek-R1 + QwQ-32B** 对每题生成**至多 32 个候选解**（原文 "up to 32 solution candidates for each problem in our dataset"，前接 "gener- ate" 断词），参数：`temperature 0.7, top-p 0.95, 上限 16384 token`。
- **难题多产 + 过滤**：难度 = Qwen2.5-72B-Math-Instruct 32 次生成的平均 pass-rate，难题给更多配额；答案不达预期的解一律删，等价性由 **Qwen2.5-32B-Instruct 当 judge**（复用 [30] prompt）。
- **没有真值的题（含全部转制证明题）用共识当真值**（原文）："For each problem where we weren't able to extract the final answer (and for all converted proofs) we treat the most common answer across all available solution candidates as the ground- truth."（断词照录）——**多数投票 = 伪标签**。
- **Table 5 逐格（过滤后 / 全部）**：QwQ-32B **0.5M / 1.0M**；DeepSeek-R1 **2.7M / 4.2M**；**Total 3.2M / 5.2M**（过滤掉约 38%）。

### 4. TIR 四阶段（§3.1–3.4）——最核心的工程

- **为什么不能靠 prompt**（§1、§3）：对 R1/QwQ 直接下指令或给 few-shot 都失败，假设是模型"被推理任务训得太死、指令跟随曝光不足"（"We hypothe- size that these models struggle to deviate from their standard solution format due to extensive training on reasoning tasks and limited exposure to instruction- following."——断词照录）。
- **Stage-0（§3.1–3.2）**：抓手是"**少量推理数据微调的 instruct 模型会保留指令跟随能力**"——用 LIMO-Qwen-32B（依据 "fine-tuning on as few as 1000 samples is sufficient to make LLM produce long- CoTsolutions"，粘连照录）零样本产 TIR（约一半题含 Python 块），合成 **1.2M** 解（temp 0.7 / top-p 0.95 / 16384 token，**>8 次代码执行即停**）。
- **过滤器（§3.2）**：Qwen2.5-32B-Instruct 给每个代码块打两类标签——(a) **novel vs verification**（拿不准一律判 Verification）、(b) **significant/moderate/trivial**（能否几步 CoT 替代）；保留规则 "keep solutions that either have at least one novel and significant code block or more than half novel and moderate code blocks"；再删答案错的、无代码的、>2 代码块的（"We also remove solutions with more than two code blocks"），```` ```python ```` 标签换 ` tool` ⇒ **1.2M → stage-0 TIR = 15k**。
- **迭代自举（§3.3）**：轮 2 用 **QwQ-32B 在 stage-0 上训 7 epoch（lr 5e-6 常数）**当生成器，产 **700K → 260K**；**此阶段 novelty/significance 过滤器反而掉分故停用**（"We find that novelty and significance filters degrade the performance at this stage, so we do not use them."）。轮 3 换**中间版 14B**（先在纯 CoT 子集训过）再生成过滤 ⇒ **最终 1.7M TIR**。
- **代码配额控制（§3.4）**：数据生成时把"**还剩几次代码执行**"的警告注入生成内容，模型会在思考里主动遵守；每题**随机给 1–8 次配额**，"We remove generations that try to use more code blocks than requested in order to reinforce the correct behavior in training." ⇒ "model learns to follow specified code execution limit."。

### 5. GenSelect（§4 · Fig 2–3）

- **动机**："We observe a considerable gap in themajority@k vs pass@k performance for our models"（粘连照录）；"majority voting [34] serves as a strong baseline, its performance falls significantly short of the theoretical maximum performance of pass@k"；且多解放一起比显著好于孤立判（"comparing multiple solutions yields significantly better results than judging each solution in isolation"）。
- **不改架构**（依 [45]）：先自然语言推理再输出 `Judgment: [IDX]`（附录 C.3 三步法：①按答案分组揪矛盾 ②评精度/逻辑/完整性/边界 ③按效率/清晰度/稳健性比选）。
- **摘要重写（§4.1）**：R1 的 summary 可能只有一句话，故用 Qwen2.5-32B-Instruct 每解合成 4 个候选摘要（≤2048 token），答案不一致即丢、无有效摘要丢样本（"No more than 5% of all samples were discarded this way."）、取最长者，全数据集重刷。
- **训练数据（§4.2）**：每题抽 2–16 摘要且强制"至少一对我错"，重复到 8 组，由 QwQ-32B 执行选择 ⇒ **1M selections → 滤掉"选了错解"者 → 565K**。
- **推理成本（§4.3）**：比较轨迹也重写成干净摘要（D.1），只损 1–2%（"only a small reduction in accuracy (1–2%)"）；输出 ≤2048、16 解 ⇒ 输入 ≤32768。Fig 2 图注：GenSelect 输入取 64 里的 16 子集、最后对其选出的答案 majority@8；"GenSelect becomes unstable when using more than 32 generations as we can no longer show all solutions in a single prompt"。
- **口径差**：566K（摘要/§5.1/结论 "The total SFT dataset size is 5.5M samples (3.2M CoT, 1.7M TIR, and 566K GenSelect)."）vs §4.2 "filter down to 565K"——并存照录。


### 6. 训练（§5.1）

- 底座 **Qwen2.5-Base**（1.5/7/14/32B），1.5B/7B 从数学特化版出发（其上下文仅 4096，不够长思维）⇒ **RoPE base 改 500K**（依 [2]）。
- **一次 SFT**：6 epoch、三任务混合（CoT/TIR/GenSelect，各带专属 prompt 切换），与顺序训练等效（"training on a mix of all tasks results in a similar accuracy compared to training on each task sequentially"）；**总数据 5.5M**。
- 优化器：AdamW（weight decay 0.01）、cosine + 10% linear warmup、起始 lr **3e-4 (1.5B) / 2e-4 (7B) / 1e-4 (14B, 32B)**、终值小 1000 倍、**batch 1024**、NeMo-Aligner 序列打包 + 上下文并行、**存 4 个等距 checkpoint 做权重平均**。
- **第二次 SFT（难例子集）**：只取 Olympiad 版块题，"we discard any problems for which Qwen2.5-Math-72B-Instruct TIR model has a pass-rate bigger than 0.3 out of 32 generations"（**pass-rate>0.3 即弃**），且**丢掉 <5000 token 的解**；**2.2M** 样本、**4 epoch**（其余同首轮）；**除 32B 外都做**（32B 会掉分）。结论句："We find that CoT results tend to significantly improve while TIR results stay stable or slightly degrade."

### 7. Kaggle 冠军工程（§6）

- **赛制**：110 题（10 参考 + 公榜 50 + 私榜 50），"a 5-hour time limit in an of- fline Jupyter notebook environment powered by four L4 GPUs"，逐题作答难并行；"Our 1st-place submission correctly solved 34 out of 50 questions on the private leaderboard."（引言作 "which cor- rectly solved 34 out of 50 problems on the private test set"——questions/problems 并存照录）。
- **冠军配方（§6.1，与正式版不同）**：Qwen2.5-14B-Base 在 **2.2M 纯 CoT（仅 R1 解、剔转制证明题）**训 8 epoch → **15k stage-0 TIR** 轻调 400 步（lr 1e-5，取末 checkpoint 不平均）→ **线性 merge**（§6.2："Sur- prisingly, the most effective approach turned out to be a simple linear combination of the two checkpoints" = `CoT*0.3+TIR*0.7`，三列见 Table 10）；**GenSelect 训练与推理都没用**（"We did not use GenSelect training or inference for the Kaggle submission."）。
- **推理优化（§6.3）**：TensorRT-LLM（in-flight batching）、**W8A16与 FP8**、**ReDrafter**（每步 3 token，"all three tokens being accepted in approximately 65% of the steps"）；采样无差异 ⇒ 近贪心（"by setting temperature to 0 and enabling the redrafter_greedy_search parameter"）。
- **早停与预算**：16 个候选里 "if the first 4-5 completions agreed on the final answer, we canceled the remaining generations" 并砍尾部 straggler；每题基础 350s、共享 buffer 借 210s（上限 560s）；沙箱 6 次代码调用/生成、2s 超时、回显前 200 字符。
- **三条败因（§6.4）**：① 每天 1 次提交 + 公榜 50 题随机顺序 ⇒ 分数方差大，本地与榜单常不一致；② 没及时换小模型（7B 公开榜 ≈/≥ 冠军 14B）；③ 正式模型同预算分更高但**平均多产 ~10% token**，与计时逻辑冲突——"Not realizing this early enough, we were unable to fix this undesirable feature before the end of the competition."。

## 与 DWC 的映射

> 共享背景：DWC = 世界树(W1–W6) + judge 判分(C3') + δ 失败签名排序 + EL 调度(B/τ) + Dreaming 回放(K₂/β) + M>1 策略修订。

## 综述 L 定位

> L 框架（2609.11873 §3）：B0 任务内 / **L1 执行人定程序** / L2 自主选改法 / L3 自定学习议程 / L4 部署改持久态 / L5 改改进机制本身；structural = 改动持久并控制下一轮，effective = 同预算独立评估下产出更好后继。（原文："…structural recursion, in which a revised improvement mechanism governs a later round… effective recursion, in which that mechanism produces stronger successors under comparable budgets and independent evaluation."）

- **L 几：L1（Autonomy over Improvement Execution），落点 Data Level 与 Training-Method Level**。回综述核：f=2，两处**都在 §1.1**（*Scaling Burdens in Model Development*），**不在 Table 2（族×等级）/Table 3（L1 系统）**——grep `Moshkov`/`AIMO`/`OpenMathReasoning` 正文只命中 §1.1 两处 + 书目。引用语境：① 人工决策负担 "developers must still determine what to improve, construct the required resources, and establish whether each change works Moshkov et al. [2025], Meta Engineering [2026]."；② 数据成本 "while NVIDIA's AIMO-2 pipeline generated 3.2 million long-reasoning solutions and 1.7 million tool-integrated solutions, in addition to curating 540,000 problems Moshkov et al. [2025]."——**三个数字与论文 Abstract/§8 完全一致**。
- **技术族**：不属 Table 2 任何一族（该表列 Promptbreeder/AFlow/AgentNAS 等）；其族是**蒸馏数据合成 + 工具集成推理 + 生成式验证选择**，与 Table 3 的 L1 Data Level 同格——**综述引其数字做"负担"证据、未收进 L1 代表系统表，是收录缺口**。
- **自举 ≠ 递归**：虽用"被改进的模型生成下一轮数据"（15k→260K→14B→1.7M），但按 L1 "the procedures governing improvement remain externally specified"，过滤 prompt、阈值（0.3、>2 代码块、<5000 token）、轮数、merge 系数**全由作者手工指定**，每轮下一步由人决定（§3.3 "we repeat this process one more time…" 主语是 we）⇒ **L1 封顶，不到 L2**；**structural / effective L5 均不适用**（改过滤器的是作者 A/B，程序每轮由人重写）。
- **与 DWC 的关系**：DWC 现处 L4 形状 + L1 判据。三件可标定工具：① 难度阈值 0.3/32 采样换确定收益（Table 6）⇒ 支持 p̂/τ 口径；② pass→maj→选择器三层差距（76.3→86.7→90.0）⇒ M>1 只 argmax 连投票层都缺；③ **共识伪标签 + 保真过滤** 是 `SPLIT_TRAIN` 从"诚实边界④"走向可用的配方。要主张 effective 本文无对照预算实验，只给**该测什么**（maj/pass 差距、未完成率、merge 三列）。
