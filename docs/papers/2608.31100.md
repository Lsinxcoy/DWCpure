## 一句话总结

S3Gym 把"经验驱动的自我改进"拆成**可分别测量的三段**（Self-Testing 探索取证 → Self-Improvement 前的 Self-Judging 自评 → 用它改后续决策），用**七个带可执行 verifier 的文字游戏**做测试台：探索期**扣住 verifier 真值分**（agent 只能看到自己给动作打的 `s_i`），评估期换更严格且 held-out 的配置；三条经验通路（History ICL / Summary Memory / 参数 Training）同种子同预算对比，结论是**改进既不自动也不均匀**——摘要只在"经验能压成可复用规则"的域赢过原始历史，参数训练在 Trust Evolution 上 0→30、在 PvZ 上却 23→6 持续负迁移，而**自评准确率与下一步改进几乎零相关（ρ(A,g) = −0.010）**。

## 核心方法

### 组件与流程

```
R_t^(p) = Explore → Judge → Consolidate → Update p → Evaluate        (Eq.1)
   p ∈ {History, Memory, Training}
```

- **两种相位**：`C_exp_g`（宽松探索分布）与 `C_eval_g`（更严的评估分布），**随机种子不相交**，且"evaluation trajectories are not added to history, memory, or training data"。
- **逐步形式化**（§4.2）：
  - `O_{x,0} = Reset(seed_x, c_x)`（Eq.2）
  - `(a_{x,i}, s_{x,i}) = π_{θ_t}(O_{x,i}, H_{x,i}; Z_t^(p))`（Eq.4）—— 模型**同时产出动作和自评即时分**，`s` "represents the model’s estimate of the immediate reward associated with its proposed action under the game rules, rather than a free-form confidence score"
  - `(O_{x,i+1}, F_{x,i}, r_{x,i}, d_{x,i}) = Env(O_{x,i}, a_{x,i})`（Eq.5）—— **`F` 可见、`r` 扣住**："verifier-computed rewards are not exposed to the agent during exploration"
  - `H_{x,i+1} = H_{x,i} ⊕ Format(O, a, s, F, O')`（Eq.6）—— 历史里带的是**自评分**，不是真值
  - `y_x = Score(τ_x)`（Eq.7）—— episode 终分只用于 benchmark 评测
- **经验整合**（§4.3）：History = `C_{t+1} = Serialize(C_t, T^exp, S^exp)`（Eq.8）；Summary = `M_{t+1} = Summarize(M_t, T^exp, S^exp)`（Eq.9），且摘要固定三槽 `M_{t+1} = (R_retain, R_avoid, D_next)`（Eq.10）= 保留策略 / 要避的错 / 下轮具体方向。
- **三条通路**（§4.5）：`Z^(History)_{t+1} = C_{t+1}`（Eq.14）· `Z^(Memory)_{t+1} = M_{t+1}`（Eq.15）· `D^SFT_t = BuildSFT(T^exp, S^exp)` → `θ_{t+1} = SFT(θ_t, D^SFT_t)`（Eq.16–17），高分动作留作正例、低分动作被过滤或替换成修正动作。**"All pathways start from the same base model and use the same exploration seeds, evaluation seeds, interaction budget, and decoding settings."**
- **指标**（§5.2）：`Avg`（Eq.18，跨 checkpoint 均值）、`Max`（Eq.19）、`AUC+ = ∫₀³⁰ max(0, y(x) − y₀) dx`（Eq.20，checkpoint 间线性插值）；原文警告 "rawAUC+ values should be comparedwithin the same game, rather than directly across games"（`rawAUC+`、`comparedwithin` 为提取粘连，按原样保留）。
- **自评可靠性指标**（§6.2）：`Agree = (1/N) Σ 1[1(s>0) = 1(r>0)]`（Eq.21）、`NMAE`（Eq.22，按各游戏 min–max 归一后取平均绝对差）、over-confidence `Pr(s>0, r≤0)` / under-confidence `Pr(s≤0, r>0)`；`g_t = (y_t − y_{t−3}) / (max_{g,τ} y − min_{g,τ} y)`（Eq.23）用于算 `ρ(A_t, g_t)`、`ρ(−E_t, g_t)` 与最高/最低自评质量三分位的增益差。
- **NABA** = `AUC+ / max(y₀, ε)`，用于跨模型同游戏的持续改进比较。

### 运行配置（Table 3 逐格）

History-ICL 输入上限 **100,000 tokens**；单次输出上限 **14,000 new tokens**；controller 每 episode **64 steps**；探索预算 **30 episodes**；**每 3 个探索 episode 评一次**；每检查点 **3 条 strict-mode episode**；检查点 `x ∈ {0,3,6,…,30}`。

### 验收规则（它自己立的隔离合同）

1. 探索期扣真值、评估期才揭盲——使 `s_i`（自评）与 `r_i`（真值）可对齐比较，同时不让真值引导决策。
2. 评估轨迹**永不回流**进 history/memory/training。
3. 三条通路同底模、同探索/评估种子、同预算、同解码设置。
4. 共享回答契约：`Answer: <ACTION>, Score: <SELF-JUDGED SCORE>.`；判终局则 `Answer: END, Score: 0`。
5. Table 1（与 7 个既有 benchmark 的对比）里 S3Gym 是**唯一** Self-Testing ✓ 且 Self-Judging ✓ 两列都打勾的；原文自评："none couples self-testing with explicit self-judging under executable environment verification"。

### RQ1 — 参数训练（Qwen3-8B，20 个 checkpoint，无任何 context 通路）

- **Trust Evolution**："The score rises from 0 to a maximum of 30 and remains above the initial baseline at 18 of the 19 updated checkpoints. The post-training average reaches 8.684 andAUC+ reaches 163.5" —— 论文称其为"the clearest evidence that interaction-derived strategies can be internalized into model parameters"。
- **Chess**：多数 checkpoint 为 0，末点 "reaches 0.0667"（稀疏但为正）。**Snake**：epoch 8/12/15 得 1 分随后回 0 ⇒ "Training therefore discovers occasional successful behavior without retaining it consistently."
- **Minesweeper / Nullify / Tetris**："Their evaluation scores remain zero throughout training."
- **PvZ 负迁移**："The initial score is 23, whereas every updated checkpoint obtains a score of 6." —— 持续退化，作者列三种可能：过拟合探索轨迹、宽松探索与严格评估错配、自评信号不可靠（**未做轨迹级验证**）。
- 总评："parameter training enables self-improvement, but not consistently across tasks."

## 与 DWC 的映射

> 共享背景：DWC = 世界树(W1–W6) + judge 判分(C3') + δ 失败签名排序 + EL 调度(B/τ) + Dreaming 回放(K₂/β) + M>1 策略修订。

| # | 机制（S3Gym） | DWC 现状（代码级） | 判定 |
|---|---|---|---|
| 1 | **探索期扣住 verifier 真值，只给 agent 自评分** `s_i`，评估期才揭盲 | `organs/judge.py` 的 TRUTH_SOURCE 明写 "自判禁止：…无任何自评打分"（`experiments/mem_guidance_vs_replay.py` 同款声明）；`memory.py` 文档头："价值只能由 access/effect 记录推出，不能由写入方自报"，且**不提供** `self_rated_value()` | **确认型**：DWC 从判据侧直接禁止自评分，S3Gym 则把自评分当作**被测对象**来量化其误差。两者同向——S3Gym 的 Table 5/6 给了"DWC 为什么不许自评"的实测数字（Chess agreement 0.496、全域 ρ(A,g)=−0.010） |
| 2 | **宽/严双配置 + 种子不相交 + 评估轨迹不回流** | `el_sched.py` 是**难度推进**（B=8、τ=6/8、代内/换代两级）而非同任务宽严双配置；`judge.py` 有 `SPLIT_DEV`/`SPLIT_TEST`（"metric 演化不许读"）与 `regression_check`（同批任务集才可比） | **半有**：隔离原则在判分面已落地（test 锁定、不回流），**缺**"同一任务的探索配置 vs 评估配置"这一维——DWC 的世界树 `legal_actions` 随揭示变化（`el_sched.py` 注释自陈"代内环境数是动态的"），没有成对的 strict-mode 副本 |
| 3 | **三条经验通路同预算对比**（raw history / 摘要 / 参数训练） | `experiments/mem_guidance_vs_replay.py` 正是三臂对照：`C none`（无记忆下界）/ `A guidance`（平铺注入）/ `B replay`（按真实失败签名 prefix-only 揭示），指标全来自 `judge.evaluate`；诚实边界自陈诚实边界原文两段（`experiments/mem_guidance_vs_replay.py`）："★ 种子记忆是**合成的**（真实历史还没有 —— 这正是 V1 要检验的系统尚未积累）" 与 `★ 任务 2 个 × repeat 默认 2 ⇒ 样本小, 报告只给**方向**不给"证明"。`（半角逗号为原文） | **确认型 + 半有**：DWC 已有同构的三臂 A/B，但 (a) 规模远小（2 任务 × 2 repeat vs 98 runs / 116,117 transitions），(b) 只测通路形态、**不测自评判据**。S3Gym 的 Table 7 给了 DWC 该测而未测的**逐游戏胜负**形态 |
| 4 | **参数训练通路** | `llm/client.py` 是云端 LLM 接入层（唯一用途 = `candidates.py` 候选生成），DWC 全链无训练 | **不适用**：DWC 不持权重、不训练。S3Gym 的负迁移结论（PvZ 23→6）对 DWC 的可迁移部分是**警告而非方案**——即"把判错的经验固化下来会覆盖原本有效行为"，对应 DWC 的记忆写入面 |
| 5 | **摘要必须是可执行动作规则**（两条件判据） | `memory.py` 的 D6 写入门："这条记忆能否成为 evolver 的输入? 不能 ⇒ 留在 PROXY 或归档区"，且"**写入时就要判的门槛**" | **确认型**：DWC 的 D6 是 S3Gym 两条件的更弱版本（只判该记忆能否成为 evolver 输入，没判够不够具体到新状态可执行）。S3Gym 的 −33.27/−22.00 负例表明：DWC 若要加，判据应升级为"含状态条件的动作规则"，可直接引这两条轨迹作反例 |
| 6 | **判决–改进耦合度量**（`ρ(A,g)`、三分位 gap、NABA 相关） | 全 src grep `相关系数|correlat|耦合|spearman|pearson` 仅命中 `candidates.py:662` 的 `mode = "delta_correlated"`（语义无关）；**没有任何自评→下轮改进的耦合度量** | **缺**：DWC 有 judge 判分（每条 c/q/m 签名），却没有"判得准 ⇒ 下一轮更好"的量化。这是 S3Gym 最可搬的一件**度量**而非机制——在 evolver 的 accept 记录上挂 `ρ(判据质量, 下轮 Δ)`，成本低且不需要改判据 |
| 7 | **`s_i` 与动作同帧产出的接口** | `actor.execute_task`/`run_dev_suite` 只回传 judge 判分，agent 不产出并列自评 | **不适用**：DWC 禁自评 ⇒ 不需要该接口。**但**若将来做"自评校准"实验（对照 S3Gym Table 5），该接口是前置条件 ⇒ 暂列不适用 |

**最可搬的一条**：把 S3Gym 的 `Agree / NMAE / over-confidence` 三件套作为**独立审计指标**挂在任何将来允许 agent 自评的面上——它不改判据、只读 `s_i` 与 judge 的 `r`，与 DWC 的 `judge` 只读原则兼容。

**不可搬**：S3Gym 的结论"参数训练能自我改进"。它只在一个开放模型（Qwen3-8B）上成立且带严重负迁移，DWC 无训练面。

## 综述 L 定位

> L 框架（2609.11873 §3）：B0 任务内 / L1 执行人定程序 / L2 自主选改法 / L3 自定学习议程 / L4 部署改持久态 / L5 改改进机制本身；structural = 改动持久并控制下一轮，effective = 同预算独立评估下产出更好后继。

- **L 几：L4。** 逐条回综述原文核：
  - 书目 "Cited by: §3.5.2 , Table 6"，而 §3.5 = "Deployment and Environmental Adaptation"（L4），§3.5.2 = "Iterative revision of the agent system"，Table 6 = L4 的三类机制表。
  - Table 6 行（原文）：`S3Gym Shi et al. [2026a] | History, summaries, or model parameters | Iterative rounds | Compares update pathways without verifier outcomes.` ⇒ 归入 L4 的 **"Iterative revision of the agent system"** 组。
  - §3.5.2 正文（原文，前缀 "S3Gym Shi et al. [2026a]" 未纳入引文）："restricts the question to the experience channel, withholding verifier outcomes so the agent must judge its own trajectories, and compares raw history, compressed summaries, and parameter training as improvement pathways."
- **技术族：在 Table 2 的 A1–E4 族×等级表里**`S3Gym` **零出现**（实测全文 3 次命中 = §3.5.2 正文 + Table 6 + 书目）⇒ **综述未给它族级定位**。按它自己的内容，最接近的族是 C6（Memory / Skill Consolidation）与 E1/E2（在线学习 / 经验回放），但**这是本报告的归类，不是综述的**，故标 `未核（综述无此定位）`。
- **structural / effective**：
  - **L5 的 structural/effective 判据对它不适用**——S3Gym 是**测量工具**，不修改自己的改进机制（它没有"改进器"，只有被测模型）。
  - 但按 L4 的语义它测的是**有效持续性**：`AUC+`（持续高于基线的面积）与 `NABA` 就是 effective 的操作化——这恰好补上综述 Table 8 里 DWC 也缺的 Retention/Transfer 维度的"会话内"版本。
- **与 DWC 的关系定位**：S3Gym 与 DWC 的 judge 判分（C3'）是**同一问题的两端**——DWC 用判据禁止自评（预防侧），S3Gym 把自评当被测变量给出失效数字（证据侧）。综述把它放在 L4 而非 L5，也说明**"改经验通道"与"改改进机制"在责任转移上不同级**：DWC 目前的记忆/经验改造属 L4 形状，判分器固定使其**不触 L5**（与 2606.26294 的映射结论一致）。
