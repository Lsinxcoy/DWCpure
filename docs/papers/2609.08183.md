## 1. 问题

### 论文自己承认的缺口

NeoHorse-1 的问题陈述与前两篇**在层级上就不同**。它不谈"harness 怎么演化"，而是问一个更前置的问题：

**§1 原文**："Realizing this vision, however, requires **a concrete mechanism through which a system observes its own capabilities and converts that evidence into the next round of learning**. Agents are natural carriers of such a mechanism."
"When an agent writes code, investigates a question, or operates software, it **leaves a record of its decisions, tool interactions, and task outcomes**; such interaction trajectories and executable tasks have already been used to train agentic models."
"The opportunity extends beyond treating these records as static supervision: agentic interaction produces **both task experience to learn from and observable evidence of model strengths and limitations**, which can shape **what a model learns next**—precisely the feedback that RSI requires."

**Abstract 里的核心论断（也是全文的立论）**："We argue that **a deployed routing harness already contains such a mechanism**: beyond task outputs, agentic interaction leaves execution trajectories together with **observable evidence of what a model can and cannot yet do**."

论文点名的具体缺口（逐条）：

1. **SFT 的粒度缺口（§4.1）**："Post-training data for an agentic model is **not adequately represented by static instruction–response pairs**." 静态 I-R 对丢掉了 reasoning–action–feedback 链。
2. **SFT 与部署的分布缺口（§4.3）**："The SFT objective in Section 4.1 learns from **recorded assistant responses**, whereas a deployed student conditions on **its own generated prefixes**." → 需要 on-policy。
3. **难度信号的可得性缺口（§2.2）**：curriculum learning "often rely on **explicit difficulty labels or dataset-specific heuristics**, which can be costly or impractical to obtain. Routing systems provide an alternative signal: their request- and context-conditioned predictions estimate the **relative capability demand** of an interaction."
4. **"谁被服务"不是"需要什么能力"（§4.2，极关键）**："The model actually served **also reflects user overrides, service availability, and deployment policies**. **Its identity alone is therefore an imperfect proxy** for the capability an interaction requires."

### §6 的自陈局限（原文，这是本篇最重要的诚实段落）

> "These results should be read as **an initial attempt** at recursive self-improvement rather than a definitive demonstration."
> 1. "The current validation concentrates on agentic and coding capabilities, along with tool use and instruction following, where we observe **preliminary but consistent gains**; **the broader range of capabilities that the harness serves has not yet been evaluated**."
> 2. "The results also reflect **a single pass of the evaluation–selection–update loop**, so **whether the gains a model realizes from being used in the harness can continue to accumulate across successive iterations remains to be tested**."
> 3. "the routing signal can itself be sharpened: turning the recorded **prediction–action–outcome separation into well-calibrated estimates of difficulty and deficiency**—including **supervision that trains the router itself**—would let the harness guide not only which data to use and where to allocate it, but what a model should attempt next."

**第 2 条是决定性的**：**本篇尚未证明递归。** 它证明的是"一轮 agentic 后训练有效" + "路由记录里存在可用的反馈信号"。**"第 2 轮会不会继续涨"是未来工作。**

## 2. 核心机制

### 2.1 三层数据结构（§3.1）——这是全文最基础也最容易抄的一节

论文在三个粒度上组织语料，**且明确了每个粒度的用途**：

| 粒度 | 定义 | 用途 |
|---|---|---|
| **Trajectory** | "a complete interaction executed by the deployment harness, preserving user requests, model responses, tool calls, environment observations, recovery attempts, and terminal outcomes" | 完整执行历史 |
| **User turn** | "begins with a user request and ends at the next user request or task termination" | **序列化的基本训练单元** |
| **Subscene** | "groups adjacent user turns that **share a local goal**"，"spans one or more user requests" | 语义刻画单元 |

**关键约束（这两条是 DWC 必须抄的）**：
- **"Tool results and harness-injected messages do not initiate a new user turn."** ← 工具结果与 harness 注入的消息**不切分 user turn 边界**。
- **上下文保留策略**："Within each user-turn record, the current request and its interleaved reasoning, tool calls, and observations are retained… **Earlier visible responses and tool interactions remain available as context, whereas reasoning from earlier turns is omitted.**" ← **历史 reasoning 被丢弃，历史可见响应被保留。** 这个不对称是有意的（论文说 consistent with DeepSeek-V3.2 的 convention）。

### 2.2 数据质量三道门（§3.2）

**(1) Deduplication and decontamination（去重与去污染）**
"the corpus is deduplicated at exact and near-duplicate granularity, and **the same matching infrastructure screens every training candidate against our evaluation suites**: records that overlap an evaluation item are removed from the training side, keeping the training corpus and the evaluation data **disjoint**."
→ **训练侧与评测侧强制不相交。** 这与 `2609.14857` ModularRSI 的 benchmark-disjoint 是同一条纪律，但实现方式不同（这里是"同一套匹配基建同时筛两边"，ModularRSI 是"外部构造 + 语义相似度筛查"）。

**(2) Structural validation（结构校验，纯规则）**
"在 turn level, the pipeline reconstructs requests, model responses, tool calls, tool observations, and terminal events. It then verifies **payload readability, supported message structure, request and response presence, causal event order, and closure of tool-call/result pairs** through identifiers and execution branches."
检测项包括："missing responses, **orphan observations**, **duplicated or conflicting tool-call identifiers**, **unresolved internal calls**, and **ambiguous terminal branches**."

**三档输出（这是可直接抄的分类法）**：
- **internally complete** → 直接进语义评估
- **partially recoverable** → **只贡献因果闭合的子轨迹**（"recoverable trajectories contribute only causally closed sub-trajectories"）
- **quarantined** → 隔离

论文的界限声明（重要）："**Structural validity establishes reliable serialization and replay, but does not imply correct tool selection or task success.**"

**(3) Semantic evaluation（六维语义评估）**
对结构可用的轨迹，构造**归一化语义事件流**，评六个独立维度：
**goal attainment（目标达成）、instruction adherence（指令遵循）、tool use（工具使用）、evidence consistency（证据一致性）、error recovery（错误恢复）、termination（终止）**

- **高确定性失败用规则检测**："High-certainty failures—such as a missing final response, an unresolved tool call, or an unrecovered terminal error—are detected **deterministically**."
- **需要任务级解释的交给语义 judge**："Cases that require task-level interpretation are evaluated by a semantic judge that is **restricted to evidence explicitly present in the trajectory**."
- **分段评估再聚合**："Long trajectories are evaluated in segments and subsequently aggregated at the turn level so that **intermediate failures can be distinguished from successful later recovery**."
- **四档评级**：`PASS` / `WARN` / `FAIL` / `NOT_EVALUATED`，且评估覆盖率单独存储。
- **关键纪律**："**Missing evidence or an interrupted judge call is never converted into a positive verdict.**" ← 这是对 `2607.12790` Double Ratchet 共谋塌缩的直接免疫。
- **不压缩成单一分数**："The quality representation therefore **retains the structural state, the six quality dimensions, and evidence coverage rather than compressing them into a single heuristic score**."

### 2.3 Subscene 级语义刻画（§3.3）——三轴体系

三条轴，各自封闭/半封闭：

| 轴 | 内容 | 取值结构 |
|---|---|---|
| **Scene** | "what the user is doing and in what context" | 封闭分类法覆盖任务类型与应用域；**每个 subscene 一个 primary 值 + 最多两个 secondary 值**；另有 **Use Context** 与 **Asking/Doing** 进一步刻画"是问信息还是要执行" |
| **Goal** | "what the user expects to achieve and **how success is to be judged**" | 用户目标被**分解为 acceptance criteria**；跨轮关系标记目标是否为 new / continued / modified / resumed / ambiguous |
| **Outcome** | "the verifiable result of the attempt" | 记录对目标的可验证结果，"so that the extent to which the task was **actually satisfied** can be distinguished from the process having **run to completion**" |

**噪声控制（值得抄）**："each attribute retains its **derivation method and confidence**. **Structural facts established by the source or deterministic rules cannot be overwritten by a semantic judge.**"
且 "Structural quality, **turn-local reasoning policy, loss masks**, and routing records remain **separate metadata**." ← 四类元数据不进语义轴，保持独立。

### 2.4 路由信号：prediction–action–outcome 三分离（§3.4）——本文的核心设计

**路由档位（这是全文最具体的可抄结构）**：
- **C0**：处理有界低风险请求
- **C1**：通用默认档
- **C2**：支持多步推理与执行
- **C3**：最大能力/可靠性
- "The tiers describe **relative capability demand under the routing policy**."
- "Models, pricing, and inference configurations may change across deployments, and **a C3 path may combine multiple proposers with an aggregator**. **Versioned tier semantics** therefore keep routing records interpretable as the serving stack evolves." ← **档位语义要版本化**，因为服务栈会变。

**路由器的输入**："The harness router operates at the **user-turn level** and estimates capability demand from the **current request, recent dialogue, previous routing decisions, and available execution state**."

**每轮保留三样东西**："For each turn, the corpus retains the **router's raw prediction**, the **policy-adjusted decision**, and the **tier actually served**, so that **predicted demand, policy constraints, and executed action remain independently analyzable**."

**三分离的意义（论文明确说了两件事）**：
1. **prediction–action 分离**："This prediction–action–outcome separation lets us **isolate the routing estimate used for curriculum ordering in Section 4.2** without treating **the tier actually served as the training label**." ← **预测用于课程排序，被服务的模型不能当训练标签。**
2. **outcome 不进课程、进分配**："**Outcome fields instead provide deficiency signals for the capability-guided allocation of Section 3.5.**"

### 2.5 能力引导的数据分配（§3.5）——闭环的最后一环

流程：
1. 当前 checkpoint 在**分层评测套件**上评估（该套件由 §3.2 的去污染保证与训练不相交）。
2. 结果按 **attributes（Scene/Goal/Outcome 轴）、quality dimensions（六维）、outcome states、routing tiers** 聚合，形成 **model-deficiency profile（模型缺陷剖面）**。
3. "This profile **shifts the next training mixture toward underperforming regions while preserving broad coverage**."
4. "**Verified successful trajectories provide positive supervision**, while **informative failures identify regions** that require additional or rebalanced coverage in subsequent mixtures."
5. "These allocation decisions **change the composition of the training data rather than introducing a separate failure-specific objective**." ← **不做单独的失败目标函数**，只改数据配比。
6. 迭代间："Existing and new data are **reallocated together** so that the corpus follows changes in usage patterns and system capability."

### 2.6 SFT 目标（§4.1，式 1）

序列 `x_i = (x_{i,1}, …, x_{i,T_i})`，二值 token 级 loss mask `m_{i,t}`：
- `m = 1`：当前 user turn 内**保留的 assistant target span**——reasoning（存在时）、序列化后的 tool calls 与参数、可见响应、end-of-response tokens。
- `m = 0`：其他一切，含 padding、system instructions、tool specifications、harness 提供的上下文、user messages、tool results。

```
L_SFT(θ; B) = − [ Σ_{i∈B} Σ_{t=2}^{T_i} m_{i,t} · log p_θ(x_{i,t} | x_{i,t}) ]
              / [ Σ_{i∈B} Σ_{t=2}^{T_i} m_{i,t} ]
```

**归一化口径（一个容易做错的地方）**："This objective weights supervised tokens equally and normalizes by **their count across the batch**, **not by total sequence length or the number of turns**."
序列构造用 **Qwen3.5 chat template + tool-call format**；"With causal attention, each assistant response can use earlier actions and tool results in the sequence, but **not later ones**."

### 2.7 路由引导课程学习（§4.2，式 2）

**打分（硬/软两种排序）**：

```
s_i = k_i                            （hard ordering，k_i ∈ {0,1,2,3} 为分配的档位索引）
      Σ_{k=0}^{3} k · π_{i,k}        （soft ordering，π_{i,k} ≥ 0, Σ_k π_{i,k} = 1）
```

"**We use `s_i` to construct the curriculum described next, not to reweight the SFT loss.**" ← 分数只控制顺序，不进损失权重。**这条纪律极其重要：它排除了"加权 vs 排序"这一类混淆。**

**打分对象也是重新估计的（§4.2 的关键动作）**："We instead **re-estimate capability demand from the request and relevant interaction history available before the first supervised assistant response**. We assign this estimate to the complete example `x_i`… using it as a **turn-level ordering proxy rather than a difficulty label for each individual action**."

**调度（Figure 5）**：
- **三个 stage**，每 stage 约 **one third** 的样本。
- **逐步引入更高分的样本**。
- **"with some lower-scored examples reserved for later stages. Reserving lower-scored examples for later stages prevents the end of training from being dominated exclusively by high-demand interactions."** ← **明确反对"最后阶段全是难题"。**
- **"Every example is used once per pass."**
- **"Training follows the same masked SFT objective throughout, **without resetting the optimizer or restarting the learning-rate schedule between stages**."** ← 阶段之间不重置优化器/学习率。这是最容易被做错的实现细节。

### 2.8 路由引导的 On-Policy Distillation（§4.3，式 3/4）——全文最复杂的部分

**上下文调度**："We use **recorded contexts immediately before assistant responses** as generation starting points. Each starting state is scored from the request and interaction history available at that point, following **Equation 2**. We apply the **same three-stage allocation** as in SFT."

**学生生成 + 教师监督**：
- 第 j stage（`j ∈ {1,2,3}`），学生 checkpoint `p_θ̄` 对 batch `𝒞 ~ ρ_j` 中的每个 context 生成**一条** assistant response → 响应 batch `ℛ`。
- "A **fixed teacher** supplies a **next-token distribution at each position**, conditioned on the corresponding context and the student's preceding response tokens."
- "**Both models render the same recorded messages and tools using their respective native templates**, with **response token IDs aligned for scoring**." ← 两边各自 native template，但 token ID 对齐。
- "We **refresh the rollout checkpoint as training proceeds**… The rollout parameters `θ̄` **remain fixed while optimizing the student** on the collected responses."

**蒸馏目标（式 3）—— 三点机制值得抄**：
1. **紧凑化**："we retain the rollout student's **top-K candidate tokens** at each position and **aggregate all remaining probability mass into one additional bin**." → 得到 K+1 个 bin 的粗化分布 `P̃_θ,r,t` 与 `Q̃_r,t`。
2. **reverse KL**：`D_KL( P̃_θ,r,t ‖ Q̃_r,t )`（**KL(学生 ‖ 教师)** 的方向）。
3. **响应级归一化**：

```
L_OPD(θ; R) = (1 / Σ_{r∈R} w_r) · Σ_{r∈R} (w_r / L_r) · Σ_{t=1}^{L_r} D_KL( P̃_θ,r,t ‖ Q̃_r,t )
```

   `L_r` = 保留的响应长度，`w_r` = 固定响应权重（unweighted setting 下等于 1）。"Each response contributes its **average token-level divergence**; **prompt tokens and padding receive no loss**."
4. **梯度路径**："Gradients are taken through the **current student's probabilities on the collected prefixes, holding the generated tokens, candidate IDs, and teacher scores fixed**." ← 标准的 detached rollout。

**阶段目标（式 4）**：

```
L_{R-OPD}^{(j)}(θ) = E_{𝒞∼ρ_j,  ℛ∼p_θ̄(·|𝒞)} [ L_OPD(θ, ℛ) ],   j ∈ {1,2,3}
```

### 3.4 轨迹分析（§5.1）——三段定性证据，含一个精确的效率数字

**(2) 规模在反馈与失败下才有回报。** WorkBuddy 代码修复：NeoHorse-1-4B "stops after a single implementation attempt without establishing an effective testing and repair loop"；NeoHorse-1-9B "follows a complete **edit–test–inspect–repair** cycle and repeatedly incorporates execution feedback until the verifier passes."

> "Relative to the 4B trajectory, the 9B trajectory reduces the number of model requests, execution time, and token usage by approximately **70.8%, 76.7%, and 83.6%**, respectively."

**论文的机制性解读（直接对应 `2609.14858` Dream-RSI 的 cost 维度）**："the larger model's advantage does **not** arise from executing more actions or conducting a broader but undirected search. ## 4. 它假定了什么

**A1 · "部署中的路由 harness 天然就是 RSI 机制"。**
这是全文的立论（Abstract："a deployed routing harness already contains such a mechanism"）。**隐含假设**：路由记录 = 能力需求估计 + 实际执行结果，**这两个量足以构成"系统观察自身能力"的反馈**。
**论文自己给了这条假设的一个补丁**（§3.4）：必须做 prediction–action–outcome 三分离，否则"被服务的模型"会混入用户覆盖与服务策略。**补丁之后，这条假设仍然依赖"路由分数是能力需求的无偏估计"**——而 §6 明确说这个估计"can itself be sharpened"，**即当前未校准**。

**A2 · 路由分数可以当作"难度"用于排序。**
论文自己反复弱化这条："using it as a **turn-level ordering proxy rather than a difficulty label** for each individual action"，且 "We use `s_i` to construct the curriculum… **not to reweight the SFT loss**"。
**残存的隐含假设**：路由分数的排序与"训练价值"的排序正相关。**论文未验证**——而 Table 3 的实验恰恰说明**同分数档内的数据质量差异很大**（Toucan vs routing-harness 差 6.26 分），说明路由分数不能反映数据质量。

**A3 · 需要自有权重 + 训练算力。**
这是**最硬的隐含前提，也是对 DWC 决定性的**。训练做了：
- `L_SFT`（式 1）：对 `p_θ` 求梯度。
- `L_OPD`（式 3）：对**学生**求梯度，rollout 参数 `θ̄` 固定但需定期刷新（"We refresh the rollout checkpoint as training proceeds"）——**这要求同时持有学生权重与一个可生成的 rollout 服务**。
- **teacher 需提供 token 级分布**（不是文本输出）——**这要求访问 teacher 的 logits**，托管 API 通常不提供。
- 部署侧："All variants of NeoHorse-1 are deployed using **SGLang v0.5.17**"——自建推理栈。

**对 DWC 的直接后果**：**本篇的核心方法 DWC 一步都执行不了。** §5 的所有数字都不能作为 DWC 的可达成目标。

**A4 · 一个固定 teacher 提供 token 级分布是可行的。**
论文说 "A **fixed** teacher supplies a next-token distribution at each position"，但**未说明这个 teacher 是谁、多大、是否比 student 强**。
**隐含假设**：存在一个可访问 logits 的强模型。**这条在开放权重时代成立（教师是开源权重），在托管 API 时代通常不成立。**

**A5 · 语义 judge 的判定不会与被评模型共谋。**
论文给了两条防护：(a) "structural facts … **cannot be overwritten by a semantic judge**"；(b) "**Missing evidence or an interrupted judge call is never converted into a positive verdict**"。
**这两条比多数论文强**（对照 `2607.12790` Double Ratchet 的塌缩结论）。**但语义 judge 的模型身份未披露**，而 §5.2 的数据对比实验用了两个不同的 judge 组合（VitaBench 用 DeepSeek-V4-Flash；训练数据质量用未指明的 semantic judge）。**若被训练的数据与被评测的数据都由同族模型判定，则 10 个基准里的一部分存在共谋风险**——论文未讨论。

**A6 · Qwen3.5 系列的 chat template 可以作为通用序列化格式。**
"we serialize each user-turn example using the **Qwen3.5 chat template** and tool-call format"。**隐含假设**：不同基座的序列化可以统一到一个模板上。**论文只评测了 Qwen3.5 派生模型**，因此这个假设从未被跨基座检验。

**A7 · "一轮有效"可以外推到"多轮累积"。**
论文**没有**做这个外推——§6 明确说 "remains to be tested"。**但摘要与标题用的是 "Towards Recursive Self-Improvement"（"towards"）**，且 §6 说 "establishing an operational basis for extending the loop across model generations"。**"towards" 与 §6 的自陈是一致的，读者不应把它当成递归已被证明。**

**A8 · 更大模型"自带"策略切换能力。**
§5.1 的三个案例都在证明 9B 比 4B 更会在受阻时换路。**隐含假设**：这种能力来自规模，且可以被后训练部分补偿。**论文只给了案例，没有量化"策略切换"这一行为**——三个案例的 token 差异（70.8%/76.7%/83.6%）是**单例**，不是统计量。

## 5. 可迁移到 DWC 的点 / 不可迁移的点

### 5.0 先回答一个必须说清的问题：**DWC 用托管模型能否执行本篇方法？**

**不能。逐项列出阻塞点**：

| 本篇要做的事 | 需要什么 | DWC 托管模型能否 |
|---|---|---|
| `L_SFT`（式 1）梯度更新 | 自有权重 + 训练框架 | ❌ 不能 |
| `L_OPD`（式 3）反向 KL | 自有学生权重 | ❌ 不能 |
| teacher 提供 **token 级 next-token 分布** | 访问教师 **logits** | ❌ 主流托管 API 只返回文本/采样 token，不返回完整分布 |
| refresh rollout checkpoint（`θ̄`） | 同时持有学生权重 + 可生成 rollout 服务 | ❌ 不能 |
| SGLang v0.5.17 部署 | 自建推理栈 + GPU | ❌ 不能（DWC 是桌面/本地 Hermes 形态） |
| 论文的硬件与超参 | **论文未报告** | ❌ 无法照抄 |

**结论**：**§4 的三个方法（式 1/2/3/4）DWC 一条都执行不了；§5 的所有数字都不能作为 DWC 的可达目标。**

**但 §3（数据侧）与部分 §4.2（课程排序的工程化形态）可以在 DWC 上执行——因为它们只需要记录、分类与排序，不需要梯度。**下面按此分界给出可迁移清单。

### 5.1 可迁移（仅限不需要权重更新的部分）

**(M1) 三层数据结构（Trajectory / User turn / Subscene）（§3.1）。**
搬什么：把 agent 的执行历史切成三个粒度，并明确各自用途。
DWC 侧接口（新建 `src/dwc/memory/granularity.py`）：

    # 对齐 NeoHorse-1 §3.1
    # trajectory: 一次完整交互（user requests + responses + tool calls + obs + recovery + terminal outcome）
    # user_turn : 从一个 user request 到下一个 user request / 任务终止
    #            **关键规则：tool result 与 harness 注入的消息不切分 user turn 边界**
    # subscene  : 共享同一局部目标的相邻 user turns

    def is_turn_boundary(msg: dict) -> bool:
        # 只有 role == 'user' 的真实请求才是边界。
        # tool_result / harness_injected 一律 False。
        return msg.get('role') == 'user' and not msg.get('tool_result') \
               and not msg.get('harness_injected')

**这条规则本身就是一个 bug 来源**：若把 tool result 当成新一轮边界，user turn 会被切得过碎，reasoning–action–feedback 链被打断。**DWC 的记忆分块应当直接采用这条边界定义。**

**(M2) 上下文的"非对称保留"策略（§3.1）。**
搬什么：**保留历史可见响应与 tool 调用，丢弃历史 reasoning。**
DWC 侧接口（接 M1）：

    def build_context(turns: list[dict]) -> tuple[str, str]:
        # 返回 (visible_history, current_turn_reasoning)
        # visible_history: 早期 user 请求 + 可见 assistant 响应 + tool calls + tool results
        # current_turn_reasoning: 只有当前 turn 的 reasoning
        # 早期 reasoning 一律丢弃 —— 这既省 token 又避免教模型模仿过时的推理链

**理由（NeoHorse-1 未明说但结构上成立的）**：早期 reasoning 是**在旧上下文中产生的**，保留它等于教模型在已经变化的条件下重复同样的推理。

**(M3) 六维语义评估 + 四档评级 + 覆盖率分离（§3.2）。**
搬什么：goal attainment / instruction adherence / tool use / evidence consistency / error recovery / termination 六维；`PASS / WARN / FAIL / NOT_EVALUATED` 四档；评估覆盖率**单独存储**；**"Missing evidence or an interrupted judge call is never converted into a positive verdict."**
DWC 侧接口（新建 `src/dwc/memory/quality.py`）：

    QUALITY_DIMS = ("goal_attainment", "instruction_adherence", "tool_use",
                    "evidence_consistency", "error_recovery", "termination")
    VERDICTS = ("PASS", "WARN", "FAIL", "NOT_EVALUATED")

    def evaluate_turn(turn, evidence: dict) -> QualityRecord:
        # 六维独立评估，不压成单一分数
        # 高确定性失败走规则：缺最终响应 / 未解析的 tool call / 未恢复的终止错误
        # 需任务级解释的走语义 judge，且 judge 只能看 turn 内显式存在的证据
        # coverage 单独存；**证据缺失绝不转成正面判定**

**三条必须抄的纪律**：
1. **不压成单一分数**（NeoHorse-1 明确 "rather than compressing them into a single heuristic score"）。DWC 若压成一个数，就丢掉了"哪一维坏了"的信息，记忆检索也就无法按成因路由。
2. **证据缺失 → NOT_EVALUATED，不是 PASS**。这是对 judge 中断/证据不全的免疫。
3. **长轨迹分段评估再聚合到 turn 级**，以便区分"中间失败但后来恢复"与"真失败"。

**(M4) 结构校验的三档输出（§3.2）。**
搬什么：`internally complete` / `partially recoverable`（**只贡献因果闭合的子轨迹**）/ `quarantined`。
DWC 侧接口（新建 `src/dwc/memory/structural_gate.py`）：

    def validate_trajectory(traj) -> tuple[str, list[dict]]:
        # 检查：payload 可读 / 消息结构受支持 / 请求与响应成对存在

**(M10) "流程跑完"与"目标被满足"的区分（Outcome 轴）。**
搬什么：`Outcome` 记录的用意是 "so that the extent to which the task was **actually satisfied** can be distinguished from the process having **run to completion**."

**(M11) "结构有效 ≠ 行为正确"的显式声明（§3.2）。**
搬什么：论文明确 "Structural validity establishes reliable serialization and replay, **but does not imply correct tool selection or task success**."
→ **DWC 侧**：在记忆 schema 上把 `structurally_valid` 与 `behaviorally_correct` 分成两个正交字段，**任何用前者推断后者的逻辑都是 bug**。这条零成本，值得立刻写进 schema 注释。

**(M12) 评测侧的纪律（可直接抄成 DWC 的评测规范）。**
- 同基准内**所有模型使用同一 harness / 同一工具接口 / 同一 context 限制 / 同一交互预算**。

### 5.2 不可迁移

- **不可迁移（决定性）：§4 的全部三个方法（`L_SFT`、`L_R-OPD`、三阶段课程作为训练调度）DWC 无法执行。** 详见 §5.0 的六项阻塞表。**DWC 是托管 API 形态，没有权重、没有梯度、没有 logits 访问。**
  - **必须诚实的后果**：**本篇的 58.94→64.87 与 65.60→69.04 这两个数字，对 DWC 是零参考价值**——它们衡量的是"拥有权重与算力的团队能把自有模型训多好"，而非"agent 系统该做哪些结构改进"。

- **不可迁移（依赖 teacher logits）：on-policy distillation 在 DWC 上有一个"降级版"但不是同一个东西。** DWC 可以做的是 **prompt-level 的行为引导**（把 routing 记录写进 system prompt / few-shot），这在能力上远弱于 token 级蒸馏，且**论文没有报告任何 prompt-level 变体的效果**（检索 0 命中）。**任何"照搬 NeoHorse-1 的 OPD 思想到 DWC"的说法都必须先承认这个降级。**

- **不可迁移（teacher 身份未知）：式 3 无法复现。** 全文 8 处提到 teacher，**没有一处说明它是哪个模型**。这不只是复现问题——**teacher 的强弱直接决定 `L_OPD` 的上限**，而论文不报告它，等于**无法判断 +5.93 里有多少来自 SFT、多少来自蒸馏**。

- **不可迁移（单遍循环，论文自陈）：§6 第一条局限就是 "a **single pass** of the evaluation–selection–update loop"。** **本篇没有证明递归。** DWC 若把本篇当作"递归自进化已可行"的证据，是误读。标题里的 "Towards" 与正文的 "single pass" 是一致的。

- **不可迁移（OPD 的净贡献未验证）：** 没有"只做 SFT"vs"SFT+OPD"的对照。**OPD 贡献多少论文未报告。**

- **不可迁移（路由分数未校准）：§6 自己把 "well-calibrated estimates of difficulty and deficiency" 列为未来工作。** 即**当前的路由分数没有被验证是能力需求的无偏估计**。M5/M6 的可用性建立在"分数的相对序有意义"这一未验证前提上。

## 6. 与其他论文的关系

### 6.1 在 RSI 图谱上的位置——这是**三篇里唯一改权重的**

| | 改什么 | 梯度需要 |
|---|---|---|
| **NeoHorse-1（`2609.08183`）** | **模型权重** | **需要自有权重 + 训练算力** |
| RRSI（`2609.24972`） | harness 源码 | 不需要 |
| ModularRSI（`2609.14857`） | harness 源码 | 不需要 |

按 `2609.13406`（GAI 框架）的两个 dial 定位 NeoHorse-1：
- **改进机制属于 agent 自身**吗？**部分是**。经验来自 agent 自己的部署轨迹，闭环由 agent 系统的运行驱动；**但改进的执行者是训练流程，不是 agent 自己**。
- **度量锚定在系统外**吗？**是**——十项外部基准，且 §3.2 有强制去污染保证训练与评测不相交。

→ **NeoHorse-1 是三篇里"度量锚定最干净"的一篇，但"自举程度"也最低**（需要人工训练流程作为改进执行者）。按 GAI 的严格标准，它离完整自举最远，但它是**唯一把 RSI 落到模型参数上**的一篇，因此是三篇里唯一提供了**能力可以被系统性提升**的证据。

### 6.2 与 `2609.24972` RRSI：层级不同，但共享一条"成本意识"的直觉

**不同点**：
- RRSI 的成本门 `ΔC ≤ β₀ + β₁·ΔS` 是**事后否决**——涨太多就不收。
- NeoHorse-1 的效率体现在**模型学到了"受阻时换路"**——PinchBench 案例中 9B 比 4B 少 **83.6% token**。这是**事前内化**而非事后过滤。
- **NeoHorse-1 的 9B 案例正好演示了 RRSI 想要的效果**：识别无效轨迹、重新分配交互预算。

**互补关系**：
- **RRSI 可以挡住"多花 token"的 harness 改动，但挡不住"模型自己在 rollout 里绕 20 圈"。** 后者只有在权重里修（NeoHorse-1）或者在 harness 里加干预（RRSI 的 recovery hint 类编辑）才能解决。
- **两者的成本口径不同**：RRSI 的 `Ĉ` 是 policy token per trial；NeoHorse-1 报的是单条轨迹的请求数/时间/token 相对降幅。**DWC 若同时采用两者，需要一个统一的成本度量。**

### 6.3 与 `2609.14857` ModularRSI：数据纪律上高度同构，且揭示一条领域级事实

**同构的三处**（这是本批次最值得注意的横向发现）：
1. **训练/演化数据与评测数据强制不相交。** ModularRSI："benchmark-disjoint"，2,000 个外部构造任务，外部语义相似度筛查。NeoHorse-1："the same matching infrastructure screens every training candidate against our evaluation suites: records that overlap an evaluation item are removed from the training side." **两篇用了完全不同的路线（外部构造 vs 内部去重）达到同一个纪律。**
2. **结构门 + 弃权档。** ModularRSI：`internally complete` / `partially recoverable` / `quarantined`（在 harness 代码上）；`infra_only` / `unreachable_fail`（在任务上）。NeoHorse-1：`internally complete` / `partially recoverable` / `quarantined`（在轨迹上）；`NOT_EVALUATED`（在语义质量上）。**三档结构门的形态完全相同。**
3. **"证据缺失不得转成正面判定"。** NeoHorse-1 原文；ModularRSI 的等价纪律是"`would_change_outcome` 允许 No、`is_culprit` 允许 false"（弃权）。

**揭示的领域级事实（三篇合起来）**：
- **ModularRSI Table 6** 证明：AHE 与 Meta-Harness 在 benchmark-disjoint 协议下只涨约 1 个百分点。
- **NeoHorse-1 Table 3** 证明：同一条 routing-guided 训练配方下，**routing-harness 数据比公开合成 agent 数据好 6.26 分**。
- **两者合起来**：**harness 自进化领域的收益，很大一部分取决于经验数据的来源与去污染纪律，而不是演化算法本身。** 这是一个对整个领域都成立的判断，且**两篇论文互相不知道对方**（ModularRSI 全文 0 命中 NeoHorse 相关引用）。

**另一处重要关系：NeoHorse-1 是"改权重"，ModularRSI 是"改 harness"。两者有强互补性**——若一个模型的权重被后训练强化了，**它更能利用一个好 harness**；反之好 harness 也会让弱权重模型表现得像强模型（ModularRSI Table 3：MiniMax-2.5 的 `Pass³` +5.62）。**NeoHorse-1 的 4B 宏平均 +5.93 与 ModularRSI 的 MiniMax 增益方向一致——都在说"用可得的手段弥补模型档位不足"。**

### 6.4 与 `2609.06396` MetaRSI：**最直接的类型学互补**

MetaRSI 的三型算子：Data-RSI / Harness-RSI / **Model-RSI**。
- **NeoHorse-1 就是 Model-RSI 的一个完整实例**：改权重、由 agent 自己的轨迹驱动、度量外部锚定。
- **RRSI 与 ModularRSI 是 Harness-RSI 的两个实例**（一个软标签正、一个硬边界 + 数据不相交）。
- **Dream-RSI / `2609.04128` 更接近 Meta 层或环境层。**

**MetaRSI 报告已指出这件事对 DWC 的价值**："DWC 的记忆如果不记录'为什么失败'，检索时无法按成因路由，只能按语义相似度。"
**NeoHorse-1 为这个论点提供了一个可执行模板**：它的 `scene / goal / outcome` 三轴 + `quality dimensions` 六维 + `routing tiers` 就是**"按成因路由"的 schema**。**DWC 若把这套 schema 用在自己的记忆上（即使不做训练），记忆的检索与分配就有了依据。**

### 6.5 与 `2607.12790` Double Ratchet：**NeoHorse-1 的防护做得比多数论文好，但未被讨论**

NeoHorse-1 有两条明确的反塌缩纪律：
- "**Missing evidence or an interrupted judge call is never converted into a positive verdict.**"（§3.2）
- "**Structural facts established by the source or deterministic rules cannot be overwritten by a semantic judge.**"（§3.3）

**这两条正是 Double Ratchet 的"grounded outside"在数据侧的实现。** 值得对比的是：Double Ratchet 证明的是"没有外部锚定时会塌缩"，**NeoHorse-1 的度量（十项 benchmark）全部外部锚定**，所以它的主实验不存在塌缩风险。
**真正的风险在训练数据侧**：语义 judge（身份未披露）用于给轨迹打六维质量分，**若这些标签反过来被用于筛选训练数据，且 judge 与被评模型同族**，就构成"被评估者影响评估者"的结构。**论文未讨论这一点**，也未报告语义 judge 的模型。

### 6.6 与 `2609.14858` Dream-RSI 与 `2609.04128` Environment Evolution：同在"证据 → 学习"的链条上，但改的东西不同

- **Dream-RSI** 改的是探索策略（编排层），用 replay world 选策略。
- **Environment Evolution（2609.04128`）** 改的是任务/环境本身。
- **NeoHorse-1** 改的是模型权重。

**共同点**：三者都认为"历史里已经有可用的信号，此前被浪费"。
- Dream-RSI：历史 = **discovery 决策树 + 执行结果** → 用来当 replay simulator。
- NeoHorse-1：历史 = **部署轨迹 + 路由记录 + 结果字段** → 用来当训练语料与难度信号。
- **差异的关键**：Dream-RSI 的历史可以**重放**（代码执行可复现），NeoHorse-1 的历史是**真实用户交互，不可重放**。**这决定了 NeoHorse-1 只能用离线数据做 SFT，无法做 Dream-RSI 那样的 replay-based RL。**

### 6.7 三篇的合起来读法（本报告的结论）

这三篇覆盖了 RSI 的三个不同层次，且**互补性大于竞争性**：

| 层次 | 论文 | 核心问题 |
|---|---|---|
| **权重层** | NeoHorse-1 | 能力本身能否被系统性提升？→ 能（+5.93 / +3.44），但只跑通一轮 |
| **脚手架层** | RRSI / ModularRSI | 能力固定时，脚手架能做到多好？→ 能（+4.86 / +3.9 OOD），但受限于基准记忆与组件归因 |
| **经验层（共同前提）** | **ModularRSI + NeoHorse-1 的数据纪律** | **收益主要取决于经验数据的来源与去污染，不只是算法。** |

**最实质的三条横向结论**：
1. **数据纪律压倒算法选择。** ModularRSI 的 AHE/Meta-Harness 在自己的协议下只 +1 分；NeoHorse-1 的 routing-harness 数据比公开数据 +6.26 分。**两篇独立地指向同一件事。**
2. **权重路径与 harness 路径不可互相替代。** RRSI 无法阻止模型在 rollout 里绕 20 圈；NeoHorse-1 无法在部署当天修补一个坏 harness。**DWC 只能走 harness 路径，但应当读懂两篇各自证伪了什么。**
3. **所有三篇都把"过拟合 / 数据污染"当作真问题处理。** RRSI 用 critic + 门；ModularRSI 用 benchmark-disjoint；NeoHorse-1 用去污染匹配 + `Pass³`。**这是本批次最重要的领域共识：单看 evolve split 的分数是不可信的。**
