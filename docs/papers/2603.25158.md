# Trace2Skill: Distill Trajectory-Local Lessons into Transferable Agent Skills

- arXiv:2603.25158 · f=5（综述 2609.11873 引用频次 refmap.json：§3.5.1 + §3.5.4 + Table 2×2 + Table 6）
- 全文: papers/arxiv_2609.11873/refs/2603.25158.txt (89,770 字符 / 1,314 行, PDF 文本层, 正文硬换行约 100 字符/行, 表格段为双栏混排)

## 一句话总结

不逐条在线改 skill、也不做 test-time 检索，而是**并行**读完一批轨迹后把所有 lesson
**树状合并成一份可移植 SKILL.md**：冻结 agent rollout → 错误/成功两个分析员各自提 patch（128 个并行）
→ 分层 merge（`L=⌈log_32 |P|⌉`，"重复出现 = 系统属性"的归纳偏置）→ diff 落地；
从 Qwen3.5-35B 轨迹蒸出的技能把 Qwen3.5-122B 在 WikiTQ 上抬 **+57.65 pp**，
且**一份合并技能在同轨迹池上稳定打赢 ReasoningBank 式 top-1 检索与顺序编辑**。

## 核心方法（细颗粒度）

### 形式化（§2.1）

技能 = 人类可读目录 `S=(M, R)`：`M` 是根 `SKILL.md`（广适用流程知识），`R` 是
references/scripts/assets（确定性工具与低频细节）。固定 agent `π_θ` 推理时用 `S`，
`P(S; π_θ, D)` = 任务集 D 的通过率。目标（**Eq 1**）：
`S* = E(S0, D_evolve; π_θ)` 且 `P(S*; π_θ, D_test) > P(S0; π_θ, D_test)` ——
**不更新 θ**。两种初始化：`S0` = 人类专家技能（Deepening）或纯参数知识生成的弱草稿（Creation）。

### Stage 1 · 轨迹生成（§2.2）

ReAct harness；每个 evolving-set 任务跑一次（带 `S0`），产出轨迹 `τ_i` = query + 推理/工具史 +
最终输出 + **二元正确性**；语料 `T` 分成失败 `T−` 与成功 `T+`。**跨任务并行**，
所以轨迹库可在提 patch 之前独立收齐。

### Stage 2 · 并行提 patch（§2.3）—— 两个**故意不对称**的分析员

- 成功轨迹 → **成功分析员 `A+`**：单轮（single-pass）工作流，从成功轨迹里找可复用行为模式。
- 失败轨迹 → **错误分析员 `A−`**：**ReAct 循环**，可查 trace 与 artifact、把输出与 ground truth
  对比、**先实现最小修复验证再提 patch**；"Failures that cannot be causally explained are excluded,
  ensuring P− is grounded in verified failure mechanisms rather than log-only guesses"。
- 两角色都先读 `S0` 再提 diff patch → patch 池 `P = P− ∪ P+`。实验里 **128 个 sub-agent 并行**
  （Stage 2，附录 A：merge batch size 32；不设单独 tool-call budget）。

### Stage 3 · 分层合并（§2.4，Eq 2）

`L = ⌈log_{B_merge} |P|⌉` 层，每层至多 `B_merge=32` 个 patch 合成一个：
`p^(ℓ+1) = M(π_θ, S0, {p^(ℓ)_1, …, p^(ℓ)_Bmerge})`，`M` 的职责 = **去重、解冲突、保留互不重叠的洞见**。
- **`π_θ` 同时充当轨迹生成器、分析员、合并算子 ⇒ 不需要外部进化/教师模型**（100% self-evolution）。
- 最终 `p*` 翻成 diff 应用，带**确定性护栏**：拒绝修改缺失文件、有行范围冲突就暂缓、校验更新后技能格式。
- **归纳泛化**：单条 patch 来自单条轨迹，"recurring edits across independent patches are evidence of
  systematic task properties rather than one-off fixes" ⇒ `M` 被指示**优先保留普遍模式、丢弃特异性改动**。
- 合并算子 prompt（附录 I.3.1）六条规则：deduplicate / resolve conflicts / preserve unique insights /
  maintain conciseness（合并后 ≤ 各唯一改动之和）/ **line-level independence**（任何两处编辑不得重叠）/
  **atomic create-link pair**（`references/*.md` 创建与其在 SKILL.md 插链接必须同生同死），
  外加一条 **Prevalent pattern bias**（独立提出同类编辑 = 该类失败/成功模式是系统性质，提升为通用原则）。

### 运行时语义（附录 I.1）

`SKILL.md` 内容**整体预载进 system prompt**（不做 skill-selection），但 `references/`、脚本
**不预载**，agent 要自己"程序性地发现"被引用的资源 —— 即：主文档是常驻指令，细节是按需查找层。

### 三个设计抉择的隔离实验设计（§4.1）

同一轨迹池 + 同一 harness 下逐个换掉一个设计（"apples-to-apples"），三组对照：
并行合并 vs 顺序编辑、整份技能 vs 检索记忆、agentic vs 单轮 LLM 错误分析；
另在附录 G 做**整系统 head-to-head**（XSkill / EvoSkill / SkillGen，共享同一开放底座），
论文明确说这组数字"conflates a design idea with its base model, harness, and engineering"，**主张仍以 §4.1 为准**。

**为什么合并有效（§4.2–4.3）**

- 122B Deepening +Combined 跑出 **323 条 map patch**，四大 SoP 被 **55.1% / 54.8% / 42.7% / 16.4%**
  的 patch 引用（和 >100% 因一 patch 可引多个）：① 公式写回必须 `recalc.py` 且 `data_only=True` 复读
  （55.1%）；② 读用 pandas、写用 `openpyxl`（54.8%，"pandas.to_excel() silently destroys formula
  relationships"）；③ 显式 read-back 验证（42.7%）；④ 结构编辑安全（16.4%，删行降序 + 先拷贝工作簿）。
  低支持观察**不丢弃**，路由进 **13 个 references/ 文件**（例：单元格颜色提取、特殊业务逻辑下 FIFO/LIFO）。
- **patch 价值是组合性的**：贪心 top-1 曲线上升几轮即平台，且**每条曲线都在整份聚合之下**（Fig 5）。
  两个机制（附录 C.2）：*patch-irrelevant regression* —— 十轮贪心 +Combined 里，选中 patch 的源任务
  与评测集零重叠，仍出现 **57 fail-to-pass vs 21 pass-to-fail**、另一步 **26 vs 46** 的双向翻转
  （"each addition simultaneously fixes and breaks tasks"）；*semantic overlap* —— 十轮选择反复回到
  同几类主题（轮 1&6 重算校验、轮 2&9 结构表头、轮 4/5/7/8 格式类型日期），后到的 patch 大多复述已编码的指引。
- **BO 子集选择（Table 6，122B Deepening）**：No Selection —— Evolve 68.00 / Vrf 65.83 / Soft 46.60 /
  Hard 27.43 / WikiTQ 76.30 / HiTab 43.45；BO Selection —— 72.83 / **69.83** / 47.27 / 28.90 /
  77.51 / **43.38（HiTab 反降 0.07）**。算法（附录 E）：候选 = coverage top `m≤15`，
  `f(x)=acc_V(S0⊕P_x)−λ‖x‖₀ (λ=0)`，`V` 只有 **32 题**验证集；TPE 式采集 `A(x)=Σ[log q(x_j;μ_G)−log q(x_j;μ_B)]`，
  每轮从 500 个候选池评 top 8，4 轮或 3 轮无改进停。论文自评："useful when the target distribution
  and validation budget are known, rather than as a replacement for the default full aggregation"。

**论文未报告 / 原文局限（诚实项）**

1. **运行时没有独立准入门**：patch 由 analyst 自己提、merge 自己合（综述 Table 6 的登记口径即
   "Error and success analysts propose and merge patches"，对照 ReasoningBank 行是"A judge labels
   trajectories before strategy extraction"）。论文的"验收"= 实验期 held-out 集，**不是落地前的 gate**；
   BO 是可选的落地前选择，但默认全量应用。
2. **长期退化未测**：只测蒸馏后一次迁移，没有"保留的技能在若干轮后是否仍有效"的纵向序列
   （综述 §3.5.4 批评的 "bounded task streams" 正中此处）。
3. 原文内部小口径不一致：**Table 2 的数学 No Skill D-Test = 91.0，Table 8/9 同条件写 92.0**
   （AIME/35B 各列一致）。以哪张为准 —— **未核**。
4. 附录 G 的三系统复现是**作者改造后的协议**（换底座、换 harness、换切片），论文自陈
   "transplanting them onto one benchmark shows behavior in our setting, not a ceiling on their design"。
5. 算力：**20,000 GPU 小时**总账（8×A100 节点），未按阶段拆分。
6. 闭源模型依赖（影响可迁移性）：主结论 100% self-evolution 在**开放 Qwen3.5 checkpoint** 上，
   不依赖闭源模型；但三处外部件用了闭源 —— **GPT-5.5-high**（OpenAI API，跨族作者/用户实验）、
   **Claude Code + Opus 4.6**（skill-creator 基线）、EvoSkill 复现的 Claude Code 代理路径。
   **DWC 不具备同等模型条件 ⇒ 这三处结论不可直接外推。**

| 并行 many-to-one 合并（128 analyst 单轮 + 3 层 merge ⇒ 3 min），顺序编辑 15/60 min 且质量更低 | DWC 是**一改一验**：`Proposal._assert_single_change` 保证单点改动，`ProposalGate.check` 逐条把关，`evolver.record_edit` 顺序入 `liquidity`；**没有"一批改动合成一次修订"的合并层** | **缺**（结构级）：最自然的落点是 `core.dream()` —— 它已按 `for _spec in specs` **逐版本并行评估**（`replay.py::policy_variants`），把"候选修订"灌进 specs 即复用同一骨架；但合并会牺牲"一改一记"的归因精度，需先决定归因粒度（可给合并后的改动按来源 patch 回溯记 `liquidity`） |

| Agentic 分析员：查 artifact + **实现最小修复并复现成功**再提 patch（vs 纯读日志：57% vs 14% 误归因） | `candidates.CandidateGenerator.generate` 有 `_baseline_reproduces`（**重放基线复现失败**）+ `_r1_range_offset`/`_r2_type_wrap` 结构变异 + `_llm_generate`；但 `failure_signature` 由 executor 提供，**没有"写修复→验证修复生效"这一步** | **半有**：复现失败已具备（同型），缺"修复验证"；可在 `ingest` 不变量② 上加一档 `verified: bool`（最小修复过 judge 才算已验证失败），直接提升 δ 的信噪比 |
| 合并后整份文档、**无 test-time 检索**，胜 ReasoningBank top-1 检索 | `MemoryKernel.recall_search/recall_many`（检索式）+ `dream()` 离线回放 + `Mutator.load_learned/persist_learned`（持久经验条目） | **部分可迁移**：结论支持"离线合并 > 逐条检索"这条路线（DWC 的 `dream()` + learned entries 方向一致）；但 DWC 记忆是 sqlite 结构化节点而非单一文档，没有"压成一份"的算子，也未做"检索 vs 合并"的同池对照 |
| patch 组合效应：贪心平台 + off-source 回归（57↔21、26↔46 翻转）+ BO 选择 | 每轮只改一处 ⇒ 天然无组合爆炸；`evolver.gain(liq, component, now_round, window)` 只测单改动窗口增益，`novelty_score` 抑制重复触碰 | **缺但低优先**：DWC 的单改设计已规避该失败模式；一旦开批量/M>1 修订，Table 6 的 BO（32 题验证 + TPE）就是现成先例，且论文给了"验证集要够大"的反例（HiTab 反降） |
| 迁移评估设计：**author ≠ user ≠ task 分布** 三维解耦（跨规模/跨族/OOD 各自留出） | `run_term` 是同 agent 前测/后测（T1–T4），无"修订者 vs 使用者"分离，无跨底座迁移 | **缺**（评估设计可迁移）：把"产生修订的 agent"与"执行修订的 agent"分离跑一遍，是判"技能/策略是否真的可移植"的最低成本实验 |

## 综述 L 定位

- **L4（Deployment & Environmental Adaptation）**，子类 **§3.5.1 Trajectory distillation**：
  综述原话 —— "Trace2Skill Ni et al. [2026] turns lessons from individual trajectories into skills
  that other models and tasks can reuse. It first rolls out a frozen agent on domain tasks. Two analyst
  roles, one focused on errors and the other on successes, then read the trajectories and propose skill
  edits, which are merged in stages into a portable skill directory. Because the consolidated document
  is read directly rather than retrieved for each episode, later agents load it once as part of their
  instructions."
- **技术族**：Table 2 **A4. LLM Reflection / Critique**（与 EDIT、GEPA、MPO、VOYAGER、ReasoningBank、
  Metis 同族，落在 L3/L4 格）。
- **Table 6 登记行（L4 三元组）**：Update target = **Portable skill document**；
  Timing = **Offline batch**；Update validation = **"Error and success analysts propose and merge patches"**
  —— 即综述把它登记为**无独立准入测试**（对照：ReasoningBank 有 judge 预标注、PANDO 用
  confidence-scored admission、HarnessDev 用 frozen replay）。这条与 DWC 的 `ProposalGate` 直接对位。
- **structural / effective**（按综述 §3.5.4 的 L4 口径）：
  - *structural*：**有** —— 改动是持久 artifact、跨 session 被后续 agent 加载（"these changes affect
    later tasks and feedback"的要件满足）。
  - *effective*：**有但 bounded** —— held-out 200 + OOD 两集 + 3 seeds + 同池三对照 + 三系统 head-to-head，
    证据比多数 L4 系统硬；但综述 §3.5.4 恰好点名它："Most evaluations cover bounded task streams and
    limited combinations of models, tasks, and environments, while repeated assessment makes longer
    studies costly Ni et al. [2026]" —— **缺"随时间/分布漂移是否仍有效"的纵向证据**。
- **不是 L5**：它改的是任务执行产物（技能文档），不改"改进机制本身"，不触碰 goal/stopping。
