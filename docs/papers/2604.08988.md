# SEA-Eval: A Benchmark for Evaluating Self-Evolving Agents Beyond Episodic Assessment

- arXiv:2604.08988 · f=4（综述 2609.11873 引用频次 refmap.json：§3.6.5 + Table 8×3）
- 全文: papers/arxiv_2609.11873/refs/2604.08988.txt (91,776 字符 / 2,011 行, PDF 文本层, 正文硬换行约 70–90 字符/行)

## 一句话总结

先给"自进化 agent"下形式定义 `SEA=(E,A,M,Φ,Ψ)` 并把 **Evolutionary Flywheel**（执行↔认知双中枢、
执行→蒸馏→增强执行三相）定为最小充分架构，再据此把评估单位从"孤立任务"换成**序列任务流**，
主指标 = 成功率 **SR** + token 消耗 **T**；五个 agent 在同底座下 SR 都在 **85%–96.7%**，
单任务 token 却差到 **31.2×**，且重复执行同一任务时 GenericAgent 的 T 降 ~68%、
OpenClaw 几乎不动、插入无关任务后还 **+22.2%** 反弹 —— 结论是
**"SR 单独看是能力幻觉"，T 沿序列单调收敛才是"真进化 vs 伪进化"的判据**。

## 核心方法（细颗粒度）

### §3.1 SEA 的形式定义（五元组）

`SEA = (E, A, M, Φ, Ψ)`：
- `E` 开放数字环境（动态状态空间、异构模态、**无预枚举动作约束**）；
- `A` 开放可扩展动作空间（**自主扩张**）；
- `M = M_p ∪ M_e ∪ M_d` 跨任务边界持久的分层记忆：`M_p` 程序性（可复用执行策略）、
  `M_e` 情景性（历史轨迹与失败归因）、`M_d` 声明性（环境约束 + 用户偏好模型）；
- `Φ: τ → ΔM` **经验蒸馏**（原始轨迹 → 结构化记忆更新）；
- `Ψ: M_t × ΔM → M_{t+1}` **选择性跨任务迁移**（决定哪些更新真的落盘）。

两个不可协商的基础特征：**① 开放环境中的复杂交互（digital embodiment）** —— 直接操作
原始 GUI 像素、动态 DOM、低层系统接口，不受预定义 API 抽象约束；
**② 连续多轮进化** —— 跨任务保持状态；"an agent that resets its cognitive state at every task
boundary is, by definition, not evolving"。退化判据是**定义级**的：episodic agent 里 `Φ`、`Ψ`
都是零操作（`ΔM=∅`、`M_{t+1}=∅`），"any system in which these functions are effectively identity
mappings is, by definition, an episodic agent"。

### §3.2 两个**必要**推论（非可选设计）

1. **Autonomous tool synthesis**：开放环境里预定义工具必然遇到未覆盖状态 ⇒ agent 必须自主合成并
   注册新原语，`|A|` 随部署时间单调增长 —— "not an optional capability enhancement but a
   structural necessity"。
2. **Implicit user alignment**：持续多轮回滚/修订/显式反馈构成高维奖励源，经 `Φ` 反复作用把
   用户工作流与隐式偏好编码进 `M_d` —— 对齐是持续蒸馏的**涌现结果**，不是单独工程件。

### §3.3 Evolutionary Flywheel（双中枢 + 三相 + 两个失败模式）

- **Execution Hub（数字肢体）**：多模态感知（屏幕/DOM/系统日志/终端输出 → 环境表征）+ 动作执行
  （含工具自合成与持久注册）。
- **Cognition Hub（认知核心）**：任务中 = 执行引导（维护任务态 + 从 `M` 取回的上下文 + 持续更新的
  执行计划，异常时改计划）；任务后 = 实例化 `Φ` 蒸馏出 `ΔM` 交 `Ψ`，"suppressing instance-specific
  noise to preserve evolutionary stability"。
- **三相闭环**：Execution（产轨迹 τ）→ Distillation（`Φ` 出 `ΔM`，`Ψ` 落盘）→
  Augmented Execution（后续任务读 `M_p`，"replacing exhaustive zero-shot reasoning with
  experience-guided execution"）。净收益条件：**执行成本的下降 > 蒸馏 + 检索的开销**。
- **两个失败模式**：*distillation failure*（`Φ` 做不了因果归因 —— 要么找不到关键决策子序列
  `τ*`、要么抽象质量不足，`M_p` 基数涨但不减成本）；*retrieval failure*（`M_p` 里有对的条目，
  相似度查询却把它排在检索阈值之下 —— 环境漂移/表面特征变化时最易发生）。**两者的行为签名相同**：
  执行成本不随序列下降、**随任务频率线性上升** ⇒ 伪进化。

### §4 评估两维与指标体系

- **Intra-task execution reliability**（不依赖既有经验的即时能力）：复杂场景适应 + 错误恢复鲁棒性。
- **Long-term evolutionary performance**：evolutionary gain / evolutionary stability / implicit
  alignment convergence 三者都要。
- **主指标**：`SR`（最低可靠性保证）+ **`T`（token 消耗，判飞轮是否真转的核心信号）**。
  选 T 的理由（§2.3）："execution step count may remain stable even as per-step reasoning depth
  increases, and wall-clock latency introduces hardware-dependent variance"。
- **任务内辅助**：`S`（决策步数）、`N_fix`（自纠错频次）、`N_undo`（人工干预/回滚频次）。
- **长期辅助（框架级，相邻两步的增量）**：`K_eff^(k) = (T_{k+1} − T_k)/ΔN`（Eq 1，从负侧趋零 =
  经验固化成功）；`K_SR^(k) = (SR_{k+1} − SR_k)/ΔN`（Eq 2）；`K_align^(k) =
  (N̄_undo,k+1 − N̄_undo,k)/ΔN`（Eq 3，`N̄` 为滑窗均值）。
  **伪进化联合判据**："when both simultaneously approach zero ... confirming evolutionary
  stagnation as the empirical manifestation of flywheel failure"。
- **实验级变体（§5.4）**：`K_eff(Evo)=(T_R1−T_R3)/T_R1`、`K_eff(Conv)=(T_R1−T_R2)/T_R1`、
  `K_trans = ½[(T_A2−T_R1)/T_R1 + (T_A3−T_R1)/T_R1]`（负 = 迁移有效）、
  `K_eff(Stab-Id)=(T_post_same−T_pre_same)/T_pre_same`、`K_eff(Stab-Sim)` 同构、
  `K_eff(Ret)=K_eff(Conv)/K_eff(Stab-Id)`。归一化（附录 A, Table 5）：SR 直用、
  `TC = clip(1−raw/max, 0, 1)`、`K_trans = clip(−raw/2, 0, 1)`、**两个 Stab 用 `exp(−|raw|)`**
  （"small fluctuations (e.g., <20%) are typically acceptable ... whereas large fluctuations
  (e.g., >50%) should be substantially penalized"）。

### §4.3 数据集构造

- **原子任务 32 个**：Web Automation **18** + Local System Operations **14**（文件管理、脚本执行、
  系统配置、原生桌面应用）；难度三档 **12 Easy / 18 Normal / 2 Hard**；**不预置工具接口**，
  GUI/命令行/API 任选，"the autonomous selection of interaction pathways is itself part of what is
  being evaluated"。每任务带 **1–2 个可替换变量槽**（检索目标、目标网站、文件名），
  换槽不换执行逻辑 —— **专防"背答案式降本"**："ensuring that efficiency changes observed across
  sequences faithfully reflect evolutionary capability rather than memorization effects"。
- **序列 = 主评估单元，长度恒为 5**（"balancing trend observability against evaluation overhead"）：
  - **Correlated** `R1→R2→R3→A2→A3`：前三步同一实例重复（看是否学到），后两步换槽实例（看是
    策略泛化还是死记 —— "If efficiency gains appear only on the identical repetitions but fail to
    carry over to the similar instances, the agent is relying on rote memorization"）；
  - **Orth-Same** `A1→B→C→D→A1`：插入无关任务后重跑同一实例（纯保持性）；
  - **Orth-Similar** `A1→B→C→D→A2`：插入后跑新实例（干扰下泛化是否存活）。
  Table 1 的 "#" 列三行都写 **"12 / 18"**（与 Easy/Normal 任务数一致；表头排版歧义，**列语义未核**）。
- **噪声注入（独立控制变量）**：Clean = 每条序列从空记忆起步；Noisy = **预载 20 条与本序列无场景
  重叠的随机技能**（"substantially exceeds the number required for any single sequence"），
  把检索鲁棒性与进化能力解耦。
- **规模（§4.3.4）**：**92 条序列 = 32 correlated + 30 orthogonal + 30 implicit intent**；
  全部人工基于公开资源设计，保证可解性与 ground-truth 可验证。
  ⚠ **implicit intent 序列在正文里没有定义**（§4.3.2 只定义了两类，"we construct two types of
  sequences"），该词仅出现在 Fig 2 的框图与 §4.3.4 的计数里 —— 结构与用途 **未核**。

### 附录 B / C（机理边界与诊断）

- `Φ` 对单条轨迹做**因果归因**（找 `τ*`）并把更新分解到 `M_p/M_e/M_d`；`Ψ` 是**门**（抑制不可泛化
  条目 + 抑制与 `M_t` 重复的冗余条目，"ensuring that M grows in quality rather than merely in
  cardinality"）。警告成对出现：**高质量 `Φ` + 过保守 `Ψ` = 压制真泛化**；低质量 `Φ` + 过宽 `Ψ` =
  实例噪声进 `M_p` 拉低检索精度。
- 两种失败的区分手段：*蒸馏失败* → 看 `|M_p|` 增长但 **strategy reuse rate**（执行步里引用 `M_p`
  策略的比例）≈ 0；*检索失败* → 看检索 trace 的排序 + **扰动下 rank 敏感度**（对 `t` 做保结构的
  表面改写，若 `m*` 的 rank 大变即检索失败）。
- 对 SEA-Eval 的落地建议：黑盒下只能"尽力而为"（`N_fix` 高且 `S` 稳 → 偏蒸馏失败；
  `N_fix` 低且 `T` 高 → 偏检索失败），"Full diagnostic resolution ... requires access to internal
  memory update logs and retrieval traces"。

## 主结果（数字带原文短引，逐格读表）

**设置（§5.1）**：五个被测 SEA = **GenericAgent (GA) / OpenClaw / Hermes / Claude Code / Codex**；
Easy-Correlated 上"the foundation model ... is uniformly set to **Claude Opus 4.6**；
Codex adopts **GPT-5.5** as an alternative due to architectural constraints"；
全部在容器化沙箱跑；footnote 7："Due to time and token cost constraints, a **15-minute timeout**
mechanism was applied when testing Hermes, Claude Code, and Codex"（**对 GA/OpenClaw 不对称**）。

**Table 2 · Easy-Correlated（token 单位 K，均值）**：

| Agent | R1 | R2 | R3 | A2 | A3 | SR |
|---|---|---|---|---|---|---|
| GA | 198.7 | 78.8 | 63.6 | 96.0 | 139.8 | 95.0% |
| OpenClaw | 1905.1 | 1058.5 | 1118.7 | 868.7 | 897.5 | **96.7%** |
| Hermes | 355.9 | 271.4 | 226.7 | 234.1 | 298.6 | **65.0%** |
| Claude Code | 252.0 | 94.2 | 99.7 | 171.5 | 104.8 | 91.7% |
| Codex | 128.7 | 116.2 | 115.3 | 107.2 | 157.8 | 85.0% |

- **能力幻觉的原文数**："OpenClaw's R1 mean (1905K) is **14.8×** that of Codex (129K)；
  Even after three learning rounds at the R3 stage, OpenClaw (1119K) remains **17.6×** that of GA (64K)"；
  归因 "OpenClaw's lack of prompt compression, resulting in excessive tokens wasted on redundant
  context transmission"。摘要与结论里的头条 **31.2×**（"token consumption differs by up to 31.2×
  between frameworks on individual tasks"）在正文**没有对应表格**，细粒度逐任务数据在项目页
  `leaperovo.github.io/SEA-Eval` —— **该数字的原始分布未核**（结论一节还写作 "up to approximately 30×"）。
- **演化速率（观察 2）**：GA "R1→R2 accounts for **88%** of total optimization"；
  Claude Code "R1→R2 decreases **63%**, R2→R3 only **6%**"；Codex "R1 →R3 decreases only **10%**"。
- **SR 与 T 的关系（观察 3）**：低消耗者（GA、CC、Codex）SR 85%–95%；Hermes 是反例 ——
  "even on tasks not terminated by timeout, its token consumption is already significantly higher"，
  即低 SR **不全是超时造成**（论文自认 "the timeout mechanism affects SR"）。

**四条 Finding（§5.3）**

1. **同任务学习幅度**：GA 的 R3 vs R1 变化率**中位数 −78%**（最高）；Codex −28%，论文为它辩护 ——
   "Codex’s R1-stage token consumption is already very low (129K), leaving limited optimization headroom"。
2. **两种演化范式**：GA = *iterative optimization*（逐轮压缩，学习曲线明显下降）；CC/Codex =
   *first-shot convergence*（首轮即近最优，后续波动小）。⚠ 关键混杂：**"both Claude Code and Codex
   benefit from prompt caching mechanisms ... lending their consumption data a degree of opacity —
   ostensibly “low consumption” partially derives from cache hits rather than genuine strategy
   optimization"**。OpenClaw = *pseudo-evolution*（原文 "with its R3 vs R1 change rate
   approaching zero"）。
3. **相似任务迁移**：GA 的 A3 vs R1 中位数 **−55%**（学习有效迁出同任务）；各家迁移**幅度**差别不大、
   **稳定性**差别很大 —— Hermes/CC/Codex 都有 token 暴涨的异常个案；OpenClaw"最稳"其实是
   "stagnation rather than robust transfer"。
4. **正交干扰（Fig 5）**：GA 的效率增益保持 —— 相同/相似任务中位数 **−35.2% / −29.2%**，
   但仍有个别上升案例，归因 "the insufficient stability of its memory retrieval mechanism"。
5. **OpenClaw 的脆弱**：Orth-Similar 中位数 **+22.2%**，而 Orth-Same 只有 **−13.1%**；
   "OpenClaw is the only agent whose median change rate turns from negative to positive under the
   Orth-Similar condition" ⇒ 诊断为 **shortcut memorization**（背操作答案，一遇变体即崩）。
   ⚠ footnote 8 明说：**"Hermes's orthogonal experiments have not been fully completed; related
   conclusions are preliminary observations to be supplemented with complete data."**

**Table 3 · 稳定性汇总（token 均值，K 列为相对变化）**：

| Agent | R2 | R3 | Stab-Id | A2 | A3 | Stab-Sim |
|---|---|---|---|---|---|---|
| GA | 78.8 | 63.6 | **−19.3%** | 96.0 | 139.8 | **+45.6%** |
| OpenClaw | 1058.5 | 1118.7 | +5.7% | 868.7 | 897.5 | +3.3% |
| Hermes | 271.4 | 226.7 | −16.5% | 234.1 | 298.6 | +27.6% |
| Claude Code | 94.2 | 99.7 | +5.8% | 171.5 | 104.8 | **−38.9%** |

⚠ **口径不一致（重要）**：§5.4 把 `K_eff(Stab-Id)` 定义成"正交干扰前后"（`post_same/pre_same`），
但 Table 3 的 R2→R3 数值来自 **Easy-Correlated** 序列（78.8/63.6 与 Table 2 完全相同，
`(63.6−78.8)/78.8 = −19.3%`），**不是干扰前后**；§5.4 正文又把 −19.3% 直接称作
"raw change rate"对应 `K_eff(Stab-Id)`。两处口径对不上 —— **未核**（按原文两处各自引用）。
同类问题：§5.4 称 GA 的归一化 `K_eff(Stab-Id)=0.648`，而附录 A 公式 `exp(−|−0.193|)=0.825`，
**算不出 0.648**（归一化实现**未核**）。

| Agent | Median | Mean |
|---|---|---|
| **GA** | **0.737** | **0.668** |
| Claude Code | 0.637 | 0.621 |
| Codex | 0.591 | 0.560 |

排序两种聚合下完全一致："GA > Claude Code > Codex > OpenClaw > Hermes"。分维读数：
- **GA**：四个学习维全领先，raw = "**68.0%** overall efficiency gain on identical tasks (R1→R3)
  and a **60.3%** convergence rate (R1→R2)"（我按 Table 2 复核：(198.7−63.6)/198.7=68.0%、
  (198.7−78.8)/198.7=60.3% ✓）；短板 = 归一化 `K_eff(Stab-Id)=0.648` **全场最低**；
  且 `K_eff(Ret)` **Median 0.643 / Mean 0**（"a few extreme degradation tasks pull the average into
  negative territory, clipped to 0"）—— 学习深度高但方差大。
- **Claude Code**：`Stab-Id 0.871`、`Stab-Sim 0.840`、`K_eff(Evo)=0.253`、`K_eff(Ret)=0.406`；
  **唯一在干扰后相似任务上继续优化的 agent**（raw −38.9%）⇒ 论文称其为当前唯一在
  "learning–stability" 上取得有利平衡者。
- **Codex**：`TC=1.000`（最优）、`Stab-Sim=0.969`，但 `K_eff(Conv)=0.095`、**`K_eff(Ret)=0.000`**
  —— 论文原话 "Codex pursues an extreme efficiency route, **trading minimal cost (TC= 1.000)**
  ... **for near-complete abandonment of learning capability** (Keff(Conv) = 0.095, K eff(Ret) = 0.000)"。
- 两原型结论：**Efficient Learning（GA）vs Stable Enhancement（CC、Codex）**，核心张力 =
  "the tension between learning depth and execution stability"。

**论文未报告（诚实项，不推测填补）**

1. **只报了 Easy 档**：全部结果来自 Easy-Correlated / Easy-Orth-Same / Easy-Orth-Similar 三条序列；
   18 个 Normal、2 个 Hard 原子任务、**30 条 implicit intent 序列均无结果**。
2. **Noisy 条件（预载 20 条无关技能）设计了却没给结果** —— §4.3.3 定义，§5 无数据。
3. `K_align`（用户干预率）、`N_fix`（自纠错）、`S`（步数）三个指标**只有定义、无数值结果**；
   `N_fix/S` 只在附录 C 当诊断启发式提及。
4. **重复次数、种子、方差、显著性检验：全文未报告**（grep 无 seed/variance/CI 语境）。
5. **31.2× 的出处正文未给**（见上，仅摘要/引言/贡献三处复述，细粒度在项目页，**未核**）。
6. 全部实验在**同一底座 Claude Opus 4.6**（Codex 除外用 GPT-5.5）下进行 —— 结论对"换底座是否成立"
   **未核**；Hermes 正交实验未做完（footnote 8 自认）。
7. Φ/Ψ 的失败模式诊断（strategy reuse rate、检索 trace、扰动敏感度）**只是方法论描述，
   论文没有实际测过任何一个**（附录 C 明说 "available in controlled experimental settings"）。

## 与 DWC 的映射（机制 | DWC 现状 | 判定）

| SEA-Eval 机制 | DWC 现状（代码级） | 判定 |
|---|---|---|
| **序列任务流替代孤立 episode**（R1→R2→R3→A2→A3、正交干扰、变量槽防背答案） | 计量单位是 `run_term`（一个改进周期，T1–T4 前测后测）；`_snapshot_worlds` 把每 term 尾的世界树快照进 ℋ（跨 term 持久）；`world_model.seed_tasks` 播种任务，但**无"同任务重复 + 换槽变体 + 插入干扰"的序列编排** | **缺**（评估设计级，可迁移）：变量槽 = `seed_tasks` 的参数化扩展；干扰插入可用 `ELScheduler` 之外的独立序列。这是综述 Table 8 "improvement trajectory" 行要求的东西 |
| **T 沿序列收敛（`K_eff`）作为主判据，SR 只是门槛** | `harness/run_term.py::CostLedger` 已记 `term_cost / cumulative_cost / rejected_cost`（"failed attempts and their costs also require recording"），`foundation/state.py` 有 `cost_used` 供 `C ≤ B` 判定；但**没有 per-task/per-round 的 T 序列，算不出 `K_eff(Evo)/(Conv)`**；`llm/client.py` 只见 `max_tokens` 参数，**实际用量是否落盘未核** | **缺**（低成本可补）：给 CostLedger 加 (round, task) 维度即得 T 序列 → 直接实现综述 Table 8 的 Efficiency 行 "Tokens; time; cost per validated gain"；这是三篇里对 DWC 最"即插即用"的一条 |

## 综述 L 定位

- **不是"技术"而是"评估"**：归综述 **§3.6.5 Evaluating L5 Recursive Improvement**，开篇即
  "SEA-Eval Jiang et al. [2026] and SEAGym Zheng et al. [2026a] contribute trajectory-based
  assessment: performance across rounds, held-out transfer, retention, and resource use."。
  它**不出现在 Table 2 的 L1–L5 技术族**里（它是 benchmark），出现位置是 **Table 8**。
- **Table 8 逐行对位**（f=4 = §3.6.5 + Table 8×3，我按 refmap 与原文双向核过）：
  | Table 8 行 | 测量项 | 本文贡献 |
  |---|---|---|
  | **Adaptivity** | Gain; improvement trajectory; time to target | **Jiang et al.（本文）** ← |
  | Retention | Replay loss; tasks fixed or broken | 归 SEAGym（Zheng et al.） |
  | Transfer | Held-out gains within and across domains | 归 SEAGym |
  | **Efficiency** | Tokens; time; cost per validated gain | **Jiang et al.（本文）** ← |
  | Stability | Harmful updates; largest temporary decline | 归 SEAGym |
  | Meta-recursion | Mechanism reuse; successor quality | 归 Zelikman/Zhang/Iacob + 综述自加的 L5 测试 |
  综述 Table 8 的 Note 限定："Trajectory measures synthesize the cited benchmarks" —— 即 Adaptivity/
  Efficiency 两行的措辞是综述**综合**两家写的，不是 SEA-Eval 的原词逐字。
- **structural / effective**（用综述 §3.6 的定义衡量它对 L5 的贡献）：
  - **对 structural L5 无测量**：综述定义 "structural evidence establishes that a revised mechanism
    is inherited and invoked"，并要求 "A mechanism audit should identify the revised artifact, record
    the evidence that motivated it, and verify its invocation in a later improvement round" ——
    **SEA-Eval 不审计任何被修订的机制**，它测的是 agent 行为轨迹（T 收敛、SR 斜率、迁移、干扰保持）。
  - **对 effective L5 提供的是"必要非充分"测量**：T 单调收敛能证伪伪进化（negative 证据强），
    但综述对 effective L5 要求"produces or selects better successors under comparable budgets and
    independent assessment" —— SEA-Eval 没有"修订前后机制同预算对比"这个实验（它比的是五个
    **现成** agent 框架，不是同 agent 修订前后）。
  - **定位结论**：L5 评估原语层（trajectory metrics），既不构成 structural 也不构成 effective 的
    L5 证据，而是给这两类证据提供测量工具 —— 这也正是综述在 Table 8 之后补提
    "goal selection 与 stopping 仍属待评估要求"的背景（SEA-Eval 无 goal/stopping 测量；
    此句为我据 §3.6.5 原文所作**转述**，非引文）。
- 与另外两篇的关系：AutoKernel（L2 技术）与 Trace2Skill（L4 技术）是**被评估对象的候选**，
  SEA-Eval 是**评估它们的坐标系** —— 但注意 SEA-Eval 的坐标系只覆盖"部署期记忆型进化"，
  不覆盖"代码/策略修订型进化"（后者才需要 Table 8 的 Meta-recursion 行）。
