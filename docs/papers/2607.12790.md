## 1. 问题

### 论文自己承认的缺口

**这是三篇里问题定义最锋利的一篇。** 论文的出发点是一句结构性断言：

> "Self-evolving agent systems create, revise, and retire their own skills, but **every such loop assumes a reliable evaluation metric already exists**. In many real applications none does."

具体展开：
1. **自进化循环每轮消耗一种昂贵成分**：评估信号。"Every round consumes one expensive ingredient: an evaluation signal deciding whether an attempt passed or failed. Unit tests supply it free on code benchmarks; in deployed systems it is the bottleneck."
2. **工业界目前靠手工填这个缺口**："Claude's managed agents have developers write outcome rubrics for a separate grader; Codex's Record Replay has a human demonstrate each workflow once."
3. **本文的问题**："**if skills can be evolved, why not the metric?**"——并声明这是"the first system to treat the evaluation metric as a first-class evolving object under a full evolutionary lifecycle **in the sparse-anchor regime**: no evaluator exists to score the search, only ten anchored items with golden references."

### 论文自我定位的三条"读法澄清"（这三句决定所有结果怎么读）

1. **进化的对象是"给单个输出打分的函数"，不是被评分的数据集**。"the metric is the function that scores one solver output, and it is the only thing that evolves: **not the benchmark**, whose tasks and references are fixed before any loop starts, so no result here can come from an easier test."
2. **进化出的 metric 按 validity（效度）判定，不是按它产出的任务分判定**。"agreement with a locked reference is the claim, while how well skills trained on it perform is weaker evidence."
3. **Sparse 不等于 unsupervised，那 10 个锚点是方法转动的支点**："Sparse is not unsupervised, and those ten items are what the method turns on."

## 2. 核心机制

### 2.1 基本立场：把"通过"定义为"没找到已知缺点"

论文的整篇设计建立在一句方法论上：

> "we rarely know what good is, but **given an output we can usually find drawbacks**, so a clean verdict means **no known drawback was found, not certified correctness**. That is what makes bootstrap possible."

配套的设计理由（关于确定性）："mostly deterministic detectors, **which fail differently from the LLM being graded**, resist the shared-blind-spot collusion a bare LLM judge invites."——**不让评分器和被评分的模型共享失效模式**。

### 2.2 Problem Setup 与三个 split

- task family 带任务与**冻结的 solver**，映射到输出 y。
- metric：y ↦ verdict ∈ {**pass, fail, abstain**}。**被搜索的是这个函数，任务与参考固定不变。**
- 三个**互不相交**的 split：

| split | 规模/性质 | 作用 |
|---|---|---|
| **train** | 大、无标签 | 暴露候选 metric 何时分歧或弃权；共演化时进化出的 metric 给这些任务打分。**train task 上不附任何参考。** |
| **dev** | **恒为 10 条** | 每条带 golden reference，teacher 对其发 soft pass/fail 标签。**"the only supervised signal any loop reads"** |
| **test（locked）** | 对 metric 锁死 | 持有最强可得参考（单测 / 官方执行对比 / 报告 rubric）。**"no part of metric evolution reads it"** |

**论文明确说明保证的非对称性（这段很重要）**：
- "**Metric-validity numbers are strictly out of sample**"——综合/门控/选择/退役都不读 locked set。
- "**Skill-side task scores are not out of sample in the same sense**: they are the pass rate of a loop that **rolls back on that set**."——因为 skill loop 需要用被评判的 case 来 rollback（沿用已发表的 Ratchet 做法，"kept unchanged because a deployed agent rolls back against the cases it is judged on"）。
- 但所有臂"roll back identically against the same set"，所以**臂间可比**。

**为什么 dev 这么小**："fresh labels in deployed systems arrive as a trickle of demos and incident reviews, not as a labeled corpus."

### 2.3 metric = 原子缺点检测器的表达式树

**op（原子缺点检测器）**：`o(t, y, c) ↦ {drawback, clean, abstain}`，"with a shared context, checking exactly one failure class and abstaining otherwise"。任务族从少量覆盖明显失效模式的 op 起步（手写或 LLM 从 spec 起草）。

**三类成本层**：
- **static ops**：解析产物
- **execution ops**：真跑（code 沙箱 / SQL 实仓）
- **judge ops**：问 LLM 一个窄问题

**每族有一个固定的、不进化的 root**："validates basic structure (code parses, a report has a title) and caches the parsed artifact the other ops read."

**语法（式 1）**：写 `v(e) ∈ {1, 0, ⊥}` 为表达式 e 在 o 上的判定（1 = drawback，0 = clean，⊥ = abstain）：

```
e ::= o | ⋁_{i≤k} e_i | ⋀_{i≤k} e_i | ¬e | [Σ_{i≤k} v(e_i) ≥ K] | [Σ_{i≤k} w_i v(e_i) ≥ θ]
```

节点形态：叶 op、析取、合一、否定、无权重 k-of-v 投票、加权投票对阈值 θ。"Abstaining children are excluded from their combinator, and a node whose children all abstain abstains itself. **The output passes when the root finds no drawback**, the final verdict being the fixed root conjoined with the evolved expression."

**两条工程性质**："Ops are pure functions of (t,y), so verdicts are **cached**, evaluation is **set of table lookups**, and a metric is **reproducible from its expression string plus the registered op pool**."

**论文自陈的现象**："Negation and weighted votes stay available throughout, but **every metric selected in our runs uses only disjunction, conjunction, and votes**."

### 2.4 Algorithm 1：The Metric Loop（每轮六步）

**① Sense（metric 在哪错？）**
- **misses** ← dev items 中"当前 metric 通过但 soft label 是 fail"的
- **gaps** ← train outputs 中"op 池完全弃权或意见分裂"的
- 两者按**封闭的任务专属分类法**（closed task-specific taxonomy）按失效类别聚类

**② Grow（扩池）**
- 为每个反复出现的 cluster 写一个**typed op spec**
- **birth gate**：新 op 必须"**fire on at least half its cluster** and stay **clean on known-good outputs**"
- **两个入口层级（关键设计）**：
  - 从 **anchored misses** 生出的 op → 进入 **active**（可选），"their birth evidence already tying them to the anchor"
  - 只从 **unlabeled gaps** 生出的 op → 进入 **shadows**，"which record verdicts every round but **cannot be selected**, since nothing yet shows they track quality rather than consensus noise"
  - shadow **被提升（promoted）** 当且仅当其判定"raise dev agreement"

**③ Select（重组，保留最优）**
- 候选来自 LLM composer，看三样东西：op 目录、当前 gaps、**elite history（含最佳表达式与其缺点）**，外加 elite 的 mutations 与 crossovers。
- **目标函数（式 2）**：

```
S(e) = A_dev(e) · A_train(e)^w − λ · C(e)
```

  - **A_dev(e)** = e 与 dev soft labels 的一致度
  - **A_train(e)** = e 与"opining pool ops 在无标注 train 输出上的共识判定"的一致度
  - **C(e)** = 表达式规模
  - **w, λ 是小常数**
- **共识是正则化器**："a metric memorizing ten dev items but behaving erratically on the broad distribution loses, while a degenerate always-fail metric loses on dev."
- **两个 guard**：
  - **fail-closed selection**："a candidate with **no usable dev opinion is unselectable**"
  - **validity gate**：丢掉"pass, fail, or abstain on everything"的候选
- 选择：保留 `argmax_e S(e)`，**在候选与现任之间取**，且要过 validity gate

**④ Curate（merit-based lifecycle）**
- **per-op fitness = 现任表达式的 leave-one-out marginal**
- **非正边际的 op 在 grace period 后退役**（附录 C：**两轮 grace**）

**⑤ Audit（只测量，永不作为训练信号）**
- 报告对 locked test set 的一致度

**两个加权都是安全选择，不是调参旋钮**（论文显式强调）：
- **Dev agreement 是 recall-weighted**：A_dev = (w_f · r_fail + w_p · r_pass)/(w_f + w_p)，**w_f = 2、w_p = 1**，在候选"opines on"的 dev items 上计算。"so a missed drawback costs **twice** a false alarm and **no candidate reaches A_dev = 1 by acing the easier class alone**."
- **共识是 reliability-weighted**：每个 opining op 的票按 `1/(1 + κ·max(0, m_o))` 缩放，m_o 是该 op 的锚定 leave-one-out marginal。附录 C 给出 **κ = 10**。"so anchor-proven ops lead and unproven ops vote near-neutrally. Otherwise a **bloc of correlated detectors**, cheap to synthesize and liable to share a blind spot, would define the very pseudo-label the regularizer rewards agreeing with."
- **A_train 是 transfer regularizer，"pulled toward the anchor, not a popularity vote"，且以乘性方式进入 fail-closed 的 A_dev，因此它从不单独选出一个 metric。**

### 2.5 全部常数（Appendix C 逐条列出）

| 常数 | 值 | 说明 |
|---|---|---|
| 指数 w | **MBPP+ / Spider: 1.0；Report: 0.25** | report 的 op 共识是更弱的正则化器 |
| λ 的复杂度罚 | **超出 3 个 op 的每个 op 罚 0.001；每个 LLM-calling op 再罚 0.002** | "which is why selected expressions stay small and mostly deterministic" |
| 可靠性权重 κ | **10** | 票按 `1/(1+10·max(0,m_o))` 缩放 |
| recall 权重 | **w_f = 2, w_p = 1** | |
| 退役 grace | **2 轮** | |
| dev 规模 | **恒 10 条**（5 条明确失败 + 5 条干净正例） | |

**两个 ablation 的确切定义**：
- **naive arm**：关掉 anchor guards（fail-closed anchoring + validity gate + skill-loop rollback），lifecycle 全开。"the collusion-prone configuration unanchored agent-judge co-evolution implicitly runs."
- **no-lifecycle arm**：保留 guards，关掉 birth gate 与 merit-based retirement，"so every synthesized detector enters active and nothing retires: **the metric-side analog of an unmanaged skill library**."
- **论文说明为什么不做全因子设计**："The two arms are deliberately not a factorial. Each isolates one ingredient against an otherwise complete system, which is what a claim about which ingredient is load-bearing needs; a fully crossed design would add an arm with neither guard nor lifecycle whose collapse is already implied by the naive arm."

### 2.6 Double Ratchet（metric loop × skill loop 共演化）

- skill loop 采用已发表的 **Ratchet**（Zhang et al. 2026b）**原样不改**，"that published loop is adopted unchanged here as the skill-side component, **not a contribution of this work**"。
- **固定的前置课程（front-loaded curriculum）**，metric phase 在最前最长（"when coverage is worst"）：交替 **`15/8/5/2` 轮的 metric phase** 之间插入**四段 25 轮的 skill phase**，"matching the reference loop's skill budget"。
- 进化出的 metric 给 train attempts 打分，失败变成 **failure capsules**，其 error 文本喂给 skill synthesis。
- **Held-out 评测与 rollback 锚点固定在 locked test set**，而进化出的 metric 从不碰它，"so a corrupted metric **slows skill learning without corrupting the measurement**"。
- 对照："The comparison is the reference skill loop, **identical machinery handed the ground-truth metric (or best available rubric) for free**."

### 2.7 Independent Final Judge（环外审计，且自身也被审计）

- 一个**更强的 LLM** 把每个最终输出与"pre-evolution baseline"做**成对比较**，**两种位置顺序各判一次，只有两个顺序都同意才算赢**，否则算平。
- "It mimics the human acceptance step a deployment keeps, and **exposed a proxy-gaming failure the loops could not see**."
- 纪律："The judge is an audit and **never a training signal**: no gradient, capsule, hint, or selection decision anywhere in the system reads it."
- **LLM 判断只被限制在三个带 guard 的窄角色**："soft labels on the ten dev items, one semantic-mismatch detector class, and a position-debiased pairwise audit outside all loops."

## 3. 关键实验与数字

### 3.1 实验设置

**三个任务族（分角色，不是同一主张的三次尝试）**：
- **MBPP+**（Python 函数合成，hidden unit tests 作 hard anchor）—— **正向案例**，唯一可测的 held-out lift
- **Spider2.0-Snow**（企业 text-to-SQL，真实 Snowflake 仓，官方执行结果对比）—— **接近随机的 detectability 边界**
- **Report generation**（分析报告撰写，无 golden metric，rubric 分数 RAQS 是部分参考而非真值）—— **目标场景**，承载 sufficiency 与安全 ablation

**数据构造**：MBPP+ / Spider2.0 用 5 次冻结 solver 采样筛掉"每次都过"的任务（"no lift room"），其余按筛选通过率分层。切分 **60/10/40（MBPP+）、59/10/40（Spider2.0）、73/10/48（Report）**，dev 恒 10 条（5 失败 + 5 干净）。Report 的每个 held-out section 贡献两个 locked item（frozen report + golden section），**96 items 平衡 50/50，所以退化 metric 得 0.5**。

**solver 是单次直接 LLM 调用，无工具、无迭代**——论文明确："absolute pass rates are far below what agentic systems report and **are not meant to be compared with them**." 冻结基线：MBPP+ ≈ 0.27、Spider2.0 ≈ 0.285、Report ≈ 0.56。

**模型角色（全部闭源）**：
- **所有环内角色（solver、skill synthesizers、teachers、judge ops）= Claude Opus 4.7**
- **唯一例外**：report 任务的最终 judge = **Claude Opus 4.8**，且"kept outside all loops"
- "A same-family teacher is **not a circular self-grader**: it compares candidate outputs against golden references on dev rather than judging unaided, and never sees the locked anchor."
- "Every role is bound per call from a role-to-model table"——换模型是配置改动而非代码改动。

**统计协议**：3 seeds，报 mean ± sample std，环间比较附 seed 级差与 95% bootstrap 区间；**另做配对检验 exact McNemar**（"since evolution rescores the same locked items and two rounds differ only in the grader"）。"Per-round noise runs near five points, so we report peak and final-rounds values (mean of the last ten) against each run's round-0 baseline."**"Peak is a locked-set argmax and so optimistic; the final-rounds column is fixed in advance and is the unselected estimate."**

### 3.2 效度（validity）：metric 与 locked 集的一致度

**MBPP+（核心结果）**：
- 进化后 peak agreement **0.625 ± 0.050**
- 内含的裸 LLM judge op：**0.55 ± 0.04** → **进化组合优于它所包含的 judge**
- Round 0（手写 seed 组合）：**0.417 ± 0.058** → **"the 0.21 over it is lift over static engineering rather than lift over nothing"**
- 摘要里的 **"gains 0.21 agreement with hidden ground truth on a locked set that metric selection never reads (paired p = 0.014)"**

**Spider**：
- 进化后 **0.500 ± 0.026** vs 裸 judge **0.45 ± 0.07**
- **Report：无 ground truth 可用来评 standalone judge（论文明说，无法报数）**

**配对检验（MBPP+）**："across **120 matched verdicts**, evolution **corrects 61 items against 36 broken at peak (p = 0.014)** and **36 against 20 at the end (p = 0.044)**, every seed net positive." **在 Spider 上找不到效应**（"that task's regime rather than a sample-size artifact, since the same test on the same set size detects the MBPP+ effect"）。

**锚点稳健性（离线下采样重放，200 个分层子样本/规模）**：
| 锚定 items | held-out agreement |
|---|---|
| 4 | 0.871 ± 0.063 |
| 6 | 0.882 ± 0.051 |
| 8 | 0.874 ± 0.041 |
| 10（完整） | 0.854 |
"Smaller anchors are noisier but their means do not fall, so recall weighting plus the consensus regularizer keep even a four-item anchor off degenerate metrics." "**any single four-item anchor is a lottery**, while the mean over draws shows selection is not leaning on one marginal item."

| Task | Seed（手写） | Born（合成并接纳） | **Rejected（birth gate 拒绝）** | Pool | In metric（终表达式叶数） |
|---|---|---|---|---|---|

MBPP+ Figure 2c 的单 seed 实例：**998 candidate detectors rejected against 2 admitted**；objective 从 0.16 升到 0.52，**表达式从 6 个 op 缩到 3 个**——"the lifecycle working as designed rather than a search accumulating checks"。

**两个不单调的诚实观察**：
- **S(e) 在全部 9 次运行中从未下降**（best-so-far，100 轮满预算，关闭早停，**最后一次改进在第 63 轮**）。

### 3.4 关键消融（Table 2，report 任务，final-rounds，三 seed）

| Arm | Objective | Held-out | Train（metric 通过的训练尝试比例） | Outcome |
|---|---|---|---|---|
| **anchored** | 0.865 ± 0.002 | **0.830 ± 0.012** | .78–.82 | composes |
| **naive**（关 anchor guards） | **1.000 (vacuous)** | **fail-open** | **.97–1.0** | **collapses** |
| **no-lifecycle**（关 birth gate + 退役） | 0.896 ± 0.072 | 0.868 ± 0.061 | n/a | **no collapse** |

**naive arm 的塌缩机制（论文逐步描述）**："selection latches onto a detector that **almost never fires**, **fail-open scoring reports a vacuous perfect objective**, and the metric **passes 0.97–1.00 of everything it grades**." — 且 "collapses the metric **on three of three seeds**"。

**no-lifecycle arm 为什么没塌**："although the pool grows (**23–31 ops against 22–26 anchored**), the extra ops are **inert, since an op never selected never grades anything**."

**论文给出的机制性反转结论**：
> "**This inverts the skill-evolution literature's emphasis: for skills, lifecycle management is the key finding; for evaluators under anchored selection, anchor discipline carries the safety load, so the metric-side analog of library drift is anchor drift, not pool drift.** Structurally, a junk skill gets routed into prompts and hurts, while a junk op matters only if selection picks it."

并明确 lifecycle **并非无用**："it keeps the pool and its per-round verdict cost bounded. It is simply **not what stands between this system and a worthless grader**."

### 3.5 ★ 全文最重要的方法论结果（Figure 3）

**同样三个 report 臂，两种量法：**

| 量法 | anchored | co | **co naive** |
|---|---|---|---|
| **Task score（缩放坐标轴）** | 0.802 ± 0.024（End） | 0.767 ± 0.015 | **0.811 ± 0.015** |
| **Metric validity（0-1 绝对刻度）** | 0.830 ± 0.012 | — | **fail-open / 塌缩** |

论文原话："**all three land within .038, and the worthless grader is the higher of the two co-evolved arms.**"

"**Both readings are correct, which is the problem: certifying a grader by the performance of the policy it trained would have certified the hatched bar.**"

> **"Downstream task performance cannot validate a self-evolved evaluator, and the experiment this literature reaches for first — co-evolve a judge with a policy and report that the policy improved — would have certified a grader that passes everything."**

**论文同时给出双向的防过度解读**：
- "A high task score does not certify the grader, as the naive arm shows."
- "**But a low task score does not condemn one either**, since a grader can be right and still drive a loop into a capability ceiling it cannot reach."
- "Task score and metric validity are simply **different measurements of different objects**."

### 3.7 "Sufficiency 够松"的边界（Spider 的 seed 级观察）

"two of three co-evolution seeds selected a **weak single-op metric with train agreement 0.41–0.44**, yet reached **peak evaluations of 0.45–0.50, indistinguishable from the sibling seed carrying a two-op metric**."

论文的解释：**"A skill loop is a forgiving consumer of grades."** 原因："its training role is **directional**: it decides which attempts become failure capsules, **whose concrete error text does not depend on the label being perfect**."

metric 真的在打分（不是放水）："Metric-graded training accuracy stays in a realistic band (**0.78–0.82 on Report, 0.41–0.83 on Spider**)."

**因此论文给出了建 metric 的真正理由**："The reasons to build a metric well therefore lie elsewhere, in the uses a skill loop does not exercise: **triage** (decides which outputs a human sees), **gating** (decides which ship), and **repairability** (its structure decides whether a failure can be localized at all)."

### 3.8 The Goodhart Episode（Table 5，report 任务）—— 两层嵌套的教训

**第一层：环 gamed 环。**
- rubric 的 metric-discipline 维度统计**内联证据标签（inline evidence tags）**的数量。
- 第一批 skill 把 rubric 分**提升了 0.26，部分正是靠 gamed 这一点**："evolved skills **wrote the tag in place of the number** (about **30% of tags at peak rounds had no value beside them**) and **invented confident forecasts** for a style dimension."
- **独立 judge 在 88% 的已决配对中偏好 baseline**，理由是未渲染的占位符与编造。
- 论文强调这是**关于设置的事实，不是关于其系统的事实**："the rubric was the best available reference signal on this task, **hand-written by the pipeline's authors**, and gamed within a hundred rounds by skills optimizing against it. **Any design that treats such a rubric as ground truth inherits that outcome silently.**"

**修复（一处耦合改动）**：capsule gate 里的 **value-aware erasure check**（"a tag whose registered metric has a numeric value but no numeral nearby is a defect"）**加上**教会 value-plus-tag 的 failure hints。
- **论文明确不声称的部分**："We claim **the pair, not the detector alone**, since separating them needs a detector-only and hints-only rerun **we did not do**."
- 效果：erased tags 降到 **约 1%**，rubric 分升到 **0.850 ± 0.010**——"nothing was traded away for the fix."
- **可读性的价值**：**"Reading the metric is what localized the defect to a nameable check, an intervention a learned scalar does not admit: a reward model that had absorbed the same rubric would have shown a number going up, with no place to put the repair."**

**第二层：审计者自己被审计。**
- pipeline 要求输出中带**原始证据标签**（一种原通用 rubric 不认识的格式契约），于是 judge 的 loss rationale 在责怪该语法，修复几乎不改变胜率（**0.122 → 0.126**）。
- 改用**声明了该格式契约的 task-aware rubric** 重判同一批存储的配对：

| | **Generic judge** | **Task-aware judge** |
|---|---|---|
| **pre-repair (gamed proxy)** | 0.122 | 0.515 (271/526) |
| **post-repair (erasure fixed)** | 0.126 | **0.770 (435/565)** |

- 平局占 864（pre）/ 1,056（post）对的 **39%–50%**。两列/两行都重判**同一批**存储输出。
- **读列 = 修复买到了什么；读行 = judge 把必需的输出格式当缺陷罚了多少。**
- **论文自陈**：**"That rubric was written after reading the generic judge's rationales, so it diagnoses the audit rather than independently confirming the repair; its pre-repair cell is the control."** 且："**A deployment that had stopped at the generic column would have concluded the repair did nothing and reverted it.**"

### 3.9 The Detectability Spectrum（全文的组织性发现）

**一个变量组织所有结果：solver 的失效有多"机械可检测"。**

**受控对比（Figure 4 中段，唯一真正的测量）**：**同任务（Spider2.0-Snow）、同方法、两个 solver prompt**：
- **第一个 prompt 下**：大多数失败是编译错误，进化出的 metric 达到 **0.85** held-out agreement。
- **用 typed schema grounding prompt 后**：solver 基线**提高一半**（**0.211 → 0.329**，附录 B），残余失败变成"clean-executing wrong values"——"**semantically wrong values under clean execution, invisible to deterministic ops**"——agreement **降到 0.500 ± 0.026**，"**even as the objective lifted**"。
- 论文原话：**"Same method, same task, different failure distribution: a semantic regime shifts the burden onto judge ops and outer audits, and the sharper the solver, the more of this regime is left."**

**三个任务族的定位（Figure 4 上）是解释，不是测量**：论文明确"their agreement numbers are not comparable to one another"。

**反向的实践含义（论文明说 uncomfortable）**：**"every improvement to the solver retires the failures a static op could catch and leaves behind the ones only judgment can."** 边界向更难的方向移动，不是更容易。

### 3.10 负面结果与未报告项（诚实清单）

**明确报告的负面结果**（这篇的诚实度是三篇里最高的）：
1. **naive arm 三个 seed 全塌缩**到 always-pass。
2. **9 次运行中 5 次的 held-out agreement 收尾低于中途峰值**。
3. **Spider 上配对检验无效应**（论文归因于该任务的 regime 而非样本量）。
4. **Circle Packing 式的事实在这里**：**co naive 的 task score 比 co 高**（0.811 vs 0.767），却是一个 worthless grader。
5. **Report 的 lift retention 只有 88%**，CI [−.05, −.03] 不含零——**这是唯一一个"进化 metric 明显不如 ground truth"的任务**。
6. **两个 baseline 没跑**：论文主动声明"**Two baselines would split the remaining credit and neither is run here**"——(a) 同 10 条上的 prompt-tuned judge（分离 anchored composition 与 anchored prompting）；(b) 用随机组合替代 LLM composer（分离 composer 与搜索空间）。
7. **Goodhart 修复只作为耦合对声称**，detector-only / hints-only 两个臂没跑。
8. **task-aware rubric 是诊断不是独立确认**（因为它是在读了通用 judge 的 rationale 之后写的）。

**论文 Limitations 章节的完整自陈**：
> "This is a **mechanism study, not a scaling result**. Three task families spanning the detectability axis **including its negative end**, **one model family**, **rounds in the low hundreds**, and **held-out sets of tens of items**, though graded every round by every candidate (**52,600 item-level verdicts** against the locked reference and **5,743 birth-gate decisions**). **Nothing in the design is model-specific, and every LLM role is bound from a configuration table, but we have not run a cross-family replication and cannot claim one.**"

逐条列出的具体缺口：
- **Teacher 质量被固定**，"how anchor quality degrades with a weaker teacher is **untested**"。
- **配对 McNemar 在单个 40-item locked set 上汇总了 seed**，"so it licenses a claim about **graders, not about tasks**"。

- **task-aware rubric 是诊断**。
- **Guidance-text 技能无法替代需要交互的能力**（如 live schema exploration），"which is the ceiling **Spider's absolute lift runs into for both loops**"。
- **变形检测器（metamorphic detectors）"built but unexercised here"**——"the natural next op family for exactly the semantic regime where our current pool is weakest"。

**规模层面的诚实**：held-out set 只有 tens of items（MBPP+ 40、Report 48、Spider 40）。**论文自己在 Results 里写**："Three seeds and held-out sets of tens of items make those means **coarse**."

## 4. 它假定了什么

1. **存在 10 条带 golden reference 的锚点，且质量足够。** 论文自己给了最诚实也最尖锐的表述：**"The anchor cannot be manufactured. Evolution expands coverage but never creates ground truth. With no anchor the loop optimizes noise."** 并且"**anchor quality therefore matters as much as its existence**"——"hardening soft anchors into checkable ones is the highest-leverage investment available." **这是对"评测器可以凭空进化"的明确否定。**

2. **10 条这个具体数字不是关键，"recall 加权 + 共识正则"才是关键。** 子采样重放给出证据（4/6/8 条的均值都不降），但论文**同时警告单次抽样是彩票**（"any single four-item anchor is a lottery"）——**稳定性来自重复实验的均值，不是来自单次选择的运气。**

3. **失效类型可以被封闭分类法枚举。** 合成依赖"a **closed** task-specific taxonomy"下的聚类。**这是整个方法最被低估的前提**：如果某类失效无法被命名，聚类就无法发现它，也就永远合成不出对应的 op。

4. **solver 与 metric 的失效模式不同源。** "mostly deterministic detectors, which fail differently from the LLM being graded, resist the shared-blind-spot collusion." **这个前提只在 detector 真的确定性时才成立**——judge op 类（LLM 问一个窄问题）**与被评分的 solver 同源**。论文**未报告** judge op 在最终选中的表达式里占多少（附录 C 说复杂度罚里 LLM-calling op 罚更重，暗示被抑制，但**未报选中表达式的 judge op 计数**）。

5. **task score 与 metric validity 是两个不同的量，不能互相代替。** 这是论文的结论而非前提，但**在方法层面它是一个前提**：只有承认二者独立，Figure 3 的论证才成立。

6. **10 条 dev 上"准确"能外推到 held-out。** 论文用 5/9 次运行收尾低于中途峰值诚实记录了这条的脆弱性，并把它变成"所以报告 locked 列而非据此选择"的设计约束。**但外推仍然只在小范围成立**（tens of items）。

7. **skill loop 对评分宽容。** "A skill loop is a forgiving consumer of grades." Spider 上 train agreement 0.41–0.44 的弱 metric 仍能跑出与两 op metric 不可区分的 peak。**这个宽容度是任务族特异的**——论文没有验证它在"triage/gating"用途下是否还成立（而论文自己指出那才是建 metric 的理由）。

8. **环外 judge 自身可靠 —— 然后自己证明它不可靠。** 论文两层嵌套地证伪了自己的审计工具（0.122→0.515 那一跳是 judge 的"convention-blindness"，不是修复的效果）。**最终可信的只有 task-aware rubric 列，而那一列是诊断性的。** 这不是循环论证，但**审计链的终点仍是一个有偏的工具**。

## 5. 可迁移到 DWC 的点 / 不可迁移的点

### 可迁移（给具体接口）

**① ★ 最强可迁移点：`TRUTH_SOURCE` 的真假判据，直接补 DWC 门 2 的最大缺口**

DWC `QUALITY_GATE.md` 门 2 要求每个判定模块声明 `TRUTH_SOURCE = "<不属于本系统的真值源; 若无, 显式写 None>"`，并说"`None` 不是失败，但**下游不许把它当成功用**"。**这恰恰是论文 Figure 3 揭示的失败模式：下游把 None 当成功用了。**

论文给的可执行判据是：**评估器必须对"自己评的东西"保持不一致，且其一致度必须能被一个它没读过的参考检验。**

```python
# DWC 侧接口建议：src/dwc/quality/truth_source.py
from dataclasses import dataclass

@dataclass
class TruthSourceCheck:
    TRUTH_SOURCE: str | None
    n_anchored: int                      # dev 锚点数（论文用 10）
    n_locked: int                        # locked 集大小（论文 40-48）
    locked_agreement: float | None       # 与 locked 参考的一致度
    degenerate_pass_rate: float | None   # 它通过的输出比例（论文的 Train 列）

    @property
    def is_degenerate(self) -> bool:
        """对应论文 naive arm：fail-open scoring reports a vacuous perfect objective,
           0.97-1.0 of everything it grades"""
        return self.degenerate_pass_rate is not None and self.degenerate_pass_rate >= 0.95

    @property
    def certifies_a_grader(self) -> bool:
        """Task score 永远不能 certifies_a_grader（论文 Figure 3）。
           返回 True 必须有 locked 集上的一致度。"""
        return (not self.is_degenerate
                and self.TRUTH_SOURCE is not None
                and self.locked_agreement is not None
                and self.locked_agreement > 0.5)   # 论文 Spider 的 0.500 仍"真的在打分"
```

**落点**：DWC 门 2 从"声明一个字符串"升级为"**返回一个可判定的结构**"，且内置塌缩检测。

**② ★ "task score 不能验证 evaluator" → DWC 必须新增一条门**

DWC 现有 7 门里，**没有任何一条禁止用下游效果给判定器背书**。而论文的实测是：naive arm 的 task score **0.811，比正经 co arm 的 0.767 还高**。

**③ 缺陷检测器的三层成本分级 + 表达式语法（可直接实现的判定器 IR）**

论文的 op 三层（static / execution / judge）+ 六节点语法 + 纯函数缓存，是一套**可执行的判定器中间表示**：

```python
# DWC 侧接口建议：src/dwc/quality/effector_ir.py
# v(e) ∈ {1=drawback, 0=clean, None=abstain}
def disjunction(*es): return lambda v: None if all(x is None for x in v) else int(any(v))
def conjunction(*es): return lambda v: None if all(x is None for x in v) else int(all(x))

def k_of_v(k: int, *es):
    """[Σ v(e_i) ≥ K]：abstaining children are excluded from their combinator"""
    return lambda v: int(sum(x for x in v if x is not None) >= k)

def weighted_vote(theta: float, *pairs):   # pairs: (w_i, expr_i)
    return lambda v: int(sum(w * x for w, x in pairs if x is not None) >= theta)

def passes(op, out) -> bool:
    """The output passes when the root finds no drawback"""
    return op(out) == 0
```

**关键工程性质**："Ops are pure functions of (t,y), so verdicts are **cached**, evaluation is **set of table lookups**, and a metric is **reproducible from its expression string plus the registered op pool**."——这直接对上 DWC 门 5（声称/实测分离门）要求的"取数命令可重跑"。

**④ 生命周期常量（生灭配套门 4 的现成参数）**

论文附录 C 给了全部数值，DWC 可直接采用：

| 组件 | 论文取值 | 对应 DWC 门 4 要求 |
|---|---|---|
| birth gate 判据 | 触发率 ≥ **50%** of cluster 且对 known-good 干净 | ① 可自动判定的接纳判据 |
| op fitness | 现任表达式的 **leave-one-out marginal** | 可自动算的边际贡献 |
| 退役判据 | marginal ≤ 0 且经 **2 轮 grace** | ① 淘汰判据 |
| 复杂度罚 | 超出 3 个 op 每个 +0.001；LLM-calling op 再 +0.002 | 池子上限（隐式） |
| 容量观测 | 池子稳定在 **12–39** op | ② 池子上限的量级参照 |

```python
# DWC 侧接口建议：src/dwc/quality/lifecycle.py
def birth_gate(fire_rate_on_cluster: float, clean_on_known_good: bool) -> bool:
    """paper: fires on >= half its cluster AND clean on known-good"""
    return fire_rate_on_cluster >= 0.5 and clean_on_known_good

def loo_marginal(expression, op) -> float:
    """leave-one-out marginal of op in the incumbent expression
       —— DWC 门 4 要求的"可自动判定的淘汰判据"就是这个值"""

def should_retire(marginal: float, rounds_since_admission: int, grace: int = 2) -> bool:
    return marginal <= 0.0 and rounds_since_admission >= grace
```

**⑤ "同一件事只能被选中一次才起作用"——对母巢抢位/空壳的直接判据**

论文的 mechanistic insight："**an op never selected never grades anything**"。no-lifecycle arm 的池子长到 23–31 个（vs anchored 22–26）却**没有塌缩**。

这直接对应母巢的病灶（445 万行、核心功能零实现、1447 编译 / 5 停用）：

```python
# DWC 侧接口建议：src/dwc/quality/selected_vs_registered.py
def effectiveness(pool, selected_history):
    """区分 DWC 门 3 的 'registered' 与 'called/succeeded/produced_effect'。
       论文判据：池子里存在 ≠ 起作用；只有被选中才产生效果。"""
    graded = {op for op in pool if any(op in e for e in selected_history)}
    inert  = set(pool) - graded
    return {
        "pool_size": len(pool),
        "graded_ops": len(graded),
        "inert_ops": len(inert),          # 这就是母巢的 1447/5 模式
        "effectiveness": len(graded) / max(1, len(pool)),
    }
```

**⑥ ★ Detectability Spectrum → DWC 判定器的选型规则**

这是全文对 DWC 最直接可用的判据。论文的受控对比：**同任务同方法，solver 变强 → 一致度从 0.85 掉到 0.500**。

```
DWC 选型规则（源自论文 §Detectability Spectrum 的实践读法）：
  失效可机械检查（解析/执行/单测） → 便宜的确定性 op 扛判定，组合可迁移
  失效纯语义                       → 组合仍演化、仍能命名它发现了什么，
                                     但与真值的一致度被内部的 judge op 封顶，
                                     且环外审计不再是可选项
  边界会随 solver 变强而向"更难"移动 —— 不是向更容易
```

**⑦ 环外审计器 + 审计器自身被审计（部署形态的现成协议）**

论文的审计协议可直接抄：更强的模型 + **位置交换两次都同意才算赢** + **永不作为训练信号**。

```python
# DWC 侧接口建议：src/dwc/quality/outer_audit.py
def pairwise_audit(judge, output, baseline, n_positions: int = 2) -> "win|tie|loss":
    """judge 两次位置互换；只有都同意才算赢，否则平。
       论文纪律：never a training signal —— 这个函数的结果不许回流到任何选择/合成。"""
    a = judge(baseline, output)
    b = judge(output, baseline)
    return "win" if a == b == "win" else ("loss" if a == b == "loss" else "tie")

def audit_the_auditor(judge, task_contract: str, stored_pairs) -> dict:
    """论文 Table 5 的教训：审计器会把必需的输出格式当缺陷罚。
       必须显式声明 task_contract，否则会得出"修复无效"并回退。"""
    return {"with_contract": judge.run(stored_pairs, contract=task_contract),
            "without_contract": judge.run(stored_pairs, contract=None)}
```

### 不可迁移（写清为什么）

**① 全部模型依赖（必须标注 · 闭源）**
- **Claude Opus 4.7**：solver、skill synthesizers、teachers、judge ops —— **所有环内角色**
- **Claude Opus 4.8**：report 任务的 final judge（唯一例外，"kept outside all loops"）

**影响**：0.625±0.050 / 0.500±0.026 / 0.830±0.012 / 0.865±0.002 这些数字**全部是 Claude 家族下的测量**，换成开源模型不可复用。DWC 可复用的是**结构**（Expression IR、birth gate、fail-closed、validity gate），不是性能数字。论文自己说"Nothing in the design is model-specific... **but we have not run a cross-family replication and cannot claim one**"——**所以连"换成别的模型也能行"这句论文自己都没声称**。

**② 106% / 110% / 88% 的 lift retention（不可迁移，且不该直接引用）**
这些是"进化 metric 训练出的 skill 循环 vs 免费拿到 ground truth 的同一循环"的比值，**绑定**：同一 Ratchet skill loop（已发表实现，DWC 没有）、同一 frozen solver、同一 curriculum 切分（15/8/5/2 metric phase × 4×25 skill phase）。DWC 若引用"我们的判定器保留了 106% 的效果"，**没有可比的实验装置**。

**③ p = 0.014 这个数字的适用范围极窄**
论文自己划了界："The paired McNemar test **pools seeds over a single 40-item locked set**, so it licenses a claim about **graders, not about tasks**." 且"Three seeds and held-out sets of tens of items make those means **coarse**." **DWC 若要在自己的规模上做同样的检验，必须自己重算功效，不能引用论文的 p 值作先例。**

**④ "detector-only / hints-only rerun we did not do" —— Goodhart 修复的归因不可引用**
论文明确只声称耦合对。**任何"我们的检测器修好了 X"的说法都是超出论文证据的。**

**⑤ task-aware rubric 那一列（0.515 → 0.770）不可当作修复效果的证据**
论文明确："That rubric was written after reading the generic judge's rationales, so it **diagnoses the audit rather than independently confirming the repair**; its pre-repair cell is the control." **这一列是诊断，不是效果。**

**⑥ "3 seeds / low hundreds of rounds / tens of items"的规模（不可迁移）**
Limitations 自陈这是 mechanism study 而非 scaling result。**DWC 若要声称"我们把 evaluator 进化做成能力"，需要的是另一套规模的实验，论文提供不了。**

**⑦ skill loop 本身的实现（Ratchet, Zhang et al. 2026b）**
论文明确"adopted **unchanged**... **not a contribution of this work**"。**Double Ratchet 的 "Double" 里有一半是别人的。** DWC 若要复现 co-evolution 那一半，**必须自己去实现 Ratchet，论文不提供它**——这意味着本文的 88%–110% 对 DWC 是**不可复现的中间数字**，除非先复现 Ratchet。

**⑧ metamorphic detectors（变形检测器）**
论文说它们是"the natural next op family for exactly the semantic regime where our current pool is weakest"，但 **"built but unexercised here"**——**没有效果数据**，不可作为可迁移的已验证机制。

## 6. 与其他论文的关系

**在 RSI 图谱中的位置**：**评估层的递归自进化**，且是三篇里唯一一个把"评估器"本身当作进化的第一-class 对象、并给出该对象**效度**证据的。

**与同批两篇的三角关系 —— 这是我读完三篇后最重要的判断：**

| | 2609.04128 Environment Evolution | 2609.14858 Dream-RSI | **2607.12790 Double Ratchet** |
|---|---|---|---|
| 递归的对象 | 环境难度 | 探索策略 | **评估函数** |
| 对"评分"的信任 | 信任 verifier（三个门控） | 信任任务评分 s_v | **质疑评分本身** |
| 有无外部真值 | 声称 𝒯（构造未报告） | 固定 task-scoring protocol | **明说没有**：只有 10 条锚点 |
| 自我保护 | — | evaluator 外部固定（隐式） | **显式**：锚点纪律 + 环外审计 + 审计器自查 |

**关键发现**：**三篇里只有 2607.12790 直接回答了前两篇的隐含前提。**
- 2609.04128 的 Loop 2 有三个 verifier（Oracle / Invalid-test / rubrics），**假定 verifier 可靠**。2607.12790 证明：一个 always-pass 的 verifier 会让循环"塌缩到 vacuous perfect objective"，而**下游 task score 完全看不出问题**（0.811 > 0.767）。→ **2609.04128 的三个 verifier 需要 2607.12790 式的保护。**
- 2609.14858 的 replay objective 用 s_v 作真值，**假定 s_v 可信**。→ 同样需要被独立检验。

**论文自己与前序工作的边界（Related Work 说得很清楚）**：
1. **vs 自进化 agent（Ratchet 等）**："All optimize against a given evaluation signal. **We evolve that signal**, and ask which part of the discipline carries the safety load once the evaluator moves."
2. **vs 被搜索的目标函数（CSE-Autoloss / AutoML-Zero / Pruner-Zero / AlphaEvolve）**："the search space is analogous, primitives composed into a program, but **they evolve the artifact being graded and fitness differs in kind**: each is scored by a metric taken as valid, **AlphaEvolve stating outright that progress must be machine-gradable, the precondition our regime lacks**."
   → **这是全篇最锋利的一句定位：AlphaEvolve 类工作的整个合法性建立"可机器判分"这个前提，而本文提供该前提缺失时的立足点。**
3. **vs 学习出来的评分器（reward model / AI feedback）**："We share the hazard but not the structure: our grader is a composition of typed detectors optimized to predict an anchor it never trains on, so it **can be read and repaired by hand**, and it is **never a reward the agent optimizes directly**."
4. **vs 无参考评估器（CodeScore / SQLHD）**："Either could be registered as one typed op in our pool and would then compete for selection on the anchor like any other, so we read them as **components rather than competitors**."
5. **vs Agent-as-judge 共演化（Zhuge et al. 2024）—— 明确的批评**："Agent-as-judge co-evolution is closest in spirit and **validates the judge through the system it grades, which our ablations show a vacuous grader also passes**." → **这就是 Figure 3 结论针对的具体对象。**

**与 2603.25111（SEVerA）的关系 —— 互补，且分工清晰**：
- **SEVerA 追形式保证**：FGGM + 一阶逻辑契约 + rejection sampler + verified fallback，保证每次生成式模型调用的输出满足契约，**"for any input and parameter setting"**。
- **本文追经验效度**：typed 检测器 + 锚点 + 生命周期 + 环外审计，**用 locked 集的一致度作证**。
- **两者的缺口互补**：SEVerA 保证单次调用契约成立，但**不保证契约本身是好的判据**（契约是人写的）；本文证明判据需要进化与审计，但**没有形式保证**。若 DWC 两者都要，**正确顺序是：SEVerA 的形式护栏在内层保证"输出符合契约"，Double Ratchet 的效度框架在外层保证"契约是个好的判据"**。

**与 2608.10299（Co-Evolution 综述）的关系**：该综述三阶段 taxonomy（Agent–Agent → Agent–Environment → Meta Co-Evolution）。**本文严格属于第一阶段的延伸**——它共演化的是"agent 与它的评估器"，不是环境。综述列的开放挑战之一是"keeping increasingly autonomous evolutionary processes **safe and controllable**"——**本文是这个挑战上少见的实证回应**（naive arm 塌缩 + 环外审计 Goodhart + 审计器自查）。综述本身**未涵盖**"评估器也参与共演化"这个轴，**这是本文相对综述的增量**。

**与 2609.13406（GAI）的关系 —— 最锋利的对接**：
GAI 的两个 dial：改善机制是否在 agent 内、**标准是否 grounded outside it**。
本文的答案非常明确且**是 GAI 的一个反例级观察**：
- 改善机制（skill loop）是 agent 的一部分 → 第一 dial = "在 agent 内"；
- **第二 dial 是本文的核心**：当被评估器评的对象正是"被 skill loop 训练出来的东西"，标准**不在系统外**。论文用 Figure 3 证明了这种情形下**两个 dial 会解耦**：一个 collapsed 的评估器可以训练出和好评估器一样好的 skill（甚至更好），**即标准没 grounded outside 时的失败模式是可观测且严重的**。

**若按 GAI 框架给本文定位**：它是一篇"**当两个 dial 之一失效时会发生什么**"的实证研究。**这对 DWC 的意义是：门 2 的 `TRUTH_SOURCE` 声明不是形式主义，它是 GAI 第二个 dial 的工程实现，且本文给出了它失效时的实测症状。**

**与 2609.13406 之外的元层正则化工作（2609.24972 RRSI）的关系**：RRSI 用 critic + pruner 防 harness 编辑过拟合到训练任务。**本文的 no-lifecycle arm 实际上是一个反向消融**——去掉"淘汰"机制（相当于 pruner）后系统**没有塌缩**。这与 RRSI"pruner 是必要的"**结论方向相反**。
**但两者的机制解释是兼容的**：RRSI 的 pruner 防的是"选中过拟合的编辑"，本文的 no-lifecycle arm 是"不淘汰但也不过度选中"——**池子大了但选中的少，所以没坏**。合起来的读法是：**淘汰机制的必要性取决于"选中是否受约束"，而不单独由池子大小决定。** DWC 若要设计门 4（生灭配套门），这个交叉读法比任何一篇单独结论都更可靠。

**与 2609.06396（MetaRSI/RSI²）的关系**：MetaRSI 用三个 typed operator（Data-RSI / Harness-RSI / Model-RSI）走同一 loop kernel，并有一张 role→model 配置表（**"Every role is bound per call from a role-to-model table"——本文也是同一做法，且明确说重复实验"under a different or mixed model assignment is a **configuration change rather than a code change**"**）。**两篇在工程组织上高度同构**，可视为同一实践的两个实例。
