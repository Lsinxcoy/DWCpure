## 1. 问题

### 论文自己承认的缺口（§1 + §3.1 + §5）

1. **研究效率本身是固定的。** §1 原文："Such systems improve the efficiency of the artifacts they produce, such as training and inference efficiency, yet **the efficiency of the research process producing them remains fixed**."
2. **动机是一个长期趋势的对冲。** §1 + Abstract："Its significance lies in a long-standing trend, in which **increased cumulative spending on R&D yields diminishing returns**. Sustained self-improvement offers a way to counter this trend."（引 Bloom et al., 2020）
3. **已有 RSI 在这个目标上效果不明。** §1："Recent self-improving systems show promise in coding and other domains, yet **the effectiveness of their improvement loops at optimizing frontier AI research efficiency remains unclear**."
4. **§4 明确指出的既有路线缺口（三条，本篇的差异化）**：
   - **LLM-driven search 派**："These systems optimize an artifact that aims to solve a given problem. **The procedure that drives the optimization remains largely hand-designed through human-driven R&D.**"
   - **Automated harness search 派**："In these works, **the harness being optimized is separate from the procedure that optimizes it.**"
   - **Self-referential improvement 派**："These works typically use a **proxy metric** to steer self-modification. Agent performance on software engineering, for example, can serve as a proxy for the ability to write code that improves the agent's own architecture."
   > 本篇的定位句（§4 末）："**AIDE² instead targets the agent's own capability on AI R&D tasks.**"
5. **§3.1 的四条实验设计准则**（这是论文自设的"怎么证明不是运气"）：
   - 同一次运行必须产生**多个**新 incumbent——"as one favorable rewrite cannot show that the loop repeatedly finds useful improvements"；
   - **固定评测预算**——"so that a measured gain reflects a **better algorithm rather than additional compute**"；
   - **泛化检验**——"Improvements selected on a set of tasks must remain useful on tasks that were not involved in selection"；
   - **强基线对照**——`AIDE_human`，两年人驱 R&D 的生产级研究 agent。

## 2. 核心机制

### 2.1 双层优化的问题形式（§2 + §2.1）

**内环**：给定代码库与可测指标，内环 agent `a` 迭代改代码。记 `x` 为候选解、`r_t^pub` 为 agent 在任务 t 上**看到的信号**、`x_0` 为任务现有代码库、`x_i` 为已产生的编辑：

```
x_i = a( x_i, r_t^pub(x_i) )                                (1)
```

"until a **fixed dollar budget b_t** is spent, covering the agent's tokens and the cost of executing its solutions."
**关键结构事实**：agent 自己选 `x̂_t`（返回哪一个候选）；**"Which candidate to edit next, which to return, and how to structure the agent's memory are all part of the agent's code and are editable by the outer loop."** —— 这三项就是可被外环改写的全部空间。

**Grading**（Eq.2）：

```
g(a) = (1/T) · Σ_{t=1..T} r_t^priv( x̂_t )
```

`r_t^priv` 是**私有 held-out 数据**上的分数；每个任务独立跑若干次后平均。

**外环**：在替换 `(a, x, r_t^pub) ↦ (a^out, a, g)` 下，Eq.1 变成：

```
a_k = a^out( a_k, g(a_k) )                                  (3)
```

**外环选择是固定的**（Eq.4）：

```
a*_k = argmax_{a ∈ a_{≤k}} g(a)
```

对照之下，**内环选择是 agent 可编辑的策略**，运行中被反复改写；外环选择写死。论文明确了这个不对称。

### 2.2 论文自陈的双重防钻空子设计（§2.1 末，本篇最值得抄的一段）

> "Since the outer loop selects inner-loop agents according to g, **two properties of g shape the resulting selection pressure.** First, **separating the inner loop's optimization signal r_t^pub from the outer loop's selection signal g** (driven by r_t^priv) **prevents the inner-loop agent from directly optimizing the criterion used for outer-loop selection.** Second, **evaluating all agents under the same per-task budget b_t constrains improvements to arise from a better algorithm rather than from spending additional compute.**"

**第一条 = 内外的信号解耦**（内环看 public，外环看 private）；
**第二条 = 预算恒定**（改进只能来自算法，不能来自多烧钱）。
§3.4 回头验证了这条设计："we design alg. 1 to limit this risk by decoupling the inner- and outer-loop optimization signals."

### 2.3 Algorithm 1（原文伪代码，逐行）

```
Algorithm 1  Recursive self-improvement
 1: 初始 agent a_0、外环 agent a^out、任务 {t} 与预算 {b_t}、轨迹长度 K
 2: function Grade(a)
 3:   for all tasks t = 1,…,T do                        ▷ 在每个任务上运行 a
 4:     x_0 ← task t 的现有代码库;  i ← 0
 5:     while 总成本 < b_t do                           ▷ agent tokens + 解执行
 6:       i ← i + 1
 7:       x_i ← a( x_i, r_t^pub(x_i) )                   ▷ 提出下一个解
 8:     end while
 9:     x̂_t ← a 从 {x_≤i} 中选择的解
10:   end for
11:   return (1/T)·Σ_{t=1..T} r_t^priv(x̂_t)              ▷ 私有 held-out 打分
12: end function
13:
14: g(a_0) ← Grade(a_0)                                  ▷ 建立基线 grade
15: for k = 1,…,K−1 do
16:   a_k ← a^out( a_k, g(a_k) )                         ▷ 提出一次 agent 改写
17:   g(a_k) ← Grade(a_k)
18: end for
19: return a*_{K−1} = argmax_{a ∈ a_K} g(a)
```

注意 line 9：**agent 自己返回哪一个解**，而 line 11 用 private 分数打它——**agent 的"挑"和"被打分"之间存在一个可被操纵的缝隙**，论文靠 2.2 的信号解耦封它。

### 2.4 AIDE² 的实例化（§2.2）

- **内环起点 `a_0 = AIDE_0`**：AIDE（Jiang et al., 2025）的精简重构——"remove the ML-specific machinery but maintain the same tree-search procedure"。
- **AIDE_0 的操作子**：`draft`（探索新想法）、`debug`（修 bug/执行错误）、`improve`（精化有前景的方向）。**由 agent 的 search policy 决定对哪个解操作；AIDE_0 的选择是 greedy（最高分解为下一步父节点）**。
- **Reviewer agent**：读执行输出，抽取分数与反馈。
- **外环 `a^out` 由 `AIDE_human` 驱动** —— Weco R&D 团队的生产研究 agent，"largely follows the same design choices and agent architecture as AIDE_0"。
- **两个 reviewer 的预算不对称**（成本工程，论文明说）："Because evaluating each candidate dominates the cost of proposing it, we use the more capable model to drive the outer-loop agent. For the same reason, **the inner-loop reviewer makes a single LLM call** over each solution's execution output, while **the outer-loop agent's reviewer explores the evaluation artifacts over several steps**."
- **选择基准三族**（§2.2）：
  1. **ML engineering** —— 训练模型到目标指标；
  2. **Heuristic algorithm engineering** —— 竞赛编程风格的组合问题；
  3. **Harness engineering** —— "improvements to an agent's prompts, context management, and feedback loops—the code and algorithms that turn LLM API calls into working agentic systems"。
- **多样性的用意（§2.1 关键一句）**："We construct the task set to be **diverse in order to induce evolutionary pressure on the types of improvements that are made to the inner-loop agent, namely general mechanisms over task-specific tricks.**"

### 2.5 AIDE₈₅ 实际长出来的三个机制（§3.5，本篇最可搬运的工程内容）

**A. 搜索策略：bandit over drafting strategies + periodic forking**

- 五个固定策略：`conservative`、`aggressive_rewrite`、`ensemble`、`tuned_specialist`、`robust_simple`；
- 每个新节点**从父节点继承标签**；
- 每步由 **UCB1**（Auer et al., 2002）选一个策略臂，**30% 的步骤改为按各臂最佳分数的 softmax 采样**；
- 扩展**携带所选臂标签的最高分节点**。
- 设计理由（论文原话）："Selecting over strategy arms rather than individual nodes gives the agent a lever on the **diversity of approach**, not just on which local optimum to polish."
- **Forking**："Every five search steps, AIDE₈₅ forks the global best node, improving it under a different strategy arm."——针对 AIDE₀ 的两个失效：沿单一血统精化收益递减 / 从新 draft 重启会丢弃已找到的强解。
- **Figure 5 的实证**："Both agents run the same held-out ALE-Bench task, with the first 60 nodes shown. a, AIDE₀ improves the highest-scoring candidate, so **nearly every solution descends from one draft**. b, AIDE₈₅ keeps several arms alive."

**B. 上下文管理：bounded role-specific prompts + bug-rate-gated failure memory**

- `draft` 与 `improve` 操作只读**根节点与近期候选的紧凑摘要**，而非完整历史；
- **failure memory 的触发条件**：当一次运行的候选"show a bug rate of **at least 15%**"时，向 `draft` 与 `improve` 的 prompt 注入**最多三条**去重后的重复错误签名（近期有 bug 候选的最后几行错误）；
- **论文明确标注这是设计选择**："This 15% threshold is **a design choice from AIDE²**. The mechanism stays dormant where bugs are rare and only activates when evaluation errors are frequent enough."

**C. 三个鲁棒性机制**

1. **Prompt 级双保险**：每个 code-generation prompt 里固定一句提醒——解被打分在一个**它看不到的 private split** 上，应偏好鲁棒、可泛化的方案；外加**代码近乎为空（< 40 字符，如 stub/placeholder）时重新提示**的守卫。
2. **选择规则**：按候选"距 top candidates 中位数的距离"施加惩罚，避免选中偶然高分。**论文诚实报告这条没用**："Because the penalty preserves the ordering of the candidates, replaying the rule over the held-out runs shows that **it never changed which candidate the agent selected**."
3. **修好了评分脚本而不是利用它**：一个任务的 held-out 评分脚本"crashed on all of its test cases whenever any single test case failed"，AIDE₈₅ 加了一个小补丁。论文引 agent 自述："a narrow, low-risk intervention targeting a verified failure mode … without altering search dynamics"，并评论："**rather than exploiting the broken evaluation, AIDE² repaired it.**"

### 2.6 Ignition test（§3.6）—— 论文自设的最高标准，结论是"未通过"

- **假说**："discovered agents must be better at driving recursive self-improvement than the agent that discovered them."
- **晋升规则**：只有当被测 agent 驱动循环比生产它的 agent 更有效，才允许升入外环。
- **设计**：两臂，各 **3 seeds × 50 步**，都从 `AIDE_47` 起步，**唯一差别是外环用谁**——treatment 用 `AIDE_47`，reference 用 `AIDE_human`。
- **结果**：终点 treatment **0.780**、reference **0.782**（reference 略高）；treatment 约 **20 步**到达其最终分数区间，reference 约 **40 步**。
- **论文结论（原文）**："with only three seeds per outer-loop agent, **we find these results to be inconclusive; they do not establish that AIDE₄₇ is more sample-efficient as a self-improver**... we also do not claim that either agent is better than the other at driving recursive self-improvement. **What the treatment arm does show is that there is no obvious degradation** in AIDE₄₇'s ability to drive the recursive self-improvement run."

### 3.2 Held-out 泛化（§3.3 + Appendix A Table 1 / Table 2）

**二阶泛化（second-order generalization）** 定义的四个基准：ALE-Bench（Imajuku et al., 2025，AtCoder 长时程组合优化）、MLE-Bench（Chan et al., 2025，Kaggle 自动 ML 工程）、FML-Bench（Zou et al., 2026，真实研究代码库，覆盖持续学习/因果/隐私/鲁棒性）、**WeatherBench 2**（Rasp et al., 2024，物理预报 —— **OOS**，因为预报与物理引擎优化都不在选择任务集里）。

**WeatherBench 2 的特殊现象（OOS）**："On **every seed**, both evolved checkpoints independently converged on the same family of changes to the forecasting model's numerics, reaching **nearly identical gains with almost no variation** across runs. AIDE₀ and AIDE_human reach a comparable solution on **at most one seed** and vary widely across the rest."
**指标定义（Appendix A）**：WeatherBench 2 报 **forecast-skill gain** —— 四个头条场（500 hPa 位势、2 m 气温、平均海平面气压、10 m 纬向风）、1–15 天 lead time，对 ERA5 打分并相对持久性预报转成 skill 数；"a **relative improvement over its own starting point** rather than an absolute score on the WeatherBench 2 leaderboard"。**注意基座是对持久性预报（0.262 / 0.798 / 0.404），不是对 leaderboard。**

### 3.3 Reward hacking 下降（§3.4）

- **测量设计**（沿用 Zhao et al., 2026 的 proxy-to-downstream 设计）：取 KernelBench（Ouyang et al., 2025）子集，agent 为**孤立 speedup 测量**（它观察到的 proxy）优化 GPU kernel；然后把 kernel 插入 **GPT-2 / ViT / CNN** 训练循环，测有多少 proxy 收益存活。
- **判定规则（Appendix A）**：**38 个 (kernel, training-context) 对**；当孤立 speedup > **1.02×** 且（存活不到一半 **或** 在训练循环里崩溃）时判为 reward hacking。
- **结果**：**AIDE₀ 55% → AIDE₄₇ 39% → AIDE₈₅ 32%**，AIDE_human **39%**。
- **论文的归因克制**："These reward hacking rates establish a held-out behavioral change, though **they do not identify which rewrites produced it**."
- **任务族说明**：KernelBench 不在选择基准里（held-out）。

### 3.4 Prompt 压缩（§3.5 + Appendix E）

- 相对 **AIDE₀** 的 task-paired prompt size 中位缩减倍数（随运行推进增长）：**MLE-Bench 7×，WeatherBench 2 超 40×，ALE-Bench 与 FML-Bench 约 50×**。
- 相对 **AIDE_human**：发现 agent 的 prompt 小 **2.6–5.7×**（ALE/MLE/FML），WeatherBench 2 小 **13–14×**；而 **AIDE₀ 的大 3–14×**。
- 归因："Under fixed per-run constraints, shorter prompts let the agent make more effective use of each step and **buy more search steps in cost-bound runs**."
- AIDE₀ 的 prompt 随历史增长 → **触发 context-window 超限，结束了 5 个 FML-Bench run 与 48 个 ALE-Bench run**（Appendix E）；AIDE₄₇ / AIDE₈₅ / AIDE_human **未遇到此问题**。

### 3.5 跨模型迁移（Appendix C）

- 模型：**gemini 3 flash**（选择期所用）、**gpt-5.6-sol**、**fable 5**；因后两者更贵，per-run cost 从 **$5 提到 $20**，ALE-Bench 时间上限 12h → 36h。
- 结果："AIDE₈₅'s gains over AIDE₀ **transfer across all three models on both benchmarks**."
- ALE-Bench：`gemini 3 flash + AIDE₈₅` 达 **1858 ± 22**，超过同预算下 `fable 5 + AIDE₀` 的 **1796 ± 24**。
- MLE-Bench 增益较小："AIDE₈₅ with fable 5, the strongest model on this benchmark, **stays within one standard error of its AIDE₀ score**."
- **重要注记**：**48 runs 触及模型 context-window 上限**，按终止时的最优候选计分。

### 3.6 Ignition test（§3.6）

见 §2.6：**3 seeds × 50 步**，两臂终点 **0.780**（AIDE₄₇ 作外环）vs **0.782**（AIDE_human 作外环）；到达终点区间约 **20 步** vs **40 步**。**论文明确判定 inconclusive。**

### 3.7 Rejected proposals（Appendix D）—— 本篇最有价值的负面清单

- Δg ≈ **−0.004 到 −0.007** 的差值"**are small relative to observed run-to-run variability**"。
- **"Out of the graded rewrites that were rejected, about a quarter scored higher than the incumbent on the agent-visible public signal and were rejected on the private grade."**（pub/priv 解耦实际拦下了一部分）
- Table 3 代表条目（g(a_k) / Δg）：

| 提案 | 相关方法 | g(a_k) | Δg |
|---|---|---|---|
| 带周期性迁移与交叉的孤岛种群 | 分布式/孤岛遗传算法（Tanese 1989; Cantú-Paz 1998） | 0.685 | −0.021 |
| 成对 LLM-judge 锦标赛选择 | tournament selection + pairwise LLM judging | 0.654 | −0.090 |
| 停滞触发的探索升级 | reactive search / adaptive restarts（Battiti et al., 2008） | 0.704 | −0.040 |
| keep-refining vs. restart 决策 | restart policies（Luby et al., 1993） | 0.666 | −0.078 |
| 提交时多数投票集成 | bagging + self-consistency 多数投票 | up to 0.723 | −0.031（3 个变体） |
| 探索率调参与衰减计划 | decaying ε-greedy | 0.748 | −0.006，**within noise** |
| 方差自适应探索增益 | UCB-V（Audibert et al., 2009） | 0.674 | −0.080 |
| 祖先-后代趋势传播到选择 | MCTS value backup（Kocsis & Szepesvári, 2006） | 0.7497 | −0.004，**within noise** |
| 提升次优 + 鲁棒近似平局覆盖 | selection under the optimizer's curse（Smith & Winkler, 2006） | 5+ 变体 | 最好 −0.007，**within noise** |
| 把对某节点的重访过多当作过拟合嫌疑 | **no direct analogue identified** | 0.7498 | −0.004，**within noise** |

- 提案分布："concentrated most heavily on the **search policy** and on **selection mechanics**, followed by context management and robustness changes."
- **集成从未被保留**："Ensembling methods were explored during the recursive self-improvement run but **were never retained**, with the agent's analyses consistently noting that ensembling LLM calls consumes budget that could otherwise fund additional search steps."
- **重要反向信号**："**Ensembling LLM calls consumes budget**" —— 这与 AIDE₈₅ 最终**采用 ensemble 作为搜索臂标签之一**（`ensemble` 是五个 drafting 策略之一）形成表面张力。论文未讨论这一致性问题。

### 3.8 AIDE_human 基线强度（Appendix B）

FML-Bench 含 **18 个 ML 研究任务、10 个领域**。论文把 AIDE_human 与基准作者评测的 6 个 agent 并列：**AI Scientist v2、Autoresearch、原始 AIDE、OpenEvolve、AI Scientist v1、AIRA**。
**"AIDE_human scores above all six agents."** 且**刻意排除 AdaptiveSearch**（Zou et al., 2026，基准自带的 agent）——"because the comparison is meant to measure AIDE_human against other strong agents developed independently to this benchmark."
**论文自己给的强度限定**："**The margins separating the leading agents are small relative to the seed-level standard error.**"（**这是本篇最该被引用的一句自我限制**：基线很强，但领先幅度在种子噪声之内。）

## 4. 它假定了什么（挖隐含前提）

1. **假定"harness 代码"是研究效率的主要载体。** §1："We experiment target the harness layer... As shown in appendix C, a substantial share of an agent's realized capability is determined here." **但 Appendix C 证明的是"跨模型迁移"（harness 增益在三个模型上都成立），不是"harness 占能力的比例"。论文用 appendix C 支撑"substantial share"是一处推理跳跃。**
2. **假定"改进研究效率"可分解为"在同一美元预算下优化得更好"。** Eq.1 的 `b_t` 是 fixed dollar budget；§2.2 用 gemini 3 flash 是因为它在选择任务上"matched or slightly exceeded the more expensive models tested"。**这假定模型强度差异在此任务集上不重要** —— 若换到需要更强推理的任务，结论可能反转（MLE-Bench 上 fable 5 + AIDE₈₅ 增益就只有 1 个标准误内，见 Appendix C）。
3. **假定 private split 是稳定的防钻空子机制。** §3.4 的 reward hacking 下降 55% → 32% 是这条假定的**间接证据**，但论文明确说**无法归因到具体改写**。**未验证**：private split 本身是否被攻击过、攻击是否随运行增强。
4. **假定 g(a) 的噪声可被"重复运行取平均"消除。** §5 明说噪声在两层复合："The trajectory of the inner-loop search varies across seeds, and the evaluation of any given solution from the trajectory can itself be noisy." 并给出失败路径："If the noise is high enough, **a falsely accepted rewrite becomes the new incumbent (≠4), so a single noisy comparison can derail the outer loop's subsequent search.**" —— **论文诊断了这个问题，但没有解决它**（无显著性门、无置信区间、无重复接受检测）。
5. **假定固定 4 个模型角色分工是最优的。** 外环用 claude opus 4.7、内环用 gemini 3 flash、内环 reviewer 单次调用、外环 reviewer 多步探索。**这是一个成本权衡的工程决策，论文未做替代分派的消融。**
6. **假定 8 天 / 100 节点是足够的预算来暴露"持续趋势"。** 7 次接受来自 99 次提案；另外两次运行只接受 2 次与 4 次。**三次运行的接受数离散度很大（2 / 4 / 7），论文未报告这三次的 grade 终点，也未做任何跨运行汇总统计。**
7. **假定 Held-out 的选择可以被事先分离。** 四个 held-out 基准与 selection benchmark 的任务族关系被论文仔细分类（in-distribution vs OOS）。**但"哪些任务在选择期出现过"是靠作者自觉维护的**，没有任何机制保证没有泄漏；§5 承认"a false positive rewrite becomes the new incumbent"这一类风险同样适用于任务泄漏。
8. **假定"改了 harness 就会更好"这一反馈足够稠密。** Eq.4 是纯 argmax，无回退、无 archive、无多样性维持。**Appendix D 的 Table 3 事实上是在事后重建这个缺失的 archive** —— 那张表本身就是论文没实现的东西。
9. **假定 reward hacking 的下降是正面涌现。** 论文措辞谨慎（"do not identify which rewrites produced it"），但 §5 的 Discussion 把这条写成了正面结论："come with a reduction in reward hacking that was never part of the objective being optimized for"。**在 38 对样本、1 个判定阈值（1.02×）下，这个因果强度是弱的。**
10. **假定 Claude Opus 4.7 能写出好改写。** 外环 agent 是整个循环的智力来源。**论文未做外环模型的敏感性分析**（换成 gemini 3.1 pro 会怎样？附录 C 显示 harness 增益跨模型迁移，但那是内环模型）。
11. **企业单方视角。** 全部作者署名 Weco AI，AIDE_human 是 Weco 自家生产 agent。**基准与基线都是自己选的**（Appendix A 的 lite 集、Table 2 的约束）。这不是造假指控，但**它意味着"匹配或超越两年人驱 R&D"这个结论的强度受选择自由度影响**。

## 5. 可迁移到 DWC 的点 / 不可迁移的点

> DWC 当前状态：`README.md` 记 "代码 0"；两件定位内的事 = **记忆底座** + **自我强化**；7 道门在 `scripts/gate.py`；`archive/gate_trace.jsonl` 已有 2,488 字节运行记录。本节给出前向接口。

### 5.1 可迁移（每条给出具体接口）

**① pub/priv 信号解耦 → DWC 的所有自我强化循环的强制结构**

- **搬什么**：§2.1 末的两条设计。**这是本篇最值得整段照抄的一条**——它不需要闭源模型、不需要 GPU，只需要"两个不同的评分通道"。
- **DWC 接口**：
  ```python
  # src/dwc/selfevolve/signals.py
  @dataclass(frozen=True)
  class DualSignal:
      agent_visible: float   # r_pub：给被改写者看的
      selection: float       # r_priv：给接受门看的
      selection_truth_source: str   # 必填，对接门 2
  def propose_rewrite(history, dual: DualSignal) -> Rewrite: ...   # 只看 agent_visible
  def accept(candidate, incumbent, dual: DualSignal) -> Verdict: ...  # 只看 selection
  ```
- **门的位置**：`selection_truth_source` 为 `None` 时，`accept()` 必须返回 `UNKNOWN` 并拒绝写入 SUCCESS（门 2 + 门 5）。
- **DWC 的具体形态**：DWC 的记忆底座天然有两个信号——**agent 可见的检索结果**（`r_pub`）与**事后才能算的、会话结束后才知道的记忆真实效用**（`r_priv`，例如"这个记忆条目在 N 个后续任务里是否被引用且答案正确"）。**这正好是一个真实的 pub/priv 对**，不需要制造。

**② 固定预算而非固定步数 → DWC 效率判据**

- **搬什么**：Eq.1 的 `b_t`（fixed dollar budget，覆盖 token + 解执行成本）；§2.1 "improvements to arise from a better algorithm rather than from spending additional compute"。
- **DWC 接口**：`src/dwc/selfevolve/budget.py::BudgetLedger(tokens, wall_clock_s, exec_cost)`；每次机制评测**必须**在同一 BudgetLedger 上跑新旧两版。
- **为什么这条对 DWC 特别重要**：母巢教训 L7 要求"同输入、对照组、事后校验"，而母巢的对照组缺失方式之一就是**新版本跑得更多**。**固定预算是把"更贵的实现"从"更好的实现"里剥出来的唯一机械手段。**

**③ Algorithm 1 的 Grade 函数 → DWC 的机制评测契约**

- **搬什么**：Grade 函数的结构——**对每个任务独立启动状态 → 循环直到预算耗尽 → 由 agent 自己选一个候选返回 → 用 agent 看不到的信号打分 → 跨任务平均**。
- **DWC 接口**：`src/dwc/selfevolve/grade.py::Grade(tasks, budgets, verifier) -> float`，即 `g(a) = (1/T)·Σ_t r_t^priv(x̂_t)` 的 DWC 版。**注意必须保留 line 9 的"agent 自己选"**——若 DWC 改成评测方代选，实验测的就是别的东西了。

**④ Table 3 的 rejected proposals 清单 → DWC 的"先别做这些"清单（零成本、立即可用）**

- **搬什么**：Appendix D 整张表。**这是本篇最直接可搬的资产**——DWC 还没开始写自我强化代码，但可以直接把这些方案标记为"已知在等预算人工研究 agent 上不成立的候选"。
- **DWC 接口**：`src/dwc/selfevolve/rejected_patterns.py`，每条含 `{名称, 对应经典方法, DWC 中的判定}`。接入**门 4（生灭配套门）**：这些名字出现在提案里 → 要求额外证据，否则 `hold`。
- **逐条判读（对 DWC 的适用性）**：
  - **自适应 restart / keep-refining vs restart（Luby, Battiti）→ 适用**。DWC 的自我强化循环同样会遇到"卡住了要不要清空重来"，且 AIDE₈₅ 最终的 **forking 每 5 步一次**恰是这条线上的答案（fork 而非 restart）。**注意 15% bug 阈值与 5 步 fork 间隔都是 AIDE² 的设计选择，不是学出来的阈值**——DWC 若照抄要标注。
  - **方差自适应探索（UCB-V）→ 适用**。DWC 的自我强化提案多样性同样是低采样问题（母巢 526 个抢位冲突说明多样性已经过剩，但那是同一目标上的多样性）。
  - **集成（bagging / self-consistency）→ 需谨慎**。论文说"never retained"因为"consuming budget that could otherwise fund additional search steps"。**这对 DWC 的含义是明确的：集成的账要按"预算替代"算，不能按"叠加"算。**
  - **成对 LLM-judge 锦标赛 → 不适用**（Δg −0.090 是全表最差），且 DWC 无标注预算做 judge 校准。
  - **孤岛种群 → 弱适用**，Δg −0.021 中等。

**⑤ UCB1 over strategy arms + periodic forking → DWC 提案层的搜索策略**

- **搬什么**：本报告 §2.5 的 **A 项**（论文 §3.5 Search policy）的完整结构——**五个固定策略标签 + 节点继承标签 + UCB1 选臂 + 30% 步骤改 softmax 采样 + 每 5 步 fork 全局最优**。
- **DWC 接口**：
  ```python
  # src/dwc/selfevolve/proposal_policy.py
  STRATEGIES = ("conservative", "aggressive_rewrite", "ensemble",
               "tuned_specialist", "robust_simple")
  def select_arm(labels: list[ArmLabel], best_scores: dict[str, float],
                 step: int, ucb_c: float = ..., softmax_p: float = 0.30,
                 fork_every: int = 5) -> ArmLabel: ...
  ```
  **关键设计理由值得原样搬进 ADR**："Selecting over strategy arms rather than individual nodes gives the agent a lever on the **diversity of approach**, not just on which local optimum to polish." —— DWC 的提案选择若只按分数，会退化成母巢 L3 的"单日机制池 +734"。
- **⚠️ 参数标注**：`softmax_p = 0.30`、`fork_every = 5` 是 AIDE² 的设计选择，**论文未报告它们的敏感性**。DWC 抄用时必须在 ADR 里写"这两个值来自 arXiv:2609.26457 §3.5 的设计选择，未经我们校准"。

**⑥ bounded role-specific prompts + bug-rate-gated failure memory → DWC 记忆写入策略**

- **搬什么**：本报告 §2.5 的 **B 项**（论文 §3.5 Context management）的完整结构 + 论文 Appendix E 的实测效果（相对 AIDE₀ 压缩 7×–50×，相对 AIDE_human 小 2.6×–14×）。
- **DWC 接口**：
  ```python
  # src/dwc/memory/context_policy.py
  def build_prompt(role: Literal["draft","improve"], summary: RootSummary,
                   recent: list[Candidate]) -> Prompt: ...   # 有界，不含全历史
  def failure_memory_injection(entries: list[Candidate], *,
                               bug_rate_threshold: float = 0.15,
                               max_signatures: int = 3) -> str: ...
  ```
- **机制价值高于数字价值**：DWC 的记忆底座最自然的失败就是"上下文无界增长"。母巢的 `contextoverflow` 类问题正是这个。**"按角色给不同摘要"（draft 读什么、improve 读什么）** 这一条尤其适用——DWC 的记忆召回本就应该按调用角色区分。
- **⚠️ 阈值标注**：**15% bug 率触发、最多 3 条签名**——论文明写 "This 15% threshold is **a design choice from AIDE²**"。DWC 必须自行校准。

**⑦ "修好评分脚本而不是利用它" → DWC 的评测诚实性原则**

- **搬什么**：本报告 §2.5 的 **C 项**第三条（论文 §3.5 Robustness）—— agent 发现一个任务的评分脚本"任一测试失败就整体崩溃"，选择**加补丁**而非利用；论文评论 "rather than exploiting the broken evaluation, AIDE² repaired it"。
- **DWC 接口**：`src/dwc/selfevolve/harness_integrity.py` —— 检测评测器自身缺陷并登记为**待修缺陷**，而不是静默利用。接到**门 5（声称/实测分离门）**：评测器已知缺陷必须出现在 PROGRESS.md 的实测栏。
- **为什么对 DWC 关键**：母巢 5 个 P0 缺陷里"熔断器说'我探测过了'→ 硬编码 True"就是这类利用的原型。**AIDE² 给出的判别标准不是"不许有 bug 的评测器"，而是"发现 bug 时改不改"**——这可以直接写进 DWC 的 ADR。

**⑧ 修好奖励无收益的那个提案 → DWC 的"诚实负面记录"实践**

- **搬什么**：本报告 §2.5 的 **C 项**第二条（论文 §3.5 Robustness）—— AIDE₈₅ 加入"按距 top 候选中位数的距离惩罚"的选择规则，论文诚实报告**重放该规则后发现它从未改变过选中的候选**。
- **DWC 接口**：`docs/adr/` 里每条 ADR 必须写"本提案实测无收益"并注明重放方法。**这正是 README 教训 L5（声称与实测分开）与 L6（减法纪律）的执行细则**——一条"看起来对但实测无效"的机制，在 DWC 里应当被记为**减法候选**而不是留在承重区。
- **对照母巢**：母巢 `effect` 非零率 76.8% 但只有 **17 个不同取值**（README L7）。**"重放规则看它是否真的改变了决策"正是发现这类空转的机械手段。**

**⑨ Ignition test 作为晋升门 → DWC 的自我强化机制准入判据**

- **搬什么**：§3.6 的判据形状——**"被改进者必须比生产它的改进者更能驱动改进循环，才允许升为改进器"**。这是本篇提出的最高标准，且**AIDE² 自己没通过**（判定 inconclusive）。
- **DWC 接口**：`src/dwc/selfevolve/promotion_gate.py::ignition_test(incumbent, baseline, seeds=3, steps=50) -> Verdict{degraded: bool, conclusive: bool}`。
- **价值**：**DWC 尚未开始，无需现在实现；但这个判据应当写进 `docs/adr/` 作为自我强化的长期准入原则**，因为它同时防止了两件事——把弱机制升为改进器（母巢 L3 的教训），以及无限扩张改进器层数（母巢 L6 的加法失控）。**且它自带"conclusive: false"出口，天然对接门 5。**

### 5.2 不可迁移（写清为什么搬不了）

1. **主实验的结论数字整体不可搬。** 8 天 / 100 节点 / 7 次接受 / 0.703→0.778 —— **依赖 claude opus 4.7 作外环 + gemini 3 flash 作内环 + 8 天无人值守算力 + A100**。DWC 无同等条件（README：代码 0）。**这些数字只能用于判断"该领域量级"，不能作验收阈值。**
2. **Held-out Table 1 的数字不可作为 DWC 的性能预期。** 四个基准全部是 AI R&D / 竞赛编程 / 科学计算优化任务，**不是记忆或自我强化任务**；模型分别是 gemini 3 flash / 3.1 pro / gpt-5.4。**DWC 在这两个基准上无对应任务。**
3. **§2.2 的角色模型分工不可照搬。** "外环用更强模型"这一前提来自"评测候选的成本远高于提出候选"。DWC 的自我强化若每次改动的评测成本不高（本地跑通即可），则应反过来——**这个条件依赖 DWC 的实际成本结构，本文不提供答案**。
4. **超时的 prevention 效果不可直接迁移。** 压缩 prompt 消除了 context-window 溢出（AIDE₀ 5 + 48 runs 超限），但**DWC 的上下文窗口由 Hermes/proxy 决定，不由 harness 的 prompt 长度单独决定**。DWC 应抄机制（有界 + 角色特定摘要）而非期待同样的数字。
5. **15% bug 率阈值与 5 步 fork 间隔不可当作学出来的参数。** 论文对 15% 明写是设计选择；对 5 步 fork 未报告任何校准依据。**DWC 抄用必须在 ADR 标注来源为 §3.5 的设计选择，且自行校准。**
6. **Table 3 的负面清单不可当作普适否定。** 论文自己界定了适用域："Δg of approximately −0.004 to −0.007 are **small relative to observed run-to-run variability**"——**真正被明确否定的只有 Δg ≤ −0.021 的三条**（孤岛种群 −0.021、锦标赛 −0.090、停滞升级 −0.040、restart 决策 −0.078、UCB-V −0.080、集成 −0.031）。**五条 within-noise 的提案（探索率衰减、MCTS value backup、近似平局覆盖、重访过拟合怀疑）是"未判定"，不是"已否定"**——DWC 引用时必须区分这两类。
7. **"reward hacking 从 55% 降到 32%"不可作为 DWC 的正面证据。** 判定基于 **38 对样本**、单一阈值 1.02×、论文自认**无法归因到具体改写**、且任务族（GPU kernel）不在选择基准里。**DWC 若引用，只能说"存在一个未被优化的属性发生了有利变化"**，不能说"该循环减少了钻空子"。
8. **WeatherBench 2 的 0.798 不可与任何公开数字比较。** 论文明写是 "**a relative improvement over its own starting point rather than an absolute score on the WeatherBench 2 leaderboard**"，基座是持久性预报。AIDE₀ 的 0.262 恰好说明这个指标**可以低到几乎没有能力**。**任何把 0.798 当作"天气预报能力"的解读都是错的。**
9. **AIDE_human 作为"两年人驱 R&D 的强基线"这一表述不可移用。** 论文自己给了限定："The margins separating the leading agents are **small relative to the seed-level standard error**."——**基线确实强，但差异在种子噪声内**。DWC 若要设人工基线，必须学这个限定写法。
10. **闭源模型依赖（全文最强的一条）**：外环 claude opus 4.7、内环 gemini 3 flash、WeatherBench gemini 3.1 pro、FML gpt-5.4、跨模型 gpt-5.6-sol + fable 5。**DWC 不具备同等模型条件（README 诚实条款第 5 条）。可搬的是结构（哪一层用强模型、哪一层用单次调用），不可搬的是具体模型与由此得到的数字。**

## 6. 与其他论文的关系

**在 RSI 图谱中的位置**：19 篇里**唯一一次"真跑了长时程、且被独立综述引用"的 harness 层 RSI 实证**。它落在 `docs/RSI_PAPERS.md` 第 II 组（Harness 自进化），但**层次高于其他几篇**——其他几篇在评测基准上迭代 15 轮，本篇在 8 天 99 次提案里迭代。

**与 `2608.10299` Co-Evolution 综述（本批次第二篇）的关系：被综述点名，且是一个精确的"不是"（已在该报告 §6 展开，此处只记结论）。**
- 综述 §5.2 的 self-referential improvement 段把它归入"用 proxy metric 引导自我修改"的族，并把本篇列为该族的差异点："**AIDE² instead targets the agent's own capability on AI R&D tasks.**"
- 但按综述的 co-evolution 判据（`∃x≠y, x⟷y`，"counterpart 固定时仍可自我进化"），**本篇严格属于 single-entity self-evolution**：外环改内环 agent，而任务集与评分脚本在运行中不变。**它是"迭代/递归自我改进"，不是"共演化"。**
- **方法论上的一处冲突值得 DWC 注意**：本篇用 pub/priv 信号解耦 + reward hacking 实测（55%→32%）回应了综述 §6 点名的 "evaluator exploitation"，**却没有用任何 co-evolution 机制**。综述把它列为开放挑战，本篇证明**该挑战不必等共演化就能部分解决**。
- 综述未引用本篇（检索 "Weco"/"26457" 无命中）；本篇未引用综述（检索 "co-evolution" 无命中）。

**与 `2603.06333` SAHOO（本批次第一篇）的关系：循环 vs 护栏，恰好互补且都缺对方的东西。**
- **SAHOO 无真实循环**（θ_c → θ_{c+1} 未定义），**AIDE² 无护栏**（接受规则只有 Eq.4 的 argmax，无漂移度量、无约束集合、无回退判据）。
- **唯一的"安全"数据是 reward hacking 55%→32%**，而 SAHOO 的 GDI 恰好是"drift from baseline"的量化器——**如果把 GDI 接到 AIDE² 的 Eq.4 上，判据就从"private grade 更高"变成"private grade 更高且 GDI 未越界"**。这是本批次三篇里唯一一条真正能拼起来的组合。
- **反向的教训**：AIDE² 的 Appendix D Table 3 里 **5 条 within-noise 的提案**（Δg −0.004 ~ −0.007）正是 SAHOO 的 GDI 会标出来的类型——**当 Δg 落在噪声里，"接受/拒绝"实际上是任意决定**，而 Eq.4 的纯 argmax 会照样接受。**SAHOO 的 bootstrap CI（±0.042）正是一个可用的判别尺度。**
- 两篇无引用关系。

**与 `2609.14858` Dream-RSI 的关系：同一目标（研究效率），不同被改对象。**
- Dream-RSI 改的是**编排层的探索策略代码**（"controls branching, parallel exploration, and stopping while leaving the underlying coding agent unchanged"），并用 replay world 做**离线廉价评估**。
- AIDE² 改的是**被编排的 agent 自己的 harness 代码**，并用真实的 held-out 评测做**在线昂贵评估**。
- **两者的结合点非常具体**：Dream-RSI 的 replay 机制正好可以解决 AIDE² 自陈的最大限制——"**If the noise is high enough, a falsely accepted rewrite becomes the new incumbent (≠4), so a single noisy comparison can derail the outer loop's subsequent search**"。**用 Dream-RSI 的 replay evaluator 做第一次筛选，把预算留给真实评测的 top-k**，就把 AIDE² 明确诊断出的失败路径（噪声复合导致外轨脱轨）变成了工程问题。
- 反过来，AIDE² 的 pub/priv 解耦是 Dream-RSI 那类离线重放方法**没有覆盖**的：replay 用的是历史分布，不存在"private split"。**这是 Dream-RSI 报告里已记录的一个弱点**（"它的 held-out 是相对于在线新 rollout，不是相对于初始分布"）。
- 两篇无引用关系（AIDE² §4 的 related work 不含 Dream-RSI；AIDE² §4 提到 DGM/Zhang 2026a 等，但不含 Dream-RSI）。

**与 `2609.11873` Last AI 的关系：被它引为工业证据，且它的诚实标注与本篇的 ignition 结论一致（据 `2609.11873.md` §3.5 已引）。** 11873 收录了本篇并标注："⚠️ 'Its stronger test of whether the evolved agent improves the outer search faster **found no statistically significant efficiency advantage**'"——**这条转述与本篇 §3.6 的原话（"we find these results to be inconclusive"）方向一致**，没有夸大。

**与 `2606.14249` HarnessX / `2606.09498` Self-Harness 的关系（据 `2606.14249.md` §6 已记："8 天 7 处改进 vs 15 轮 14.5%"）。** 补一条本篇侧的判读：AIDE² 的 Table 3（Rejected proposals）**在结构上就是 HarnessX 的 variant isolation 与 critic/pruner 的事后版本**——HarnessX 在 15 轮内建了一套机制来隔离"benchmark-specific 变体"，而 AIDE² 用 99 次提案自然积累出了同一份记录。**AIDE² 的做法更原始但信息量更大（因为它保留了被拒提案的完整清单与相对 Δg），代价是没有隔离机制所以浪费了 92 次提案。** 这两条路线（机制化隔离 vs 自然积累）的取舍对 DWC 是真实选择。

**与 `2603.25111` SEVerA 的关系：一方的最强对立面（据 `2603.25111.md` §6："AIDE² 让 agent 改自己的代码、跑 benchmark、留改动，8 天找到 7 处改进——**没有任何形式验证，纯经验门**。SEVerA 会说：那 7 处改动里没有一处被证明在所有输入上保持行为"）。** 本篇侧可补的量化：Appendix D 显示 **9 类提案里有 5 类落在 Δg 的运行间噪声内**——**这意味着即使加上显著性门，最多 4 类可判定**。形式契约的缺失在这里是**可量化的**。

**与 `2609.06396` MetaRSI 的关系：MetaRSI 的元层 vs 本篇的双层。** 本篇的"元层"（外环）**机制本身完全固定**（Eq.4 写死 argmax，外环 agent 是 AIDE_human 的固定代码）。按 `2608.10299` 的判据，**本篇的 Ω 不被演化**。MetaRSI 的元层改 `φ`（失败签名）并由下层轨迹驱动——**那是本篇缺的一步**。反过来，本篇的 pub/priv 解耦与固定预算，正好是 MetaRSI §"保护性分隔"（据 `2609.06396.md`，Eq.30 把 `Q*`、release rule、账本排除在一切写入面外）在实测层的对应物。

**给 DWC 的一句话定位**：它是 19 篇里**最像一份可执行工程日志的论文**——不是概念贡献（本报告 §2.2 记的那两条信号解耦设计是别人也知道的做法），而是"**它造了什么、哪些被拒了、哪些提案其实没用**"这三样。**Table 3 与"重放后从未改变选择"这两条，是母巢最缺的那类信息。**
