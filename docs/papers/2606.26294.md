## 一句话总结

把"评估标准"本身放进搜索循环：搜索被切成 **epoch**，epoch 内评估器冻结（保住 HGM 的逐 epoch 收敛保证），epoch 边界上 challenger 评估器只跟**独立 ground-truth anchor** 上的 ε-best-belief 下界比，赢了才换、换掉的 slot 的效用记录**选择性抹除**（selective erasure）；实测在 Polyglot 上用 1.35×–1.72× 更少搜索 token 把 held-out 通过率从 69.9% 推到 71.7%，在无论文/无证明基准的领域把 writer 接收率 21.8%→40.5%，并用一个**对抗目标**把过度偏爱 AI 生成文本的 reviewer 校准到对人机一视同仁。

## 核心方法

### 组件（术语按原文）

| 组件 | 原文定义 |
|---|---|
| **archive 节点 = 多 agent workspace** | 每个节点 `a` 是共享可演化 workspace，含 K 个 agentic role（task agent + evaluator），各 role 有独立任务池 `D_r`；节点还配一个 meta-agent 可编辑整个 workspace（含它自己的循环/提示/工具面） |
| **evaluator-dependent vs evaluator-independent** | 前者无 ground truth（论文写作、证明），通过可替换的 **evaluator slot** 打分；后者有固定 benchmark（Polyglot 测试） |
| **epoch 向量 j = (j₁,…,j_M)** | M 个 evaluator slot 独立替换，各槽位自己的 epoch 计数；`p_{r,d,j}(a)` 的下标 j 让成功率、效用全部 **epoch-local** |
| **ground-truth anchor** | 每个 domain 的固定 held-out 数据集：APReS 接收/拒稿、IMO-GradingBench 人工分、Polyglot 可执行测试、CRAVE PR 接受标签 |
| **utility transition** | 定义 F.2：把 slot m 的判据 `κ(j_m)` 换成 `κ(j'_m)`，并对 `dep(z)` 含该槽位的记录施加 `Erase_m`，然后**从保留记录重算全部派生统计**（S/F 计数、role/task 计数、clade 计数、Thompson 统计） |

### 流程（Algorithm 1，App B）

```
1  T←{a₀}; j[m]←1; E[m]←Freeze(Incumbent(m)); TrainEval(a₀,…)
5  while N < B:                                    # B = 12,288 evaluations
7    b ← min{c ∈ C : c > N} ∧ B                    # 指数 checkpoint（power-of-two）
9    if ExpandGate(T,N):                           # UCB-Air: N_t^α ≥ |T_t|, α=0.6
        a_p ← SampleCladeByCMP(T); a' ← EditWorkspace(a_p, …)
        if Valid(a'): T ← T∪{a'}; TrainEval(a', …)  # 训练分只做 lineage 证据
17   a ← SampleCladeByCMP(T)                       # Thompson on clade 成功率
18   (r,d) ← LeastMeasuredCell(a,R)                # 角色/任务两级"最少已测者优先"
19   o ← ValEval(a,r,d,E,B̄_val); AddUtilityRecord(…); N ← N+1
22   # 只在 checkpoint 上、且只按 anchor best-belief 换评估器
25   BB[e] ← I⁻¹_ε(1+S^gt_e, 1+F^gt_e)  for e ∈ {incumbent} ∪ Challengers
26   e★ ← Best(Γ_m, BB; tie = 在位者)
27   if e★ ≠ E[m]: j[m]++; E[m]←Freeze(e★); EraseSlotRecords(T,m); RecomputeCMPStats(T)
34  a★ ← BestBeliefNode(T,ε)
```

### 关键公式

- **CMP（clade metaproductivity，继承 HGM）**：`CMP(a) = n^C_success(a) / (n^C_success(a) + n^C_failure(a))`，节点按 clade 池化成功率做 Thompson 采样——"一个节点自己的成功率可能预测不了它的后代"。
- **ε-best-belief（选择与替换共用同一把尺）**：`BB_ε(a) = I⁻¹_ε(1+S_a, 1+F_a)`，即 Beta 后验的 ε 分位数，是"以概率 1−ε 被超越的保守下界"。
- **效用（两层均匀平均）**：`p_{r,j}(a) = (1/|D_r|) Σ_d p_{r,d,j}(a)`，`U_j(a) = (1/|R|) Σ_r p_{r,j}(a)`——刻意用均匀而非按样本加权（"some tasks can generate unbounded evaluations"）。
- **Prop 1（working posterior 相合）**：在 w-平衡采样下，池化 Beta 后验均值 `M_n(a) = (1+S_a)/(2+n) → U_j(a)` a.s.；论文自陈它"is not an exact Bayesian posterior for the role–task mixture"（意译：它不是 role–task 混合的精确贝叶斯后验），是**过离散的工作后验**，因此对下界解读是保守的。
- **Prop 3（epoch 内固定判据）**：每个 epoch 内每个 (a,r,d) 诱导时齐二元分布 ⇒ 每个 epoch 都是 HGM 意义上的固定判据搜索问题。
- **Prop 4（下界轨迹）**：单次选择 `Pr(U(a★) ≥ BB_ε(a★)) = 1−ε`；L 次选择联合 ≥ `1−Lε`。**Rem 6**：对同一 anchor 上被晋升的 K 个评估器，联合 ≥ `1−Kε`，且明确写"not a guarantee that the realized anchor accuracy improves monotonically"（意译：不是 anchor 准确率单调提升的保证）。
- **Prop 6（指数 checkpoint 的摊还）**：每个 checkpoint 最多重处理 c 条旧记录，指数进度 `⌊hρ^q⌋` 下总重处理 `O(B)`，常数 ≤ `ρ/(ρ−1)`；ρ=2 时 ≤ 2B。**Rem 7**：均匀 checkpoint 是 `Θ(B²/h)`。

### 验收规则（论文自己的硬约束）

1. **数据隔离**：节点只见 train split；**节点选择只由 validation split 驱动**；最终报分在独立 test split。meta-agent 指令原文写死："your utility is computed on a HELD-OUT validation set you NEVER see" 与 "Do NOT hardcode answers"。
2. **anchor-only 替换（Rem 3）**：`BB_ε` 只吃 evaluator-independent 的 anchor 计数，"no slot-dependent utility record enters it"，且平票判给在位者 ⇒ "a replacement is never worse than retention at the moment it is made"。
3. **抹除必须干净（Def F.1 / Prop 2）**：记录 `z = (a,r,d,o,dep(z),κ(z),j(z))`；`dep(z)` 为空的记录对所有 epoch 都有效（anchor 证据永不被抹）。原始 artifact 缓存与不可变审计日志可留，但**不得进入派生统计**。
4. **成本口径**：blended tokens = 输入+输出、**输出按 5× 输入计价**，生成与评估调用都算；best-belief agent 的成本记为**它首次达到最高 BB 的时刻**，不是 run 结束时刻；不确定度用 **95% central Beta (Jeffreys) 区间**。
5. **搜索配置固定不可被 meta-agent 改**（Table 3）：ε=0.05 + "five-outcome anchor minimum"、checkpoint power-of-two、α=0.6、预算 12,288 = 8,192+4,096、Polyglot 10/49/166 划分、三个 anchor test set 各 100 条。Table 4 列出**暴露给 meta-agent 的可编辑面**（每调用 32,768 输出 token、coder 每任务 ≤16 次工具调用、meta-agent 每轮 ≤40 次工具调用等）。
6. **对抗目标干预（唯一一次"改目标"）**：paper 域第一次替换后，被换掉的 reviewer 接收过的 AI 生成论文构成 adversarial pool，下一 epoch **额外奖励拒绝这些论文**、同时维持在人类 APReS 数据上的准确率；替换本身仍锚定 APReS。

## 主结果

> 所有数字来自原文表格/正文；引号内为原文短引（已按 `re.sub(r'\s+',' ',t)` 回原文核过）。

### RQ1 — 有 ground truth 时，多一路学习型评估信号仍有增益（Polyglot，166 条 held-out）

- 摘要级："the RQGM uses 1.35×–1.72× fewer tokens"；正文："The RQGM exceeds the HGM-H held-out pass rate for both the specialist and generalist at 1.35×–1.72× lower token cost"。
- 通过率（Fig. 1）：**71.7% vs 69.9%**——"the RQGM reaches a held-out pass rate of 71.7% against the prior SOTA ’s 69.9%"。
- Table 5（逐格，n=166）：RQGM specialist (node 104) = **119**、RQGM generalist (node 100) = **119**、HGM-H (node 95) = **116** passes。→ 差距只有 **3 题**，两臂同为 119/166 = 71.69%。
- 为什么共享代码有效："in the Polyglot run, 90% of accepted patches modify shared task-agent functionality or infrastructure used by both the coder and the reviewer, rather than role-specific code"；Fig. 10 全 GPT-5.5 run 中 **shared + infrastructure 面占 59–90%** 的被接受补丁，Nemotron 3 Super run 是离群点（**42%** 的边改 meta-agent 指令模块，作者推测是为可靠性）。

### RQ2 — 无客观基准的域（Table 1 论文写作，四 reviewer 固定面板，逐格）

| Writer | Search Tokens | Sakana | DGM-H | HGM-H | RQGM adversarial | Mean (%,↑) |
|---|---|---|---|---|---|---|
| HGM-H writer | 42.5M | 1.0±2.2 | 12.0±6.3 | 64.0±9.3 | 10.0±5.9 | **21.8±4.0** |
| RQGM writer (generalist) | 44.6M | 2.0±2.9 | 43.0±9.6 | 81.0±7.6 | 29.0±8.8 | **38.8±4.8 (1.78×)** |
| RQGM writer (specialist) | 221.8M | 5.0±4.3 | 40.0±9.5 | 86.0±6.8 | 31.0±9.0 | **40.5±4.8 (1.86×)** |

- 同预算点："our writer already achieves a 1.78× higher reviewer-panel acceptance rate on average"；全程最优 1.86×。→ 摘要的 "1.78×–1.86× higher acceptance rates"。
- **注意可比性陷阱**：generalist 44.6M 与 HGM-H 42.5M 同量级，specialist 221.8M 是**5 倍 token**，1.86× 那一列不是等预算比较。
- 生成物接收率绝对值只有 38.8–40.5%（四 reviewer 平均），**没有人类评分**（App G："no human grading of the generated papers or proofs was performed"）。

### RQ3 — 替换 = 对 archive 的课程（Fig. 3–4）

- 每次替换后 pre/post 排名的 Spearman ρ **永远回不到 1**，"settles well below 1 and never recovers"（原句主语是数学斜体 ρ，故只引可核子串）；**no-erasure 对照** "The no-erasure control (rightmost) stays high"，(ρ≥ 0.90) ⇒ 抹除是重排的必要条件。
- 微观：Fig. 4 中最优 lineage 在三次替换中**存活不中断**，而 top-8 其余成员全部被重排（promoted/churned）。
- Fig. 3 标注的实际替换点：code review @ 258 / 512 / 2,050 evals；paper review @ 8,192；proof grading @ 1,024 / 2,048。

### RQ4 — 评估器本身也被改进

- **Grader（Fig. 5）**："The co-evolved RQGM grader reaches the best IMO-GradingBench accuracy at 3× lower search cost than HGM-H"；specialist 点 9.3/37.9M vs HGM-H 28.0M。摘要给的量级是 "co-evolved graders reach 9% higher ground-truth accuracy"。
- **Reviewer（Fig. 6 / Table 5）**：HGM-H reviewer "accepts AI-generated papers at 1.42×–1.91× the rate of human ones"（摘要写 "up to 1.91× the human rate"）；RQGM 对抗 reviewer 的落地状态是 "the reviewer accepts AI-generated and real papers at similar rates while retaining 80% ground-truth accuracy"。
- Table 5（逐格，n=100 APReS）：HGM-H specialist 88 acc / 45 accept · RQGM specialist 84/40 · RQGM generalist pre-repl. 84/42 · **RQGM adversarial post-repl. 80/32** · DGM-H (published) 73/25 · Sakana prompt 63/13。
  → 对抗版准确率 80% **低于** HGM-H 的 88%，作者承认它"What it gains is calibration"，换到的是校准。

### 消融（Table 7，Nemotron 3 Super，12,288 evals，逐格：writer val. acc.† / reviewer anchor acc.）

| Run | Repl. | Pool | Erase | Writer val. acc.% † | Reviewer anchor acc.% |
|---|---|---|---|---|---|
| Full mechanism | on | on | on | 90.1±3.5 | 95.0±10.3 |
| Replacement only | on | off | on | 89.5±13.7 | 91.2±7.4 |
| No erasure | on | on | off | 90.0±10.7 | 92.9±10.8 |
| Fixed critic | off | off | – | **100.0±1.7** | **78.2±4.4** |

- "The fixed critic saturates"：关掉替换后 writer 拿到 **75/75** 被自己的冻结 critic 接收（分母饱和、纯刷分），anchor 准确率反而最低 78.2%。
- "Without erasure the utility stays stale"：退役 critic 的分数留在官方效用里 → slot 出现 A→B→A 回摆、替换不再触发、搜索反复重访同一批节点。
- "Ending at an anchor result of 52/57"（只开替换、关对抗池）。
- † 每格 critic 不同，作者明确警告该列"not"跨 run 可比。

### 成本与杂项（Fig. 7 / 9 / App C.4）

- 成本结构："validation carries roughly 65–69% of blended tokens, expansion 18–23%, and train-time evaluation (at three train samples per node) 12–14%"；正文说 expansion "of total search cost across our domains" ≈20%。
- 混合模型（Sec. 5.5）：把搜索期 task-agent 调用换 Nemotron 3 Ultra、meta-agent 仍用 GPT-5.5 (low) ⇒ "13.0 × lower cost"（Fig. 7 图内标注；正文口径为 "reduces search- token costs by ≈13.0×"，`search- token` 为提取断词原样），口径是 GPT-5.5-price-equivalent：`0.20B + 0.80(0.10B) = 0.28B`，B = 6.68M → 1.87M；单价取 $5/M 输入、$30/M 输出（GPT-5.5）与 $0.5/$2.2（Nemotron 3 Ultra）。
- 一次失败案例的机制（Listing 2）：prover 的 node 66 把继承来的自我修订**默认关掉**，理由是修订"could degrade a correct/near-correct detailed proof into a weaker black-box citation-based proof"。

### 论文自陈的负面结果与局限（App G + §6.1）

1. "operate strictly at an epoch-local level, bounding neither transition counts, cumula- tive regret from erased evidence, nor long-term convergence to a globally optimal agent–evaluator pair"（原文该句主语为 "our mathemati- cal guarantees"，`mathemati- cal` 系提取断词）。
2. "evaluator quality is only as good as its anchor: a weak or biased anchor could yield uninformative evaluators"（APReS 决定与 IMO-GradingBench 分数本身就不完美）。
3. "all of our main experimental results relied exclusively on GPT-5.5 (low)"；"The current preprint provides a preliminary empirical in- vestigation"（提取文本有连字符断词，原文即 preliminary）；"We intend to explore longer search horizons in future updates."
4. "The reviewer panel inherently measures cross-reviewer acceptance behavior rather than objective, ground-truth scientific merit, and no human grading of the generated papers or proofs was performed."
5. Asm. 2 在真实部署中不可能严格成立（供应商侧模型更新、非确定性工具、硬件波动）。
6. 搜索循环本身是手写的："While our search loop is robust, it is still hand-crafted" —— 可演化面**不包括** scheduler 与 replacement 规则，扩面"While our search loop is robust, it is still hand-crafted"。
7. "precluded its inclusion in this version of our work"（原文前置 SWE-bench 的引用标号 [51]）

**论文未报告**：跨 domain 的统一 all-role 树、超参扫描、方差外的显著性检验（无 p 值/多 seed）、人类对论文/证明的评分、长 horizon 下的最终结论、被抹除证据的累计 regret 实测。

## 与 DWC 的映射

> 共享背景：DWC = 世界树(W1–W6) + judge 判分(C3') + δ 失败签名排序 + EL 调度(B/τ) + Dreaming 回放(K₂/β) + M>1 策略修订。判定四档：缺 / 半有 / 确认型 / 不适用。

| # | 机制（RQGM） | DWC 现状（代码级） | 判定 |
|---|---|---|---|
| 1 | **评估器共演化**：challenger 与在位者在同一 anchor 上比 BB_ε，赢了换 | `src/dwc/organs/judge.py` 文档头写死："★ 它**不进递归**（2608.24876 §5.1.1 硬要求: "𝒢_fixed 不能进递归。 递归改记忆，判分器不动。"）"；全仓 grep 无 challenger→judge 替换路径 | **缺（且是判据层面刻意的缺）**：DWC 把"判分器固定"当硬约束，RQGM 恰恰主张它是可演化对象。要搬必须先改判据而不是加代码 |
| 2 | **独立 anchor + 保守下界**：BB_ε 只吃 anchor 计数，1−ε 下界 | judge 有 `SPLIT_DEV`（"锚点集，恒小，每条带 golden reference"）与 `SPLIT_TEST`（"锁定集，metric 演化不许读"），`TRUTH_SOURCE = config/anchors/dev.json`，`_check_truth_source` 启动时指向不到文件就 raise | **半有**：anchor/锁定集齐全，但**选择规则不是统计下界**——judge 是规则比对 + `regression_check`（`delta < 0 ⇒ regression`），没有 Beta 分位数、没有"平票判在位者"、没有 1−ε 口径 |

| 6 | **对抗目标校正 judge 自偏好** | `judge.py` 的 c/q 分类是"**规则**分类，非 LLM"，`m` 才归 LLM 且"第一版确定性 ⇒ 无 LLM ⇒ m 留空并**显式标注**" | **不适用**：RQGM 的对抗项是为 LLM-judge 的 self-preference bias 而生（`judge.py` 无此失效模式）。DWC 若未来引入 LLM 评分面，这条才转为"缺" |
| 7 | **成本/不确定度口径**：blended tokens（输出 5×）、95% Jeffreys 区间 | `foundation/state.py:51` 有 `wm_dev_n  # 样本量（置信区间必需）`，但全仓无 Jeffreys/区间实现 | **缺（区间实现）/ 未核（DWC 报告链是否产区间）**：仅见字段注释，未见任何区间计算调用——`未核` |
| 8 | **训练分不进选择**："utility is computed on a HELD-OUT validation set you NEVER see" | `evolver.accept` 硬分支：`held_out 缺失时必须返回 "decision": "blocked"`（`Δ_in ≥ 0 ∧ Δ_ho ≥ 0` 双 split 约束）；judge 有 `SPLIT_TEST` locked | **确认型**：两侧独立地做出同一条"验证集不可见、只由外部判据选"的决定，RQGM 的实测（75/75 刷分、119/116 小差）给这条纪律补了反例证据。`实际运行中 held_out 是否被提供 ⇒ 未核` |

**最可搬的一条**：把 `dep(z)` 依赖集搬进 judge——DWC 每条判分证据记录写入时带上"由哪些判据/哪次改动产生"，这样将来任何一次判据或记忆规则变更都能做**定向失效**而不是全量失效或全量保留。这是纯数据结构改动，不动判据本身。

**不可搬**：RQGM 的收敛叙事。它是 epoch-local 的（原文自陈），DWC 现有的 `regression_check` 是跨轮保护组回归——两者对"跨轮是否更好"都没有保证，不能拿 RQGM 当背书。

## 综述 L 定位

> L 框架（2609.11873 §3）：**B0** 任务内输出变化（无持久系统改变）→ **L1** 执行人定程序 → **L2** 自主选改法（目标/验收仍外部固定）→ **L3** 自定学习议程 → **L4** 部署后改持久态 → **L5** 改"改进机制本身"。**structural L5** = 改动持久存在并控制下一轮；**effective L5** = 修订后的机制在**可比预算 + 独立评估**下产出/选出更好后继。

- **L 几：L5。** 证据链（逐条回综述原文核）：
  - §3.6.2（Improving Successor Evaluation 子方向）把 RQGM 作为该子方向的代表，原文："Its learned evaluator remains frozen within an epoch. At a scheduled boundary, challenger evaluators are compared against an independent ground-truth anchor"。
  "addresses this by freezing evaluators within each epoch and validating replacements against an independent ground-truth anchor"
  - §6（挑战章）："addresses this tension through evaluator co-evolution"，并把它作为「改 judge 会破坏跨轮可比性 / 不改 judge 会被钻空子」这对两难的一个解（意译 §6 原句）。
  - Table 7 行：`RQGM | Next-epoch selection | Evaluator; agent code | Anchor; replacement schedule`（可改的是评估器+agent 代码；外部固定的是 anchor + 替换排程）。
- **技术族：E4 Adaptive / Co-Evolving Evaluator（L5 格）**，同时出现在 Table 2 的 D3（Reward Model / LLM-as-a-Judge）与 D4（Regression Testing / Model Selection）行、以及 A1（Evolutionary Search）行——Table 2 中 RQGM 共 4 处，与书目 `Cited by: … , Table 2 , Table 2 , Table 2 , Table 2 , …` 的 4 次一致。**⚠️ D3/D4/A1 各行的 L 列归属在提取文本里单元格边界不可唯一确定 ⇒ 未核**（只有 E4 行可无歧义读出 `— | — | — | DecoEvo | RQGM`）。
- **structural vs effective**：
  - **structural：满足**。被晋升的评估器代码持久存在并**控制下一轮** epoch 的打分（Algorithm 1 行 27–30 是控制点）。
  - **effective：半有**。等预算比较存在（RQGM vs HGM-H 同 12,288 evals；Fig. 5 明确 3× 成本下更准；Table 7 逐格关闭机制对照），且替换判据是**评估器之外**的 anchor——这正是 effective 想要的"独立评估"。但 (a) 论文自陈 preliminary + 短 horizon，(b) 没有"修订后的 evaluator vs 原 evaluator 在同预算下的多 seed 显著性"，(c) 综述也只肯说它"addresses part of this problem"。
  - 综述对该方向的总评（Table 7/§3.6.5 的负面清单）不含 RQGM 的回退案例——**RQGM 没有被综述记录到负面结果**，这与 STOP/Gödel Agent/HyperAgents 各带一条负面形成对比。
- **与 DWC 的关系定位**：DWC 现处 **L4 形状 + L1 判据**（记忆/技能可持久改，但判分器固定且判据在可写面外）。RQGM 提供的是**L5 第 2 子方向（改后继评估）**的完整工程样板：epoch 冻结 + anchor 晋升 + 定向抹除 + 指数 checkpoint 摊还。它与 2608.10299 综述的 G-b（evolvable verifier 缺口）指向同一处。
