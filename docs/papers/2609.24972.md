## 1. 问题

### 论文自己承认的缺口

RRSI 的问题陈述在 Introduction 里写得很直白：**harness 递归演化会过拟合，而现有方法没有任何针对这件事的机制。**

原文逻辑链（§1）：

1. harness 决定 agent 能不能干活——"whether the same model reads the right file before editing it, recovers from a failed command, manages efficient working context"。近期 agent 产品的进展 "came from harness engineering rather than from new model weights"。但这些工程是**手动的**，"so progress is limited by how many trajectories an engineer can read"。
2. 近期方法把这个循环自动化（propose → select 组件级编辑），构成了 agent-system 层的 RSI。
3. **但**：test-time harness evolution "repeatedly proposes and selects edits using feedback from a finite evolve set, creating an adaptive overfitting risk: evolve-set performance may improve without corresponding gains on unseen tasks"。

论文把过拟合拆成**三个耦合行为**（这是本文最有价值的诊断，也是它区别于"我们加个正则化"这类论文的地方）：

| 论文的专有名词 | 原文定义 | 为什么危险 |
|---|---|---|
| **benchmark-specific fitting** | "The evolution search may encode benchmark-specific patterns" | 编辑里写死了基准特有的任务名 / 实体名 / 答案 |
| **noise chasing** | "promote candidates favored by the evaluation noise" | 同一个 evolve set 被自适应地反复看，随机赢家被固化成永久状态 |
| **complexity accumulation** | "accumulate complexity that improves evolve-set scores without improving the underlying agent mechanism" | 只涨 token 不涨机制，且 score-only 演化**没有删除任何东西的动机** |

**论文自陈的关键 framing（值得抄）**：既然已有工作 "explicitly separate evolution and evaluation tasks to measure generalization"，RRSI 就把这个分离当作**前提**，把研究问题定义为 "the generalization problem in recursive self-improvement, which is defined as evolved harness transferring to unseen benchmarks **with different task descriptions, tool interfaces, or verifiers**"。注意这三个"不同"是硬条件——不是同分布的 held-out 切分。

### Limitations 章节原文（全文只有这一段，逐条列出）

1. "Our study focuses on harness-level recursive self-improvement with **frozen backbone models**, and therefore does not address settings where model weights are updated during evolution."
2. "RRSI still relies on a **finite evolve set and several regularization hyperparameters**, so its effectiveness may depend on the quality of the feedback signal and the chosen search budget."
3. "although we evaluate transfer across multiple domains, benchmarks, and policy models, **broader validation is needed** to determine how well the method generalizes to substantially different agent architectures, tool ecosystems, and longer-running self-improvement processes."

**注意第 3 条**：论文自己承认它的 OOD 证据只在"同一套方法学家族"内成立——三域（coding / agentic workspace / engineering design）都是"agent 用工具 + 逐任务 rubric 或测试判分"，**没有一个真正异构的域**（没有长时程多 agent，没有非确定性环境）。

## 2. 核心机制

### 2.1 形式化起点（§2 Preliminaries）

- agent `A = (π, H)`：`π` 是冻结骨干，`H` 是 harness = "everything around the weights"——system/task prompt、控制流（何时 plan/act/reflect/stop）、工具接口及其描述、memory 与 skill 文件、context management。
- 轨迹 `τ ~ A(·|x)`，verifier 打分 `r(x,τ) ∈ [0,1]`；`c(τ)` = 该轨迹消耗的 **policy token 数**。
- 两个度量（式 1）：`S(H;𝒟) = E_x E_τ[r(x,τ)]`，`C(H;𝒟) = E_x E_τ[c(τ)]`。
- harness evolution 的通用循环（式 2）：

```
ℋ_t = {H_t⁽¹⁾,…,H_t⁽ᵐᵗ⁾} ~ P₀(· | H_t, ℱ_t)
H_{t+1} = argmax_{H' ∈ ℋ_t ∪ {H_t}} Ŝ(H'; 𝒟_evolve)
```

- 经验分数与经验成本（式 3）：

```
Ŝ(H) = (1/(k·|𝒟_evolve|)) Σ_{x∈𝒟_evolve} Σ_{j=1..k} r(x, τ_x⁽ʲ⁾)
Ĉ(H) = (1/(k·|𝒟_evolve|)) Σ_{x∈𝒟_evolve} Σ_{j=1..k} c(τ_x⁽ʲ⁾)
```

- **RRSI 的形式化替换（式 8，Appendix C.1）**：

```
ℋ_t ~ P_reg(· | H_t, ℱ_t, ℒ_t, b_t, ℰ_t, ℬ_t) ⊆ Ω(H_t)
H_{t+1} = argmax_{H' ∈ ℋ_t ∩ 𝒜_t} Ŝ(H')
```

其中 `ℒ_t` 是编辑历史，`b_t` 是退火编辑预算，`ℰ_t` 是探索指令，`ℬ_t` 是剪枝目标集，**`𝒜_t` 是允许替换 incumbent 的候选子集**。若 `𝒜_t = ∅` 则 `H_{t+1} = H_t`。

**关键设计立场（论文反复强调）**：`Ω(H)` **保持完全开放**——"prompts, control flow, configuration, context management, tools, skills, memory, and subagents may all be modified, added, or removed"。RRSI 不限制假设空间，只**正则化穿过它的搜索轨迹**。这是与"我们只允许改 prompt"这类方法的根本分歧。

### 2.2 提案侧三个正则器（§3.2）

**(1) `L₀`-Style Annealed Update Sparsity（退火编辑稀疏度）**

把第 t 轮的一个候选表示成原子编辑池 `E_t` 上的 0/1 选择向量 `z_t ∈ {0,1}^{|E_t|}`，`z_{t,j}=1` 表示包含第 j 个编辑（**池每轮重抽，故 `|E_t|` 不固定**）。约束是 `‖z_t‖₀ ≤ b_t`，其中

```
b_t = ⌈ b_min + (b_max − b_min) · ½(1 + cos(π t / T)) ⌉          (式 4)
```

余弦退火：`t=0` 时 `b_t = b_max`，`t=T` 时 `b_t = b_min`。论文明确 `b_min = 1`（三个 instance 全是，见 Table 5）——**最后一轮只允许一个可独立归因的编辑**。

为什么这有用（原文逻辑）：不约束的 proposer 会把"很多互不相关的修改"捆成一个候选，"Such candidates have high effective capacity: they can fit more idiosyncrasies of the current feedback, and any measured change is difficult to attribute to a particular mechanism"。**论文自己声明这只是类比**："The analogy applies to update sparsity rather than to a fixed model parameter vector … we do not optimize an `L₀`-penalized objective."

**(2) Evidence-Aware Credit Assignment（证据感知信用分配）**

维护编辑历史（式 10）：

```
ℒ_t = { (t_i, ℓ_i, h_i, d_i, ΔS_i, ΔC_i, a_i) : i ≤ n_t },  a_i ∈ {0,1}
```

每个被评估候选里的每个原子编辑都打三个标签：组件 `ℓ`、假设 `h`、源码 diff `d`。**`a_i = 1` 当且仅当携带编辑 i 的候选成为该轮赢家**；通过了所有门但输给更高分候选的，`a_i = 0`（记为 "admissible but lost"，是有用信息）。

两个派生摘要（式 11）：

```
𝒯_t = { ℓ_i : i ≤ n_t }
g_t(ℓ) = max{ ΔS_i : ℓ_i = ℓ, t − t_i ≤ n_prune },   max∅ = −∞
```

**(3) Structured Exploration（结构化探索）**

停滞检测 `σ_t = 1[Ŝ_t − Ŝ_{t−w} ≤ δ]`（式 13）。停滞时，把一小部分提案配额留给**本轮运行中从未被测量过的组件**。可编辑组件词表：

```
𝒦    = { prompt, control_flow, config, output_plumbing,
         context_mgmt, client_tool, skill, memory, subagent }   (式 12)
𝒦_str = { client_tool, skill, memory, subagent }               (式 15)
𝒰_t  = 𝒦 ∖ 𝒯_t        ← 从未被测量过的组件
ℰ_t  = ( σ_t, 𝒰_t, m_draft )                                   (式 13)
```

### 2.3 选择侧四个非补偿判据（§3.3）

论文反复强调 "**non-compensatory** criteria"——即每一项独立否决，不能用别的项补偿。这是与 HarnessX seesaw 式门的关键差别。

**(1) Leakage Screening（泄漏筛查）**
在**完整评估之前**，critic 读每个候选 diff，拒绝 "edits that explicitly encode task names, entity names, task-specific values, answers, or other logic specific to the evolve benchmark"，以及 "edits that add inert machinery"。筛查目标是 benchmark-specific **内容**，不是特定组件——"generic prompt or tool-description improvements remain valid candidates"。论文解释了为什么必须前置："a leaking candidate never receives the inflated evolve-set score that could make it attractive to subsequent rounds."

**(2) Stability-Aware Acceptance（稳定性门）**
演化前**反复评估未改动的 base harness** 估计经验噪声带 `δ`。判据：

```
Ŝ(H') ≥ S⋆ − δ                                                  (式 5)
```

论文的论证："The floor prevents the search from walking downhill through a sequence of regressions that are individually small enough to be mistaken for noise."（并引 Dwork et al. 2015 的 adaptive data analysis 作为理论依据。）

**(3) Ridge/`L₂`-Style Complexity-Aware Acceptance（成本—收益门）**

```
ΔS = Ŝ(H') − Ŝ(H_t)
ΔC = (Ĉ(H') − Ĉ(H_t)) / Ĉ(H_t)                                  (式 6)
对 ΔS > δ 的候选：要求 ΔC ≤ β₀ + β₁·ΔS                            (式 7)
```

`β₀` = 可容忍的零收益成本增量；`β₁` = 收益增大时额外允许的成本。`β₀/β₁` **在 evolve set 上选定后对所有 transfer 评估固定不变**（D.1 重复了两次）。

**(4) Lasso/`L₁`-Style Structural Pruning（结构剪枝）**
`ℬ_t = { ℓ ∈ 𝒯_t : g_t(ℓ) ≤ 0 }`（式 14）——在最近剪枝窗口内**没有产生严格正收益**的组件被标为删除目标，下一轮 proposer 收到 `ℬ_t` 并被要求移除。论文的机制性论证："a mechanism must continue to earn its place rather than persist simply because score-only evolution has no incentive to remove it."

### 2.4 选择侧的实现细节（Appendix C.3）——这部分是论文最有工程价值的地方

**新颖度 `ν`（式 16）**：`ν_t(H') = Σ_{ℓ∈𝒦_str} 1[ ℓ ∈ comp(H') ∧ N_t(ℓ) = 0 ]`
即"本候选触及的、此前从未进入过获胜编辑路径的结构型组件类型的个数"。**prompt / control_flow / config / output_plumbing / context_mgmt 拿不到这个新颖度奖励**——这是刻意的：防止"改 prompt"成为探索捷径。

**噪声带内的可接受性规则（式 17，正文只在 Appendix 提到）**：

```
w_s·ΔS − w_c·ΔC + w_n·ν_t(H') > 0,   w_s, w_c, w_n ≥ 0
```

这是 RRSI 论文里最被忽视但最实用的一条：**当 ΔS ≤ δ 时，式 7 不适用**，改用一个带新颖度奖励的线性打分。含义：**噪声带内的微小提分本身不足以让候选被接受，必须靠降成本或靠"首次尝试某类结构机制"来换取接受。** 论文特别说明 coding instance 设 `w_s = 0`——"a score increase that remains within δ cannot by itself make a coding candidate admissible"。另两个 instance 用正的 `w_s`。

**DomainGuard（域特定的非补偿守卫）**：
- coding / agentic-workspace：`g ≡ 1`，无额外守卫。
- **engineering-design**：valid-output rate 相对 incumbent 下降 > **0.03**，或 no-submission rate 上升 > **0.02**，直接拒绝。论文的用意："These guards prevent a gain in the primary pass-rate objective from compensating for a substantial degradation in basic execution validity."

### 2.5 Algorithm 1 / Algorithm 2 逐行结构

**Algorithm 1（提案侧）**：输入 `(H_t, ℒ_t, t, T, b_min, b_max, w, δ)`
1. `ℱ_t ← Analyze(H_t, 𝒟_evolve)` — analyst LLM 写跨轮失败反馈
2. `b_t ← ⌈b_min + (b_max − b_min)·½(1 + cos(πt/T))⌉`
4. `σ_t ← 1[Ŝ_t − Ŝ_{t−w} ≤ δ]`
5. `𝒯_t ← {ℓ_i : (t_i, ℓ_i, …) ∈ ℒ_t}`；`𝒰_t ← 𝒦 ∖ 𝒯_t`
6. `ℰ_t ← (σ_t, 𝒰_t, m_draft)`
7. `ℬ_t ← {ℓ ∈ 𝒯_t : g_t(ℓ) ≤ 0}`
8. `ℋ_t ~ P_reg(· | H_t, ℱ_t, ℒ_t, b_t, ℰ_t, ℬ_t)`
9. "tag each atomic edit with component and hypothesis metadata"
10. "return candidates that pass the pre-evaluation screen"

**Algorithm 2（选择侧）**：输入 `(screened ℋ_t, (H_t, Ŝ_t, Ĉ_t), S⋆, δ, k, β₀, β₁, w_s, w_c, w_n)`
- 对每个候选**并行**评估 `Evaluate(H', 𝒟_evolve, k)`；算 `ΔS`、`ΔC`、`ν ← ν_t(H')`
- **分支 1**（`ΔS > δ`）：`c ← [ΔC ≤ β₀ + β₁·ΔS]`
- **分支 2**（否则）：`c ← [w_s·ΔS − w_c·ΔC + w_n·ν > 0]`
- `g ← DomainGuard(H_t, H')`
- **总接受条件（三个 AND）**：`Ŝ' ≥ S⋆ − δ` ∧ `c` ∧ `g`
- `H_{t+1} ← argmax_{H'∈𝒜_t} Ŝ'`，否则 `H_t`
- `S⋆ ← max(S⋆, Ŝ_{t+1})`
- "record each measured edit with `a=1` iff its candidate is `H_{t+1} ≠ H_t`" ← 这就是信用分配闭环的写回点

## 3. 关键实验与数字

### 3.1 基准与样本（Appendix A 逐个说明）

| 域 | Evolve split | 规模 | 判分方式 | Held-out |
|---|---|---|---|---|
| coding | **Terminal-Bench 2.1** | **89** 个容器化终端任务 | 任务自带单测（"reward is exact and cannot be produced by a plausible-looking answer"），容器在 arm 之间拆掉重建 | **SWE-bench Verified**（fail-to-pass + pass-to-pass 都满足才算解决） |
| agentic workspace | **Harvey LAB** | 25 个 practice area；**固定划分 120 evolve / 40 held-out** | 每任务 20–100 条独立判据，全量约 **14,000 条 criterion verdicts**；逐条由 Gemini-3.5-Flash 隔离判分；缺交付物 = 该任务全部判据失败 | JobBench、GDPval、APEX-Agents（**480 任务全分母**）、Harvey LAB ID held-out |
| engineering design | **EngDesign** | **61** 个免许可子集任务 | **每任务自己的冻结模拟器 / 测试台，确定性，无 judge**；无 ID held-out（"the suite is too small to spend tasks on one"） | Frontier-Eng（26 域；v1 集 47 任务，EngDesign 域剔除 + 环境构建失败者不计分 → **38 任务计分，两 arm 同任务集**） |

**base harness（三个域各不相同）**：coding 用 **Terminus-2**；agentic workspace 用 **ReAct loop over MCP tool gateway + dynamic toolbelt**；Harvey LAB 与 EngDesign 用 **ReSum-style context management**。

|---|---|---|---|---|---|---|

| TTHE | 91.1 | 88.5 | 35.2 | 47.0 | 31.7 | 38.0（**"TTHE by 1.7 points"** 低于 `H₀`） |

**这张表的读法（论文自己的话）**："Every one of them works well on evolve set. The performance on in-distribution held-out split is quite similar. The separation appears out of distribution, and there **the ranking inverts**."

**RRSI 的交易被论文明说**："RRSI posts the **smallest evolve-set gain** of any evolved harness and the only out-of-distribution average that clears `H₀` by more than a point."

### 3.3 三域的 headline 数字（§4.2 正文）

- Evolve split 增益：Terminal-Bench 2.1 **+6.0**、EngDesign **+4.9**、Harvey LAB **+1.1**（论文原文逐个列出）。
- SWE-bench Verified **+1.8**（"although repository-level bug fixing was never scored"）。
- Harvey LAB ID held-out **+2.3**。
- 三个 OOD agentic 基准 **+3.5 到 +4.7**，即 **7.2% 到 13.1%** 相对提升。
- Frontier-Eng **+4.3 Medal points = 24.3% 相对提升**。
- **"No held-out split regresses anywhere, which is the failure a memorizing harness produces."**

**抗 judge-artifact 的论证**：Harvey LAB / JobBench / GDPval 都由 judge model 打分，理论上 harness 可以"学会按 judge 口味写作"。论文用 EngDesign/Frontier-Eng 关掉这条路——"each EngDesign and Frontier-Eng task is graded by its own simulation or testbench, the grading is deterministic, and a design either meets the stated constraints or does not. The gains survive there unchanged."

### 3.4 消融（Table 2，agentic workspace，各 arm 共享 base / policy / evolve split / 轮数 / 候选预算）

| Variant | Harvey LAB (Evolve) | ID Held-out | OOD Avg. | Tokens/trial (M) ↓ |
|---|---|---|---|---|
| `H₀` | 89.4 | 86.9 | 39.7 | **1.56** |
| **Unregularized evolution** | **92.8（全场最高）** | 88.9 | 40.3 | 3.80 |
| w/o proposal regularizers | 90.7 | 88.8 | 41.9 | 2.69 |
| w/o acceptance regularizers | 91.5 | 88.7 | 41.0 | 3.59 |
| **RRSI** | 90.5 | **89.2** | **43.6** | **2.42** |

**三条论文点明的读数**：
1. 去掉 acceptance 约束：evolve 从 90.5 → 91.5，**OOD 从 43.6 → 41.0**，token 涨一半。论文归因："an unconstrained selection rule spends most of its accepted edits on noise and on context rather than on mechanism."
2. 去掉 proposal 约束：**evolve 只掉 0.2**，**OOD 掉 1.7**。"suggesting that steering where the search looks matters even when nothing is rejected."
3. 两者都去掉：evolve 92.8 最高，OOD 40.3（"within a point of the unevolved harness"），3.80M tokens vs RRSI 2.42M。**这就是 RRSI 全部主张的实验骨架：evolve-set 分数与 transfer 是反向的。**

- **未参与的 Gemini 3.1 Flash Lite：11.2 → 14.6（+3.4，30.4% 相对提升）**

论文的洞见表述（值得直接抄进设计文档）："**A harness is a program, not a set of weights, so a mechanism that helps only the policy it was searched against is an artifact of that policy rather than a reusable one.**"

### 3.6 成本（Figure 4，agentic workspace evolve split）

- **`H₀` 是最便宜的：1.56M tokens / trial、21.2 步**。
- **RRSI 2.42M tokens / trial、26.3 步 / trial**。

- **负面结果**：**论文正文与表格中没有一条 RRSI 自身低于 `H₀` 的 held-out 数字**——作者把 "No held-out split regresses anywhere" 当作卖点主动陈述。但**有两条基线的负结果被明确记录**：AHE 与 TTHE 的 OOD 均值低于未演化 harness（TTHE 低 1.7 分）；HarnessX 的 OOD 均值与 base 完全相同（增量 0.0）。

- **失败 / 崩塌案例**：论文只给了 4 个定性案例（Appendix E），**没有报告演化过程中出现过的 reward hacking、路径坍缩、或 critic 误杀**。唯一接近的是 R0-B / R8-B 这两个"被正确拒绝"的案例。**论文未报告任何一次 critic 误杀（false positive）导致的假阴性。**
- **超参敏感性**：**完全未报告。** 没有 `δ` / `β₁` / `b_max` 的扫描曲线，只有单点取值（Table 5）。
- **统计显著性**：**论文未报告**（无 error bar、无多 seed 方差、无显著性检验）。δ 是"噪声容限"但不是"置信区间"。
- **演化 token 总成本**：**论文未报告**（只报告每 trial 的稳态成本，没报告 20/40 轮 × k 次 trial × 每轮多候选的累计消耗）。

## 4. 它假定了什么

这一节把论文没明说但成立所依赖的前提挖出来。**每条都标出它是否被论文检验过。**

**A1 · 有限 evolve set 的自适应重看 = 标准意义上的"过拟合"。**
论文引 Dwork et al. 2015（adaptive data analysis / holdout reuse）作为噪声带 `δ` 的理论依据。**隐含假设**：`𝒟_evolve` 的自适应重看造成的过拟合，与经典统计学习里的 holdout reuse 过拟合在行为上相似、且可以用同一个 `δ` 修正。**论文未做理论证明**，也未检验"这个类比在多轮（20–40 轮）下还成不成立"——Dwork 的界通常依赖复用次数，而这里的复用次数等于轮数 × 每轮候选数，**论文未报告这个乘积**。

**A2 · `Ω(H)` 开放但"可归因的编辑"存在。**
RRSI 假设可以干净地把一轮的 harness diff 切成若干 "independently attributable edits"，每条打一个组件标签 `ℓ`。**但 harness 源码的 diff 常常不可分解**——改一个 `control_flow` 分支可能同时改变 prompt 拼装与 context 压缩行为。论文通过 `b_t → 1` 来缓解（最后一轮只许一个编辑），**但论文未报告有多少候选真的能被干净归因**，也未报告 `g_t(ℓ)` 的标签质量如何被验证。

**A3 · policy token 数是"复杂度"的合格代理。**
式 7 用 `Ĉ`（policy token 数）当 `L₂` 的对应物。**隐含假设**：一个 harness 的"资源足迹"可以用 token 成本代表。**这漏掉了**：prompt 变长导致的 prefill 成本（不在 rollout 里）、harness 代码本身的维护复杂度、以及"多花 20% token 换来 4.9 倍可靠性提升是否划算"这种价值判断。论文自己的例子 R0-B 恰好说明了这个代理的不完美——**它拒绝了一个可能是好机制的改动，仅仅因为成本**。

**A4 · critic 能可靠识别 benchmark-specific 内容。**
Leakage Screening 是一个 **LLM critic**（Claude Opus 4.8）读 diff 做判断。**隐含假设**：Opus 4.8 级别的模型能区分"通用的、可能复用的改动"与"写死了任务名的改动"。**论文未报告**：critic 的漏检率、误检率，也没有人工标注的对照。critic 与 proposer 同为 Opus 4.8，**自评偏置未被检验**（cf. `2607.12790` Double Ratchet 关于共谋塌缩的实证）。

**A5 · 每个域都能找到一个"确定性判分"的下游基准来证伪 judge-artifact。**
论文用 EngDesign/Frontier-Eng 的确定性模拟器作为"harness 不是在取悦 judge"的证据。**隐含假设**：至少存在这样的下游面。**对 DWC 的直接后果**：DWC 的记忆/进化能力**没有确定性 verifier**——它的正确性判据本身就是 LLM 判的。**RRSI 这条抗-artifact 论证在 DWC 上无法复制。**

**A6 · "更小、更通用"的编辑假设带来 transfer。**
这是论文的核心主张。**隐含假设**：能在 evolve set 上以低成本小幅提升的编辑，其信息量密度更高，因而更可能 transfer。**论文未提供直接证据**——没有"单编辑 ΔS 与该编辑 OOD ΔS 的相关性"这类归因分析。对比：HarnessX 报告了 per-lever 命中率，RRSI 报告的是 `g_t(ℓ)` 剪枝判据，两者不是一回事。

**A7 · 只有 harness 变，权重不变。**
Limitations 第一条自陈。这带来一个论文未讨论的好处和一个未讨论的坏处：
- 好处：harness 是程序，跨骨干可移植（Table 3/4 证明）。
- 坏处：**上限被骨干钉死**。`H₀` 在 Gemini 3.1 Flash Lite 上只有 11.2，RRSI 只能把它抬到 14.6。**harness 无法弥补模型能力的绝对差距**，只能榨取相对增益。

**A8 · 超参可以在 evolve set 上定，且定完对 transfer 仍合适。**
`δ` 从 base harness 重复评估校准，`(β₀,β₁)` 在 evolve set 上选。**隐含假设**：evolve set 上的成本—收益交换率在 OOD 域上大致相同。**论文用一个事实支持它**（β₁ 按"每 pass / 每 100 criterion"的物理单位换算，跨域口径一致），**但没有敏感性分析**——如果 β₁ 在 OOD 域上该是 2 倍或 0.5 倍，整篇论文的结论会变。**这是全文最脆的一根承重柱，且论文自己没意识到。**

**A9 · 非补偿门比补偿门更适合 harness 演化。**
论文把所有判据设计成 AND，且明确说 "non-compensatory"。**隐含假设**：不存在"某个指标的小幅退化可以被另一个指标的大幅提升补偿"这种合法情况。**代价**：engineering-design 域的 DomainGuard（valid-output 掉 0.03 即拒）会让某些合法的能力扩展被误杀。**论文未报告 DomainGuard 触发过几次**（Table 6 的 Engineering R2 是被接受的案例，不是被 DomainGuard 拒的）。

RRSI 的消融表（Table 2）证明了一件事：**"evolve set 上的分数"不是一个可以单独优化的目标**。DWC 的母巢目前没有 held-out split，它的每次演化报告只有一个数字。**正确的形状是：每次演化必须同时报告 evolve split 与一个切分不同的 held-out split 的差值**——这不是抄公式，是抄验收指标的结构。

### 5.2 不可迁移

- **不可迁移（闭源模型，最硬的一条）：整个 meta-agent 环 = Claude Opus 4.8。** proposer、analyst、leakage critic 三角色全部是 Opus 4.8；policy 也是 Opus 4.8。这不是"性能更好"的问题，而是**三个判据性角色必须彼此独立才能构成有效门**——当 proposer 与 critic 同权重同厂商时，RRSI 的泄漏筛查与信用分配都建立在"Opus 能审自己"这个未验证的前提上（A4）。DWC 用托管/免费模型时**不能假定同等判别力**。
  - **公平的说法**：RRSI 的机制（预算、账本、剪枝、门）与 proposer 能力弱耦合——它可以被弱模型执行而只损失质量。但**A4 的 critic 质量是外生的**，DWC 必须自己标定 critic 的漏检率，否则泄漏门是装饰性的。

- **不可迁移（证据面不成立）：抗 judge-artifact 的论证在 DWC 上无解。** RRSI 用 EngDesign/Frontier-Eng 的确定性模拟器证明"harness 不是在取悦 judge"。DWC 的记忆与进化**没有确定性 verifier**——判据本身就是 LLM 判的。**这意味着 DWC 无法复制 RRSI 最强的那条抗-artifact 论证**，只能复制"更少涨分、更能跨切分"这种弱得多的主张。

- **不可迁移（组件归因前提）：`ℓ` 标签要求失败可归因到已构造的组件。** RRSI 的整条账本建立在"这条编辑改的是哪个已存在的组件"之上。**DWC 母巢的已知病是"核心功能零实现"**——组件本身就没被构造出来，`𝒦` 里的词条在代码里没有对应物。**这是三篇里对 DWC 最不利的一条**：M3/M4/M6 全部依赖 `ℓ` 可填。**若组件不存在，账本只能记到文件级，`g_t(ℓ)` 的语义从"机制收益"退化为"文件收益"，剪枝门会退化成"删掉最近没改动的文件"——这是危险的。**
  - 可行的折中：先给 DWC 建 `COMPONENT_VOCAB` 的**声明式映射表**（哪个文件/类对应哪个组件名），把"组件"从物理实体降级为**约定标签**，并在账本里记录 `ℓ ∈ declared_only` 标记，让 M4 的剪枝门**默认对 declared_only 组件关闭**。

- **不可迁移（无统计口径）："improves every held-out split"缺显著性。** RRSI 未报告 error bar / 多 seed 方差 / 显著性检验。Harvey LAB 的 40 任务 held-out 是一次性划分。**DWC 若拿 RRSI 的 +1.8 / +2.3 这类小增量做设计依据，会踩到"噪声内改进"的坑**——而这恰恰是 RRSI 自己用 `δ` 攻击的对象。**搬机制前必须先把 `δ` 标定做出来（M7），否则无法区分 RRSI 的真增益与噪声。**

- **不可迁移（结论数字不可外推）：+14.1 / +4.7 / +22.9% 不能直接引用。**
  - **+14.1 只发生在 Gemini 3.5 Flash 上**（Opus 4.8 上是 +6.0），**摘要与 Figure 1 用的是这个最好的数**。
  - **+4.7 是五个 OOD 切分里最好的一个**（agentic 区间 +3.5~+4.7 的上端；SWE-bench 只有 +1.8）。
  - **"outperforming the average prior baseline by up to 22.9%"**（§1 末）的算式**论文未给出**；按 Table 1 复核，RRSI 的 OOD 均值 43.6 vs 四基线均值约 39.4 → **约 +10.6%**，不是 22.9%。**这个 22.9% 无法从论文给出的表格复现，引用时应标注"算式未公开且与 Table 1 复核不符"。**
  - **evolve split 数字是峰值**：Table 1 里 RRSI 的 Harvey LAB evolve 90.5 **低于**四个基线全部。

- **不可迁移（轮数与预算量级）：20/40 轮 × k=2/4 次 trial × 每轮多候选，全量评估。** 论文未报告累计 token。**DWC 的演化预算比这低一到两个数量级**，必须先做"代理评估 + 确认评估"两段式——**RRSI 完全未涉及这个设计**。

- **不可迁移（超参敏感性未知）：`β₁` 取 44.5 / 35.4 / 24.4，`δ` 取 0.017/0.004/0.020，无任何扫描。** 论文 Limitations 第 2 条自陈依赖 "the chosen search budget"。**DWC 若照抄这三组值而不重标定，正确性没有任何保障。**

- **不可迁移（编辑池语义）：RRSI 的 `E_t` 每轮从开放空间重抽，`|E_t|` 不固定。** DWC 的母巢如果有固定的候选台账，"每轮重抽"意味着**上一轮被拒的编辑不会被自动重试**。RRSI 的 `a_i=0`（admissible but lost）只影响信用、不影响重试——**DWC 若需要一个"被拒编辑的重试队列"，RRSI 没有给这个机制。**

## 6. 与其他论文的关系

### 6.1 在 RSI 图谱上的位置

RRSI 属于**harness 自进化派**，且是该派里**唯一把"过拟合"当作一等公民问题来形式化**的一篇。它的方法论来源不是 agent 领域，而是**自适应数据分析与压缩理论**（Dwork et al. 2015 的 holdout reuse；Louizos et al. 2018 的 `L₀` 稀疏；Hastie et al. 2009 的 Lasso/Ridge；Haarnoja et al. 2018 的熵正则作为多样性类比）。**论文自己反复声明这些只是类比**（"The analogy is qualitative"、"we do not optimize an `L₀`-penalized objective"）——这是诚实的，但也说明它的"正则化"是**工程直觉的重新命名，不是可证明的映射**。

按 `2609.13406`（GAI 框架）的两个 dial 定位 RRSI：
- **改进机制属于 agent 自身**吗？**是**——proposer 读自己的 trace、提出自己的 harness 编辑。
- **度量锚定在系统外**吗？**是**——固定 verifier；且 APEX-Agents 用全分母 480 任务显式防止"崩溃的 harness 看起来更好"。

→ RRSI 是 **GAI 框架在 harness 层的一个高完成度实例**，且它比 `2606.14249`（HarnessX）更早明确写下"递归演化本身需要被正则化"这个命题。

### 6.2 与 `2606.14249` HarnessX（直接竞争，且被 HarnessX 报告为对照）

这是本批次里**最需要对照阅读的一对**。HarnessX 报告的 §6 已确认 RRSI 是其四个对照之一。

| 维度 | HarnessX（`2606.14249`） | RRSI（`2609.24972`） |
|---|---|---|
| 编辑空间 | 九维 typed 组件 + `singleton_group` 互斥 + 变体隔离 | `Ω(H)` 完全开放，9 个组件只是**归因标签**不是可编辑边界 |
| 防过拟合手段 | **变体隔离**（不同任务簇用互不干扰的 variant）+ seesaw（不得回归已通过任务） | **提案侧退火预算 + 信用分配 + 结构化探索；选择侧泄漏筛查 + 噪声地板 + 成本门 + 结构剪枝** |
| 门的强度 | seesaw：不得回归已通过任务 | **三个非补偿 AND**：`Ŝ' ≥ S⋆−δ` ∧ 成本规则 ∧ DomainGuard |
| 成本处理 | **无显式成本门**（HarnessX 报告 100M–175M meta-agent token / 15 轮） | **成本是一等判据**（`ΔC ≤ β₀+β₁ΔS`），RRSI 是全部 arm 里最便宜的演化 harness |
| held-out | **明确不评估**（HarnessX §7.7 第一条） | **8 个基准、3 域、6 个 held-out 切分、2 个 backbone、1 个跨骨干迁移** |
| 病理记录 | **有**（GAIA R10 reward hacking / R11 trace 检出 / R12 加 guard；Global 峰值 −24.3%） | **无**（只有 4 个"被正确拒绝"的案例；没有一次 harness 出现 reward hacking） |
| meta-agent | Claude Opus 4.6，15 配置 | **Claude Opus 4.8，三角色同权重** |

**关键的互补点**：HarnessX 用实验证明了 **per-edit gating 会被亚阈值耦合绕过**（Telecom R7：连续 5 轮同类型编辑，第 6 条触发 −14.0%），RRSI 的 `σ_t` 停滞检测 + `m_draft` 探索配额 + `𝒰_t = 𝒦 ∖ 𝒯_t`（强制去碰未测组件）**正是在补这个洞**——如果 proposer 连着五轮改 prompt，RRSI 会把下一个候选的配额挪给 `skill`/`memory`。**这是 RRSI 相对 HarnessX 的一个真实增量，而不只是正则化包装。**

**但要公平地说反向的**：HarnessX 的 seesaw 是全局回归门（"不得回归已通过任务"），RRSI 的地板是**相对历史最好分数的 `δ` 带**（`Ŝ' ≥ S⋆ − δ`）——**RRSI 允许小幅累积退化**（每轮 −δ 以内可以），HarnessX 不允许。RRSI 的补偿手段是 `S⋆` 只增不减的更新（`S⋆ ← max(S⋆, Ŝ_{t+1})`），所以退化不能连续发生。**这是一个真实的设计分歧，不是同一件事的两种写法。**

### 6.3 与 `2606.09498` Self-Harness（同一问题域，RRSI 是它的直接升级路径）

Self-Harness 的自述局限第一条是 "accepted edits may still reflect benchmark-specific failure patterns"——**RRSI 的问题陈述就是这一条**。RRSI 的对策（critic 筛 benchmark-specific 提案 + 预算约束 + pruner）是对 Self-Harness "并行提出 K 个 + 全部合并" 的无界策略的直接修补。

**双向的差别值得记下**：Self-Harness 有 **held-in / held-out 双切分非退化判据** `Δ_in ≥ 0 ∧ Δ_ho ≥ 0 ∧ max(...) > 0`，**比 RRSI 的 `Ŝ' ≥ S⋆−δ` 更严**（RRSI 允许 held-out 小幅退化）。但 RRSI 有 Self-Harness 没有的：**成本门**（`ΔC`）、**退火预算**、**新颖度奖励**。**两者是门严性 vs 成本纪律的取舍，不是优劣关系。**

### 6.4 与 `2609.14857` ModularRSI（同期、直接竞争，且是同一批里最该并排读的一对）

| 维度 | RRSI | ModularRSI（`2609.14857`） |
|---|---|---|
| 防 benchmark 记忆的手段 | **在 evolve set 上正则化**（critic 事前筛 + 门控接受） | **在数据层面根除**：2,000 个与评测基准完全不重叠的演化任务（Table 1 的 "Do Not Use Benchmark Data ✓"） |
| 证据归因手段 | 组件标签 + 编辑历史 + `g_t(ℓ)` | **五模块分解**（Agent Loop / Observation Management / Tool Use / Context Management / Task Completion Detection）+ **同任务成功-失败对比** |
| 门 | 三个非补偿 AND + DomainGuard | **三道验证门**：Program Check（AST/import/protocol/发现契约/静态自审）→ Diff Review（Code-Modify Agent 自审是否 task-specific）→ Execution Validation（每次改动随机抽 2 任务实跑，runtime error 即回滚） |
| 演化预算 | T = 20/20/40 轮，k = 2/2/4 | **3 epochs**，5 模块各 3 轮 + 1 轮跨模块整合 |
| 进化数据 | evolve set = **下游基准本身**（Terminal-Bench 2.1 / Harvey LAB / EngDesign） | evolve set = **2,000 个 benchmark-disjoint 任务**，每个实验只用 120+120 |
| 对照实验 | 4 个 harness 演化方法（Meta-Harness / AHE / TTHE / HarnessX） | AHE + Meta-Harness，**在 benchmark-disjoint 协议下重跑** |
| 关键发现 | evolve 涨分与 transfer 反向（92.8→40.3 vs 90.5→43.6） | **joint all-module 演化（44.19）与 non-modular 演化（46.44）都低于 baseline（47.57）**，只有模块独立演化 + 整合能涨（52.43） |

**互补关系（三点，都是实质性的）**：

1. **RRSI 证明"在基准上演化会过拟合"，ModularRSI 证明"不在基准上演化就解决了"。** 两者合起来给出一条完整因果链：ModularRSI §6.4 把 AHE 与 Meta-Harness 放到自己的 benchmark-disjoint 协议下重跑，得到 "accuracy changes of approximately one percentage point"——**也就是说，那两个方法在 RRSI 的 Table 1 里之所以 evolve set 涨 3.6 分（93.0 vs 89.4），涨的主要是基准记忆**。RRSI 自己在正文里没有做这个交叉实验（它没有 benchmark-disjoint 数据），ModularRSI 做了。

2. **RRSI 的 `𝒦`（9 个组件标签）与 ModularRSI 的五模块是同一次分解的两种切法。** RRSI 的 `𝒦` 是**归因标签**（不限制编辑边界），ModularRSI 的五模块是**硬边界**（`locked_module` 字段强制本轮只能改一个模块）。**ModularRSI 的实验证明了硬边界是必要的**：joint 演化低于 baseline。**RRSI 的软标签没有这个保护**——RRSI 允许一个候选同时改 `control_flow` 和 `memory`，其归因质量因此可能更差。**但 RRSI 用 `b_t → 1` 在末轮部分弥补了这一点，两者是不同强度的解。**

3. **ModularRSI 的 Diff Review 与 RRSI 的 Leakage Screening 是同一件事的两次实现，但审查者的可信度不同。** RRSI 的 critic 是与 proposer **分离**的 Opus 4.8 角色；ModularRSI 的 diff 审查由**同一个 Code-Modify Agent** 执行（"The agent under evolution itself serves as the Code-Modify Agent for both trajectory analysis and harness modification"）。**按 `2607.12790` Double Ratchet 的结论（被评估对象与评估机制同源会共谋塌缩），ModularRSI 的 Diff Review 在结构上更脆弱**——这是一个两篇论文都未讨论的分歧。**RRSI 的角色分离是更强的设计。**

### 6.5 与 `2609.06396` MetaRSI（类型学上的同构）

MetaRSI 的 Data-RSI / Harness-RSI / Model-RSI 三型算子，与 RRSI 的"harness 全可编辑、权重冻结"立场一致。RRSI 的贡献是把 **Harness-RSI 这一型的失败模式（过拟合）第一次量化**——MetaRSI 给出类型，RRSI 给出该类型下"不做正则化会怎样"的实测。**两篇互补，不重叠。**

### 6.6 与 `2609.14858` Dream-RSI（元层的间接竞争）

Dream-RSI 防过拟合的手段**完全不同**：它用 held-out 的 replay world 做选择，而 RRSI 用正则化约束搜索本身。Dream-RSI 报告已指出："Dream-RSI 不用正则化，而是用 held-out 的 replay world 做选择——但 replay world 就是历史，历史恰恰是从初始分布来的"，且 "Dream-RSI 全文未涉及泛化/过拟合讨论"。

**RRSI 的贡献在这里是双重的**：它不只是自己防过拟合，它**把"过拟合"确立为 harness 自进化这一派必须处理的公开问题**，而 Dream-RSI 那篇（同期）连这个问题是否存在都没意识到。

### 6.7 与 `2607.12790` Double Ratchet（一个必须诚实指出的方向性冲突）

`2607.12790` 的 no-lifecycle arm（去掉淘汰机制）实验显示系统**没有塌缩**。这与 RRSI "pruner 是必要的" **结论方向相反**。

**HarnessX 报告已给出一个兼容解释**："RRSI 的 pruner 防的是'选中过拟合的编辑'，本文的 no-lifecycle arm 是'不淘汰但也不过度选中'——池子大了但选中的少，所以没坏。"**这个解释成立，并且 RRSI 的 Table 2 消融提供了直接证据**：去掉 acceptance 约束（含 DomainGuard 与成本规则）后 OOD 从 43.6 掉到 41.0、token 涨 48%——**掉的是"选择"，不是"池子"**。

**但 RRSI 论文自己从未讨论这个冲突**，也没跑"只有 pruner 没有其他门"的隔离消融（见 §3.9）。**这是 RRSI 消融设计的一个真实缺口，也是它与 Double Ratchet 的矛盾无法在现有证据下彻底解决的原因。**

### 6.8 与 `2609.04128` Environment Evolution（方向相反的防过拟合路径）

`2609.04128` 报告已定位这个对比："本文的做法在某个维度上是**反向的**——它通过'只用 held-out 基准 Terminal-Bench 2.1'来防过拟合，但环境演化本身是从种子分布**继承**并**收窄**的。"

RRSI 的立场更保守：它**承认在基准上演化**（8 个基准里 3 个是 evolve set），并用机制把记忆效应压到最小。**因此两篇的适用面不同**：RRSI 证明的是"在基准上演化时如何少记忆"，Environment-RSI 证明的是"演化环境本身时多样性如何流失"。**RRSI 完全未涉及环境 / 任务侧的演化。**

### 6.9 一句话定位

**RRSI 是 harness 自进化派里"统计意识"最强的一篇：它把"在有限 evolve set 上自适应重看会过拟合"这个工程直觉，第一次翻译成了四个可执行的、带物理单位的门（预算 / 信用 / 地板 / 成本），并用一张消融表证明"evolve set 分数最高的那一臂，transfer 反而最差"。它最不可替代的三个贡献是：(a) `ΔC ≤ β₀+β₁ΔS` 让"成本"第一次成为 harness 演化的硬判据；(b) 式 17 的噪声带 shaped 规则（微涨分本身不足以放行）；(c) `𝒰_t = 𝒦 ∖ 𝒯_t` 的强制探索。最需要打折的三处是：全文依赖 Opus 4.8 三角色、没有任何显著性检验、以及摘要里那个算式未公开且与 Table 1 复核不符的 "22.9%"。**
