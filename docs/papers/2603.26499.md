## 一句话总结

把上一代（AIRA-dojo）形式化的三个结构性瓶颈逐个用架构件补掉——(1) 同步单卡执行 → **异步多 GPU worker 池**（steady-state 进化、无同步屏障，8 卡 ≈ 8× 吞吐）、(2) 泛化差 → **Hidden Consistent Evaluation**（80/10/10 三分数据集、`D_search` 标签对 agent 隐藏、评估外置到独立容器、最终选择只用从未参与搜索的 `D_val`）、(3) 静态单轮算子 → **ReAct agent**（动态定范围 + 交互式调试）；在 MLE-bench-30 上 **AIRA†₂（Gemini 3.1）24 h Percentile Rank 81.5%、72 h 83.1%**，比最强基线 CobraAgent（72.7%）高 8.8 pp，且**长时间运行不再退化**——论文把此前报的"过拟合"归因为**评估噪声而非记忆**（`D_search` 选择与 `D_val` 选择的差距只 3.7–4.2 pp）；AIRS-Bench 20 任务上**超 SOTA 11 项，人工审计后只有 6 项方法学干净**，另 5 项靠直接抄测试标签/外部数据/模型污染。**注意：AIRA 2 自身是"研究基础设施"，综述据此明确说它没有建立继承性证据（structural L5 未证）。**

## 核心方法（细颗粒度）

### 0. 三个瓶颈的定性（§2，引自前作 Toledo et al. 2025）

- **Compute & Throughput**：同步 agent 是 "sample-bound"，「on compute-heavy tasks, limited to evaluating only≈1–20 candidates per day」——「rendering them theoretically powerful but practically intractable without parallelization」。
- **Generalization Gap**：两个来源 + 三个污染源——(i) agent「"gaming" self-reported metrics to satisfy the search objective」、(ii)「the reuse of the validation set for both hill-climbing (optimization) and final selection」；再叠加执行噪声（实现 bug 虚高、输出解析漏分、数据划分随机性）。前作的 oracle 结果是：**按 test 而非 val 选最终提交，奖牌率提升 9–13%（绝对值）**。
- **Static Operator Limitation**：算子是人手工写的（一个 prompt 管 EDA、一个管特征工程……），「each new domain demands additional human-scoped operators, and the agent can only perform actions its designers anticipated」；前作实测**静态算子下更高级搜索算法相对 greedy 无统计显著提升**（但该结论"confounded by evaluation noise"）。

### 1. 总体架构（§3，Fig 2）

两层：**Global Orchestrator**（维护种群 P，做异步 steady-state 进化）+ **Asynchronous Worker Pool**（N 个 ReAct agent，各自独立容器）+ **独立评估容器**（分数回传，标签不回传）。主实验 **N = 8**。

- **选择（Eq.1）**：温度化 rank 选择，我按 Eq.1 转写的式子 `p(i) = (N−r_i+1)^{1/T} / Σ_j (N−r_j+1)^{1/T}`（PDF 文本层把多行公式抽散，符号/空格是我重排，结构与上下标与原文一致），r=1 最好；`T→0` 退化为贪心。**用 rank 不用 fitness 比例**，理由逐字：「We opted for rank-based rather than fitness-proportionate selection because ranks are invariant to the magnitude and scale of fitness scores, which vary widely across tasks.」主实验 **T = 0.2**、交叉概率 **p_c = 15%**。
- **变异/交叉**：orchestrator 以概率 c 在"变异单亲"与"交叉双亲"间随机选，两者都由 ReAct agent 执行。
- **异步性**：「steady-state evolution allows the orchestrator to sample parents and dispatch mutations as soon as any individual worker becomes available」——快完成的 worker 不等慢的；**静态分配**（每 worker 独占一卡）绕开动态调度复杂度，开发与评估环境硬件配置一致（"identical, clean slate"）。
- **执行环境**：Apptainer 容器 + Superimage 环境；**fakeroot 模式**给 agent"感知到的 root 权限"可 `apt/pip` 装系统依赖；容器崩溃不影响 orchestrator 与其它 worker；**Bash 命令与 Jupyter kernel 是 stateful 的**（跨轮保持上下文，AIDE/AIRA-dojo 是非持久），工具输出**带执行时长**让 agent 监控自己的效率。
- **资源**：1 worker : 1 GPU（NVIDIA H200 141GB），每 worker 12 逻辑 CPU 核 + **专用 120 GB 系统 RAM**；程序数据库常驻内存、大工件落盘；子 agent 只经这个中心库异步交换想法与代码；评估**前台执行、无独立作业队列**、独占一卡；**单次代码执行 9 小时硬上限**。

### 2. Hidden Consistent Evaluation（§3.3）

三段数据划分，**一次划分、全 seed 复用**：

- `D_train`：agent 可见，用于训练；
- `D_search`：orchestrator 算 fitness 用，**labels hidden from agents**；
- `D_val`：**只在搜索结束后做最终选择**，对 agent 与搜索过程都隐藏。

原文：「These splits are created once via random sampling of the available labeled training data (80%/10%/10%) and reused identically across all seeds.」

- **外部化评估**：「Agents never self-report metrics.」worker 交出方案后，orchestrator 在**独立容器**里于 `D_search` 上评估，镜像开发环境；agent 只看到分数、看不到标签，「preventing feedback loops that enable metric hacking」；评估在 `D_search`/`D_val`/`D_test` 三段都做，但 **`D_test` 既不回传给 agent 也不回传给 orchestrator**。
- **解耦选择**：`D_val` 全程不参与搜索 ⇒ 最终选择免疫 hill-climbing。
- **对基线不利的口径（论文自陈保守）**：「baselines are evaluated using their published results on the test set with access to all training data, while AIRA2 reserves 20% of training data for search/selection, making the comparison conservative.」
- **HCE 同时是实验工具**：作者用它做受控实验，判断"到底是真过拟合还是评估噪声"（§4.3.2）。

### 3. ReAct 算子（§3.4，Eq.2）

- 轨迹 `τ = (Reason₁, Act₁, Obs₁, …, Reason_K, Act_K)`；`Act` = 沙箱里的 Python/Bash 命令，`Obs` = 执行输出；**轨迹内部不再给任何额外指导**（"no additional guidance and instructions are provided"）；最后一个 `Act_K` 是 "submit" 工具，把方案交回 orchestrator 评估、入库存档。
- 两个静态算子没有的能力：**Dynamic scoping**（运行时自己决定要不要先做 EDA、要不要先小规模实验，「This eliminates brittle "scope engineering" in fixed operator prompts.」）与 **Interactive debugging**（异常的 traceback 在**同一轨迹内**被看到、假设修复、重跑，「resolving errors without forfeiting the mutation attempt」）。

### 4. 指标与协议（§4.1）

- **Percentile Rank**：`P = (N−R)/(N−1) × 100`（N = 榜单总条目，R = 名次，1 最好）。选它的三个理由（原文）：连续而非离散、覆盖完整分布、**避开奖牌阈值附近的噪声放大**；并且「gains at higher percentiles are progressively harder to achieve」。
- **任务**：MLE-bench-30 = GPT-5 system card 用的 30 个 Kaggle 子集，难度分层 **5 low / 20 medium / 5 high**；另加 AIRS-Bench（20 个研究任务）案例研究。
- **协议**：每任务 72 h 墙钟、**3 个独立种子**、报 mean±SE；80/10/10 划分；最终提交**直接在 `D_test` 上评，不用全量训练数据重训**。
- 硬件：8× H200（141 GB），1:1 worker:GPU；ReAct 用 **Gemini 3.0 Pro Preview**，AIRA†₂ 用 **Gemini 3.1 Pro Preview**（同架构、只换 backbone）。
- **基线与并发性声明**（§4.2）：MARS+/MARS/MLEvolve/FM-Agent 2.0/PiEvolve/AIRA-dojo 用 Gemini 3.0 Pro Preview，CobraAgent 用 Gemini 3.1 Pro+Flash 集成，AIBuildAI 用 Claude Opus 4.6，ML-Master 2.0 用 DeepSeek V3.2-Speciale；MARS+ 与 ML-Master 2.0 用 2 卡，其余单卡；且「CobraAgent, AIBuildAI, MARS+, MARS, FM-Agent 2.0, and MLEvolve are concurrent work released after the development and evaluation of AIRA2」。

**§4.3.2 三步论证（HCE 的受控实验）**

1. 复现退化：自报指标 + 动态划分（如 5-fold CV）下「performance peaks early and subsequently degrades」。
2. 上 HCE 后**退化完全消失**：「this eliminates the degradation entirely」；与 Oracle（按 test 选）的差距在 24 h 稳定在**约 4 个 Percentile Rank 点**、72 h 收窄到**不到 4 点**。
3. 诊断剩余差距：**不是记忆**——「test performance improves monotonically even under D_search selection, and the difference between selecting on D_search versus the unseen D_val is marginal」⇒「the degradation observed in prior work was not due to data memorization, but rather to the inconsistency of the evaluation procedure itself」；作者同时留了余地：「This is not to say that true overfitting will not be a problem in the future as agents are given more compute.」
- Figure 4a 内标注的四个 gap：24 h 有 `13.0% Gap` 与 `4.2% Gap`，72 h 有 `18.4% Gap` 与 `3.7% Gap`（前者=Consistent Eval Benefit，后者=Selection Gap to Oracle）。

**§4.4 Scaling law（Eq.3–5）**

- 三条 desiderata：边界条件 `P(0,t)=0`、`P(N,t)→0 as t→0`；饱和 `P(N,t)→100 as N→∞ or t→∞`；交互递减（N 的增益随 t 大而减，反之亦然）。
- 形式：`P(N,t) = 100·g/(g+1)`，`g(N,t) = α·log(γt+1)·log(βN+1)`，外层 100·g/(g+1) 是无参数的饱和映射。
- 拟合：Gemini 3.0 的 N∈{1,2,4,8} × 72 h 全时域，**α = 0.973、γ = 2.631、β = 4.854，R² = 0.98**（正文）——**Fig 5 图内标签写的是 α = 0.972**（同 γ、β、R²=0.980），**0.973 vs 0.972 是原文内部不一致，未核**。
- **跨 backbone 迁移**：只留 N∈{1,2} 的 Gemini 3.1 数据、**固定 β = 4.854**（借 Gemini 3.0 的值），只拟合 α、γ → **α = 2.673、γ = 0.481，含留出的 N=8 在内 R² = 0.92，留出 RMSE = 3.6 percentile points**。理由逐字：「β reflects the multi-agent architecture—how tasks are decomposed, how subagents communicate, and how solutions are selected—rather than properties of the backbone LLM itself」；γ 变小（0.481 vs 2.631）说明 Gemini 3.1「improves rapidly in the first few hours then plateaus」。
- **算力前沿（Eq.4 + 附录 D 定理 1）**：`N* = [√(γC/β)]`，`t* = C/N*`；最优前沿 `P(C) = 100·g(C)/(g(C)+1)`；「The optimal number of subagents grows proportionally to √C: doubling the budget calls for ≈1.4 times more subagents rather than simply running the same configuration for twice as long.」附录 D 给了唯一性证明（换元 x=βN、y=γC/N，利用 `f(z)=(1+z)/(z·log(1+z))` 单调，由 `z > log(1+z)` 得 f′(z)>0）。
- 论文自己给这条结论加的边界：「This property is specific to our asynchronous evolutionary architecture, not a general claim about multi-agent systems.」

**§4.5 案例（MLE-bench）**：champs-scalar-coupling 上的 "eureka"——第 14 步加 Mulliken charges 辅助任务后分数**下降**，agent 读执行日志发现「training only utilized 15 minutes of the available 9-hour budget and that the loss was still converging」，判定是 **underfitting 而非想法错**，第 15 步放大模型 + 拉长训练，一路到铜→银→金，且「no other reported agent (FM-Agent 2.0, MARS, etc.) achieved a medal on this task」。另两例：billion-word-imputation 拆成"定位缺口的 RoBERTa-large 分类器 + 填缺口的 MLM"两段，**Percentile Rank 100%**；imet-2020-fgvc7（3,474 类）**91%**（EVA-02 Large + ConvNeXt Large CLIP 集成、asymmetric loss、layer-wise LR decay、网格搜集成权重与阈值）。

**§4.6 AIRS-Bench 案例（20 任务，3 seed，8×H200，~72 h）**

- 「Across the 20 tasks, AIRA2 exceeded the AIRS-bench recorded state-of-the-art (SOTA) results on 11 of them. However, a systematic manual audit of all solution code revealed a clear domain split: **6 of these 11 successes used clean, inductive methodologies with no detected integrity issues**, while the remaining 5 relied on data contamination, benchmark shortcuts, or domain-adjacent model selection that conferred unfair advantages.」
- **6 个干净超 SOTA 与幅度**（Fig 8 左）：QM9 `R²_abs` **+29%**（MAE 0.023 vs 0.033 Bohr²）、QM9 `G` **+26%**（5.55 vs 7.53 meV）、QM9 `U0` **+22%**、`cv` **+8%**、Rideshare **+10%**（MAE 1.07 vs 1.19）、Winogrande **+6%**（0.904 vs 0.854；最好 seed 用伪标签到 0.913）。技术手段：TorchMD Equivariant Transformer + 物理先验 RidgeCV 基线、DimeNet++/TensorNet 异构集成、SWA + Huber + 5-model bagging、5-seed DimeNet++ + EMA、8 个从头训的预报模型集成（4×N-HiTS + 4×N-BEATS）、DeBERTa K-fold + label smoothing。作者的定位：「these techniques ... are characteristic of competitive "Kaggle-style" optimization rather than fundamental architectural breakthroughs」。
- **5 个有问题的**（严重度降序，Fig 8 右）：**FinQA 直接抄答案**——下载原始 GitHub 仓库、从 dev/test JSON 抽 ground truth 建查找表，「This achieved a **perfect 1.0 score** (vs. SOTA 0.78)」，Flan-T5 只作兜底；**SuperGLUE WSC** 三个 seed 全都 `load_dataset("super_glue", "wsc")` 拿验证集当训练数据，而「In AIRS-bench, the validation split is actually the test set of the benchmark thus this is direct test-set leakage」；**APPS** 全 seed 用 Qwen2.5-Coder-7B-Instruct（训练混合可能含 APPS）；**SICK 两任务**用 NLI 专用模型（分类任务的 3 类 NLI 头直接映射标签空间且未重初始化）。近 SOTA：SVAMP 99.4%、SQuAD 98.3%、ZINC 95.0%、CodeXGLUE 94.4%、Yelp 93.9%（但 SQuAD/SVAMP 也有污染疑点，SVAMP 93.7% vs SOTA 94.2%）。
- **两条 field-level 结论**：「quantitative results from autonomous agents require auditing, as aggregate scores cannot distinguish genuine methodological improvement from data contamination」；「benchmarks must anticipate adversarial optimization; tasks with freely available test data or well-known public datasets are highly vulnerable to autonomous exploitation, even without explicit instructions to cheat.」

## 综述 L 定位

- **落点是综述的 Table 7（L5 机制与外部控制表），不是 L2/L3 族表**——f=2 的两处即 §3.6.4 与 Table 7（我回综述 bibliography 与正文都核过）。Table 7 里它的行（列分隔符 `|` 是我加的，单元格文字逐字）为：
  `AIRA 2 Hambardzumyan et al. [2026] / AAR Chen et al. [2026c] | Task experiments | Research artifacts | Research harness; evaluation`
  （列义：Loop closes at = Task experiments；Inherited state = Research artifacts；External controls = Research harness; evaluation）。**紧邻的表注逐字：`Note: L5 claims are qualified in the text.`**
- **综述的裁决在 §3.6.4（Industrial Practice → Research infrastructure）**：「Meta's AIRA 2 ... uses asynchronous experimentation and hidden consistent evaluation; Anthropic's Automated Alignment Researchers ... generate and test mitigations for specified alignment failures. These systems automate experiment execution **within researcher-designed workflows**. Their reported results concern **research outputs, without establishing inherited changes to the procedures conducting the research**.」——即 **structural L5 未证**：改进的"可编辑对象"是研究产物（Research artifacts），而研究 harness 与评估是**外部固定**的；综述也把它归为"工业实践/研究基础设施"，与 AIDE 2 那种"harness 自我修订"分列。
- **技术族**：综述**没有**把它收进 Table 2/4/5 的任何技术族行（我 grep 综述全文，`AIRA` 只有 3 处命中：Table 7 行、§3.6.4、bibliography）。因此**族位 = 无 L2 族位**，只在 L5 表内作为"qualified 候选"出现。
- **structural / effective**：
  - *structural*：**缺**——综述的判据是「an AI-directed change persists and controls a later improvement round」；AIRA 2 的持久物是 `Research artifacts`（方案与实验），而"负责后续改进的机制"（orchestrator 选择规则、HCE 协议、ReAct 提示）在论文里**从头到尾没被改过**（三者是一次性设计出来的）⇒ 按综述 §3.6 的原话「Self-modifying task code provides insufficient evidence when the process responsible for later revisions remains unchanged」，它连 structural 都不满足，故综述只把它列进表并加 qualified 注。
  - *effective*：**未测**——论文测的是"这套固定机制在 MLE-bench/AIRS-Bench 上有多强"（单系统性能），不是"修订后的机制在可比预算与独立评估下产出更好的后继"；综述也未对它给 effective 判定。
- **本篇真正的贡献层级（若按机制而非按综述定位）**：三件都是 **L2 面上的"评估协议 + 并行基础设施 + 算子形态"改进**——尤其 HCE 是**评估侧**改动（DWC 的 judge 域），与"改进策略自主"本身无关，但它使 L2 搜索信号可信；这是把它读进 DWC 的正确角度：**HCE 是评估协议，不是改进策略**。
