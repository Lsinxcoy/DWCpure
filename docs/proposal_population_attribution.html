② 综述原文锚 — 这不是我发明的, 是综述点名的待建方向

"Future systems should turn diagnoses into testable intervention hypotheses and use controlled comparisons to estimate individual effects and interactions. Selective component freezing, targeted ablations, and explicit records of dependencies could help distinguish a useful repair from compensation for an upstream defect. Coordinated search should then allocate effort across data, models, harnesses, and environments as constraints shift."
出处: 2609.11873 · "Cross-Component Diagnosis and Coordinated Improvement" 段（最近节号 5.6 — 字符偏移核得, 段名逐字）。
动机句（同段）: "an observed failure rarely identifies the component that should change" — 失败不指明该改哪组件 = 归因问题的原文表述; Humanlaya 案例: 失败抽取被判为文档质量问题, 实际该改的是质检器决策规则 （改错组件正是无归因的代价）。

四要素对映（原文 → 本稿）:
综述原文要素本稿落点
controlled comparisons 估 individual effects and interactions 四跑消融 + 三读数（主效应A/B + 交互项）— §④
selective component freezing（选择性冻结） 消融臂 = 冻结其余只回退一成员（臂间只差一个键域）— §⑤

④ 可分性数学与 τ 分流（核心判据）

效应分解（组合 A⊕B 对基线 0 的得分）:
s(A⊕B) = f(A) + f(B) + I_AB
I_AB = s(A⊕B) − s(A) − s(B) + s(0)　　（交互项）
三读数（全部由四跑直接算, 无模型拟合）: 
主效应 A  = s(A)   − s(0)      单独加 A 的增益
主效应 B  = s(B)   − s(0)      单独加 B 的增益
交互 I_AB = s(A⊕B) − s(A) − s(B) + s(0)   合作/拮抗的额外量
τ 分流判据（归因去向的二岔）: 
|I_AB| < τ   ⇒ **可加** : 拆分归因 — A/B 各记各的主效应, 单点纪律原样继续,
                        组合解散（单点已足够解释 ⇒ 交叉无净信息）
|I_AB| ≥ τ   ⇒ **交互** : 组合是整体 — 整体归档(六段档 attribution 记
                        interaction), 不拆功不冒领单点功劳;
                        进一步: I_AB 显著为负 ⇒ 「补偿式修复」候选
                        （综述原话: useful repair vs compensation for
                        upstream defect 的二分入口）

★ τ 初值（无明文 ⇒ 初值纪律 = β 同款, 且用 DWC 自己的实测定标）:
  τ₀ = 跑间噪声量级 = 0.2 —— 来源: R105c 同配置跨跑 guidance 0.60→0.80
  （单跑 n=10 臂间差 ≤ 跑间抖动的实测）· 标注「初值待校准」,
  不是文献数字（文献无此协议 — §③）。
  判据实现成带版本常量 + 校准记录位（calibration_note 必填）。
为什么交互项是关键: 没有它, 组合增益只能整笔糊涂账（AgentNAS 单种子问题的根）; 有了它, 每次多改都必须回答「合作还是各自为政」— 这才是「种群归因」四字的完整逻辑: 归因粒度从单点升级到效应分解。

⑤ 消融回路执行流（受控定向 — 综述 targeted ablations）

触发:  组合 A⊕B 通过 no_worse_than_current（有资格进归因, 不是所有改动都跑）

跑序（每跑 = 稿② matched-term 协议: 同底/同锚 sha8 断言/同预算/π̂ 可选）:
  s(0)   基线        — 通常已有(本轮 π0 账), 缺则补 1 跑
  s(A⊕B) 组合        — 触发时已跑(否则不叫有资格)
  s(A)   冻结 B 只回 A — 新跑 ①（选择性冻结: 臂间只差 B 的键域）
  s(B)   冻结 A 只回 B — 新跑 ②
  ⇒ 常规成本 = +2 跑 (不是 K 倍种群账); 交互接近 τ 时加跑 ③④ = 重复采样
    定噪声（pass^k 同族, 方差口径接 R100 报告）

输出:  {主效应A, 主效应B, I_AB, τ, 分流: additive|interactive,
       compensation_flag: I_AB 显著为负}
  → 六段档 attribution 段（§⑥）· 成本入 CostLedger（§3.6.5 字面）

终止:  分流=interactive 且 I_AB<0 ⇒ A⊕B 标「补偿候选」— 不进继承链主干,
       走六段档 rejected/或 accepted_with_caveat（接受但记录缺陷型）
确定性: 四跑臂同 seed 同任务集同 executor ⇒ 可复跑（R110 协议原样）; 区分度边界: golden 替身下四跑可能恒等（R107/R110 结构必然的延伸）— 消融的效度依赖区分度任务集或 LLM executor 臂, 见 §⑨。

⑥ 单点纪律升级设计 — _assert_single_change 不废, 升格

现状（evolver.py:1168, 构造时拦）: 一次改动只许一处, 否则归因失效。
M1 升级（本稿设计, 执行在 M1 轮）: 
新契约（二选一, 构造期判定）:
  路径甲（现状不变）: 改动只有一处 ⇒ 直接过（单点, 全部现有测试零破坏）
  路径乙（新增）    : 改动多处 ⇒ 必须带 attribution_plan 字段:
      {
        "members": ["A键域", "B键域"],      # 成员=键域, 不是自由文本
        "ablation_budget": {"n_runs": 2, "cost_ledger_肩注": true},
        "tau": 0.2, "calibration_note": "初值=R105c 抖动量级, 待校准",
        "fork_rule": "A∩B键域=∅ (同键冲突构造期拒 — §⑦)"
      }
      缺字段/缺键域冲突/预算为 0 ⇒ raise（与现单点 raise 同款严厉）

★ 向后兼容判据（M1 验收字面）:
  · 现有单点测试全绿零改动（路径甲不回头）
  · 新增破坏测试: 拿掉 τ 分流 ⇒ 红 / 拿掉 attribution_plan 校验 ⇒ 红
  · gate 8/8 原样（G1-G8 判据不动 — 升级的是 evolver 内部断言不是门）

⑦ 组合表示 — 基因型的最小形式化（交叉的合法域）

基因位点 = PolicySpec 锁值键（R86: from_mapping 锁值拒未知键 — 键域已有强类型约束, 天然是位点表）: 
组合 A⊕B := PolicySpec.from_mapping( merge(A.map, B.map) )
合法条件: keys(A) ∩ keys(B) = ∅        # 同键冲突 = 交叉非法, 构造期 raise
         （两变体改同一键 ⇒ 无法分解主效应 — 「谁改的」不可答 ⇒ 拒）

⇒ 这就是「种群」在 DWC 的最小形态: 不是自由文本 prompt 的种群,
   是**锁值键域不相交的变体组合** — 有界(键数有限)、可枚举、可消融。
★ 交叉 ≠ 随机拼接: 合法交叉只发生在键域不相交的成员间;
  键域相同只能二选一（select_policy 已有 argmax V 路径）— 不发明第三种。
与 M>1 现状的关系: R85/86 的四变体（单键域各自修订）已是「种群成员 的雏形」; 本稿补的是成员间组合 + 组合的归因（缺的正是交互项那一块）。

⑨ 诚实条款

1. 本稿不给实测 — 无四跑数字（M0 纯设计）; 执行轮的恒等风险已预告: golden 替身下消融四跑可能全等（R107/R110 结构必然的同源延伸）— M1 验收明确要求区分度任务集或 LLM executor 臂, 恒等则如实报结构必然。
2. τ₀=0.2 是自家实测量级不是文献值（R105c 跨跑抖动）— 文献无此协议 （§③）; calibration_note 必填, 校准后改值须走六段档 supersedes。
3. 不声称文献空白 — 组合归因经典理论他域成熟; 本稿=最小消融版装进 已立协议; 横搜探针未专测此题, 要声称须另做横搜（本稿不做该声称）。
4. 补偿式修复的判定是候选不是判决 — I_AB 显著为负触发 flag, 人工/后续轮裁, 不自动拒（W5 不覆盖 + 生产门裁决归用户）。
5. AgentNAS/经典 GA 的对打义务留 M2 — M0/M1 不引入搜索器, 原裁决④的「搜索器须先过经典 baseline」之问原样保留。
