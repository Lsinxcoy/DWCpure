# DWC · 34 个进化维度能不能都塞进来？（独立 agent 视角）

> 2026-10-03 · 判据：只报实测
> 问题：之前总结的 34 个进化维度，能不能都塞进 DWC？
> 约束：DWC 是**独立 agent**（不是母巢那种外挂记忆，也不是 ARSI 那种宿主观测器）

---

## 一、先说结论

```text
不能。而且"能不能都塞"这个问法本身要换一个。

★ 换问法:
  不是"这些维度能不能塞进 DWC", 而是
  "对一个独立 agent, 哪些维度有可改变的载体?"

  有载体的 → 能进化
  无载体的 → 不是"不能进化", 是"没有可改的东西"

★ 34 个里, 只有一部分对独立 agent 有真实载体。
  剩下的不是被排除, 是它们的载体不存在。
```

---

## 二、判据：独立 agent 的"可改变载体"有哪几类

```text
DWC 是独立 agent ⇒ 它的全部可改变物只有五类:

  ① 提示词    (prompt)        —— 文本, 可写可回滚
  ② 参数      (param)         —— 标量/配置, 可写可回滚
  ③ 代码      (code)          —— 自己实现的模块, 可写可回滚
  ④ 记忆内容  (memory)        —— 三区里的条目, 可增删改
  ⑤ 策略/路由 (policy)        —— 决策规则/阈值, 可写可回滚

★ 这五类之外, 任何"维度"若不能映射到其中一类, 就没有载体。
★ 注意: 没有"外部机制库"这一类 ——
  母巢/Ultra 可以"从 GitHub 拉机制"(T3) 或"从论文编译机制"(T4),
  那是它们的载体。DWC 作为独立 agent, 若不做同样的事, 就没有这个载体。
```

## 四、★ 决定性判据：你自己写过的两条

这不是我发明的——是你在 `SYNTHEX_EVOLUTION_INSIGHTS.md` 里写的。

### 4.1 §17「全系统有机化是个陷阱：先分区，再演化」

```text
原文的决策矩阵:

| 维度       | 必须保持无机              | 可引入有机            |
|-----------|--------------------------|----------------------|
| 正确性     | 绝对正确（0容忍）          | 统计最优（可容错）    |
| 变化频率   | 季度级（核心账务规则）      | 小时级（运营策略）    |
| 决策延迟   | 实时确定性（<100ms）       | 可接受概率性长尾      |
| 因果追溯   | 全链路审计（合规）          | 可接受黑箱            |
| 故障影响   | 单点故障致系统性风险        | 局部可降级自愈        |

原文结论: "演化机制（进化引擎、经验库、记忆巩固）**只能作用于血肉区**,
          碰骨骼区就是制造灾难性失控。"
```

### 4.2 §28「变化分流矩阵」

```text
原文的表:

| 变化类型 | 应放位置     | 处理方式           |
|---------|-------------|-------------------|
| 表达变化 | 交互边界     | Adapter / BFF      |
| 策略变化 | 策略边界     | 规则引擎 / 策略插件 |
| 流程变化 | 流程边界     | 工作流 / Saga      |
| 模型变化 | 智能边界     | Model Gateway/Eval |
| 概念变化 | 可能触及内核 | 重新评估内核        |

原文结论: "任何演化提案先过这张矩阵, 概念变化才许碰内核,
          其余锁死在对应边界。**这直接防住 §17 担心的'演化碰骨骼区'**。"
```

**★ 这两条就是答案**：不是"能不能都塞"，而是**先分区，再决定哪些可进化**。

### 5.2 第一版建议：只支持 6 个

```text
理由: 母巢 88 文件 932KB 支持"全都能改", 代价是 24 个模块无生产引用。
      DWC 第一版要窄, 要能全部验证。

第一版 6 个 (按"载体最硬 + 验证最易"排):
  ① 提示词 (2)     —— 载体 = 文本, 回滚最容易

  ③ 策略 (9)       —— 载体 = 决策规则
  ④ 技能 (3)       —— 载体 = 记忆条目 (进化的直接对象, 见 2608.24876)
```

## 六、为什么"都塞进去"是错的（三条硬理由）

```text
理由 1 · 无载体的维度塞进去就是空壳
  协作 (11): 独立 agent 没有第二个 agent, "协作进化"无从谈起
  执行环境 (14): 环境是宿主机器, DWC 改不了
  训练桥 (24): 托管 LLM 不能训练
  ★ 母巢的反面: 88 文件里 24 个无生产引用 —— 塞了但不能用

理由 2 · 有载体的维度不等于该进化
  评估器 (16): 有载体 (代码), 但改它撞原则 1
  控制/安全 (25): 有载体, 但 ARSI 明确冻结
  ★ "能改"和"该改"是两件事

理由 3 · 你自己已经写下了答案
  §17: 先分区, 再演化 —— 骨骼区禁碰
  §28: 变化分流矩阵 —— 概念变化才许碰内核
  ★ 这两条不是为了限制, 是为了让进化"敢开"——
    因为知道边界在哪, 所以敢在边界内放开
```
