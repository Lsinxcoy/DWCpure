① 文献锚 — HCE（AIRA2, 2603.26499 §3.3 逐字）

"Hidden Consistent Evaluation（80/10/10 三分数据集、D_search 标签对 agent 隐藏、评估外置到独立容器、最终选择只用从未参与搜索的 D_val）"
两个实测数字（引用带口径）: · D_search 选择与 D_val 选择的差距只 3.7–4.2 pp — 论文据此把此前的 "过拟合"归因为评估噪声而非记忆（这个差距读数本身就是拆分的收益观测, DWC 要建同款读数 — §⑦）; · 同篇自陈: AIRS-Bench 20 任务"超 SOTA 11 项, 人工审计后只有 6 项方法学 干净, 另 5 项靠直接抄测试标签/外部数据" — 标签泄漏的实害是它自己报的。

② DWC 现状与缺口（精读映射判定: 半有）

HCE 件DWC 现状判定
三分数据集 80/10/10 SPLIT_DEV（锚点集恒小, 每条 golden）+ SPLIT_TEST （锁定集「metric 演化不许读」, sealed 文件） 半有 有 dev/test 两段, dev 内无 search/val 再分
D_search 标签对 agent 隐藏 judge 独立 + r_priv 不读 + anchors 文件 agent 不可写 半有 文件级保护在, 但搜索反馈循环对 dev 全量 开放（含将来的"选择信号"用途）
评估外置独立容器 judge 器官独立于执行/进化链 + TRUTH_SOURCE 系统外文件 有 外置性由 G2 保证
最终选择只用 D_val select_policy argmax V — V 来自回放/判分, 未区分搜索信号 与选择信号 缺 本稿要补的核心
D_test 不回传 orchestrator SPLIT_TEST 锁定 + sealed raise 有
为什么 dev 一肩挑两职是问题: 同一批任务既喂进化搜索又当验收标准 ⇒ 搜索可以对它过拟合（AIRA2 的动机）; DWC 的 judge 虽外置, 但选择信号与 搜索信号同源 ⇒ 「哪个改动更好」的判定能被搜索侧间接污染。拆 = 让 最终选择只信从未参与搜索的子集。

③ 拆分设计 — 三分映射（DWC 十任务的落法）

映射（HCE 80/10/10 → DWC 实际数据）:
  D_test   = SPLIT_TEST/sealed            ★ 已有（第三段不动）
  D_search = dev 中 8 任务                搜索期判分/进化信号来源
  D_val    = dev 中 2 任务                最终选择专用, 搜索期标签隐藏
  ⇒ dev 10 = 8 + 2（HCE 的 10% val 按 10 任务取 2: 让 val 有最小统计意义
    且**分层覆盖两类判分** — 不是 1 任务的抛硬币）

D_val 挑选（确定性, 可复核 — 不随机不挑好挑坏）:
  · 分层: behavior 类与 keyword_match 类**各有代表**
  · 层内规则: 任务清单**字典序末位**进 val（机械规则, 任何人可复算）
  · 划分落盘: config/anchors/dev.json 加顶层 "_split":
      {"search": [8 ids], "val": [2 ids], "rule":
       "分层+层内字典序末位（稿⑥§③）", "hce": "2603.26499 §3.3"}
    （"_split" 以下划线开头 = 非任务条目, 与现有 "_" 约定一致）

比例诚实: HCE 是 80/10/10 三分全集; DWC 的 test 已独立成 sealed ⇒
dev 内拆 8/2 = 「search:val = 4:1」与 HCE 的 80/10 中 search:val=8:1
不同 — **不硬凑比例**（任务数 10 太小, 硬凑 8:1 ⇒ val=1 抛硬币）;
如实标注为「DWC 适配比例, 非 HCE 原比例」。

④ 标签隐藏机制 — 搜索期不读 D_val 反馈

judge.evaluate 加 split_mode 参数（向后兼容关键）:
  mode="legacy"（**默认**）: 现行为一字不改 — 全部现有调用/测试零破坏
  mode="search": D_val 任务 ⇒ 返回 not_evaluated（success=None,
      reason="D_val 标签隐藏 — 搜索期不可读（HCE §3.3）"）
      ★ None 语义复用 judge 既有纪律:「未评价不许当 0/1」—
        隐藏 = 未评价, 不是失败（不污染分子分母）
  mode="select": D_val 任务 ⇒ 真判（最终选择专用通道）

谁用什么模式:
  进化/迭代/回放判分链     → search（新链显式传; 旧链 legacy 不动）
  select_policy 前的终评   → select（§⑤）
  meta-eval/审计          → legacy（全集审计不受隐藏影响 — 审计不是搜索）

隐藏的物理面: 只挡**反馈内容**（golden 不进 verdict）, 不挡任务存在 —
与 HCE「标签隐藏」语义一致（agent 知道有这个任务, 看不到对错反馈）。

⑤ 最终选择只用 D_val — select_policy 的信号拆分

现状: select_policy(v_by) argmax V — V 混合了搜索信号。
新链（M>1 变体选择/提案验收时启用）:
  ① 搜索期: 各变体在 D_search 上出 v_search（现行链不动, legacy 兼容）
  ② 短名单: v_search top-K（K=2 初值, 标注管理口径）
  ③ 终评:   短名单变体在 D_val 上跑 mode="select" ⇒ v_val
  ④ 裁决:   argmax v_val（**只用从未参与搜索的信号** — HCE 字面）
      平键 ⇒ 字典序（现行平键规则沿用）
      ★ v_val 平票/样本太小(2 任务) ⇒ 回落 v_search 并标
        "val_tie_fallback"（诚实字段, 不装终评有分辨力）

读数（HCE 3.7–4.2pp 同款监测）: 报表出
  gap_search_vs_val = mean(v_search over D_search) − mean(v over D_val)
  ⇒ 该差距 = 搜索过拟合的早期信号（DWC 版"选择差距读数"）
2 任务 val 的分辨力是真约束 — §⑧ 如实; 终评靠 K=2 短名单 + 平票回落兜底, 不假装 2 任务有强统计力（HCE 30 任务的 val=3, 我们 10 任务 val=2 已是比例上限内最稳取法）。

⑧ 诚实条款

1. 比例非 HCE 原比例 — 10 任务 dev 拆 8/2 是 DWC 适配（val=1 抛硬币 不可取）, 不硬凑 80/10/10; 如实标注。
2. D_val=2 任务分辨力有限 — 终评的统计力弱, 靠 K=2 短名单 + 平票回落兜底; gap 读数在 n=2 上只报方向（R67/R105c 同口径）。
3. legacy 默认是兼容承诺也是渐进约束 — 新链逐点切换, 不一次性全局 屏蔽（那会破 830 测试与既有判分语义）; 切换进度由调用点 grep 报表跟踪 （执行轮给计数, 不装"已全切"）。
4. 本稿不给实测 — 拆分/隐藏/终评的数字在执行轮; 3.7–4.2pp 是 HCE 的 数, 不外推为 DWC 预期值。
5. 隐藏 ≠ 防住一切过拟合 — HCE 只降低选择信号被搜索污染的面; agent 仍可能从 D_search 泛化作弊路径（S3Gym 抽题行为的反面教材在位）— 盲审计(稿⑤审计B)是第二道。
