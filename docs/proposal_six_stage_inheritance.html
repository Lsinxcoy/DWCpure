① 为什么缺它 — 一句话

综述 §7 点名「跨轮继承缺产物格式」：DWC 每轮收官有知识档（knowledge3_R*.json） 与提交，但没有一份「这轮改了什么→凭据→判过没→后来被用没」的跨轮标准产物 —— 改了不算数的继承侧缺口。R106 的三列连接（evidence→subsequent use→old vs new）是 雏形，本稿把它扩成综述原文的六段并给 schema、写入点、校验判据。 设计稿 · 待过审不默认动代码
溯源：综述 §7 原文六段格式被 SYNTHESIS.md §二·4 点名待建；R98 方案 §⑦T5「设计稿 · 六段继承产物格式」= 本稿；T5 族 6 条归族机器源 papers/arxiv_2609.11873/matrix_families.json（family=T5_递归与继承）。

② 综述 §7 原文六段

parent state → proposed change → motivating evidence
             → evaluation configuration → acceptance decision
             → subsequent use
（§7 原文, 经 SYNTHESIS §二·4 逐字引回; 中译: 亲代状态 → 拟议改动 → 动因证据 → 评估配置 → 接纳决定 → 后续使用）— 六段 = 一份「改动物料」的 完整生命周期记录, 缺任何一段 ⇒ 继承物不可审计（接收方无法判断 「拿这个改动能不能直接跑、凭什么信、在什么评估下过、过了没、后来有用没」）。

③ DWC 逐段映射（现状盘点 — 有/缺/半）

六段DWC 现有对应物（代码证据）状态
parent state
亲代状态		 evolver PROPOSAL_STATES（evolver.py:1027, draft/gated/rejected/ adopted/adopted_not_implemented）+ 知识条目 target_layer/component （evolver:1043-1060 迁移实录） 有 状态机齐；缺「本轮快照版本号」
proposed change
拟议改动		 Candidate(patch+source+grounding)（candidates.py:96-112, 无 patch/ 无 grounding 即 raise）；applier 回执 {"candidate": patch, "readback_at_copy": ok} （applier.py:281） 有 可执行语义已在（patch 字符串）
motivating evidence
动因证据		 grounding（依据哪条 diff, 纪律②）+ failure_signature 三元组 (c,q,m)（judge 聚簇）+ R99 repair_layer 三来源映射 有 证据链在
evaluation configuration
评估配置		 TRUTH_SOURCE=config/anchors/dev.json（G2, 指向不到即 raise）+ SPLIT_DEV/SPLIT_TEST + judge frozen（RQGM 同构, R98 T5-5）+ dw_version 契约（run_term 铁律 T3） 有 但散在: 每轮档未记录「当轮评估配置指纹」
acceptance decision
接纳决定		 ProposalGate.check → Evolver.accept；e2e 三态 candidates_accepted/rejected/no_candidates（已硬记账）；R106 遵循率报表 （memory PROPOSAL 源） 半有 接纳在, 但接纳理由/门回执不进知识档
subsequent use
后续使用		 memory recall()→access_count+1 / record_effect()→effect_count+1 （memory.py:317-329）+ R106 三列连接中 subsequent_use 列 缺 R106 实测双缺口: 生产零调用方 + 默认 :memory: 不落盘（读数存在/数据断供）
盘点结论: 六段中 4 段有实体、1 段半有（接纳决定不进档）、1 段缺 （后续使用 — 已在 R106 如实入档为候选硬规则）。本稿做的是「把六段 装进一份标准产物」+「补 3 个缺口的接线设计」，不是造新机制。

④ 四工业对照物对齐（方案 §⑦T5 指定）

对照物它保证什么DWC 六段的对应设计
Lark 时间接地 每段变更带可信时间戳, 可回答「先后」 六段每段带 at（ISO-8601, UTC）+ 顶层 gen（第几轮）; 写入即 stamp, 禁事后改（改=新档+supersedes 指针）
Humanlaya 版本化 产物版本链可回溯 parent_gen（上一份六段档的 gen）+ supersedes（被替代 的档 id）⇒ 跨轮链可走（同 knowledge3 round 字段延续, 只扩不破）
Hyra 可执行经验 经验不是文本是可执行物 proposed_change 必带可执行形态之一: patch（diff 串）/ config_delta（dial 变更）/ rule（RULES 条目）; 三者皆无 ⇒ 该段非法（写入时 raise — G1 定位声明同款）
ARA 轨迹实证 主张须挂轨迹/运行证据, 不接受孤证文本 motivating_evidence 必带机器可回查引用之一: trial_report（docs/*.json 路径+字段）/ commit（hash）/ gate_trace（archive/gate_trace.jsonl 行）; 纯叙述 ⇒ 非法
对齐语义 四对照物不是照抄实现, 是给六段的 四个必备属性打样: 时间可信（Lark）、链可信（Humanlaya）、改动可执行（Hyra）、 证据可回查（ARA）。违反任一属性 ⇒ 该档不合格, 不进继承链。

⑤ knowledge3 档字段扩展（核心设计）

原则: 现有 knowledge3_R*.json（每轮一档, 已 107 份）只扩不破 — 新档加六段对象 inheritance, 旧档保持 legacy 无该键（读取方按 「有键走六段, 无键=legacy」判, 不迁移不改写历史档）。 
// 新档必带（写入即校验, 缺段 raise — 方案验收『三列连接齐全』的六段版）
{
  "round": "R108",
  "date": "2026-10-09",
  ...现有字段照旧...,

  "inheritance": {
    "gen": 108,                       // ① Lark: 轮次即代号
    "at": "2026-10-09T…Z",            // ① Lark: 写入即 stamp
    "parent_gen": 107,                // ② Humanlaya: 链
    "supersedes": null,               // ② 改档时指旧 id（不原地改）

    "parent_state": {                 // §7 段1: 亲代状态
      "commits": 113,                 //   改前 git rev-list
      "proposal_states": {"adopted": 0, "gated": 1},   // 有则记, 无则 {}
      "config_fingerprint": "…"       //   dials/anchors sha8（评估配置快照）
    },

    "proposed_change": {              // §7 段2: 拟议改动（Hyra: 必可执行）
      "kind": "patch | config_delta | rule",
      "exec_form": "diff 串 / {"dial":…} / RULES 条目 id",
      "files": ["src/…", "scripts/…"]
    },

    "motivating_evidence": {          // §7 段3: 动因证据（ARA: 必可回查）
      "refs": [{"type": "trial_report | commit | gate_trace | test",
                 "ref": "docs/…json#field /  / 行号",
                 "claim": "本档主张对应的那句话"}],
      "numbers": {"pytest": 806, "gate": "8/8", "e2e_rc": 0}
    },

    "evaluation_config": {            // §7 段4: 评估配置（G2 落指纹）
      "truth_source": "config/anchors/dev.json",
      "truth_sha8": "…",              //   变了 = 分数不可比（R99 同口径）
      "splits": ["SPLIT_DEV", "SPLIT_TEST"],
      "judge_frozen": true,
      "dw_version": "…"
    },

    "acceptance_decision": {          // §7 段5: 接纳决定（R106 补进档）
      "gate": "三层验证字面: pytest/gate/e2e",
      "verdict": "accepted | rejected",
      "evidence_ref": "e2e log 路径 + RC",      // 门回执可回查
      "user_decision": null           //   4b 裁决类必填（用户拍板的档）
    },

    "subsequent_use": {               // §7 段6: 后续使用（R106 三列的持续版）
      "status": "pending | invoked | effective | not_assessable",
      "access": null, "effect": null, //   接 recall/record_effect 记账
      "observed_at_gen": null,        //   哪一代观察到被用
      "gap_note": null                //   断供时如实写（R106 双缺口同款）
    }
  }
}
与 R106 的关系: R106 三列（evidence / subsequent_use / old_vs_new_effect）= 六段的子集映射 — 三列继续管「遵循率报表行」, 六段管「整轮档」; old_vs_new_effect 并入六段的 evaluation_config.numbers 前后对比（同轮 pytest 数即最简 新旧读数, 不发明新度量）。

⑥ 写入点与校验

写入点（唯一）: 每轮收官流程的档写入处 — 即现有 archive/knowledge3_R*.json 写入脚本段（每轮收官 execute 段内）。 本稿过审后 = 收官段加 inheritance 构造（git rev-list 取 parent_state, sha8 取 truth 指纹, 三层结果填 acceptance）。

校验（写入即 raise, 不留读取期发现）: 
六段齐全     : parent_state/proposed_change/motivating_evidence/
               evaluation_config/acceptance_decision/subsequent_use 一个不缺
段2 可执行   : kind ∈ {patch, config_delta, rule} ∧ exec_form 非空
段3 可回查   : refs 至少 1 条 ∧ 每条 type+ref 齐
段4 指纹     : truth_sha8 8 位 hex ∧ judge_frozen 是 bool
段5 判定     : verdict ∈ {accepted, rejected}（本轮三层红=档不写 — 现行纪律）
段6 诚实     : status ∈ 五值; 断供 ⇒ gap_note 必填（不许留 null 装有）
时间/链     : at 是 ISO-8601; parent_gen == 上一档 gen（链断 raise）
不做的: 不动旧档（不迁移）、不建新数据库（档即产物）、不自动改判据 （六段是记录格式不是行为）— 与方案「设计先行不默认动」一致。

⑧ 验收清单 + 执行序

验收（执行轮 — 本稿过审后）: 
□ 新档 inheritance 六段构造 + 写入即校验（缺段/坏段 raise 的探针测试 ≥5）
□ parent_gen 链连续（连续两档跑出 parent_gen == gen 前值, 断链红）
□ 段2/段3 非法形态（纯叙述、无 exec_form）被拒的破坏测试
□ 现有 107 份 legacy 档零改动（读取方兼容分支测试）
□ 三层验证不变: pytest 全绿 · gate 8/8 · e2e rc=0
□ 一档一提交一知识档（同批自洽 current+1）
执行序: 本稿 + 稿②（matched-term 对照）→ 用户过审 → 执行轮（实现→三层→档→提交, 只做实现不做新设计）→ 4b 四项裁决逐项独立轮。

⑨ 诚实条款

1. 六段格式不评估任何东西 — 它是记录/继承格式, 不是判据; 「改了算数」 仍靠 R106 遵循率 + 三层验证, 本稿只让跨轮可审计。
2. 段6 未来多数时间是 pending — 在 R106 双缺口（零喂数调用 + :memory: 不落盘）接线前, subsequent_use 读不出有效 数据; 档会如实写 gap_note, 不装有。
3. 字段值示例中的数字（806/8/…）是现轮实测, 未来档以当轮实测为准。
4. 四工业对照物为属性对齐 — 未读其论文实现, 不声称行为级兼容 （refs 需时再补原文核）。
