R438 · 19 项进化对象落地总案

口径：“落地”= 有产物文件 + 有消费者读它 + 有试验能判好坏 + 能回滚。 四项缺一，就不算落地 —— 只是又造了一个没人读的 JSON。

零、先说三条硬约束

  1. 第 15 项（评估器）与第 18 项（训练桥→external_source）按设计只读 （K_META["evaluator"]=False / K_META["external_source"]=False，G10 密封）。 让评估器可进化 = 自己改考卷 ⇒ 整个适应度失去意义。 这两项的“落地”= 登记 + 显式拒绝编辑 + 拒绝留痕，不是让它变异。
  2. 第 7 项（架构）须人工批准（K_META["architecture"]=True 但 G3 人类主权）。 落地 = 提案进审批队列 + 人工批准后才写，不自动 apply。
  3. 第 20/21 项（外部机制源）本轮搁置（用户指示）。

二、统一机制（不造 11 套轮子）

信号 → 车道路由 → 起草 → 试验 → 门 → 落地（带备份）→ 读回 → 台账
  • Target：复用 organs/applier.py::Target（getter/setter/has/delete/flush， 写后立即读回）。
  • 产物注册表：src/dwc/organs/evo_targets.py TARGETS: Dict[str, TargetSpec]，每项含 path / schema / read / merge / trial / rollback。
  • 驱动器：src/dwc/organs/evo_driver.py run_component_round(component, signals)，与 dwc_evo_round.py 共用 ProposalGate + Evolver.accept。
  • 台账：var/evolution_ledger.jsonl，每行 {ts, component, key, decision, before_hash, after_hash, backup, trial}。

为什么统一：11 套独立轮子 = 11 套 bug + 11 种台账口径（R426 同族教训）。

四、每阶段的验收（统一四条）

  1. 产物存在：文件真的被写出来，不是内存里改了。
  2. 消费者生效：新进程读到它，且行为有可观测差异。
  3. 可回滚：--rollback 后文件恢复原状，行为回退。
  4. 可区分：降级/拒绝/成功三种状态在台账里可区分（不许静默）。
