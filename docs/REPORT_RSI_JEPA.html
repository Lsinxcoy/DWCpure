② JEPA-Anything：正交预测因子分解（OPF）

机制（opf.py 444 行逐行读毕）

把完整潜状态 d 分解为 K 组正交预测坐标（硬契约 K·r = d，构造期校验，违反即 ValueError）：

decompose:  factors = einsum("...d,krd->...kr", state, basis)   # 分析
compose:    state   = einsum("...a,da->...d", factors, pinv(P))  # 合成(伪逆)
audit:      allclose(P·Pᵀ, I, atol=dtype容差)                     # 几何审计

三条值得偷的设计纪律：

  • 因子匿名原则——"The class guarantees no semantic interpretation: factor indices remain anonymous predictive coordinates until experiments establish a meaning"。因子先无名，实验建立意义后才命名。DWC 的机制命名应该同德。
  • dtype 感知容差——几何判据阈值按精度分档（float64: 1e-10 / f32: 1e-5 / f16: 1e-2 / bf16: 5e-2）。判据阈值是精度的函数，不是拍脑袋常数（DWC Layer 22 同族）。
  • 审计与操作分离——transpose_synthesize_state 只为审计暴露，操作路径用 compose_state（伪逆）。"测的"和"用的"分开，防止用审计函数干生产的事。

③ RSI-Anything：四层协议（DWC 真正该抄的东西）

第一层：预测引导选择（2.3）

候选打分 R_d(τ) = Σⱼ w_j·r_j(τ) − Δ_d(τ)（效用加权和减去不确定性惩罚）；化学任务用冻结校准先验 + EI（selector.py 60 行）：反馈只更新 incumbent 与已测排除，预测表全程冻结——防反馈污染预测器。

第二层：条件世界模型适应 + 复用判定

新经验到达 → checkpoint_reusable() 判定复用旧 checkpoint 还是重训；重训数据 = 新经验 + replay 旧行（防遗忘）；训练请求带 input_new_hash / input_replay_hash / parent 三重身份校验，checkpoint 文件再做 sha 校验——result 归属错请求即拒。

第三层：递归保留（2.5 + rsi.py 79 行 — 全论文最核心）

每代 generation:
  1. 现任 (world, policy, controller) rollout → 收集经验
  2. policy 训练: new + replay 旧数据, parent 指针
  3. 世界模型条件适应: checkpoint_reusable? 复用 : 重训(new+replay)
  4. ★保留决策（dev 上, test 未开）:
       olddev = rollout(现任, dev)          # 基线
       newdev = rollout(候选, dev)
       promoted = (newdev.success - olddev.success >= promotion_gain)      # 效用判据
               AND (newdev.seconds <= olddev.seconds × promotion_cost_ratio) # 成本判据
  5. manifest 冻结: {"test_not_opened_yet": True, ...}    # 版本先冻结
  6. promoted ⇒ 换任 incumbent; 否则现任留任
  7. ★★ 四臂交叉评估（test 解封后）:
       (old_world×old_policy) (old_world×new_policy)
       (new_world×old_policy) (new_world×new_policy)
       —— 分离 world 与 policy 各自的贡献 = 配对检查的实验形式

配对检查的动机（原文）："a policy can generate candidates for which an otherwise improved predictor is unreliable, and a predictor can change which candidates are selected"——policy 换了，predictor 必须在新候选分布上重新验证。单组件过检 ≠ 组合可用。

第四层：工作流收据（runner.py 185 行）

stage 完成时记录输出文件 sha；resume 前逐个校验"已完成 stage 的输出没变"（Completed stage output changed 即拒）；identity = digest(config+source+plan+files)——配置或源码变过就不许 resume 旧目录。

⑥ R231 · 预测器底座 src/dwc/organs/predictor.py（P0）

定位（G1）：DWC-AUTO 的行为结果预测器——"agent 对自己动作结果的预测"，不是环境模拟器

学什么：给定上下文特征，预测本次动作/任务的成功概率。特征键两族（★调整A：树键读树不另记，杜绝双写）：

★树键   = "tree:{tree_id}/{node_id}" ⇒ 读 world_model 谱系 (n_obs,n_pass)
         p̂=(n_pass+1)/(n_obs+2) — 与收束判据同源(Beta(1,1) 后验均值), 不另记
 台账键 = (op 或 task_rung 或 fail_mode, 简化上下文桶) ⇒ 自记观测
观测   = 台账族每次 run_user_task 完成后回写: success ∈ {0,1} + 证据 id
         ★ 树族绝不另写（树=事实层, predictor 单向读 — 见⑤b边界）
模型   = Beta(α, β) 共轭后验（每键独立; 新键继承全局先验 Beta(1,1) 的收缩版）
输出   = p̂ = α/(α+β)          # 校准成功率
       + uncertainty = 1/(α+β) # 不确定度
       + Brier 滚动跟踪（预测 vs 实际, 按版本记录 — 校准度不是声称是实测）

⑦ R232 · 预测式选择 dwc_bench.py 增强（P0）

机制（selector.py 同构 + 论文 2.3）：每轮 bench 前用 predictor 给 10 任务打分, 选"信息量最大"的子集

★ 调整B：本选择只作用于评测层与调度层——世界树的任务源层（收束排序键）不受影响，合流仅 dial 可选默认关。

score(τ) = w_useful·p̂(τ) + w_info·uncertainty(τ)      # 利用×探索双项
         = p̂ + λ·sqrt(p̂(1-p̂)/n) 形式（λ 由 config/dials.yaml 新拨盘 bench_explore 控制, 默认 0.5）
排除已跑任务（-inf 同 selector.py:47）；平局按任务 ID 升序（确定性可复现）
★ 预测表在一轮 bench 内冻结（feedback 不中途改选择 — RSI 冻结先验纪律）

对照实验设计（声称=实测的落地）

bench_cron 每日轮 A/B 交替：奇数日 predictor 选择, 偶数日全量顺序（现有行为）——两侧都记 var/dwc_bench_results.json。7 天后对比同预算 pass 率——增益是实测的, 不是方案声称的。首轮验收只看"选择逻辑跑通 + 每任务有预测记录", 增益留给时间。

测试锁

  • ★★★ 选择确定性锁：同一预测状态两次选择序列完全一致
  • ★★ 排除锁：已跑任务不再入选
  • ★★ λ 拨盘锁：λ=0 ⇒ 纯按 p̂ 排序；λ 很大 ⇒ 纯按不确定性排序（两端极限行为）

⑧ R233 · 保留协议 src/dwc/foundation/retention.py（P0 — 论文最核心机制）

定位：组件检查 + 配对检查 + 双判据晋升 + test 冻结 —— 先试点于 bench 演进环

候选提交（agent_quality consolidate / 手动改进）时:
  1. 组件检查: bench 子集 pass 率 vs 现任基线（component_pass）
  2. 配对检查（四臂 — rsi.py:63 同构, 维度换成执行器×预测器）:
       A: old_exec × old_pred   B: old_exec × new_pred
       C: new_exec × old_pred   D: new_exec × new_pred
     —— 分离贡献: Δ_exec = score(D)-score(B); Δ_pred = score(D)-score(C)
     ★ 若 Δ_exec 为负而组件单独过检 ⇒ 配对不兼容, 拒（论文动机句的机器化）
  3. 双判据晋升:
       promoted = (Δscore >= promotion_gain)          # 默认 0.02, dial: retention_gain
               AND (cost_ratio <= promotion_cost_max)  # 默认 1.2, dial: retention_cost
  4. ★ test 冻结程序锁:
       versions_frozen.json 写入 {candidate_sha, pred_version, "test_not_opened_yet": true}
       → bench test split 才允许评估 → 结果回填 manifest
  5. 未晋升 ⇒ 现任留任 + rejected 档（含四臂数据 — RSI raw_rejected_candidates_reported 同款）

与继承档的关系（结构完整性）

retention 不替代 knowledge3 档 — 档继续记 lineage；retention 是档的 acceptance_decision 的量化升级：verdict 从"人判/门判"升级为"预声明判据+四臂数据"。档的 acceptance_decision 字段扩展 retention_ref 指向 manifest。G10/G11 仪表扩展读 retention manifest（零新判定面）。

测试锁（tests/test_r233_retention.py）

  • ★★★ 晋升判据锁：Δ=0.05/cost=1.0 ⇒ promote；Δ=0.05/cost=1.5 ⇒ 拒（成本否决）；Δ=0.01 ⇒ 拒（增益不足）
  • ★★★ 配对不兼容锁：new_exec 单独过组件检但四臂显示 Δ_exec(D−B)<0 ⇒ 拒 — 论文动机句的直接机器化
  • ★★ test 冻结锁：未写 versions_frozen 就评估 test ⇒ 报错（程序锁不靠自觉）
  • ★★ rejected 留痕锁：拒绝的候选四臂数据完整入档

不抄清单（诚实边界）

  • OPF 张量分解不抄——DWC 无 torch 训练循环；偷的是纪律（匿名因子→实验命名、dtype 分档判据、审计/操作分离），不是张量。
  • 阶段收据 resume不抄——DWC e2e 是全量重跑语义，无 resume 需求。需求出现时按 runner.py:121-127 抄。
  • RL 策略梯度（GUI policy_train）不抄——DWC 的"policy"是执行器代码+配置，演进方式是带保留协议的版本替换，不是梯度。

  • iwm 的窗口信任（R215）与 predictor 正交：iwm 管 arms 选择信任, predictor 管结果预测——两者数据源相同（台账）但判据面不同, 不合并（G1 定位门）。

  • 全部新拨盘进 config/dials.yaml（现校验器直接管）。
