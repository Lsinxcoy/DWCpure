① 论文语义与 DWC 现状

论文 §2.7 逐字：policy-development agent 接收 π_t^m 的 replay 轨迹与分数 + 前几次修订的反馈，"identify successful decisions and recurring failures"，然后修订可执行的策略代码，在同一组 replay worlds 上评估；π_{t+1} = π^{m*}（argmax V^m，含 current）。

DWC 现状（R81 后 π^0 的可参数化点）：① δ 排序权重（-dmap.get(node,0) 硬编码 1.0）② 候选过滤（_can_reveal）③ root 兜底；EL 的 B/τ 与 β/δ=0.15 均为生产锁值（校准纪律）。

② 修订范围（纪律边界）

推荐：只动纯选择逻辑参数，锁值不进修订域 
可修订域 π^m = { w_delta: float,          # δ 排序权重（0=纯字典序, 1=现行）
                  prefer_revealable: bool }  # 是否只选能揭新的（R81 补丁开关）
不动域（生产锁值）= { τ, B, β₁/β₂, δ=0.15, ... }   # 修订撞锁值 = 违校准纪律, 构造校验拒

理由：锁值各有校准协议（R58/R63-R67/R79 稿裁决③）；策略修订是探索行为的调度，不是判据/阈值的再校准——两者混动 = 无法归因（约束 4：一处变更）。

③ 修订方式（裁决点）

缺口：论文的产生侧=LLM agent 修订策略代码；DWC 的策略是参数逻辑而非可改代码，且 LLM 修订引入非确定性（测试/复现成本）。
推荐裁决 A：网格枚举变体（起步）+ LLM 修订（二期） 
M-1 个变体从**预定义网格**确定性生成（w_delta ∈ {0, 0.5, 1.0} × prefer_revealable ∈ {T,F} 截取）
  + π^0（现行参数）⇒ 候选集必含 current（§2.7 单调性支点自动满足）
★ 确定性: 无 LLM 依赖, replay 评估可复现（测试锁）; 论文未限定产生方式
  （框架只要求"评估 M 个版本选优"）—— 网格是合法子集
二期 B: LLM policy-development（贴论文"从反馈开发"语义）— 等 A 框架验证后接
  （candidates.py 候选生成同族先例已有）

④ 循环骨架（设计）

dream(k2_max, *, policy_variants=None) -> DreamReport   # M>1 扩展
    ℋ = 快照序列（R80 机制不变）
    πs = [π^0(现行)] + 网格变体（或 policy_variants 显式传）
    for m in πs:                                 # 每版本每树单独评估完才下一版本（§2.5）
        for (tid, T_i) in ℋ: 按 π^m 的 w_delta/_can_reveal 跑 rollout → V_i^m
        V^m = mean_i(V_i^m)
    m* = select_policy(V^m, current="π0")        # R74 既有（current 必含）
    assert no_worse_than_current(...)            # §2.7 单调性 — M>1 时**非平凡**
    DreamReport 加: policy_variants（参数集）, v_by_version 全表
★ M=1 行为完全不变（默认 policy_variants=None ⇒ π^0 单版本）—— 零破坏向后兼容
