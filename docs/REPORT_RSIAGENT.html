RSIAgent：在新环境中自主探索的递归自改进

0 · 一句话总览与硬结论

RSIAgent 是免训练的三智能体递归自改进框架：Curriculum 出题、Actor 用代码执行、Verifier 独立验收，经验经"蒸馏→对账→诊断"三步进可演化记忆；探索分 BRS 先并行铺广度、DRS 再串行打深度，记忆冻结后直接复用，全程不动模型参数。OSWorld-2 partial 71.97→78.98、ALE 83.75→84.82，开源 GLM-5.3＋Kimi-K3 超 GPT-6 Astra（partial 口径）。
阅读本报告前必须先看的三句：① 作者自承 RSI 列不是纯 RSI 均值——OSWorld 82 单里 41 个是 RSI 分、41 个是保留的基线分，ALE 是 19＋48，且"非 matched 协议对照"（§4 有详审）；② Binary 全对率 ALE 50.75 vs GPT-6 的 52.24——partial 超了，binary 没超；③ 四任务阶段消融的 cohort 是按"有过提升"挑出来的，Full RSI 值是两次历史评估的均值。这三条不影响方法的真实价值，但决定你怎么引用它的数字。

1 · 问题形式化（§2）

任务指令 q，环境 E，动作序列 a1..T；t 步智能体 πθ(·|q,ht,M)，ht 为交互史（切任务即重置），M 为跨任务持久记忆（唯一的学习载体）。动作空间取 code-as-policy：每个动作是一段可执行程序（Python/Bash），runtime 回 combined stdout＋exit code——GUI 应用也靠程序驱动，不靠点坐标。RSI 问题定义：给新环境 E，先自主探索建 M，再冻结复用做下游题；θ 全程不动。

2 · 方法深读（三角色＋两阶段＋冻结）

2.1 三角色与信息边界（§3.2＋附录 A.1/Table A1，论文最硬的设计）

角色看到什么产出什么、有何禁区
Actor（可演化记忆）任务＋环境＋执行反馈＋持久记忆可执行动作与候选产物；验证通过后才亲自做记忆更新（加/改/删都行，也可不动）；更新被后继 Actor 实例继承
Verifier（环境反馈）任务要求＋候选所处环境。禁区：Actor 私有推理、记忆、执行日志全不可见基于证据的 PASS/FAIL（target 口还有 UNVERIFIED）；零记忆写权。隔离是为了去相关错误
Curriculum（探索总控）target query＋已完成探索结果＋记忆的一次性拷贝＋Actor 的学习诊断出练习题/输入夹具/继续-or-停止；禁区：不给候选打分、不改记忆一字（本地改动不同步回去）
三权分立的本质：出题的不判分，判分的不写记忆，写记忆的不出题。学习诊断（learning diagnosis）是 Actor 给 Curriculum 的专用 handoff——只讲结论与不确定性，不给私有 CoT 与逐轮 transcript（Prompt P7）。

2.2 BRS → DRS → 冻结（§3.3＋Algorithm A1）

BRS（广度）：每轮 Curriculum 并行提多个方向的题（名义预算 8 个、至多 4 并发，预算只在整波完成后检查——实际数可超 8），Actor 并行执行、Verifier 并行验收，收齐后再定下一波。DRS（深度）：从一次真实 target 尝试起步，串行"尝试→验证→进记忆→Curriculum 复盘→出针对性练习"，难度递增；成功的练习不自动停，失败才优先出"能区分 competing 解释"的题。冻结评估：记记忆文件树 hash、拷进评估环境、关 Curriculum、禁写回，Actor–Verifier 照常跑，最后官方 evaluator 在一切智能体上下文之外打分。
六步 A1：初始化 M→BRS 波循环→DRS 首尝试→（verifier_pass 直接跳 7，否则问 Curriculum）→串行练习→target 通过＋无新练习则收→冻结评估。护栏：UNVERIFIED 与 infra 失败挂起推进，不转成败；走完流程不要求 target 一定过。

2.3 记忆更新：三步全 Actor-owned（附录 A.2＋Prompt P5–P7）

一次 verified 经历进记忆要过：蒸馏（什么程序/约束/教训值得留，FAIL 也可留证据但不许记成 verified 成功）→对账（全文 review 记忆库，修矛盾、砍过期、给没证据的结论加限定——不许只 append）→诊断（给 Curriculum 的 handoff）。记忆是 Actor 写的无 schema 文件集合（几个文件、多长都行）；工作期编辑在进学习前丢弃，Curriculum 的拷贝只读。并行波内：同波各分支从同一不可变快照出发、互相不可见； verdicts 收齐后原 Actor 上下文按 Curriculum 定的顺序逐个 resume 提交——并发采集、串行提交。

7 · 停止策略与执行护栏（配置级事实）

BRS 停：Curriculum 自判 SATURATED（附证据）或 STALLED（实在没题出）；8 项目是名义预算、波不断半。DRS 停（默认 curriculum_review）：target PASS 后无新练习即可收；练了必须再考一次 target；另有 verifier_pass 变体（PASS＋进记忆即收）。READY_FOR_TARGET 只是"练的期望价值不如回去考"，不是"题对了"。执行护栏：target actor 500 iters＋10 小时 watchdog（practice/curriculum 2000 iters＋24h，单程序调用 600s）；primary 采样 temp 1.0/top-p 1.0、单调用 65,536 tokens；卡住可切一次角色（Kimi-K3 当 actor、GLM-5.3 当 verifier）；evaluator 用 GPT-5.4、user sim 用 GPT-4o；baseline 记忆禁用。
Loop 微机制（core/loop.py，1805 行）：done-bounce（空 declare 打回）、split-gate（视觉分歧未闭合卡首 done）、witness-gate、doubt-gated 复检、repetition detector（program md5＋stdout md5）、summary-mode 折叠（WORK LOG 压 history）、eyes 归档（v32.5：把模型实际看到的图存下来复核——曾有 alpha-flatten bug 藏了 3 轮）。

9 · 验证体系（RELEASE.md＋CI）

发布校验（2026-09-14）：718 portable tests（54 文件、562 test funcs，参数化展开后 718）＋ pinned OSWorld 环境内 2 个 evaluator 专项（opt-in）＋ 108 题 batch dry-run（432 命令）＋ 7 档 model profile 设置复核。真机 smoke：OSWorld HTTP/virtio 各 10 项、ALE Linux 16 项（ALE Windows 与 GPU 没在真机测过，明示）。tools/check_rsi_release.py 一键跑 portable 套件（phase 边界、恢复、记忆完整性、VM 归属、角色配置、batch、ALE 适配）。测试命名即覆盖面：phase1_wave_authoring/recovery、phase2_stop_policy、verifier_isolation/continuity/control、practice_loop/memory_recovery、target_isolation、no_leakage、exam_fence、evaluator_corrections、rsi_infrastructure_recovery……与论文 §4.6 三失败机制一一对应（探索/验证/记忆各有回归网）。CI（tests.yml）＋blocklist_012.txt。官方分永远在环外：audit 文件放 results/ 不进 prompt；evaluator 修正必须单列上报；infra 失败是 unscored 不是 0 分。

10 · 局限与伦理（§7 原文四条＋一条）

① 探索即成本（500 iters/10h 量级 × N 题——复现门槛首先是钱）；② 天花板＝预算＋停止策略＋记忆质量三者；③ verifier 误判会进记忆再带偏后学（§4.6 已实证，fidelity gaps 3/6）；④ 各环境组件贡献没拆开（harness vs 记忆 vs 模型，分不清）。伦理：自主探索＋执行程序＋持久记忆＝误操作/越权/隐私泄漏风险，实验限受控环境——这套东西跑在生产网就是武器化自改进 agent，落地必须配 sandbox＋审计。

11 · 落地清单（给 DWC 的六条可复用＋三条红线）

① 三权分立＋信息边界：DWC 的 judge 现在既判分又进记忆（R266 回流），可借"判分的不写记忆"——judge 只出 verdict＋findings，记忆措辞权还给执行方。
② 蒸馏→对账两步更新：DWC 的 reflect 一次写 EXPERIENCE，缺"全文 review 旧记忆修矛盾"步；T065 的 index 教训（跨分支记录要重枚举）可直接抄。
③ SATURATED 语义停止：nightbench 现在是固定 N 单，BRS 式"期望价值不足即停"可省 LLM 钱——先给 curriculum 配预算计数器。
④ 冻结＋hash 评估：DWC 的 A/B 臂现在只控 judge/ctx，记忆快照 hash（_manifest 式）可让"哪次记忆赢的"可归因。
⑤ FAIL 也学：revision_pair 已在做（R258），P5 的"失败不记成功、但留证据"措辞可直接进 prompt。
⑥ handoff 机判：Curriculum 的 WAVE/SATURATED/STALLED 三 decision＋JSON 信封是现成的机判协议，DWC 的 planner 输出可借此收敛格式。
红线 ① 引用数字必须带口径（RSI 列＝混合列、非 matched、binary 没超）——报告里不许写"开源反超闭源"不加限定。
红线 ② verifier 误判污染是已实证风险：DWC 若让 judge 直写记忆，必须配对账步，否则坏规则永生。
红线 ③ 成本量级：单题 500 iters/10h watchdog——DWC 的 nightbench 照搬前先算钱，BRS 并发 4 的 VM/端点成本另计。
