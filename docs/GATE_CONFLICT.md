## 一、★★★ 先说裁决结果

```text
★★ "HarnessX 与 Self-Harness 的门互相矛盾" —— **这个说法不准确，需改写**。

两篇的门**并不矛盾**，它们约束的是**不同的粒度**：
  HarnessX    seesaw 约束: "the candidate **must not regress any previously solved
                            task** recorded in 𝒯_t"

⇒★⇒ "取并集"这个动作本身就是错的: 两个门不是同层的两个选项,
  而是**同层的一个门的两个判据**
⇒ 而"并集能否同时满足"这个问题也随之消解: 它们不是两个约束, 是一个约束的两种粒度
```

## 二、★★ 真正的冲突在哪（HarnessX 自己用它自己的失败证明了）

### 2.1 HarnessX 的 seesaw 约束被自己的实验击穿（原文逐字）

```text
★★★★ 两处独立实测, 都是"门通过但系统退化":

① τ³-Bench Telecom (Section 6.6):
   "five consecutive same-type edits (R2–R6) accumulated **sub-threshold coupling
    undetected by the seesaw constraint**; the sixth edit (R7) triggered a visible
    **−14.0% regression**, yet **no individual edit violated the constraint**"

② 提醒器实验:
   "The sixth reminder degraded compliance from **94.7% to 80.7% (−14.0%)** …
    This regression **evaded the seesaw constraint** because
    **pass@2 registers only per-task binary flips, not sub-threshold coupling**"

★★★ ⇒★★ seesaw 约束的**结构性盲区**（不是实现缺陷, 是设计层面的）:
   · 它只看"已解决 vs 未解决"的**二值翻转**
   ⇒ 连续的小幅退化（同类型编辑反复叠加）**永远不触发**
   ⇒ 与母巢 score_in 的"量化阶梯内 gain 恒 0"是**同一类病**（不同表现）
   ⇒ 而 HarnessX 提的解法是 **variant isolation（变体隔离）**:
     "the seesaw constraint **rejects it, protecting stability but discarding a
      locally beneficial change**"
     ⇒ ★ 即: 它承认 seesaw **过严** ⇒ 用"分叉成多个变体"替代"否决"
```

### 2.2 Self-Harness 的双 split 是否有同样盲区

```text
★ Algorithm 1 line 13 的判据是**聚合分数**: Δ_in ≥ 0 ∧ Δ_ho ≥ 0 ∧ max > 0
  ⇒ 逐任务的"过了又掉"在**聚合后互相抵消** ⇒ 同样看不见 sub-threshold 退化
★ 但它比 seesaw 多一道: **held-out 不得下降**
  ⇒ 这能抓住"整体在 in 上变好、ho 实际变差"
  ⇒ ★★ 但抓不住"两个 split 都微涨、某些任务微跌"
  ⇒ ⇒ 结论: **双 split 与 seesaw 有同一个盲区, 不是互补**
```

### 2.3 ★★ 真正的三条冲突（都可裁决）

```text
冲突① 粒度: seesaw = per-task; 双 split = 聚合分数
  ⇒ 二者不是"取并集", 而是**同层的两种粒度**
  ⇒ ★★ 聚合会掩盖逐任务退化（2.2 已证）
  ⇒ ⇒ 裁决: **以逐任务为准, 聚合只作补充**

冲突② 严格度: seesaw 严到"丢一个局部有益改动就整体否决"
  ⇒ HarnessX 原文承认这点, 用 variant isolation 解决
  ⇒ ⇒ 裁决: DWC 不做变体隔离（架构更重）, 但**必须有归档态**兜住被否决的局部有益改动
     ⇒ ★ 这正好接上 §9 第 25 项 (c) 的三态保留「入 archive 待选」
     ⇒★★ ⇒ 三态保留从"enhancement" 升级为**跨篇冲突的解法**

冲突③ sub-threshold 累积: 两篇都看不见
  ⇒ HarnessX 实测: 5 次同类型编辑累积 → 第 6 次显性 −14.0%
  ⇒ ⇒ 裁决: 必须加**累积口径**的第三道判据（见 §三）
```

### 3.1 ★ 第⑦步的判据形式（本裁决的核心产物）

```text
★ 依据: HarnessX 的 −14.0% 实测（5 次同类型编辑累积, 第 6 次显性）
★ 形式: 对每个保护组 j, 检查**连续 N 轮的逐组退化趋势**
  ∀j: (连续 N 轮中, 组 j 的「非翻转退化」累积量) ≤ Λ_j
  其中「非翻转退化」= 该任务仍被判 solved 但**分数下降**的部分
    （pass@2 的二值信号看不见它 —— 这正是 HarnessX 的盲区）

★★ 为什么这道必须单列, 不能并入 ④:
  ④ 看的是 split 聚合分, 无法区分
    「一组任务真变好」 vs 「另一组微跌但被前者盖过」
  ⇒ 必须有一个**逐组**的量, 且它看的不是翻转而是**分数**本身
★ 与 §9 第 25 项 (c) 的分工:
  25(c) 的 r̂_{t,j} ≤ ϵ_j 是**截面**（当前低于历史峰值多少）
  ⇒ ★ 第⑦步是**趋势**（连续累积的方向）⇒ 两者互补, 不重叠
```

## 八·bis、★★★★★ 立论降级（2026-10-04 第二轮，实测推翻）

```text
★★★ 本文档 §2.3 / §3.1 的立论**须降级**（实测见 TASK_SCORE_TRACKING §七）:

      —— 该措辞隐含"它比 seesaw 灵敏得多"

  ⇒⇒ ★★ 第⑦步**不可能**检出"小于一个断言"的退化

  ⇒ 它比 seesaw **更严**（不需要跌破 PASS_AT 就算）
  ⇒ 但它**不比 seesaw 灵敏**（最小可观测量同为 1/n）
  ⇒⇒ ⇒ 它是"**更严的 seesaw**", 不是"无限灵敏的探针"

★★★ 混合场景实测仍然成立, 但要加限定:
  ✓ seesaw 看不见 · 双 split 看不见 · 第⑦步看得见
  ★★ 但若那组微跌的幅度 < 1/n_assertions, 第⑦步**也**看不见
  ⇒ ★★ 本文档 §九 的结论须读作: "在幅度 ≥ 1 个断言时, 第⑦步是唯一可见的"

★★★★ 另一处更严重的问题: Λ 的取值
  实测 median(n_assertions)=2 ⇒ 1/median = 0.5
  ⇒ Λ ∈ {0.01, 0.03, 0.10, 0.33} 全部 < 0.5 ⇒ **死判据（物理上不可能触发）**
  ⇒⇒ ★★ 若沿用我在 §3.1 隐含的 Λ=0.03, 第⑦步**永远不触发**
  ⇒⇒ 修正: Λ 须锚在 1/median 量级, 或改用"掉了几个断言"的**计数口径**
```
