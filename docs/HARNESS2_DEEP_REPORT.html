0 · 一句话结论

这篇论文直接指出 DWC 现在做错了一件事。
它实测：直接改 harness、不看参考执行 / 候选探针 / 库 ⇒ 性能反而下降 （WB-code 73.4 → 63.2）。而 DWC 的进化轮正是这个模式：读签名 → 起草 → 试跑， 并且把上一轮的 p.code 当作下一轮的起草起点 —— 这是论文明确反对的继承。
它给出的替代方案是两层递归：任务级用「对比式探针」，harnessing 级用「改进库」。

核心问题

Can recursive self-improvement improve both the current harness and how future harnesses are improved?

两个开放世界的难题：

  • 没有 ground truth：任务在 harness 设计时未见过，测试时也是新的，没有可靠的验证器
  • RSI 高度任务特化：为一个任务改好的 harness 到下一个任务就失效

2 · 两层递归（核心贡献）

层级改什么怎么改何时更新
任务级执行 harness（当前任务的运行时）对比式 Propose–Probe–Compose；可并行（宽 k）或串行（深 k）任务内
Harnessing 级改进 harness（改进机制本身）反思整个改进过程 → 把采纳的 harness + 经验写进库每个任务结束后
关键区分：执行 harness 是被改进的系统；改进 harness 是改进它的机制。 任务级递归期间改进 harness 保持固定，任务结束后才通过"库"更新。

这条定义直接对应 DWC 的 meta_evolution（R438 #14）—— 但 DWC 只实现了"调一个旋钮"（auto_apply_max_per_round），没有"改进器带库"。

3 · 任务级递归：对比式 Propose–Probe–Compose

3.1 三步

步做什么关键细节
Propose先拿一次参考执行，再提两个候选 invariant 候选针对跨领域的通用缺陷（规划/工具/上下文/委派）；domain 候选针对当前领域的知识、流程、约束
Probe在同模型同环境下跑每个候选 与参考执行对比得到行为对比：缓解 / 无变化 / 引入回归。不是验证正确性
Compose读参考、候选、diff、全部本地证据，形成后继 harness 可合并、可改写冲突、可选其一、可保留原样；每个决定都要绑定一个具体观测

3.2 并行 vs 串行

形态机制论文结果
并行（宽 k）收集 k 次参考执行，独立提 k 个 invariant + k 个 domain 候选，k 个组合会话各拿到完整候选池WB-code 76.5 → 80.8；WB-office 79.5 → 83.4
串行（深 k）链式 k 步，每步以上一步的 harness 与累计历史为条件k=2 时在 Code 上更高；k=5 时整体低于并行
两种形态在 k=2 时就超过所有基线在 k=5 的成绩 —— 说明"递归改进 harness"比"单纯增加推理预算"更有效。 对照：Harness Scaling 在 k=2→3 时回退。

3.3 最终选择

k>1 时由一个 agentic selector 比较匿名化的交付物，只能选一个现有输出， 不能改写、不能合成新内容。选中的 harness 记为 H*（星号表示"被采纳"而非"已验证最优"）。

4 · Harnessing 级递归：改进库

4.1 库的形态（`core/library.py` 实测）

<root>/<run-tag>/<mode>/<domain>/
    INDEX.md                                  # 每条一行 cue
    harnesses/<task>/harness/<rel>            # 采纳的完整树（不是摘要）
    harnesses/<task>/EXPERIENCE.md            # cue / lesson / evidence / confidence

4.2 四条硬规则（全部可读代码验证）

#规则代码证据
1缺证据不入库：cue/lesson/evidence 三项任一为空 ⇒ 直接返回 Nonelibrary.py:43-47,120-121
2防泄漏：写库前断言树与 EXPERIENCE 里没有 grader verdictlibrary.py:122-123
3只保留当前任务之前的条目（防未来信息泄漏）library.py:101-104
4存整棵树，不存摘要（"The whole tree is carried, never a summary"）library.py:22-23

4.3 反思的门槛

"Lessons are retained only when supported by execution contrasts; selecting an output alone does not establish transferability."

这句话是整篇最硬的一条纪律：选中一个结果，不等于它能迁移。 必须有执行对比支撑，才允许写成经验。

4.4 选择性复用，而不是继承

下一个任务从共同的 H0 开始，不是从上个任务改好的 harness 开始。 库里的组件通过 Propose 被按需复用或改写。

这正是 DWC 做反的地方。DWC 的 Mutator.propose 把上一轮的 p.code 当作起草起点 —— 这是"继承"。论文实测直接继承会掉分（见 §5.3）。

5.3 ★ 最重要的一条（对 DWC 的直接警告）

直接改基础 harness，不看参考执行 / 候选探针 / 库：

WB-code   73.4 → 63.2    (−10.2)
WB-web    69.9 → 65.0    (−4.9)

加上 k=1 的库 ⇒ 只能"恢复"到基线
加上 k=5 的库 ⇒ 才开始产生 +0.9 / +4.4 / +5.1 的增益
读法："直接编辑"不是"效果差一点"，而是负收益。 库不是锦上添花，它是把负收益拉回零、再往上走的前提。

5.6 同模型当编辑者

五个模型（GLM-5 → Claude Opus 5）在三个基准上全部提升。 Opus 5 在 WB / JB / LAB 上 +3.3 / +5.5 / +3.0；GLM-5 在 LAB 上 +13.7。

结论：harness 改进不需要比执行器更强的编辑器。 这对 DWC 很重要 —— 它现在用的就是和任务同一档的模型。

5.7 案例（JobBench）

基线 43.1，轨迹显示的是流程失败而非知识缺口：数字从未跨文件核对，产出写完后从未重开验证。 两个干预：

  • invariant：流程级护栏 —— 强制盘点所有输入、把数字追到确切来源、用脚本重开产出核对
  • domain：领域技能 —— 提供日程/场地/人力/预算文件的核对机制，加数字格式的工具指引

组合后重跑 77.8（+34.7）。

6.2 值得抄的两个工程细节

① 无效树回退（D.2）

树不合法（技能无触发句 / 脚本不编译 / 引用未打包的 helper）
  ⇒ 带校验消息重试一次
  ⇒ 再失败 ⇒ 继承起始树，并记录 fallback

这是"失败也要留痕且不炸整轮"的标准做法，DWC 的 `trial` 目前是 fail-closed 直接返回 None。

② 通道与模型必须成对覆盖

if (kind is None) != (model is None):
    raise ValueError("channel and model must be overridden TOGETHER")

理由写得很直白："a bare-id/provider-prefixed mismatch fails silently downstream"。 这正是 DWC 反复踩过的"配置写了但不生效"那类坑。

7 · DWC 能学到什么

7.1 六项采纳

机制DWC 现状阶段
两层递归（执行 + 改进）meta_evolution 只调一个旋钮P4
对比式探针只比分数，不比行为P1-c
双候选作用域（通用/领域）不区分能力缺陷与领域知识P2 扩展
改进库（全树 + 经验）有 lessons/skills，无捆绑P4
证据门槛已有"不可复现不进候选"，但可更严P4
选择性复用而非继承做反了：p.code 当下轮起点P1-c 前置

7.2 三项拒绝

机制理由
并行递归 k=5成本 ×5；DWC 日预算 96/80 吃不下。串行 k=2 可作为 P4 可选项
8 组件文件级重写DWC 对象是配置/规则级，改文件树会破坏 19 对象隔离
无效树回退（照搬）DWC 没有"树"概念；但"失败留痕不炸轮"的精神可借

7.3 对 DWC 最重要的三条结论

① 直接编辑是负收益
DWC 现在的进化模式（读签名→起草→试跑，继承上轮 code） 正是论文实测会掉 10 分的做法。P1-c 必须先做。
② 库是前提不是装饰
k=1 的库只能把性能拉回基线；要正收益必须积累到 k≥5 的探索量。 所以 P4 不能省，但要接受"前期只有恢复、没有提升"。
③ 不需要更强的编辑器
五个模型全部提升，GLM-5 在 LAB 上 +13.7。 DWC 用同档模型做编辑者是可行的。

7.4 与 HarnessPro 的关系

维度HarnessProHarness²DWC 取谁
目标性能 + 成本性能（开放世界）成本取前者，递归取后者
反馈LLM 生成测试行为对比（无判据）DWC 有真值，用真值 + 行为对比
跨任务不跨（每轮重来）库 + 经验取后者
候选数3 计划 × 3 rollout2 候选（通用/领域）× k取"2 候选"，不取 k=5
