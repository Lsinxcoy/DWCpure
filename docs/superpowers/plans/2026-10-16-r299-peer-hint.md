# R299 · adopt 门 feeding：code 路 held_out 缺席根治（plan）

## 1. 根因（实测，非推测）

手动 apply 轮（2026-10-16，r298_apply2.log）：

- 簇 1（报数路）：`drafted=false`，起草 3 次全废（LLM 输出无可用 JSON）
- 簇 2（写码路）：`drafted=true, trial success=True, mode=code`，但 `adopt=blocked`，`landed=false`，rules.json 未落

门逻辑（`evolver.py:accept`，R27）：`b_ho/c_ho` 任一 None ⇒ `blocked`。
`c_ho` 即 trial dict 的 `held_out`，来自 `_peer_held_out_code`
（LLM 为 peer 题重写码 → 沙箱跑 → `held_out_score` 本地判）。
免费模型 peer 写码失败率高 ⇒ ho 常 None ⇒ 门恒 blocked。

关键结构事实：

- 判分本身是本地的（`held_out_score→evaluate(split=TEST)→_diff` 真源，judge 零改，R295 纪律 intact）
- LLM 环节的真正价值是**跨题翻译**（dev `average` → peer `str_002` 不同函数名/语义，直接套跑必缺函数 → `run_code_observed` 回 None）
- 所以"peer 去 LLM 化"不可行（A 否决）；降门（B 否决，动判定）；加 attempts（C 治标）

## 2. 方案（B：trial 成功码喂 peer 当 few-shot）

`_peer_held_out_code(judge, llm, task, max_tokens)` 加可选参 `hint_code=None`：

- 非空时拼进 `_peer … prompt`："已验证对的 dev 解（同族思想，仅供参考，按 peer 签名重写）"
- trial 成功码是**本轮已验证**的算法，翻译成功率 > 从零写
- hint 缺席/空 ⇒ 老路（prompt 不变，行为零变）
- ho 仍 None ⇒ 门仍 blocked（门语义零改，不降门）

附带（报数路起草 3 全废）：R294 已证伪报数通道，code 路是主路；
本 R 报数路 prompt 不动（不动判定、不动起草语义，只修 feeding）。
