# R301 · 问答任务死循环三修（A+B+C 全做）

## 1. 实证根因（session 现场，非推测）

- 第一问（自进化"对你有影响吗"，T_1016_170253）：开放主观问→首步空 op→
  R4 形状非法→revision 硬塞 `run ls -la`→字符串非 argv→失败→第 2 轮 final
  编借口交差（"任务太开放无可验证答案"）。
- 第二问（6 轮上限，T_1016_170342）：62 轮耗尽。read 同 path（LLM 每次
  limit=1）→3 次后 R1 noisy→`_revise_step` 建议"换路径/换参数"→LLM 出
  grep→Windows 无 grep→FileNotFoundError→绕回 read→再 R1……僵尸循环。
- 根①（A）：R1 去重键=(op,target)，不看 args。R247 修了翻页（offset/limit），
  但去重没跟上——翻页=重复，修了个寂寞。
- 根②（B）：`_revise_step` prompt 不感知平台。"换一条路径/换参数/换动作"
  在 Windows 下 LLM 首选 grep/ls（训练偏好），而执行器只认 argv+Windows
  无此命令——建议者与执行器对平台认知不一致。
- 根③（C）：执行器假设"任务皆可执行验证"。问答任务的完成标准就是答案本身，
  系统无"零工具步直答"通道——用执行器的尺子量问答者（与 R300 门量错对象同构）。

## 2. 方案

### A. R1 去重键加参数指纹（step_judge.py）

- `_tgt` 扩展为 `(op, target, args指纹)`：read→path+offset+limit；run→argv
  全串；其余→target 原口径。
- 同 (op,target) 但 args 不同⇒不算重复（翻页放行）；同 (op,target,args)
  ≥2⇒R1（真复读仍砍）。
- R1 注释"连续 ≥2"与实现 `len(same)>=2` 对齐说明（实现是"历史有 2 即判"，
  注释"连续"——核对 recent_obs 只取近 6 轮 obs，连续性隐含；注释补一句即可，
  不改阈值）。
- 老测若断言 R1 why 文案⇒同步期望（只改期望）。

### B. revise 平台感知（task_exec.py::_revise_step）

- prompt 加一句平台子句：Windows（`os.name=="nt"`）⇒
  "本机 Windows 无 grep/ls/curl 管道：搜索文件用 python -c（os.walk），
  命令必须是 argv 列表"；POSIX 原样。
- 不动执行器（`_do_action` 白名单不动），只修建议者——建议与执行对齐。
- 另：`ls -la` 字符串案是 LLM 形状错，validate 已挡（R4）——B 修后 LLM
  被明示 argv，该类错应下降；不另加规则。

### C. 开放问直答通道（task_exec.py 主循环＋step_judge.py）

- 任务分流（进主循环前，一次 LLM 分类，零工具成本用规则先筛）：
  规则：任务含"觉得/是否/为什么/是什么/介绍/有没有"且无"执行/跑/修/查/写/
  落盘"动词⇒`qa_mode=True`。误判⇒走原执行路（fail-closed：规则只放行纯问句，
  边界任务走执行路，老路零变）。
- qa_mode 下：首步即允许 final（judge 对 final 本就不判——"final 不判"已在
  step_judge；主循环放行首轮 final，不强制先动作）。
- 防编答案（C 的门，不降标准）：qa final 须带 `cites`（依据：读过的 path /
  回答依据的已知事实）；`validate_step` final 分支加：qa_mode 下 answer 为空
  或长度<10⇒非法（空交差挡掉；内容真实性由调用方/用户判——系统只保"非空"，
  不保"对"，诚实边界写进注释）。
- 非 qa 任务零变（execute 路 op/final 流程不动；R4 仍砍空 op）。
