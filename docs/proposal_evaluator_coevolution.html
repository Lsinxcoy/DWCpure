① 裁决与两篇的作用域调和 — 冲突在作用域, 不在对错

裁决（用户拍板）: 评估器共演化 做 —— 理由: 进化要彻底到连进化 方式与评估标准一起进化, 更符合 RSI。
方案义务（R98 §⑨②原文）: 「开 = 先改判据设计」且「dep(z) 与 epoch/checkpoint 必须同批设计」⇒ 本稿 = 该判据设计（E0）。
两篇看似冲突, 实际作用域不同（本稿最锋利的论点）:
篇它固定/演化的是什么原文依据
Recuris
2608.24876		 固定 = 记忆 patch 的验收门 𝒢_fixed（外部验收边界包住递归的记忆 控制层）; 递归改记忆, 验收判定者不动 "The fixed gate provides an external acceptance boundary around the recursively evolving memory-control layer"; 𝒟_dev 含 anchor tasks; test/trajectories/scores never enter localization/patch/admission
RQGM
2606.26294		 演化 = 评估器（打分标准）, 但 epoch 内冻结 + 换界只按 独立 ground-truth anchor 的 best-belief 比 + 平票判在位者 + 换掉 slot 的效用记录选择性抹除 "only at checkpoints and only by anchor best-belief"（Algorithm L22–27）; "freeze within epoch"; "selective erasure"
⇒ 共同点 = 两篇都固定独立锚（Recuris 的 anchor tasks / RQGM 的 ground-truth anchor）。真正的硬约束不是「评估标准永不进化」, 而是 「锚永不进化」+「验收边界外部化」 — RSI 的彻底性在锚之上的层实现。

② RQGM 四件套（精读原文细节 — 执行轮直接照抄的骨架）

机制一：epoch 内评估器冻结 — 搜索切成 epoch, epoch 内 evaluator frozen（保住 HGM 的逐 epoch 收敛保证）; Algorithm 1 L22 注释逐字: "只在 checkpoint 上、且只按 anchor best-belief 换评估器"。

机制二：challenger vs 在位者同锚比 —
BB_ε(a) = I⁻¹_ε(1+S_a, 1+F_a)　（Beta 后验 ε 分位 = 以概率 1−ε 被超越的保守下界）
e★ ← Best(Γ_m, BB; tie = 在位者)　（平票判在位者 — 保守原则）
机制三：换代即选择性抹除 — 评估器换掉后 EraseSlotRecords(T, m); RecomputeCMPStats(T)（被换 slot 的 效用记录抹除并重算统计）— 这就是 dep(z) 在 RQGM 的形式 （RUMINATE 探针③: dep(z) 两篇独立命名同型 = RQGM + Metis invalidate, 从直觉升级为「文献已知做法」）。

机制四：指数 checkpoint（power-of-two, 把重处理压到 O(B)）+ 训练分只做 lineage 证据。

实测（论文数字）: Polyglot 用 1.35×–1.72× 更少搜索 token 把 held-out 通过率 69.9%→71.7%; writer 接收率 21.8%→40.5%; 对抗目标把 reviewer 校准到人机一视同仁。
论文自报限制: 无 p 值/多 seed 显著性、被抹除证据的累计 regret 未实测 — 引用时如实带。

③ 𝒢_fixed 三性质 — 判据要改哪句, 先看清它保护什么

DWC 现状判据（judge.py 文档头逐字, RQGM 精读亦引）: 「★ 它不进递归（2608.24876 §5.1.1 硬要求: "𝒢_fixed 不能进递归。 递归改记忆，判分器不动。"）」— 全仓 grep 无 challenger→judge 替换路径。 RQGM 精读判定:「缺（且是判据层面刻意的缺）… 要搬必须先改判据而不是加 代码」— 本稿就是「先改判据」的那一步。
Recuris 𝒢_fixed 保护的三件事（§2.3.3 精读）: 
① 外部验收边界 : 判定者固定 ⇒ 记忆层不能自改准入标准（防自我放行）
② 锚点任务回归 : 𝒟_dev = held-out anchor tasks — 回归判据=不破坏已会做的
③ 三重隔离     : test / trajectories / scores 从不进 localization、
                 patch generation、admission
递归边界（Eq.10 明列）: 固定 base LLM + 𝒜_fixed + 𝒫_fixed + 𝒢_fixed
逐条核对: 哪些在「评估器共演化」下仍然要保? ① 保 — 记忆 patch 的验收门照旧外部化（验收门 ≠ 评估器: 门判 「这个改动能不能进」, 评估器判「这个行为得几分」— 两个对象）; ② 保 且加强 — 锚任务是 challenger 比对的场地（两篇共同点）; ③ 保 — test 隔离原样（DWC 的 SPLIT_TEST「metric 演化不许读」字面）。 ⇒ Recuris 真正禁止的只是「验收门自身被递归改写」, 不禁止评估策略层 在锚约束下演化 — 判据重述见 §④。

④ 分层判定 — 判据重述（「先改判据设计」的字面落点）

层对象判定依据
L-inner 锚 golden 对值比对 · TRUTH_SOURCE 文件 · SPLIT_TEST 锁定集 永不进化 两篇共同点; 锚进化 = 无真值 = 自己给自己判分（S3Gym 自评 0.496≈抛硬币 的实测反面）
L-gate 验收门 patch admission（𝒢 式外部边界）· 三层验证 pytest/gate/e2e 外部化保持 Recuris 三性质①③; 生产门裁决归用户（既有纪律）
L-mid 评估策略 dev 内任务权重 · 门槛 · pass^k 口径 · 回归判据的参数 · challenger 评估器本体 可共演化 RQGM 主张; RSI 彻底性层 — 但必须过 §⑤epoch 合同 + §⑥dep(z) + challenger 准入门
L-outer 元评估 R100 meta-eval（macro-F1=1.0 实测）· 锚回归一致率 challenger 准入门 新评估器上岗前先过 meta-eval + 锚上与在位者同场比对; 1−ε Beta 下界 留位（T5-5 半有, 无核口径不发明）
judge.py 判据声明的重述（E1 执行轮改字面, 本稿是设计）: 
旧（现状）: "判分器不进递归。递归改记忆，判分器不动。"
新（分层）: "**锚与判分执行**（golden 对值比对 / TRUTH_SOURCE /
            SPLIT_TEST）不进递归; **验收门外部化**（patch admission +
            三层验证）不可自改; **评估策略层**（dev 权重/门槛/口径/
            challenger 评估器）可经『epoch 内冻结 + 点界 challenger
            对锚比对 + 平票在位者 + dep(z) 抹除』共演化 — 依据:
            RQGM 2606.26294 四件套 + Recuris 2608.24876 三性质的作用域
            拆分（设计稿④ R112, 用户裁决: 做）。"
⇒ 这是"改判据而非加代码"的顺序: 判据声明先行, 代码后动（E1）。

⑤ epoch/checkpoint 合同（同批义务 — 方案原文）

epoch 定义 : term 批 = 2^n（power-of-two, RQGM 指数 checkpoint 同款;
             DWC 落点 = run_term 计数, CostLedger 已有逐 term 账可定界）
段内合同   : evaluator_frozen = true — 段内任何评估器改动非法
             （六段档 evaluation_config.judge_frozen 字段已在, E1 把它
              从"记录"升为"约束": 段内改评估器 ⇒ 构造期 raise）
点界动作   : ① challenger 提案（评估策略层任一键的修订）
             ② challenger vs 在位者: 同锚同任务集对拍
                - 准入: meta-eval macro-F1 ≥ 在位者 − δ（δ 初值待校准）
                - 比对规则: 平票判在位者（RQGM 字面, 保守）
             ③ 赢 ⇒ 换代: 新评估器治理下一 epoch + dep(z) 抹除（§⑥）
             ④ 输 ⇒ 在位者续任, challenger 记录归档（不静默丢 — G7）
checkpoint : 与 el_sched 代/环境两级推进的"代"对齐（B=8, τ=6/8 已有
             分段推进形状）— 段界才可换 = RQGM/T5-6 的"段内冻结段界换"
             （DWC 现状半有: 有分段推进, 缺"段内判据冻结"合同 ⇒ 本稿补）
成本: challenger 对拍 = +2–4 次 matched 跑（同稿②协议）, 计入 CostLedger（§3.6.5 评估成本入预算字面）; 不常发（点界才跑）。

⑥ dep(z) 定向失效 — 与裁决① HCE 合流（同一份记录两处用）

dep(z) 语义（RQGM selective erasure + Metis invalidate 同型, RUMINATE 探针③: 文献已知做法, 两篇独立命名）: 换评估器 ⇒ 只抹依赖该评估器的记录, 其余历史不动。
DWC 落点（六段档指纹驱动 — R109 已埋的字段正好是依赖记录）: 
依赖声明 : 每份知识档的 inheritance.evaluation_config 带
           {truth_sha8, judge_fingerprint, epoch_id}   ← E1 加 judge 指纹
换代时   : dep(z) 扫描 — evaluation_config.judge_fingerprint == 旧评估器
           的档/分数 ⇒ 置 status="deprecated_by_evaluator_change"
           + 记 {old_judge, new_judge, at, gen}
           ★ 不物理删（Humanlaya 版本化 — 历史可审计）只改有效性状态
消费规则 : 汇报/报表只统计 status≠deprecated 的分数; 被弃分数仍可查
           （带弃置标注）— 与 RQGM "discarded" 同义但保留轨迹

与裁决①(HCE 第三段)的合流:
  HCE 要拆 dev 的搜索/选择信号 ⇒ split 结构变更同样触发 dep(z)
  （split 是 evaluation_config 的一员 — 指纹变 ⇒ 依赖旧 split 的分数同弃）
  ⇒ 一份 dep(z) 记录机制同时服务「评估器换代」与「split 重组」,
    E1 只建一次（方案义务"同批设计"的最省实现）

⑦ 旧分弃置与历史可比性（动 eval 结构的声明义务）

可比性规则:
  同 judge_fingerprint + 同 truth_sha8 + 同 split ⇒ 分数可横比
  任一不同 ⇒ 不可横比（报表分栏, 不混算 — R99 truth_sha8 口径延伸）
弃置三态: active | deprecated_by_evaluator_change | deprecated_by_split_change
声明义务: 换代轮的六段档 acceptance_decision 必带 "historical_comparability":
          {broken_since: gen, reason, dep_scan: {n_deprecated, refs[]}}
          —— "历史分数可比性受影响" 从裁决①的警告变成**结构化字段**
报告纪律: 跨换代的趋势图必须断开（不连不可比的两段 — 禁止视觉误导）
这就是方案说「影响一切历史分数可比性」的正面处置: 不是不碰, 是碰了以后让不可比性可见、可查、可分栏 — 装作可比才是真危险。

⑧ 渐进 E0→E2 — 先记录层, 后换代层

级内容验收（进执行轮写死）
E0 本稿 判据分层设计 + epoch 合同 + dep(z) + 可比性规则过审（用户）
E1 记录与约束层 judge.py 判据声明重述（§④）· 档加 judge_fingerprint+epoch_id · dep(z) 扫描器（deprecated 置位）· 段内评估器改动构造期 raise · 报表分栏（弃置分不混算） □ 判据声明字面 = 本稿 §④（逐字比对）
□ dep(z) 破坏测试: 换指纹⇒依赖档被置 deprecated, 其余不动
□ 段内改评估器⇒raise 探针
□ 六段链连续 + 三层 + 同批自洽
□ 本级不引入任何评估器换代（纯记录/约束, 零行为风险）
E2 首次换代（真正开演化） challenger 机制 + 点界对拍 + 平票在位者 + 换代 dep(z) 联动 + 首个非默认评估器提案（如 dev 权重修订） □ challenger 准入=meta-eval+锚对拍跑通（对拍脚本可复跑）
□ 平票判在位者断言 · 输者归档不静默
□ 换代后历史分弃置清单 + 可比性字段齐全
□ 首次换代结果呈用户过目后才常态化（生产门纪律延伸）
E1 零行为风险的设计意图: 记录层先落, 换代层后开 — 即使 E2 最终被 叫停, E1 的 dep(z)/指纹/分栏对现有体系是纯增益（可比性从隐式变显式）。

⑨ 诚实条款

1. 本稿无实测 — E0 纯设计; challenger/换代的数字在 E2 执行轮, 且 1−ε Beta 下界留位不发明（T5-5 半有, 无核口径）— 准入暂用 meta-eval+锚对拍, 标注为最小替代。
2. RQGM 实测的引用边界: 69.9→71.7 等数字是 Polyglot/writer 域, 与 DWC 域不同 — 不外推; 其「无多 seed 显著性」自报限制一并带。
3. S3Gym 反面弹药在位: 自评 0.496≈抛硬币、ρ(A,g)=−0.010 ⇒ challenger 永不许只靠自评 — 锚对拍是硬门（分层表 L-outer）。
4. 𝒢_fixed 重述的边界: 本稿只重述作用域（验收门≠评估器）, 不解除「验收门外部化」与 test 隔离 — Recuris 三性质①②③全保。
5. E2 首次换代须呈用户（本稿按方案义务设计, 但第一次真换标准的 执行轮结果呈你过目 — 评估标准变化的影响面太大, 不默认常态化）。
